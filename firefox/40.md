# Firefox 40 release notes for developers

[To test the latest developer features of Firefox, install Firefox Developer Edition](https://www.firefox.com/en-US/channel/desktop/developer/ "External link (opens in new tab)") Firefox 40 was released on August 11, 2015. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [CSS](#css)

*   Prefixed rules (`-moz-`) for [`text-decoration-color`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-color), [`text-decoration-line`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-line), and [`text-decoration-style`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-style) have been removed ([Firefox bug 1097922](https://bugzil.la/1097922 "External link (opens in new tab)")).
*   The property [`text-align`](/en-US/docs/Web/CSS/Reference/Properties/text-align) now supports the `match-parent` value ([Firefox bug 645642](https://bugzil.la/645642 "External link (opens in new tab)")).
*   In Quirks Mode, [`empty-cells`](/en-US/docs/Web/CSS/Reference/Properties/empty-cells) now defaults to `show`, like in standard mode ([Firefox bug 1020400](https://bugzil.la/1020400 "External link (opens in new tab)")).
*   The [`-moz-orient`](/en-US/docs/Web/CSS/Reference/Properties/-moz-orient) non-standard property, used to style [`<meter>`](/en-US/docs/Web/HTML/Reference/Elements/meter) and [`<progress>`](/en-US/docs/Web/HTML/Reference/Elements/progress) element has been adapted for vertical writing-modes: the value `auto` has been dropped and the values `inline` and `block` added, with `inline` being the new default value ([Firefox bug 1028716](https://bugzil.la/1028716 "External link (opens in new tab)")).
*   The property [`font-size-adjust`](/en-US/docs/Web/CSS/Reference/Properties/font-size-adjust) has been fixed so that `0` is treated as a multiplier (leading to a `0` height for the font, hence hiding it) instead of the `none` value (leading to no adjustment, or a `1.0` value) ([Firefox bug 1144885](https://bugzil.la/1144885 "External link (opens in new tab)")).
*   Fix text-overflow doesn't work in vertical writing mode ([Firefox bug 1117227](https://bugzil.la/1117227 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   Unreachable code after [`return`](/en-US/docs/Web/JavaScript/Reference/Statements/return) statement (including unreachable expression after [semicolon-less return statements](/en-US/docs/Web/JavaScript/Reference/Statements/return#automatic_semicolon_insertion)) will now show a warning in the console ([Firefox bug 1005110](https://bugzil.la/1005110 "External link (opens in new tab)"), [Firefox bug 1151931](https://bugzil.la/1151931 "External link (opens in new tab)")).
*   [`Symbol.match`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/match) has been added ([Firefox bug 1054755](https://bugzil.la/1054755 "External link (opens in new tab)")).
*   Passing an object which has a property named [`Symbol.match`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/match) with a [truthy](/en-US/docs/Glossary/Truthy) value to [`String.prototype.startsWith`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/startsWith), [`String.prototype.endsWith`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/endsWith), and `String.prototype.contains` now throws a [`TypeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypeError) ([Firefox bug 1054755](https://bugzil.la/1054755 "External link (opens in new tab)")).
*   [`RegExp`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp) function returns pattern itself if called without [`new`](/en-US/docs/Web/JavaScript/Reference/Operators/new) and pattern object has a property named [`Symbol.match`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/match) with a [truthy](/en-US/docs/Glossary/Truthy) value, and the pattern object's `constructor` property equals to [`RegExp`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp) function. ([Firefox bug 1147817](https://bugzil.la/1147817 "External link (opens in new tab)")).
*   Support for the non-standard JS1.7 destructuring for-in has been dropped ([Firefox bug 1083498](https://bugzil.la/1083498 "External link (opens in new tab)")).
*   [Non-standard initializer expressions](/en-US/docs/Web/JavaScript/Reference/Errors/Invalid_for-in_initializer) in [`for...in`](/en-US/docs/Web/JavaScript/Reference/Statements/for...in) loops are now ignored and will present a warning in the console. ([Firefox bug 748550](https://bugzil.la/748550 "External link (opens in new tab)") and [Firefox bug 1164741](https://bugzil.la/1164741 "External link (opens in new tab)")).
*   [`\u{xxxxxx}`](/en-US/docs/Web/JavaScript/Reference/Lexical_grammar#unicode_code_point_escapes) Unicode code point escapes have been added ([Firefox bug 320500](https://bugzil.la/320500 "External link (opens in new tab)")).
*   `String.prototype.contains` has been replaced with [`String.prototype.includes`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/includes), `String.prototype.contains` is kept as an alias ([Firefox bug 1102219](https://bugzil.la/1102219 "External link (opens in new tab)")).
*   If the [`DataView`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/DataView) constructor is called as a function without the [`new`](/en-US/docs/Web/JavaScript/Reference/Operators/new) operator, a [`TypeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypeError) is now thrown as per the ES2015 specification.
*   An issue regressed in Firefox 21, where proxified arrays without the `get` trap were not working properly, has been fixed. If the `get` trap in a [`Proxy`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy) was not defined, [`Array.length`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/length) returned `0` and the `set` trap didn't get called. A workaround was to add the `get` trap even if was not necessary in your code. This issue has been fixed now ([Firefox bug 895223](https://bugzil.la/895223 "External link (opens in new tab)")).
*   `WeakMap.prototype` and `WeakSet.prototype` have been updated to be just ordinary objects, per ES2015 specification ([Firefox bug 1055473](https://bugzil.la/1055473 "External link (opens in new tab)")).

### [Interfaces/APIs/DOM](#interfacesapisdom)

#### New APIs

*   The [Push API](/en-US/docs/Web/API/Push_API) has been experimentally implemented ([Firefox bug 1038811](https://bugzil.la/1038811 "External link (opens in new tab)")). Controlled by the `services.push.enabled` pref, it is disabled by default.

#### Web Animations API

Improvement in our experimental Web Animations implementation, mostly to match latest spec changes:

*   [`AnimationPlayer.currentTime`](/en-US/docs/Web/API/Animation/currentTime "AnimationPlayer.currentTime") now can also be set ([Firefox bug 1072037](https://bugzil.la/1072037 "External link (opens in new tab)")).
*   `Animatable.getAnimationPlayers()`, available on [`Element`](/en-US/docs/Web/API/Element) has been renamed to [`Element.getAnimations()`](/en-US/docs/Web/API/Element/getAnimations) ([Firefox bug 1145246](https://bugzil.la/1145246 "External link (opens in new tab)")).
*   `Animation` and `AnimationEffect` have been merged into the newly created `KeyframeEffectReadOnly` ([Firefox bug 1153734](https://bugzil.la/1153734 "External link (opens in new tab)")).
*   `AnimationPlayer` has been renamed to [`Animation`](/en-US/docs/Web/API/Animation) ([Firefox bug 1154615](https://bugzil.la/1154615 "External link (opens in new tab)")).
*   [`AnimationTimeline`](/en-US/docs/Web/API/AnimationTimeline) is now an abstract class, with [`DocumentTimeline`](/en-US/docs/Web/API/DocumentTimeline) its only implementation ([Firefox bug 1152171](https://bugzil.la/1152171 "External link (opens in new tab)")).

#### CSSOM

*   The CSS Font Loading API is now enabled by default in Nightly and Developer Edition releases ([Firefox bug 1088437](https://bugzil.la/1088437 "External link (opens in new tab)")). It is still deactivated by default in Beta and Release browsers.
*   The `CSSCharsetRule` interface has been removed and such objects are no longer available in CSSOM ([Firefox bug 1148694](https://bugzil.la/1148694 "External link (opens in new tab)")). This matches the spec (recently adapted) and Chrome behavior.

#### WebRTC

*   WebRTC: the [`negotiationneeded`](/en-US/docs/Web/API/RTCPeerConnection/negotiationneeded_event "negotiationneeded") event is now also sent for initial negotiations, not only for re-negotiations ([Firefox bug 1149838](https://bugzil.la/1149838 "External link (opens in new tab)")).

#### DOM & HTML DOM

*   When unable to parse the [`srcset`](/en-US/docs/Web/HTML/Reference/Elements/img#srcset), the [`HTMLImageElement.currentSrc`](/en-US/docs/Web/API/HTMLImageElement/currentSrc) method doesn't return `null` anymore but `""`, as requested by the latest specification ([Firefox bug 1139560](https://bugzil.la/1139560 "External link (opens in new tab)")).
*   Like for images, Firefox now throttles [`Window.requestAnimationFrame()`](/en-US/docs/Web/API/Window/requestAnimationFrame) for non-visible [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) ([Firefox bug 1145439](https://bugzil.la/1145439 "External link (opens in new tab)")).
*   [`Navigator.taintEnabled`](/en-US/docs/Web/API/Navigator/taintEnabled) is no longer available for Web workers ([Firefox bug 1154878](https://bugzil.la/1154878 "External link (opens in new tab)")).

#### Web Audio API

New extensions to the [Web Audio API](/en-US/docs/Web/API/Web_Audio_API):

*   The [`AudioContext.state`](/en-US/docs/Web/API/BaseAudioContext/state "AudioContext.state") and [`AudioContext.onstatechange`](/en-US/docs/Web/API/BaseAudioContext/statechange_event "AudioContext.onstatechange") properties as well as the methods [`AudioContext.suspend()`](/en-US/docs/Web/API/AudioContext/suspend), [`AudioContext.resume()`](/en-US/docs/Web/API/AudioContext/resume), and [`AudioContext.close()`](/en-US/docs/Web/API/AudioContext/close) have been added ([Firefox bug 1094764](https://bugzil.la/1094764 "External link (opens in new tab)")).
*   [`AudioBufferSourceNode`](/en-US/docs/Web/API/AudioBufferSourceNode) now implements the [`AudioBufferSourceNode.detune`](/en-US/docs/Web/API/AudioBufferSourceNode/detune) [k-rate](/en-US/docs/Web/API/AudioParam#k-rate) attribute ([Firefox bug 1153783](https://bugzil.la/1153783 "External link (opens in new tab)")).

#### Web Workers

*   Slight improvement in our [Service Worker API](/en-US/docs/Web/API/Service_Worker_API): the [`update()`](/en-US/docs/Web/API/ServiceWorkerRegistration/update "update()") method has been moved from [`ServiceWorkerGlobalScope`](/en-US/docs/Web/API/ServiceWorkerGlobalScope) to [`ServiceWorkerRegistration`](/en-US/docs/Web/API/ServiceWorkerRegistration) ([Firefox bug 1131350](https://bugzil.la/1131350 "External link (opens in new tab)")).
*   [`ServiceWorkerRegistration`](/en-US/docs/Web/API/ServiceWorkerRegistration) is now available in Web workers ([Firefox bug 1131327](https://bugzil.la/1131327 "External link (opens in new tab)")).
*   `DataStore` is now available in Web workers ([Firefox bug 916196](https://bugzil.la/916196 "External link (opens in new tab)")).

#### IndexedDB

*   [`IDBTransaction`](/en-US/docs/Web/API/IDBTransaction) are now non-durable by default ([Firefox bug 1112702](https://bugzil.la/1112702 "External link (opens in new tab)")). This favors performance over reliability and matches what other browsers are doing. For more information, read our [durability definition](/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology#durable).

#### Dev Tools

*   The property [`console.timeStamp()`](/en-US/docs/Web/API/console/timeStamp_static "console.timeStamp()") has been added ([Firefox bug 922221](https://bugzil.la/922221 "External link (opens in new tab)")).

## [Security](#security)

*   Using an asterisk (`*`) in a [CSP](/en-US/docs/Glossary/CSP) does not include the schemes `data:`, `blob:` or `:filesystem` anymore when matching source expressions. So those schemes now need to be explicitly defined within the related header to match the CSP ([Firefox bug 1086999](https://bugzil.la/1086999 "External link (opens in new tab)")).

## [Changes for add-on and Mozilla developers](#changes_for_add-on_and_mozilla_developers)

### [XUL](#xul)

*   It is no longer possible to create transparent top-level windows [Firefox bug 1162649](https://bugzil.la/1162649 "External link (opens in new tab)").

### [JavaScript code modules](#javascript_code_modules)

*   Dict.jsm has been removed [Firefox bug 1123309](https://bugzil.la/1123309 "External link (opens in new tab)"). Use [`Map`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map) instead.

### [XPCOM](#xpcom)

*   The `nsIClassInfo.implementationLanguage` attribute has been removed, along with the `nsClassInfo::GetImplementationLanguage()` function.
*   The following XPCOM interfaces have been removed; you should use the standard HTML interfaces instead:
    *   `nsIDOMHTMLBRElement`
    *   `nsIDOMDivElement`
    *   `nsIDOMHTMLHeadingElement`
    *   `nsIDOMHTMLTableCaptionElement`
    *   `nsIDOMHTMLTableElement`
    *   `nsIDOMHTMLTitleElement`

### [Other](#other)

*   Places Keywords API has been deprecated and will be removed soon ([Firefox bug 1140395](https://bugzil.la/1140395 "External link (opens in new tab)")).
*   The automated testing system now supports skipping individual test functions. See [running conditional tests](https://firefox-source-docs.mozilla.org/testing/xpcshell/index.html#conditionally-running-a-test "External link (opens in new tab)") in XPCShell testing.
