# Firefox 51 release notes for developers

[To test the latest developer features of Firefox, install Firefox Developer Edition](https://www.firefox.com/en-US/channel/desktop/developer/ "External link (opens in new tab)"). Firefox 51 was released on January 24, 2017. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

*   [Network Monitor now shows a "Blocked" state for network requests.](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html#timings "External link (opens in new tab)")
*   [All devtools bugs fixed between Firefox 50 and Firefox 51](https://bugzilla.mozilla.org/buglist.cgi?list_id=13263768&resolution=FIXED&classification=Client%20Software&chfieldto=2016-09-19&query_format=advanced&chfield=resolution&chfieldfrom=2016-08-01&chfieldvalue=FIXED&bug_status=RESOLVED&bug_status=VERIFIED&component=Developer%20Tools&component=Developer%20Tools%3A%20about%3Adebugging&component=Developer%20Tools%3A%20Animation%20Inspector&component=Developer%20Tools%3A%20Canvas%20Debugger&component=Developer%20Tools%3A%20Computed%20Styles%20Inspector&component=Developer%20Tools%3A%20Console&component=Developer%20Tools%3A%20CSS%20Rules%20Inspector&component=Developer%20Tools%3A%20Debugger&component=Developer%20Tools%3A%20DOM&component=Developer%20Tools%3A%20Font%20Inspector&component=Developer%20Tools%3A%20Framework&component=Developer%20Tools%3A%20Graphic%20Commandline%20and%20Toolbar&component=Developer%20Tools%3A%20Inspector&component=Developer%20Tools%3A%20JSON%20Viewer&component=Developer%20Tools%3A%20Memory&component=Developer%20Tools%3A%20Netmonitor&component=Developer%20Tools%3A%20Object%20Inspector&component=Developer%20Tools%3A%20Performance%20Tools%20%28Profiler%2FTimeline%29&component=Developer%20Tools%3A%20Responsive%20Design%20Mode&component=Developer%20Tools%3A%20Scratchpad&component=Developer%20Tools%3A%20Shared%20Components&component=Developer%20Tools%3A%20Source%20Editor&component=Developer%20Tools%3A%20Storage%20Inspector&component=Developer%20Tools%3A%20Style%20Editor&component=Developer%20Tools%3A%20User%20Stories&component=Developer%20Tools%3A%20Web%20Audio%20Editor&component=Developer%20Tools%3A%20WebGL%20Shader%20Editor&component=Developer%20Tools%3A%20WebIDE&product=Firefox "External link (opens in new tab)").

### [HTML](#html)

*   [`<hr>`](/en-US/docs/Web/HTML/Reference/Elements/hr) elements can now be used as separators in [`<menu>`](/en-US/docs/Web/HTML/Reference/Elements/menu) elements ([Firefox bug 870388](https://bugzil.la/870388 "External link (opens in new tab)")).
*   The [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) and [`<textarea>`](/en-US/docs/Web/HTML/Reference/Elements/textarea) elements' `selectionStart` and `selectionEnd` attributes now correctly return the current position of the text input cursor when there's no selection, instead of returning 0 ([Firefox bug 1287655](https://bugzil.la/1287655 "External link (opens in new tab)")).

### [CSS](#css)

*   Implemented [`:indeterminate`](/en-US/docs/Web/CSS/Reference/Selectors/:indeterminate) for <input type="radio"> ([Firefox bug 885359](https://bugzil.la/885359 "External link (opens in new tab)")).
*   Implemented [`:placeholder-shown`](/en-US/docs/Web/CSS/Reference/Selectors/:placeholder-shown) for `<input type="text">` ([Firefox bug 1069015](https://bugzil.la/1069015 "External link (opens in new tab)")).
*   The [`::placeholder`](/en-US/docs/Web/CSS/Reference/Selectors/::placeholder) pseudo-element is now unprefixed ([Firefox bug 1069012](https://bugzil.la/1069012 "External link (opens in new tab)")).
*   Fixed the [`:valid`](/en-US/docs/Web/CSS/Reference/Selectors/:valid) CSS pseudo-class which didn't match valid [`<form>`](/en-US/docs/Web/HTML/Reference/Elements/form) elements ([Firefox bug 1285425](https://bugzil.la/1285425 "External link (opens in new tab)")).
*   The `plaintext` value of [`unicode-bidi`](/en-US/docs/Web/CSS/Reference/Properties/unicode-bidi) now also works with vertical writing modes ([Firefox bug 1302734](https://bugzil.la/1302734 "External link (opens in new tab)")).
*   The `fill-box` and `stroke-box` values of [`clip-path`](/en-US/docs/Web/CSS/Reference/Properties/clip-path) are now properly supported; previously, they were aliases of `border-box` ([Firefox bug 1289011](https://bugzil.la/1289011 "External link (opens in new tab)")).
*   Clamp flex line's height (clamping stretched flex items), in single-line auto-height flex container w/ max-height (spec change) ([Firefox bug 1000957](https://bugzil.la/1000957 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   The ES2015 [`Symbol.toStringTag`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/toStringTag) property has been implemented ([Firefox bug 1114580](https://bugzil.la/1114580 "External link (opens in new tab)")).
*   The ES2015 [`TypedArray.prototype.toString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/toString) and [`TypedArray.prototype.toLocaleString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/toLocaleString) methods have been implemented ([Firefox bug 1121938](https://bugzil.la/1121938 "External link (opens in new tab)")).
*   The [`DateTimeFormat.prototype.formatToParts()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat/formatToParts) method is now available ([Firefox bug 1289340](https://bugzil.la/1289340 "External link (opens in new tab)")).
*   [`const`](/en-US/docs/Web/JavaScript/Reference/Statements/const) and [`let`](/en-US/docs/Web/JavaScript/Reference/Statements/let) are now fully ES2015-compliant ([Firefox bug 950547](https://bugzil.la/950547 "External link (opens in new tab)")).
*   Using [`const`](/en-US/docs/Web/JavaScript/Reference/Statements/const) in [`for...of`](/en-US/docs/Web/JavaScript/Reference/Statements/for...of) loops now has a fresh binding for each iteration and no longer throws a [`SyntaxError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/SyntaxError) ([Firefox bug 1101653](https://bugzil.la/1101653 "External link (opens in new tab)")).
*   The deprecated [`for each...in`](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#statements_2) loop now presents a warning in the console ([Firefox bug 1293205](https://bugzil.la/1293205 "External link (opens in new tab)")). Please migrate your code to use the standardized [`for...of`](/en-US/docs/Web/JavaScript/Reference/Statements/for...of) loop.
*   [Generator functions](/en-US/docs/Web/JavaScript/Reference/Statements/function*) can't have a [label](/en-US/docs/Web/JavaScript/Reference/Statements/label) anymore and `let` as a label name is disallowed now ([Firefox bug 1288459](https://bugzil.la/1288459 "External link (opens in new tab)")).
*   Deprecated [legacy generator functions](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features) will now throw when used in [method definitions](/en-US/docs/Web/JavaScript/Reference/Functions/Method_definitions) ([Firefox bug 1199296](https://bugzil.la/1199296 "External link (opens in new tab)")).
*   The `next()` method of the [iterator protocol](/en-US/docs/Web/JavaScript/Reference/Iteration_protocols#the_iterator_protocol) will now throw a [`TypeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypeError) if the returned value is not an object ([Firefox bug 1016936](https://bugzil.la/1016936 "External link (opens in new tab)")).
*   Child-indexed pseudo-class selectors should match without a parent ([Firefox bug 1300374](https://bugzil.la/1300374 "External link (opens in new tab)")).

### [WebGL](#webgl)

*   [WebGL 2](/en-US/docs/Web/API/WebGL_API) is now enabled by default. See [webglsamples.org/WebGL2Samples](https://webglsamples.org/WebGL2Samples/ "External link (opens in new tab)") for a few demos.
    
    *   WebGL 2 provides the [`WebGL2RenderingContext`](/en-US/docs/Web/API/WebGL2RenderingContext) interface that brings OpenGL ES 3.0 to the [`<canvas>`](/en-US/docs/Web/HTML/Reference/Elements/canvas) element.
    *   New features include:
        *   [3D textures](/en-US/docs/Web/API/WebGL2RenderingContext/texImage3D),
        *   [Sampler objects](/en-US/docs/Web/API/WebGLSampler),
        *   [Uniform Buffer objects](/en-US/docs/Web/API/WebGL2RenderingContext#uniform_buffer_objects),
        *   [Sync objects](/en-US/docs/Web/API/WebGLSync),
        *   [Query objects](/en-US/docs/Web/API/WebGLQuery),
        *   [Transform Feedback objects](/en-US/docs/Web/API/WebGLTransformFeedback),
        *   Promoted extensions that are now core to WebGL 2: [Vertex Array objects](/en-US/docs/Web/API/WebGLVertexArrayObject), [instancing](/en-US/docs/Web/API/WebGL2RenderingContext/drawArraysInstanced), [multiple render targets](/en-US/docs/Web/API/WebGL2RenderingContext/drawBuffers), [fragment depth](/en-US/docs/Web/API/EXT_frag_depth).
*   The `WEBGL_compressed_texture_es3` extension (implemented in Firefox 46) has been renamed to [`WEBGL_compressed_texture_etc`](/en-US/docs/Web/API/WEBGL_compressed_texture_etc) ([Firefox bug 1316778](https://bugzil.la/1316778 "External link (opens in new tab)")) and is no longer included by default in WebGL 2 contexts ([Firefox bug 1306174](https://bugzil.la/1306174 "External link (opens in new tab)")).
    
*   The [`EXT_disjoint_timer_query`](/en-US/docs/Web/API/EXT_disjoint_timer_query) extension has been updated to use [`WebGLQuery`](/en-US/docs/Web/API/WebGLQuery) objects instead of `WebGLTimerQuery` objects ([Firefox bug 1308057](https://bugzil.la/1308057 "External link (opens in new tab)")).
    
*   The [`OES_vertex_array_object`](/en-US/docs/Web/API/OES_vertex_array_object) extension now uses the WebGL 2 [`WebGLVertexArrayObject`](/en-US/docs/Web/API/WebGLVertexArrayObject) object instead of its own `WebGLVertexArrayObjectOES` object ([Firefox bug 1318523](https://bugzil.la/1318523 "External link (opens in new tab)")).
    
*   You can now use [`ImageBitmap`](/en-US/docs/Web/API/ImageBitmap) objects as a sources for texture images in methods like [`WebGLRenderingContext.texImage2D()`](/en-US/docs/Web/API/WebGLRenderingContext/texImage2D), [`WebGLRenderingContext.texSubImage2D()`](/en-US/docs/Web/API/WebGLRenderingContext/texSubImage2D), [`WebGL2RenderingContext.texImage3D()`](/en-US/docs/Web/API/WebGL2RenderingContext/texImage3D), or [`WebGL2RenderingContext.texSubImage3D()`](/en-US/docs/Web/API/WebGL2RenderingContext/texSubImage3D) ([Firefox bug 1324924](https://bugzil.la/1324924 "External link (opens in new tab)")).
    

### [IndexedDB v2](#indexeddb_v2)

*   [IndexedDB](/en-US/docs/Web/API/IndexedDB_API) version 2 implementation is now complete:
    *   Supports for the new [`IDBObjectStore.getKey()`](/en-US/docs/Web/API/IDBObjectStore/getKey) method has been added ([Firefox bug 1271506](https://bugzil.la/1271506 "External link (opens in new tab)")).
    *   Supports for [`IDBCursor.continuePrimaryKey()`](/en-US/docs/Web/API/IDBCursor/continuePrimaryKey) method has been added ([Firefox bug 1271505](https://bugzil.la/1271505 "External link (opens in new tab)")).
    *   Binary keys are now supported ([Firefox bug 1271500](https://bugzil.la/1271500 "External link (opens in new tab)")).
    *   See also ["What's new in IndexedDB 2.0?" – Mozilla hacks](https://hacks.mozilla.org/2016/10/whats-new-in-indexeddb-2-0/ "External link (opens in new tab)")

### [Canvas](#canvas)

*   The non-standard `CanvasRenderingContext2D.mozFillRule()` method has been removed; the fill rule can be defined using a parameter of the standard [`CanvasRenderingContext2D.fill()`](/en-US/docs/Web/API/CanvasRenderingContext2D/fill) method ([Firefox bug 826619](https://bugzil.la/826619 "External link (opens in new tab)")).
*   The [`CanvasRenderingContext2D.imageSmoothingEnabled`](/en-US/docs/Web/API/CanvasRenderingContext2D/imageSmoothingEnabled) has been unprefixed ([Firefox bug 768072](https://bugzil.la/768072 "External link (opens in new tab)"))

### [SVG](#svg)

*   Added [`tabindex`](/en-US/docs/Web/SVG/Reference/Attribute/tabindex) attribute ([Firefox bug 778654](https://bugzil.la/778654 "External link (opens in new tab)")).
*   Added [`href`](/en-US/docs/Web/SVG/Reference/Attribute/href) attribute, which renders [`xlink:href`](/en-US/docs/Web/SVG/Reference/Attribute/xlink:href) obsolete ([Firefox bug 1245751](https://bugzil.la/1245751 "External link (opens in new tab)")).
*   You can now use custom data attributes on SVG elements through the [`HTMLElement.dataset`](/en-US/docs/Web/API/HTMLElement/dataset) property and the [`data-*`](/en-US/docs/Web/SVG/Reference/Attribute/data-*) set of SVG attributes ([Firefox bug 921834](https://bugzil.la/921834 "External link (opens in new tab)")).
*   CSS Animations used in an SVG image which is presented in an [`<img>`](/en-US/docs/Web/HTML/Reference/Elements/img) element now work again; this was an old regression ([Firefox bug 1190881](https://bugzil.la/1190881 "External link (opens in new tab)")).

### [Web Workers](#web_workers)

*   The non-standard and obsolete `onclose` event handler and [`Worker`](/en-US/docs/Web/API/Worker) use of the `close` event have been removed from Firefox.

### [Networking](#networking)

*   Scripts served with an `image/*`, `video/*`, `audio/*` or `text/csv` MIME type are now blocked and are not loaded or executed. This happen when they are declared using [`<script>`](/en-US/docs/Web/HTML/Reference/Elements/script), or loaded via [`WorkerGlobalScope.importScripts()`](/en-US/docs/Web/API/WorkerGlobalScope/importScripts), [`Worker()`](/en-US/docs/Web/API/Worker/Worker "Worker()"), [`SharedWorker()`](/en-US/docs/Web/API/SharedWorker/SharedWorker "SharedWorker()") ([Firefox bug 1229267](https://bugzil.la/1229267 "External link (opens in new tab)") and [Firefox bug 1288361](https://bugzil.la/1288361 "External link (opens in new tab)")).
*   Support for SHA-1 certificates from publicly-trusted certificate authorities has been removed ([Firefox bug 1302140](https://bugzil.la/1302140 "External link (opens in new tab)")). See also [Phasing Out SHA-1 on the Public Web](https://blog.mozilla.org/security/2016/10/18/phasing-out-sha-1-on-the-public-web/ "External link (opens in new tab)") for more information.
*   New WoSign and StartCom certificates will no longer be accepted ([Firefox bug 1309707](https://bugzil.la/1309707 "External link (opens in new tab)")), see [Distrusting New WoSign and StartCom Certificates](https://blog.mozilla.org/security/2016/10/24/distrusting-new-wosign-and-startcom-certificates/ "External link (opens in new tab)") for more information.
*   The [PAC](/en-US/docs/Web/HTTP/Guides/Proxy_servers_and_tunneling/Proxy_Auto-Configuration_PAC_file) `FindProxyForURL(url, host)` function now strips paths and queries from https:// URLs to avoid information leakage (see [Firefox bug 1255474](https://bugzil.la/1255474 "External link (opens in new tab)") and [CVE-2017-5384](https://nvd.nist.gov/vuln/detail/cve-2017-5384 "External link (opens in new tab)")).

### [XHR](#xhr)

*   The [`XMLHttpRequest.responseXML`](/en-US/docs/Web/API/XMLHttpRequest/responseXML) property no longer returns a partial [`Document`](/en-US/docs/Web/API/Document) with a <parsererror> node placed at the top when a parse error occurs attempting to interpret the received data. Instead, it correctly returns `null` ([Firefox bug 289714](https://bugzil.la/289714 "External link (opens in new tab)")).
*   To match the latest specification an [`XMLHttpRequest`](/en-US/docs/Web/API/XMLHttpRequest) without an [`Accept`](/en-US/docs/Web/HTTP/Reference/Headers/Accept) header set with [`setRequestHeader()`](/en-US/docs/Web/API/XMLHttpRequest/setRequestHeader "setRequestHeader()") is now sent with such a header, with its value set to `*/*` ([Firefox bug 918752](https://bugzil.la/918752 "External link (opens in new tab)")).
*   Fixed [`XMLHttpRequest.open()`](/en-US/docs/Web/API/XMLHttpRequest/open) so that, when omitted, the `username` and `password` parameters now default to `null`, per the specification ([Firefox bug 933759](https://bugzil.la/933759 "External link (opens in new tab)")).

### [WebRTC](#webrtc)

*   The [`RTCPeerConnection.removeStream()`](/en-US/docs/Web/API/RTCPeerConnection/removeStream) method has been removed. It was deprecated back in Firefox 22, and has been throwing a `NotSupportedError` [`DOMException`](/en-US/docs/Web/API/DOMException) for a long time. You need to use [`RTCPeerConnection.removeTrack()`](/en-US/docs/Web/API/RTCPeerConnection/removeTrack) instead, for each track on the stream.
*   WebRTC now supports the VP9 codec by default. When added in Firefox 46, VP9 was disabled by default, but when enabled was the preferred codec; however, it has been moved to be the second choice (after VP8) due to its current level of CPU usage.
*   The method [`HTMLMediaElement.captureStream()`](/en-US/docs/Web/API/HTMLMediaElement/captureStream), which returns a [`MediaStream`](/en-US/docs/Web/API/MediaStream) containing the content of the specified [`<video>`](/en-US/docs/Web/HTML/Reference/Elements/video) or [`<audio>`](/en-US/docs/Web/HTML/Reference/Elements/audio). It's worth noting that this is prefixed still as `mozCaptureStream()`, and that it doesn't yet exactly match the spec.

### [Audio/video](#audiovideo)

*   Added FLAC support ([FLAC codec](https://xiph.org/flac/index.html "External link (opens in new tab)")) in both FLAC and Ogg containers ([Firefox bug 1195723](https://bugzil.la/1195723 "External link (opens in new tab)")). Supported FLAC MIME types are: `audio/flac` and `audio/x-flac`. For FLAC in Ogg, supported MIME types are: `audio/ogg; codecs=flac`, and `video/ogg; codecs=flac`.
*   Added support for FLAC in MP4 (both with and without MSE) ([Firefox bug 1303888](https://bugzil.la/1303888 "External link (opens in new tab)")).
*   Throttling in background tabs of timers created by [`Window.setInterval()`](/en-US/docs/Web/API/Window/setInterval), [`WorkerGlobalScope.setInterval()`](/en-US/docs/Web/API/WorkerGlobalScope/setInterval), [`setTimeout()`](/en-US/docs/Web/API/Window/setTimeout "setTimeout()") and [`setTimeout()`](/en-US/docs/Web/API/WorkerGlobalScope/setTimeout "setTimeout()") was changed in Firefox 50 to no longer occur if a [Web Audio API](/en-US/docs/Web/API/Web_Audio_API) [`AudioContext`](/en-US/docs/Web/API/AudioContext) is actively playing sound. However, this didn't resolve all scenarios in which timing-sensitive audio playback (such as music players generating individual notes using timers) could fail to work properly. For that reason, Firefox 51 no longer throttles background tabs which have an [`AudioContext`](/en-US/docs/Web/API/AudioContext), even if it's not currently playing sound.

### [DOM](#dom)

*   The [`DOMImplementation.hasFeature()`](/en-US/docs/Web/API/DOMImplementation/hasFeature) now returns `true` in all cases ([Firefox bug 984778](https://bugzil.la/984778 "External link (opens in new tab)")).
*   The [`HTMLInputElement`](/en-US/docs/Web/API/HTMLInputElement) and [`HTMLTextAreaElement`](/en-US/docs/Web/API/HTMLTextAreaElement) properties `selectionStart` and `selectionEnd` now correctly return the current position of the text input cursor when there's no selection, instead of returning 0 ([Firefox bug 1287655](https://bugzil.la/1287655 "External link (opens in new tab)")).
*   The [`HTMLImageElement`](/en-US/docs/Web/API/HTMLImageElement) interface and the corresponding [`<img>`](/en-US/docs/Web/HTML/Reference/Elements/img) element now support the `onerror` event handler, sending [`error`](/en-US/docs/Web/API/HTMLElement/error_event "error") events to the element whenever [errors occur attempting to load or interpret images](/en-US/docs/Web/API/HTMLImageElement#errors).
*   You can now change a Web [`Animation`](/en-US/docs/Web/API/Animation)'s effect by setting the value of its [`effect`](/en-US/docs/Web/API/Animation/effect "effect") property. Previously, this property was read-only ([Firefox bug 1049975](https://bugzil.la/1049975 "External link (opens in new tab)")).
*   The Permissions API method [`Permissions.revoke()`](/en-US/docs/Web/API/Permissions/revoke) has been put behind a preference (`dom.permissions.revoke.enable`) and disabled by default since its design and even its very existence is under discussion in the [Web Application Security Working Group](https://www.w3.org/2011/webappsec/ "External link (opens in new tab)").
*   The [Storage API](/en-US/docs/Web/API/Storage_API)'s [`Navigator.storage`](/en-US/docs/Web/API/Navigator/storage) property and [`StorageManager.estimate()`](/en-US/docs/Web/API/StorageManager/estimate) method have been implemented along with the needed supporting code. Storage unit persistence features are not yet implemented. See [Firefox bug 1267941](https://bugzil.la/1267941 "External link (opens in new tab)").
*   For privacy reasons, both [`BatteryManager.chargingTime`](/en-US/docs/Web/API/BatteryManager/chargingTime) and [`BatteryManager.dischargingTime`](/en-US/docs/Web/API/BatteryManager/dischargingTime) now round the returned value to the closest 15 minutes ([Firefox bug 1292655](https://bugzil.la/1292655 "External link (opens in new tab)")).

### [Events](#events)

*   Firefox now supports the [`onanimationstart`](/en-US/docs/Web/API/Element/animationstart_event "onanimationstart"), [`onanimationiteration`](/en-US/docs/Web/API/Element/animationiteration_event "onanimationiteration"), and [`onanimationend`](/en-US/docs/Web/API/Element/animationend_event "onanimationend") event handlers, in addition to supporting the corresponding events using [`addEventListener()`](/en-US/docs/Web/API/EventTarget/addEventListener "addEventListener()") ([Firefox bug 911987](https://bugzil.la/911987 "External link (opens in new tab)")).
*   Firefox now supports the [`ontransitionend`](/en-US/docs/Web/API/Element/transitionend_event "ontransitionend") event handler ([Firefox bug 911987](https://bugzil.la/911987 "External link (opens in new tab)")).

### [Security](#security)

*   When login pages (i.e., those containing an [`<input type="password">`](/en-US/docs/Web/HTML/Reference/Elements/input/password) field) are created so that they would be submitted insecurely, Firefox displays a crossed-out lock icon in the address bar to warn users ([Firefox bug 1319119](https://bugzil.la/1319119 "External link (opens in new tab)")).

### [Removals](#removals)

*   The non-standard Simple Push API, mainly intended for use with Firefox OS and now superseded by the [W3C Push API](/en-US/docs/Web/API/Push_API), has been completely removed from Gecko ([Firefox bug 1296579](https://bugzil.la/1296579 "External link (opens in new tab)")).
*   The non-standard Alarms API, mainly intended for use with Firefox OS, has been completely removed from Gecko ([Firefox bug 1300884](https://bugzil.la/1300884 "External link (opens in new tab)")).
*   Support for prefixes in the [Page Visibility API](/en-US/docs/Web/API/Page_Visibility_API) has been removed ([Firefox bug 812701](https://bugzil.la/812701 "External link (opens in new tab)")).

*   You can now [embed a WebExtension in a legacy add-on type](https://web.archive.org/web/20210528055219/https://developer.mozilla.org/en-US/docs/Archive/Add-ons/Embedded_WebExtensions "External link (opens in new tab)") ([Firefox bug 1252215](https://bugzil.la/1252215 "External link (opens in new tab)")).
    
*   [Clipboard access](/en-US/docs/Mozilla/Add-ons/WebExtensions/Interact_with_the_clipboard) is now supported ([Firefox bug 1197451](https://bugzil.la/1197451 "External link (opens in new tab)"))
    
*   The arguments passed to the callback of [`tabs.executeScript()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/executeScript) have been fixed ([Firefox bug 1290157](https://bugzil.la/1290157 "External link (opens in new tab)"))
    
*   [localStorage](/en-US/docs/Web/API/Window/localStorage) is now cleared when a WebExtension is uninstalled ([Firefox bug 1213990](https://bugzil.la/1213990 "External link (opens in new tab)"))
    
*   A changed [`Content-Type`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Type) header in Web Extensions is now taken into account ([Firefox bug 1304331](https://bugzil.la/1304331 "External link (opens in new tab)"))
    

### [Other](#other)

*   The [`multiprocessCompatible` property of `install.rdf`](https://web.archive.org/web/20210421140209/https://developer.mozilla.org/en-US/docs/Archive/Add-ons/Install_Manifests#multiprocesscompatible "External link (opens in new tab)") must now be explicitly set to `false` to prevent multiprocess from being enabled in Firefox when the add-on is installed.
    
*   The Mozilla-specific Social API has been substantially changed (largely to remove APIs no longer used), as follows:
    
    *   The `MozSocial` interface and the `Navigator.mozSocial` property which supports it have been removed.
    *   The Social Bookmarks API has been removed.
    *   The Social chat functionality has been removed.
    *   The Social Status API has been removed.
    *   All of the social widgets, except for the Share panel, have been removed. This includes the social sidebar, flyover panels, and so forth.
    *   All supporting user interface features and functionality for the removed APIs have been removed as well.
    *   Social service provider manifest properties supporting the removed functionality are no longer supported.
*   If an add-on uses `mimeTypes.rdf` to provide a file extension to MIME type mapping, it must now register an entry in the `"ext-to-type-mapping"` category ([Firefox bug 306471](https://bugzil.la/306471 "External link (opens in new tab)")).
    
*   The [Browser API](https://web.archive.org/web/20210124171655/https://developer.mozilla.org/en-US/docs/Mozilla/Gecko/Chrome/API/Browser_API "External link (opens in new tab)") now includes a `detail` object on the event object of the `mozbrowserlocationchange` event that contains `canGoForward`/`canGoBack` properties, allowing retrieval of the mozBrowser's back/forward status synchronously ([Firefox bug 1279635](https://bugzil.la/1279635 "External link (opens in new tab)")).
