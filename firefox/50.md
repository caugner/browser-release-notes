# Firefox 50 release notes for developers

[To test the latest developer features of Firefox, install Firefox Developer Edition](https://www.firefox.com/en-US/channel/desktop/developer/ "External link (opens in new tab)"). Firefox 50 was released on November 15, 2016. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [HTML](#html)

*   The default style of [`<bdo>`](/en-US/docs/Web/HTML/Reference/Elements/bdo) now sets [`unicode-bidi`](/en-US/docs/Web/CSS/Reference/Properties/unicode-bidi) with the `isolate-override` value ([Firefox bug 1249497](https://bugzil.la/1249497 "External link (opens in new tab)")).
*   Setting the [`<track>`](/en-US/docs/Web/HTML/Reference/Elements/track) element's [`src`](/en-US/docs/Web/HTML/Reference/Elements/track#src) attribute now works correctly ([Firefox bug 1281418](https://bugzil.la/1281418 "External link (opens in new tab)")).
*   The `referrerpolicy` attribute on [`<area>`](/en-US/docs/Web/HTML/Reference/Elements/area), [`<a>`](/en-US/docs/Web/HTML/Reference/Elements/a), [`<img>`](/en-US/docs/Web/HTML/Reference/Elements/img), [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) and [`<link>`](/en-US/docs/Web/HTML/Reference/Elements/link) elements is now available by default ([Firefox bug 1223838](https://bugzil.la/1223838 "External link (opens in new tab)"), [Firefox bug 1264165](https://bugzil.la/1264165 "External link (opens in new tab)")).

### [CSS](#css)

*   Corners with border-radius and with dashed and dotted styles are now rendered with the specified style instead of a solid style ([Firefox bug 382721](https://bugzil.la/382721 "External link (opens in new tab)")).
*   The non-standard `:-moz-full-screen-ancestor` pseudo-class selector has been removed ([Firefox bug 1199529](https://bugzil.la/1199529 "External link (opens in new tab)")).
*   The [`box-sizing: padding-box`](/en-US/docs/Web/CSS/Reference/Properties/box-sizing) has been removed, since it's no longer a part of the spec and Firefox was the only major browser implementing it ([Firefox bug 1166728](https://bugzil.la/1166728 "External link (opens in new tab)")).
*   The three values `isolate`, `isolate-override`, and `plaintext` of the [`unicode-bidi`](/en-US/docs/Web/CSS/Reference/Properties/unicode-bidi) property have been unprefixed ([Firefox bug 1141895](https://bugzil.la/1141895 "External link (opens in new tab)")).
*   In quirks mode, the bullet of a list item now inherits the size of the list, like in standards mode ([Firefox bug 648331](https://bugzil.la/648331 "External link (opens in new tab)")).
*   The [`:in-range`](/en-US/docs/Web/CSS/Reference/Selectors/:in-range) and [`:out-of-range`](/en-US/docs/Web/CSS/Reference/Selectors/:out-of-range) pseudo-classes have changed behavior to not match disabled or read-only inputs ([Firefox bug 1264157](https://bugzil.la/1264157 "External link (opens in new tab)")).
*   The [`:any-link`](/en-US/docs/Web/CSS/Reference/Selectors/:any-link) pseudo-class is now unprefixed ([Firefox bug 843579](https://bugzil.la/843579 "External link (opens in new tab)")).
*   The `space` value for [`border-image-repeat`](/en-US/docs/Web/CSS/Reference/Properties/border-image-repeat) has been implemented ([Firefox bug 720531](https://bugzil.la/720531 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   The ES2015 [`Symbol.hasInstance`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/hasInstance) property has been implemented ([Firefox bug 1054906](https://bugzil.la/1054906 "External link (opens in new tab)")).
*   The ES2017 [`Object.getOwnPropertyDescriptors()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/getOwnPropertyDescriptors) method has been implemented ([Firefox bug 1245024](https://bugzil.la/1245024 "External link (opens in new tab)")).
*   The behavior of \\W in [`RegExp`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp) with unicode and ignoreCase flags is changed to match recent draft spec. Now it doesn't match to K, S, k, s, and KELVIN SIGN (U+212A), and LATIN SMALL LETTER LONG S (U+017F) ([Firefox bug 1281739](https://bugzil.la/1281739 "External link (opens in new tab)")).

### [Developer Tools](#developer_tools)

*   [The Web Console now understands source maps.](https://firefox-source-docs.mozilla.org/devtools-user/web_console/console_messages/index.html#source-maps "External link (opens in new tab)")
*   [The Storage Inspector now lets you delete individual items from IndexedDB object stores.](https://firefox-source-docs.mozilla.org/devtools-user/storage_inspector/index.html#indexeddb "External link (opens in new tab)")
*   [The Memory tool is enabled by default.](https://firefox-source-docs.mozilla.org/devtools-user/memory/index.html "External link (opens in new tab)")
*   [The Box model view is moved into the Computed view.](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/ui_tour/index.html#computed-view "External link (opens in new tab)")
*   [The Web Console now displays stack traces for XHR or Fetch() network requests.](https://firefox-source-docs.mozilla.org/devtools-user/web_console/console_messages/index.html#viewing-network-request-details "External link (opens in new tab)")

[All devtools bugs fixed between Firefox 49 and Firefox 50](https://bugzilla.mozilla.org/buglist.cgi?list_id=13263766&chfield=resolution&chfieldfrom=2016-06-06&chfieldvalue=FIXED&resolution=FIXED&classification=Client%20Software&chfieldto=2016-08-01&query_format=advanced&bug_status=RESOLVED&bug_status=VERIFIED&component=Developer%20Tools&component=Developer%20Tools%3A%20about%3Adebugging&component=Developer%20Tools%3A%20Animation%20Inspector&component=Developer%20Tools%3A%20Canvas%20Debugger&component=Developer%20Tools%3A%20Computed%20Styles%20Inspector&component=Developer%20Tools%3A%20Console&component=Developer%20Tools%3A%20CSS%20Rules%20Inspector&component=Developer%20Tools%3A%20Debugger&component=Developer%20Tools%3A%20DOM&component=Developer%20Tools%3A%20Font%20Inspector&component=Developer%20Tools%3A%20Framework&component=Developer%20Tools%3A%20Graphic%20Commandline%20and%20Toolbar&component=Developer%20Tools%3A%20Inspector&component=Developer%20Tools%3A%20JSON%20Viewer&component=Developer%20Tools%3A%20Memory&component=Developer%20Tools%3A%20Netmonitor&component=Developer%20Tools%3A%20Object%20Inspector&component=Developer%20Tools%3A%20Performance%20Tools%20%28Profiler%2FTimeline%29&component=Developer%20Tools%3A%20Responsive%20Design%20Mode&component=Developer%20Tools%3A%20Scratchpad&component=Developer%20Tools%3A%20Shared%20Components&component=Developer%20Tools%3A%20Source%20Editor&component=Developer%20Tools%3A%20Storage%20Inspector&component=Developer%20Tools%3A%20Style%20Editor&component=Developer%20Tools%3A%20User%20Stories&component=Developer%20Tools%3A%20Web%20Audio%20Editor&component=Developer%20Tools%3A%20WebGL%20Shader%20Editor&component=Developer%20Tools%3A%20WebIDE&product=Firefox "External link (opens in new tab)").

### [HTTP](#http)

*   The experimental (and deprecated) [SPDY](https://en.wikipedia.org/wiki/SPDY "External link (opens in new tab)") 3.1 is now disabled by default [Firefox bug 1287132](https://bugzil.la/1287132 "External link (opens in new tab)").
*   Support for [`X-Content-Type-Options`](/en-US/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options) has been added ([Firefox bug 471020](https://bugzil.la/471020 "External link (opens in new tab)")).
*   The cookie prefixes `__Host-` and `__Secure-` have been implemented. See [`Set-Cookie`](/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie) and [Firefox bug 1283368](https://bugzil.la/1283368 "External link (opens in new tab)").
*   The [`Referrer-Policy`](/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy) header has been implemented [Firefox bug 1264164](https://bugzil.la/1264164 "External link (opens in new tab)").

### [Security](#security)

*   The [`ping`](/en-US/docs/Web/HTML/Reference/Elements/a#ping) attribute of [`<a>`](/en-US/docs/Web/HTML/Reference/Elements/a) element now abides by the [`connect-src`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src) [CSP 1.1 policy directive](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy) ([Firefox bug 1100181](https://bugzil.la/1100181 "External link (opens in new tab)")).
*   Support for the [`sandbox`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox) [CSP](/en-US/docs/Web/HTTP/Guides/CSP) directive has been added ([Firefox bug 671389](https://bugzil.la/671389 "External link (opens in new tab)")).
*   It's now possible to set a [content security policy for workers](/en-US/docs/Web/API/Web_Workers_API/Using_web_workers#content_security_policy) ([Firefox bug 959388](https://bugzil.la/959388 "External link (opens in new tab)")).
*   The [`Navigator.sendBeacon()`](/en-US/docs/Web/API/Navigator/sendBeacon) method no longer throws an exception if the beacon data couldn't be sent due to a [Content Security Policy](/en-US/docs/Web/HTTP/Guides/CSP) restriction; instead, it returns `false` as expected ([Firefox bug 1234813](https://bugzil.la/1234813 "External link (opens in new tab)")).
*   Support for RC4 encryption was deprecated in Firefox 36 and disabled by default in Firefox 44. The one-year grace period has ended, so Firefox 50 removes all support for RC4 (Google Chrome removed support for RC4 in August 2016). From now on, any time Firefox encounters RC4 encryption, it will report an `SSL_ERROR_NO_CYPHER_OVERLAP` error.

### [Networking](#networking)

*   When an error has happened during an asynchronous [`XMLHttpRequest`](/en-US/docs/Web/API/XMLHttpRequest), the [`XMLHttpRequest.getAllResponseHeaders()`](/en-US/docs/Web/API/XMLHttpRequest/getAllResponseHeaders) method now returns an empty string ([Firefox bug 1286744](https://bugzil.la/1286744 "External link (opens in new tab)")).
*   Instead of returning a `NetworkError`, asynchronous [`XMLHttpRequest`](/en-US/docs/Web/API/XMLHttpRequest) that fails for CORS or other network constraints now raises an [`error`](/en-US/docs/Web/API/XMLHttpRequestEventTarget/error_event "error") that can be caught like any other error ([Firefox bug 709991](https://bugzil.la/709991 "External link (opens in new tab)")).
*   [`XMLHttpRequest.getResponseHeader()`](/en-US/docs/Web/API/XMLHttpRequest/getResponseHeader) and [`XMLHttpRequest.getAllResponseHeaders()`](/en-US/docs/Web/API/XMLHttpRequest/getAllResponseHeaders) now also return empty headers by default. This can be controlled via the preference `network.http.keep_empty_response_headers_as_empty_string` ([Firefox bug 918721](https://bugzil.la/918721 "External link (opens in new tab)")).
*   The `only-if-cached` option has been added to [`Request.cache`](/en-US/docs/Web/API/Request/cache) ([Firefox bug 1272436](https://bugzil.la/1272436 "External link (opens in new tab)")).

### [DOM](#dom)

*   The `once` option for [`EventTarget.addEventListener()`](/en-US/docs/Web/API/EventTarget/addEventListener) is now supported ([Firefox bug 1287706](https://bugzil.la/1287706 "External link (opens in new tab)")).
*   The interface [`NodeList`](/en-US/docs/Web/API/NodeList) are now iterable and the methods [`forEach()`](/en-US/docs/Web/API/NodeList/forEach "forEach()"), [`values()`](/en-US/docs/Web/API/NodeList/values "values()"), [`NodeList.entries()`](/en-US/docs/Web/API/NodeList/entries) and [`NodeList.keys()`](/en-US/docs/Web/API/NodeList/keys) are now available ([Firefox bug 1290636](https://bugzil.la/1290636 "External link (opens in new tab)")).
*   The interface [`DOMTokenList`](/en-US/docs/Web/API/DOMTokenList) are now iterable and the methods [`forEach()`](/en-US/docs/Web/API/DOMTokenList/forEach "forEach()"), [`values()`](/en-US/docs/Web/API/DOMTokenList/values "values()"), [`DOMTokenList.entries()`](/en-US/docs/Web/API/DOMTokenList/entries) and [`DOMTokenList.keys()`](/en-US/docs/Web/API/DOMTokenList/keys) are now available ([Firefox bug 1290636](https://bugzil.la/1290636 "External link (opens in new tab)")).
*   The methods [`Document.createElement()`](/en-US/docs/Web/API/Document/createElement) and [`Document.createElementNS()`](/en-US/docs/Web/API/Document/createElementNS) now have an optional `options` parameter for creating [custom elements](/en-US/docs/Web/API/Web_components/Using_custom_elements) ([Firefox bug 1276579](https://bugzil.la/1276579 "External link (opens in new tab)")).

### [SVG](#svg)

*   The `allowReorder` attribute has been dropped and the behavior it was setting is now the default for SVG [`<switch>`](/en-US/docs/Web/SVG/Reference/Element/switch) elements ([Firefox bug 1279690](https://bugzil.la/1279690 "External link (opens in new tab)")).
*   The `defer` keyword for the [`preserveAspectRatio`](/en-US/docs/Web/SVG/Reference/Attribute/preserveAspectRatio) attribute on SVG [`<image>`](/en-US/docs/Web/SVG/Reference/Element/image) elements has been removed to follow the latest SVG2 specification ([Firefox bug 1280425](https://bugzil.la/1280425 "External link (opens in new tab)")).

### [Drag and Drop API](#drag_and_drop_api)

*   The [`DataTransfer.items`](/en-US/docs/Web/API/DataTransfer/items) property has been implemented, allowing access to multiple items being dragged and dropped using the HTML Drag and Drop API. To allow this, the [`DataTransferItem`](/en-US/docs/Web/API/DataTransferItem) and [`DataTransferItemList`](/en-US/docs/Web/API/DataTransferItemList) interfaces are now supported as well ([Firefox bug 906420](https://bugzil.la/906420 "External link (opens in new tab)")). This is enabled by default.
*   The old, obsolete Firefox specific drag and drop API events `dragdrop` and `draggesture` are no longer supported. Be sure to update any code still using them to use the [HTML drag and drop API](/en-US/docs/Web/API/HTML_Drag_and_Drop_API) ([Firefox bug 1162050](https://bugzil.la/1162050 "External link (opens in new tab)").

### [Pointer Lock API](#pointer_lock_api)

*   The [Pointer Lock API](/en-US/docs/Web/API/Pointer_Lock_API) is now unprefixed ([Firefox bug 991899](https://bugzil.la/991899 "External link (opens in new tab)")).
*   Before Firefox 50, [`requestPointerLock()`](/en-US/docs/Web/API/Element/requestPointerLock) asked for permission using a doorhanger, and pointer lock would not be enabled until the user granted permission. From Firefox 50, pointer lock is like the [fullscreen API](/en-US/docs/Web/API/Fullscreen_API): it's granted immediately, but a notification is displayed explaining to the user how to exit ([Firefox bug 1273351](https://bugzil.la/1273351 "External link (opens in new tab)")).

### [IndexedDB](#indexeddb)

*   A [`close`](/en-US/docs/Web/API/IDBDatabase/close_event "close") event is now sent to the [`IDBDatabase`](/en-US/docs/Web/API/IDBDatabase) object when the corresponding database is unexpectedly closed ([Firefox bug 1151017](https://bugzil.la/1151017 "External link (opens in new tab)")).

### [Service Workers](#service_workers)

*   The [`WindowClient.navigate()`](/en-US/docs/Web/API/WindowClient/navigate) method has been implemented. This method lets you open a specified URL into a client window which is being controlled by the service worker ([Firefox bug 1218148](https://bugzil.la/1218148 "External link (opens in new tab)")).

### [WebGL](#webgl)

*   The [`EXT_shader_texture_lod`](/en-US/docs/Web/API/EXT_shader_texture_lod) WebGL extension has been implemented ([Firefox bug 1111689](https://bugzil.la/1111689 "External link (opens in new tab)")).
*   The texImage methods have been updated for [WebGL 2](/en-US/docs/Web/API/WebGL2RenderingContext) to implement PBOs (`PIXEL_UNPACK_BUFFER`) ([Firefox bug 1280499](https://bugzil.la/1280499 "External link (opens in new tab)")).

### [WebRTC](#webrtc)

*   Adding a track to a [`MediaStream`](/en-US/docs/Web/API/MediaStream) now generates the [`addtrack`](/en-US/docs/Web/API/MediaStream/addtrack_event "addtrack") event as described in the specification. The event is of type [`MediaStreamTrackEvent`](/en-US/docs/Web/API/MediaStreamTrackEvent) and is fired on the stream to which the track was added. You can use either [`MediaStream.addEventListener('addtrack', ...)`](/en-US/docs/Web/API/EventTarget/addEventListener "MediaStream.addEventListener('addtrack', ...)") or the `onaddtrack` property to handle `"addtrack"` events.
*   The [`MediaStreamTrack`](/en-US/docs/Web/API/MediaStreamTrack) interface now supports the [`ended`](/en-US/docs/Web/API/MediaStreamTrack/ended_event "ended") event and its event handler.
*   Firefox now supports the [`MediaStreamTrack.readyState`](/en-US/docs/Web/API/MediaStreamTrack/readyState) property, which indicates whether the track is live or permanently ended.
*   The [`MediaStreamTrack`](/en-US/docs/Web/API/MediaStreamTrack) methods [`getConstraints()`](/en-US/docs/Web/API/MediaStreamTrack/getConstraints "getConstraints()") and [`getSettings()`](/en-US/docs/Web/API/MediaStreamTrack/getSettings "getSettings()") have been implemented; these let you get the most recently applied set of customized property constraints and the actual values of all of the track's constrainable properties, respectively. The accompanying data types have been documented as well.
*   The `RTCDataChannel.stream` property has been removed. This was replaced with [`RTCDataChannel.id`](/en-US/docs/Web/API/RTCDataChannel/id) in [Firefox 24](/en-US/docs/Mozilla/Firefox/Releases/24), but was supported for backward compatibility. Please be sure to update your code to use the `id` property if you haven't done so yet.

### [Web Audio API](#web_audio_api)

*   The [`PannerNode`](/en-US/docs/Web/API/PannerNode) interface now supports the 3D Cartesian space properties for the position ([`PannerNode.positionX`](/en-US/docs/Web/API/PannerNode/positionX), [`PannerNode.positionY`](/en-US/docs/Web/API/PannerNode/positionY), and [`PannerNode.positionZ`](/en-US/docs/Web/API/PannerNode/positionZ)) and directionality ([`PannerNode.orientationX`](/en-US/docs/Web/API/PannerNode/orientationX), [`PannerNode.orientationY`](/en-US/docs/Web/API/PannerNode/orientationY), [`PannerNode.orientationZ`](/en-US/docs/Web/API/PannerNode/orientationZ)) of an audio source.
*   The interface [`IIRFilterNode`](/en-US/docs/Web/API/IIRFilterNode), which implements a general [infinite impulse response](https://en.wikipedia.org/wiki/Infinite_impulse_response "External link (opens in new tab)") (IIR) filter, has been implemented.
*   Throttling in background tabs of timers created by [`Window.setInterval()`](/en-US/docs/Web/API/Window/setInterval), [`WorkerGlobalScope.setInterval()`](/en-US/docs/Web/API/WorkerGlobalScope/setInterval), [`setTimeout()`](/en-US/docs/Web/API/Window/setTimeout "setTimeout()") and [`setTimeout()`](/en-US/docs/Web/API/WorkerGlobalScope/setTimeout "setTimeout()") no longer occurs if a [Web Audio API](/en-US/docs/Web/API/Web_Audio_API) [`AudioContext`](/en-US/docs/Web/API/AudioContext) is actively playing sound. This should help prevent issues with timing-sensitive audio playback (such as music players generating individual notes using timers) in the background ([Firefox bug 1181073](https://bugzil.la/1181073 "External link (opens in new tab)")).

### [Audio/Video](#audiovideo)

*   The `AlignSetting` enum (representing possible values for [`VTTCue.align`](/en-US/docs/Web/API/VTTCue/align)) incorrectly previously included the value `"middle"` instead of `"center"`. This has been corrected ([Firefox bug 1276130](https://bugzil.la/1276130 "External link (opens in new tab)")).
*   The non-standard and experimental method [`HTMLMediaElement.seekToNextFrame()`](/en-US/docs/Web/API/HTMLMediaElement/seekToNextFrame) now seeks to the next frame in the media asynchronously, rather than synchronously, and returns a [`Promise`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) which resolves once the seek is complete.
*   The implementation of [`HTMLTrackElement`](/en-US/docs/Web/API/HTMLTrackElement) has been corrected to allow [`<track>`](/en-US/docs/Web/HTML/Reference/Elements/track) elements to load resources even if not in a document ([Firefox bug 871747](https://bugzil.la/871747 "External link (opens in new tab)")).

### [Battery API](#battery_api)

*   The `Navigator.battery` property, which has been deprecated since Firefox 43, is now obsolete and has been removed. Use the [`navigator.getBattery()`](/en-US/docs/Web/API/Navigator/getBattery) method instead to get a battery [`Promise`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise), which will resolve when the [`BatteryManager`](/en-US/docs/Web/API/BatteryManager) is available for use; the [`BatteryManager`](/en-US/docs/Web/API/BatteryManager) is passed into the fulfillment handler for the promise ([Firefox bug 12593355](https://bugzil.la/12593355 "External link (opens in new tab)")).

### [Files and directories](#files_and_directories)

*   A subset of the [File and Directory Entries API](/en-US/docs/Web/API/File_and_Directory_Entries_API) has been implemented, to improve compatibility with sites that were previously only compatible with Google Chrome ([Firefox bug 1265767](https://bugzil.la/1265767 "External link (opens in new tab)")).
    
    *   The asynchronous API interfaces have been implemented, with the caveat that only reading of files is supported; for example, the [`FileSystemFileEntry.createWriter()`](/en-US/docs/Web/API/FileSystemFileEntry/createWriter) method is a no-op.
        
    *   These interfaces have been implemented:
        
        *   [`FileSystem`](/en-US/docs/Web/API/FileSystem)
        *   [`FileSystemEntry`](/en-US/docs/Web/API/FileSystemEntry) (properties only; the methods have not been implemented)
        *   [`FileSystemFileEntry`](/en-US/docs/Web/API/FileSystemFileEntry) (except for [`createWriter()`](/en-US/docs/Web/API/FileSystemFileEntry/createWriter "createWriter()"))
        *   [`FileSystemDirectoryEntry`](/en-US/docs/Web/API/FileSystemDirectoryEntry) (except for [`removeRecursively()`](/en-US/docs/Web/API/FileSystemDirectoryEntry/removeRecursively "removeRecursively()"))
        *   [`FileSystemDirectoryReader`](/en-US/docs/Web/API/FileSystemDirectoryReader)
    *   [`HTMLInputElement.webkitdirectory`](/en-US/docs/Web/API/HTMLInputElement/webkitdirectory) as well as the [`webkitdirectory`](/en-US/docs/Web/HTML/Reference/Elements/input#webkitdirectory) attribute of the [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) element have been implemented; this lets you configure a file input to accept directories instead of files ([Firefox bug 1258489](https://bugzil.la/1258489 "External link (opens in new tab)")).
        
    *   [`HTMLInputElement.webkitEntries`](/en-US/docs/Web/API/HTMLInputElement/webkitEntries) has been implemented; this returns an array of [`FileSystemEntry`](/en-US/docs/Web/API/FileSystemEntry)\-based objects representing the selected items.
        
    *   [`File.webkitRelativePath`](/en-US/docs/Web/API/File/webkitRelativePath) has been implemented; this contains the path of the file relative to the root of the containing [`FileSystemDirectoryEntry`](/en-US/docs/Web/API/FileSystemDirectoryEntry) that was among the items in the list returned by [`HTMLInputElement.webkitEntries`](/en-US/docs/Web/API/HTMLInputElement/webkitEntries).
        
    *   These APIs are now enabled by default; some were previously available but only behind a preference ([Firefox bug 1288683](https://bugzil.la/1288683 "External link (opens in new tab)")).
        
*   We've implemented [`DataTransferItem.webkitGetAsEntry()`](/en-US/docs/Web/API/DataTransferItem/webkitGetAsEntry) as part of the [File and Directory Entries API](/en-US/docs/Web/API/File_and_Directory_Entries_API); this lets you obtain a [`FileSystemEntry`](/en-US/docs/Web/API/FileSystemEntry) representing a dropped file ([Firefox bug 1289255](https://bugzil.la/1289255 "External link (opens in new tab)")). This is enabled by default.
    
*   The `HTMLInputElement.directory` property, part of the [Directory Upload API](https://wicg.github.io/directory-upload/proposal.html "External link (opens in new tab)") proposal, has been renamed to `allowdirs` ([Firefox bug 1288681](https://bugzil.la/1288681 "External link (opens in new tab)")). This property is hidden behind a preference.
