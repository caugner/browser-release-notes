# Firefox 22 release notes for developers

Firefox 22 was released on June 25, 2013. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [HTML](#html)

*   The HTML5 [`<data>`](/en-US/docs/Web/HTML/Reference/Elements/data) element has been implemented ([Firefox bug 839371](https://bugzil.la/839371 "External link (opens in new tab)")).
*   The HTML5 [`<time>`](/en-US/docs/Web/HTML/Reference/Elements/time) element has been implemented ([Firefox bug 629801](https://bugzil.la/629801 "External link (opens in new tab)")).
*   The `range` state of the [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) element (`<input type="range">`) has been implemented, behind the preference `dom.experimental_forms_range`, only enabled by default on Nightly and Aurora channel ([Firefox bug 841948](https://bugzil.la/841948 "External link (opens in new tab)")).
*   The support for the [`<template>`](/en-US/docs/Web/HTML/Reference/Elements/template) element, part of the Web component specification has been implemented ([Firefox bug 818976](https://bugzil.la/818976 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   [Asm.js](http://asmjs.org/spec/latest/ "External link (opens in new tab)") optimizations are enabled, making it possible to compile C/C++ applications to a subset of JavaScript for better performance.
*   ES2015 [Arrow Function](/en-US/docs/Web/JavaScript/Reference/Functions/Arrow_functions) syntax has been implemented ([Firefox bug 846406](https://bugzil.la/846406 "External link (opens in new tab)")).
*   The new [Object.is](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/is) function has been added ([Firefox bug 839979](https://bugzil.la/839979 "External link (opens in new tab)")).
*   [`arguments`](/en-US/docs/Web/JavaScript/Reference/Functions/arguments) in generator expressions is now inherited from enclosing lexical scope ([Firefox bug 848051](https://bugzil.la/848051 "External link (opens in new tab)")).
*   The ES2015 Proxy [`preventExtensions`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/preventExtensions) trap have been implemented ([Firefox bug 789897](https://bugzil.la/789897 "External link (opens in new tab)")).

### [DOM](#dom)

*   Support for the `multipart` property on `XMLHttpRequest` and `multipart/x-mixed-replace` responses in `XMLHttpRequest` has been removed. This was a Gecko-only feature that was never standardized. [Server-Sent Events](/en-US/docs/Web/API/Server-sent_events), [Web Sockets](/en-US/docs/Web/API/WebSockets_API) or inspecting `responseText` from progress events can be used instead.
*   Support for [Web Notifications](/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API) has been landed ([Firefox bug 782211](https://bugzil.la/782211 "External link (opens in new tab)")).
*   The [`FormData`](/en-US/docs/Web/API/FormData) `append` method now accepts a third optional `filename` parameter ([Firefox bug 690659](https://bugzil.la/690659 "External link (opens in new tab)")).
*   `Node.isSupported` has been removed ([Firefox bug 801562](https://bugzil.la/801562 "External link (opens in new tab)")).
*   `Node.setUserData` and `Node.getUserData` has been removed for web content and are deprecated for chrome content ([Firefox bug 842372](https://bugzil.la/842372 "External link (opens in new tab)")).
*   The [`Element.attributes`](/en-US/docs/Web/API/Element/attributes) property has been moved there from [`Node`](/en-US/docs/Web/API/Node) as required by the spec ([Firefox bug 844134](https://bugzil.la/844134 "External link (opens in new tab)")).
*   The Mac OS X backend for **Ambient Light Events** has been implemented.
*   Elements in the HTML namespace with local names `<bgsound>`, `<multicol>`, and `<image>` no longer implement the [`HTMLSpanElement`](/en-US/docs/Web/API/HTMLSpanElement) interface. `<bgsound>` implements [`HTMLUnknownElement`](/en-US/docs/Web/API/HTMLUnknownElement) and `<image>` implements [`HTMLElement`](/en-US/docs/Web/API/HTMLElement).
*   The [`NodeIterator.detach`](/en-US/docs/Web/API/NodeIterator/detach) method has been changed to do nothing ([Firefox bug 823549](https://bugzil.la/823549 "External link (opens in new tab)")).
*   The [`BlobEvent`](/en-US/docs/Web/API/BlobEvent) interface has been implemented ([Firefox bug 834165](https://bugzil.la/834165 "External link (opens in new tab)")).
*   The properties `HTMLMediaElement.crossorigin` and `HTMLInputElement.inputmode` has been removed to match the spec in [`HTMLMediaElement.crossOrigin`](/en-US/docs/Web/API/HTMLMediaElement/crossOrigin) and `HTMLInputElement.inputMode`, respectively ([Firefox bug 847370](https://bugzil.la/847370 "External link (opens in new tab)") and [Firefox bug 850346](https://bugzil.la/850346 "External link (opens in new tab)")).
*   WebRTC: the Media Stream API and Peer Connection API are now supported by default.
*   Web Components: the `Document.register()` method has been implemented ([Firefox bug 783129](https://bugzil.la/783129 "External link (opens in new tab)")).
*   The `ProgressEvent.initProgressEvent()` constructor method has been removed. Use the standard constructor, [`ProgressEvent()`](/en-US/docs/Web/API/ProgressEvent/ProgressEvent "ProgressEvent()") to construct and initialize [`ProgressEvent`](/en-US/docs/Web/API/ProgressEvent) ([Firefox bug 843489](https://bugzil.la/843489 "External link (opens in new tab)")).
*   Manipulated data associated with a [`cut`](/en-US/docs/Web/API/Element/cut_event "cut"), [`copy`](/en-US/docs/Web/API/Element/copy_event "copy"), or [`paste`](/en-US/docs/Web/API/Element/paste_event "paste") event can now be accessed via the [`ClipboardEvent.clipboardData`](/en-US/docs/Web/API/ClipboardEvent/clipboardData) property ([Firefox bug 407983](https://bugzil.la/407983 "External link (opens in new tab)")).
*   The [`HTMLTimeElement`](/en-US/docs/Web/API/HTMLTimeElement) interface has been implemented ([Firefox bug 629801](https://bugzil.la/629801 "External link (opens in new tab)")).
*   When a [`Worker`](/en-US/docs/Web/API/Worker) constructor is passed an invalid URL, it now throws [`DOMException`](/en-US/docs/Web/API/DOMException) of type `SECURITY_ERR` ([Firefox bug 587251](https://bugzil.la/587251 "External link (opens in new tab)")).

### [CSS](#css)

*   Support for [CSS Flexbox layout](/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Basic_concepts) has been enabled by default ([Firefox bug 841876](https://bugzil.la/841876 "External link (opens in new tab)")).
*   Following a spec change, the initial value for [`min-width`](/en-US/docs/Web/CSS/Reference/Properties/min-width) and [`min-height`](/en-US/docs/Web/CSS/Reference/Properties/min-height) has been changed back to `0`, even on flex items ([Firefox bug 848539](https://bugzil.la/848539 "External link (opens in new tab)")).
*   Support for CSS Conditionals ([`@supports`](/en-US/docs/Web/CSS/Reference/At-rules/@supports) and [`CSS.supports()`](/en-US/docs/Web/API/CSS/supports_static "CSS.supports()")) has been enabled by default ([Firefox bug 855455](https://bugzil.la/855455 "External link (opens in new tab)")).
*   Support for [`background-clip`](/en-US/docs/Web/CSS/Reference/Properties/background-clip) and [`background-origin`](/en-US/docs/Web/CSS/Reference/Properties/background-origin) properties in the [`background`](/en-US/docs/Web/CSS/Reference/Properties/background) shorthand has been implemented ([Firefox bug 570896](https://bugzil.la/570896 "External link (opens in new tab)")).

## [Changes for add-on and Mozilla developers](#changes_for_add-on_and_mozilla_developers)

*   The `properties` parameter has been removed from the `nsITreeView.getCellProperties()`, `nsITreeView.getColumnProperties()` and `nsITreeView.getRowProperties()` methods of `nsITreeView`. These methods should now return a string of space-separated property names ([Firefox bug 407956](https://bugzil.la/407956 "External link (opens in new tab)")).
*   The `inIDOMUtils.getCSSPropertyNames()` method has been implemented and will return all supported [CSS property](/en-US/docs/Web/CSS/Reference) names.
*   See [the Mozilla blog](https://blog.mozilla.org/addons/2013/06/03/compatibility-for-firefox-22/ "External link (opens in new tab)") for more changes.

### [Firefox Developer Tools](#firefox_developer_tools)

*   [Font inspector](https://hacks.mozilla.org/2013/04/developer-tools-update-firefox-22/ "External link (opens in new tab)") shows which fonts on your computer are applied to the page.
*   Visual paint feedback mode shows when and where a page is repainted.
*   The dev tools may now be docked to the right side, not just the bottom of the browser.
*   Some panes within the dev tools have switched from [XUL to HTML](https://bugzil.la/875727 "External link (opens in new tab)"). For example, the CSS rule viewer is now chrome://browser/content/devtools/cssruleview.xhtml, not `cssruleview.xul`. Instead of adding an overlay directly to extend features of these panes, you may add an overlay and script to the outer xul document, to add load listeners and change these HTML documents.
*   The stack trace is now shown as a breadcrumb near the top, and the script listing is now at the left panel of the debugger.
