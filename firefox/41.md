# Firefox 41 release notes for developers

[To test the latest developer features of Firefox, install Firefox Developer Edition](https://www.firefox.com/en-US/channel/desktop/developer/ "External link (opens in new tab)") Firefox 41 was released on September 22, 2015. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

Highlights:

*   [Take a screenshot of a DOM node](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_html/index.html#element-popup-menu "External link (opens in new tab)")
*   [Copy as HAR/save as HAR](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html#copysave-all-as-har "External link (opens in new tab)")
*   ["Add Rule" button in the Rules view](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_css/index.html#add-rules "External link (opens in new tab)")
*   [View source in a tab](https://firefox-source-docs.mozilla.org/devtools-user/view_source/index.html "External link (opens in new tab)") (Disabled by default)
*   [More options to copy CSS rules](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_css/index.html#copy-rules "External link (opens in new tab)")
*   [Copy image as data: URL in the Rules view](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/view_background_images/index.html "External link (opens in new tab)")
*   Added command to _GCLI_ to display CSP info

### [CSS](#css)

*   Support for laying out vertical scripts has been activated by default ([Firefox bug 1138384](https://bugzil.la/1138384 "External link (opens in new tab)")). That means that the following CSS properties are now available:
    
    *   Choosing the direction of writing: [`writing-mode`](/en-US/docs/Web/CSS/Reference/Properties/writing-mode).
    *   Controlling orientation of characters: [`text-orientation`](/en-US/docs/Web/CSS/Reference/Properties/text-orientation).
    *   Direction-independent equivalents of [`width`](/en-US/docs/Web/CSS/Reference/Properties/width) and [`height`](/en-US/docs/Web/CSS/Reference/Properties/height): [`block-size`](/en-US/docs/Web/CSS/Reference/Properties/block-size) and [`inline-size`](/en-US/docs/Web/CSS/Reference/Properties/inline-size).
    *   Direction-independent equivalents of [`min-width`](/en-US/docs/Web/CSS/Reference/Properties/min-width) and [`min-height`](/en-US/docs/Web/CSS/Reference/Properties/min-height): [`min-block-size`](/en-US/docs/Web/CSS/Reference/Properties/min-block-size) and [`min-inline-size`](/en-US/docs/Web/CSS/Reference/Properties/min-inline-size).
    *   Direction-independent equivalents of [`max-width`](/en-US/docs/Web/CSS/Reference/Properties/max-width) and [`max-height`](/en-US/docs/Web/CSS/Reference/Properties/max-height): [`max-block-size`](/en-US/docs/Web/CSS/Reference/Properties/max-block-size) and [`max-block-size`](/en-US/docs/Web/CSS/Reference/Properties/max-block-size).
    *   Direction-independent equivalents of [`margin-top`](/en-US/docs/Web/CSS/Reference/Properties/margin-top), [`margin-right`](/en-US/docs/Web/CSS/Reference/Properties/margin-right), [`margin-bottom`](/en-US/docs/Web/CSS/Reference/Properties/margin-bottom) and [`margin-left`](/en-US/docs/Web/CSS/Reference/Properties/margin-left): [`margin-block-start`](/en-US/docs/Web/CSS/Reference/Properties/margin-block-start), [`margin-block-end`](/en-US/docs/Web/CSS/Reference/Properties/margin-block-end), [`margin-inline-start`](/en-US/docs/Web/CSS/Reference/Properties/margin-inline-start) and [`margin-inline-end`](/en-US/docs/Web/CSS/Reference/Properties/margin-inline-end).
    *   Direction-independent equivalents of [`padding-top`](/en-US/docs/Web/CSS/Reference/Properties/padding-top), [`padding-right`](/en-US/docs/Web/CSS/Reference/Properties/padding-right), [`padding-bottom`](/en-US/docs/Web/CSS/Reference/Properties/padding-bottom) and [`padding-left`](/en-US/docs/Web/CSS/Reference/Properties/padding-left): [`padding-block-start`](/en-US/docs/Web/CSS/Reference/Properties/padding-block-start), [`padding-block-end`](/en-US/docs/Web/CSS/Reference/Properties/padding-block-end), [`padding-inline-start`](/en-US/docs/Web/CSS/Reference/Properties/padding-inline-start) and [`padding-inline-end`](/en-US/docs/Web/CSS/Reference/Properties/padding-inline-end).
    *   Direction-independent equivalents of [`border-top`](/en-US/docs/Web/CSS/Reference/Properties/border-top), [`border-right`](/en-US/docs/Web/CSS/Reference/Properties/border-right), [`border-bottom`](/en-US/docs/Web/CSS/Reference/Properties/border-bottom) and [`border-left`](/en-US/docs/Web/CSS/Reference/Properties/border-left) and their longhands for width, style and color: [`border-block-start`](/en-US/docs/Web/CSS/Reference/Properties/border-block-start), [`border-block-start-width`](/en-US/docs/Web/CSS/Reference/Properties/border-block-start-width), [`border-block-start-style`](/en-US/docs/Web/CSS/Reference/Properties/border-block-start-style), [`border-block-start-color`](/en-US/docs/Web/CSS/Reference/Properties/border-block-start-color), [`border-block-end`](/en-US/docs/Web/CSS/Reference/Properties/border-block-end), [`border-block-end-width`](/en-US/docs/Web/CSS/Reference/Properties/border-block-end-width), [`border-block-end-style`](/en-US/docs/Web/CSS/Reference/Properties/border-block-end-style), [`border-block-end-color`](/en-US/docs/Web/CSS/Reference/Properties/border-block-end-color), [`border-inline-start`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-start), [`border-inline-start-width`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-start-width), [`border-inline-start-style`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-start-style), [`border-inline-start-color`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-start-color), [`border-inline-end`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-end), [`border-inline-end-width`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-end-width), [`border-inline-end-style`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-end-style) and [`border-inline-end-color`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-end-color).
    *   Direction-independent equivalents of [`top`](/en-US/docs/Web/CSS/Reference/Properties/top), [`right`](/en-US/docs/Web/CSS/Reference/Properties/right), [`bottom`](/en-US/docs/Web/CSS/Reference/Properties/bottom) and [`left`](/en-US/docs/Web/CSS/Reference/Properties/left): `offset-block-start`, `offset-block-end`, `offset-inline-start` and `offset-inline-end`.
*   Support the [`transform-origin`](/en-US/docs/Web/CSS/Reference/Properties/transform-origin) property in SVG and implement the [`transform-box`](/en-US/docs/Web/CSS/Reference/Properties/transform-box) property ([Firefox bug 923193](https://bugzil.la/923193 "External link (opens in new tab)")).
    

### [HTML](#html)

*   [`<a>`](/en-US/docs/Web/HTML/Reference/Elements/a) without an `href` attribute is no longer classified as interactive content. Clicking it inside [`<label>`](/en-US/docs/Web/HTML/Reference/Elements/label) will activate labeled content ([Firefox bug 1167816](https://bugzil.la/1167816 "External link (opens in new tab)")).
*   SVG icons are now supported for site icons, that is favicons and shortcut icons ([Firefox bug 366324](https://bugzil.la/366324 "External link (opens in new tab)")).
*   The [`crossorigin`](/en-US/docs/Web/HTML/Reference/Elements/link#crossorigin) attribute is now supported for [<link rel='preconnect'>](/en-US/docs/Web/HTML/Reference/Elements/link) ([Firefox bug 1174152](https://bugzil.la/1174152 "External link (opens in new tab)")).
*   The picture element does not react to resize/viewport changes ([Firefox bug 1135812](https://bugzil.la/1135812 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   `Date.prototype` is now an ordinary object, not a [`Date`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date) instance anymore ([Firefox bug 861219](https://bugzil.la/861219 "External link (opens in new tab)")).
*   [`Date.prototype.toString`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/toString) is now a generic method ([Firefox bug 861219](https://bugzil.la/861219 "External link (opens in new tab)")).
*   [`Symbol.species`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/species) has been added ([Firefox bug 1131043](https://bugzil.la/1131043 "External link (opens in new tab)")).
*   [`Map[Symbol.species]`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map/Symbol.species) and [`Set[Symbol.species]`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set/Symbol.species) getters have been added ([Firefox bug 1131043](https://bugzil.la/1131043 "External link (opens in new tab)")).
*   Non-standard [let expressions](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#statements_2) support has been dropped ([Firefox bug 1023609](https://bugzil.la/1023609 "External link (opens in new tab)")).
*   [Destructured parameters with default value assignment](/en-US/docs/Web/JavaScript/Reference/Functions/Default_parameters#destructured_parameter_with_default_value_assignment) are now supported ([Firefox bug 1018628](https://bugzil.la/1018628 "External link (opens in new tab)")).
*   Per ES2015, curly braces are required for [method definitions](/en-US/docs/Web/JavaScript/Reference/Functions/Method_definitions). Syntax without them will fail from now on ([Firefox bug 1150855](https://bugzil.la/1150855 "External link (opens in new tab)")).
*   [Method definitions](/en-US/docs/Web/JavaScript/Reference/Functions/Method_definitions) (except for generator methods) are not constructable anymore ([Firefox bug 1059908](https://bugzil.la/1059908 "External link (opens in new tab)") and [Firefox bug 1166950](https://bugzil.la/1166950 "External link (opens in new tab)")).
*   As part of ES2015 specification compliance, parenthesized [destructuring](/en-US/docs/Web/JavaScript/Reference/Operators/Destructuring) patterns, like `([a, b]) = [1, 2]` or `({a, b}) = { a: 1, b: 2 }`, are now considered invalid and will throw a [`SyntaxError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/SyntaxError). See [Jeff Walden's blog post](https://whereswalden.com/2015/06/20/new-changes-to-make-spidermonkeys-and-firefoxs-parsing-of-destructuring-patterns-more-spec-compliant/ "External link (opens in new tab)") for more details.
*   The [`new.target`](/en-US/docs/Web/JavaScript/Reference/Operators/new.target) syntax has been added ([Firefox bug 1141865](https://bugzil.la/1141865 "External link (opens in new tab)")).

### [Interfaces/APIs/DOM](#interfacesapisdom)

#### HTML Editing API

*   Cut, copy and paste commands handling has been revamped and now allow programmatic copying and cutting from JS for Web content:
    *   With the `'paste'` command as argument, [`Document.queryCommandSupported()`](/en-US/docs/Web/API/Document/queryCommandSupported) now returns `false` if has insufficient privileges to actually perform the action ([Firefox bug 1161721](https://bugzil.la/1161721 "External link (opens in new tab)")).
    *   With the `'cut'` or `'copy'` command as argument, [`Document.queryCommandSupported()`](/en-US/docs/Web/API/Document/queryCommandSupported) now returns `true` if called within the context of a user-initiated or privileged code ([Firefox bug 1162952](https://bugzil.la/1162952 "External link (opens in new tab)")).
    *   With the `'cut'` or `'copy'` command as argument, [`Document.execCommand()`](/en-US/docs/Web/API/Document/execCommand) now works, but only within the context of user-initiated or privileged code ([Firefox bug 1012662](https://bugzil.la/1012662 "External link (opens in new tab)")).
    *   Instead of raising an exception, [`Document.execCommand()`](/en-US/docs/Web/API/Document/execCommand) when the command is not supported or enabled ([Firefox bug 1027560](https://bugzil.la/1027560 "External link (opens in new tab)")).

#### Events

*   The non-standard `initCloseEvent()` method of the [`CloseEvent`](/en-US/docs/Web/API/CloseEvent) event and the ability to create a [`CloseEvent`](/en-US/docs/Web/API/CloseEvent) using the [`document.createEvent('CloseEvent')`](/en-US/docs/Web/API/Document/createEvent "document.createEvent('CloseEvent')") method has been removed; use the standard constructor, [`CloseEvent()`](/en-US/docs/Web/API/CloseEvent/CloseEvent "CloseEvent()") instead ([Firefox bug 1161950](https://bugzil.la/1161950 "External link (opens in new tab)")).
*   On Desktop, [`PointerEvent`](/en-US/docs/Web/API/PointerEvent) is now activated by default in Nightly; it is not activated in Developer Edition, Beta or Release and won't be for at least some versions ([Firefox bug 1166347](https://bugzil.la/1166347 "External link (opens in new tab)")).
*   The unprefixed version of [`MouseEvent.movementX`](/en-US/docs/Web/API/MouseEvent/movementX) and [`MouseEvent.movementY`](/en-US/docs/Web/API/MouseEvent/movementY) have been added; the prefixed versions are deprecated and will be removed at some point in the future ([Firefox bug 1164981](https://bugzil.la/1164981 "External link (opens in new tab)")).

#### Web Crypto

*   [`SubtleCrypto.importKey()`](/en-US/docs/Web/API/SubtleCrypto/importKey) and [`SubtleCrypto.exportKey()`](/en-US/docs/Web/API/SubtleCrypto/exportKey) now supports `ECDH` keys ([Firefox bug 1050175](https://bugzil.la/1050175 "External link (opens in new tab)")).

#### Canvas API

*   [`HTMLCanvasElement.captureStream()`](/en-US/docs/Web/API/HTMLCanvasElement/captureStream) and `CanvasCaptureMediaStream` have been added and allow you to stream the display of a [`<canvas>`](/en-US/docs/Web/HTML/Reference/Elements/canvas) in real-time ([Firefox bug 1032848](https://bugzil.la/1032848 "External link (opens in new tab)")).
*   [`MediaStream.id`](/en-US/docs/Web/API/MediaStream/id) now returns the unique id of a stream ([Firefox bug 1089798](https://bugzil.la/1089798 "External link (opens in new tab)")).
*   The initial value of [`CanvasRenderingContext2D.filter`](/en-US/docs/Web/API/CanvasRenderingContext2D/filter) is now correctly set to `none` ([Firefox bug 1163124](https://bugzil.la/1163124 "External link (opens in new tab)")).

#### Service Workers

*   Improvement to our experimental [Service Worker](/en-US/docs/Web/API/Service_Worker_API) implementation:
    
    *   [`ServiceWorkerGlobalScope.skipWaiting()`](/en-US/docs/Web/API/ServiceWorkerGlobalScope/skipWaiting) has been implemented ([Firefox bug 1131352](https://bugzil.la/1131352 "External link (opens in new tab)")).
    *   [`Clients.claim()`](/en-US/docs/Web/API/Clients/claim) has been added ([Firefox bug 1130684](https://bugzil.la/1130684 "External link (opens in new tab)")).
    *   The other functional events of Service Workers have been made to inherit from [`ExtendableEvent`](/en-US/docs/Web/API/ExtendableEvent), giving them access to the [`waitUntil()`](/en-US/docs/Web/API/ExtendableEvent/waitUntil "waitUntil()") method ([Firefox bug 1160527](https://bugzil.la/1160527 "External link (opens in new tab)")).
*   The [`CacheStorage`](/en-US/docs/Web/API/CacheStorage) and [`Cache`](/en-US/docs/Web/API/Cache) interfaces are now supported ([Firefox bug 1110144](https://bugzil.la/1110144 "External link (opens in new tab)")).
    

#### WebGL

*   The `failIfMajorPerformanceCaveat` WebGL context attribute has been added and can be set when creating a WebGL context with [`HTMLCanvasElement.getContext()`](/en-US/docs/Web/API/HTMLCanvasElement/getContext) to indicate if a context creation should fail if the system performance is low ([Firefox bug 1164970](https://bugzil.la/1164970 "External link (opens in new tab)")).

#### WebRTC

*   Firefox no longer offers a default STUN server to be used if none are specified when constructing a new [`RTCPeerConnection`](/en-US/docs/Web/API/RTCPeerConnection). You'll need to provide one in order to successfully establish a WebRTC connection.

#### Miscellaneous

*   On OS X and Windows, [`Navigator.onLine`](/en-US/docs/Web/API/Navigator/onLine) now changes regarding network connectivity (it always returned `true`, unless "Work offline" mode was selected) before ([Firefox bug 654579](https://bugzil.la/654579 "External link (opens in new tab)")).
*   [`MessagePort`](/en-US/docs/Web/API/MessagePort) and [`MessageChannel`](/en-US/docs/Web/API/MessageChannel) now available in [Web workers](/en-US/docs/Web/API/Web_Workers_API), and are enabled by default in all contexts ([Firefox bug 952139](https://bugzil.la/952139 "External link (opens in new tab)")) and ([Firefox bug 911972](https://bugzil.la/911972 "External link (opens in new tab)")).
*   The User Timing API is now available in [Web workers](/en-US/docs/Web/API/Web_Workers_API) ([Firefox bug 1155761](https://bugzil.la/1155761 "External link (opens in new tab)")).
*   The [Notifications API](/en-US/docs/Web/API/Notifications_API) is now available in [Web workers](/en-US/docs/Web/API/Web_Workers_API) ([Firefox bug 916893](https://bugzil.la/916893 "External link (opens in new tab)")).
*   `DOMRequest` and `DOMCursor` are now available in [Web workers](/en-US/docs/Web/API/Web_Workers_API) ([Firefox bug 1167650](https://bugzil.la/1167650 "External link (opens in new tab)")).
*   The [CSS Font Loading API](/en-US/docs/Web/API/CSS_Font_Loading_API) has been completely implemented and is now enabled by default ([Firefox bug 1149381](https://bugzil.la/1149381 "External link (opens in new tab)")).
*   Shared workers can no longer be shared between private (i.e., browsing in a private window) and non-private documents (see [Firefox bug 1177621](https://bugzil.la/1177621 "External link (opens in new tab)")).
*   The [`URL.searchParams`](/en-US/docs/Web/API/URL/searchParams) property is now read-only ([Firefox bug 1174731](https://bugzil.la/1174731 "External link (opens in new tab)")).
*   The [`HTMLAnchorElement.hash`](/en-US/docs/Web/API/HTMLAnchorElement/hash) property no longer decodes URL fragment ([Firefox bug 1093611](https://bugzil.la/1093611 "External link (opens in new tab)")).

### [MathML](#mathml)

#### New default and fallback font handling

Mathematical formulas require special fonts. So far, these fonts were hard-coded in the `mathml.css` user agent stylesheet (which sets the font-family on [`<math>`](/en-US/docs/Web/MathML/Reference/Element/math "<math>") tag) and in the preference option `font.mathfont-family` (which sets the fallback fonts to use for stretchy and large operators). Firefox 41 introduces an internal `x-math` language that is automatically set on the `<math>` tag as well as corresponding preference options (e.g., `font.name.serif.x-math`). The user agent stylesheet now sets font-family to serif on the `<math>` tag and the preference option `font.mathfont-family` is replaced with `font.name.serif.x-math`. All platforms now essentially use the same list of fallback fonts, with "Latin Modern Math" as the first one. The default/fallback fonts can be configured from the standard per-language font preference menu. For more details, see [Firefox bug 947654](https://bugzil.la/947654 "External link (opens in new tab)") and [Firefox bug 1160456](https://bugzil.la/1160456 "External link (opens in new tab)").

### [SVG](#svg)

*   Site icons (favicons, shortcut icons) now support SVG ([Firefox bug 366324](https://bugzil.la/366324 "External link (opens in new tab)")).

### [Audio/Video](#audiovideo)

*   The `media.autoplay.enabled` preference now also applies to untrusted [`HTMLMediaElement.play()`](/en-US/docs/Web/API/HTMLMediaElement/play) invocations too, that is calls from non-users activated scripts ([Firefox bug 659285](https://bugzil.la/659285 "External link (opens in new tab)")).

## [Networking](#networking)

*   The `X-Content-Duration` header is no longer supported ([Firefox bug 1160695](https://bugzil.la/1160695 "External link (opens in new tab)")).
*   Draft versions of the HTTP/2 protocol are no more supported ([Firefox bug 1132357](https://bugzil.la/1132357 "External link (opens in new tab)")).

## [Security](#security)

*   The [CSP](/en-US/docs/Web/HTTP/Guides/CSP) 1.1 `manifest-src` [directive](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy) is now supported ([Firefox bug 1089255](https://bugzil.la/1089255 "External link (opens in new tab)")).
*   Previous versions of Firefox incorrectly expected the [Content Security Policy](/en-US/docs/Web/HTTP/Guides/CSP) referrer directive's value `origin-when-cross-origin` to be spelled `origin-when-crossorigin`. This has been corrected to include the missing dash character.
