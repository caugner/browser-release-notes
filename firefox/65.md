# Firefox 65 release notes for developers

This article provides information about the changes in Firefox 65 that will affect developers. Firefox 65 was released on January 29, 2019.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   The [Flexbox inspector](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_flexbox_layouts/index.html "External link (opens in new tab)") is now enabled by default.
*   Support has been added to the [JavaScript Debugger](https://firefox-source-docs.mozilla.org/devtools-user/debugger/index.html "External link (opens in new tab)") for XHR Breakpoints ([Firefox bug 821610](https://bugzil.la/821610 "External link (opens in new tab)")).
*   Right-click on an item in the accessibility tree from the Accessibility viewer to [print it as JSON](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html#print-accessibility-tree-to-json "External link (opens in new tab)") to the JSON viewer.
*   The [color contrast](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html#color-contrast "External link (opens in new tab)") display of the Accessibility Picker has been updated so that if a text's background is complex (e.g., a gradient or complex image), it shows a range of color contrast values.
*   The Headers tab of the [Network Monitor](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html "External link (opens in new tab)") now displays the Referrer Policy for the selected request ([Firefox bug 1496742](https://bugzil.la/1496742 "External link (opens in new tab)")).
*   When displaying stack traces (e.g., in console logs or the JavaScript debugger), calls to framework methods are identified and collapsed by default, making it easier to home in on your code.
*   In the same fashion as native terminals, you can now use reverse search to find entries in your JavaScript console history (`F9` on Windows/Linux or `Ctrl` + `R` on macOS, then type a search term, followed by `Ctrl` + `R`/`Ctrl` + `S` to toggle through results).
*   The JavaScript console's `$0` shortcut (references the currently inspected element on the page) now has autocomplete available, so for example you could type `$0.te` to get autocomplete suggestions for properties like `$0.textContent`.
*   The edits you make in the Rules view of the Inspector are now listed in the Changes panel ([Firefox bug 1503920](https://bugzil.la/1503920 "External link (opens in new tab)")).

### [HTML](#html)

*   Events are now dispatched on disabled HTML elements, i.e., [`<button>`](/en-US/docs/Web/HTML/Reference/Elements/button), [`<fieldset>`](/en-US/docs/Web/HTML/Reference/Elements/fieldset), [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input), [`<select>`](/en-US/docs/Web/HTML/Reference/Elements/select), and [`<textarea>`](/en-US/docs/Web/HTML/Reference/Elements/textarea) elements with `disabled` attributes set on them ([Firefox bug 329509](https://bugzil.la/329509 "External link (opens in new tab)")).
*   Removing the `src` attribute of an [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) element now causes `about:blank` to be loaded into it, giving it parity with Chrome and Safari ([Firefox bug 1507842](https://bugzil.la/1507842 "External link (opens in new tab)")). Previously removing `src` had no effect on the `iframe` content.
*   We have added support for the [`referrerpolicy`](/en-US/docs/Web/HTML/Reference/Elements/script#referrerpolicy) attribute on [`<script>`](/en-US/docs/Web/HTML/Reference/Elements/script) elements ([Firefox bug 1460920](https://bugzil.la/1460920 "External link (opens in new tab)")).

### [CSS](#css)

*   The [`image-rendering`](/en-US/docs/Web/CSS/Reference/Properties/image-rendering) property's `crisp-edges` value has now been unprefixed ([Firefox bug 1496617](https://bugzil.la/1496617 "External link (opens in new tab)")).
    
*   A [`scrollbar-color`](/en-US/docs/Web/CSS/Reference/Properties/scrollbar-color) value of `auto` now resolves to `auto`, rather than two colors ([Firefox bug 1501418](https://bugzil.la/1501418 "External link (opens in new tab)")).
    
*   The `break-*` properties have been implemented, and the legacy `page-break-*` properties have been aliased to them ([Firefox bug 775618](https://bugzil.la/775618 "External link (opens in new tab)")):
    
    *   [`break-before`](/en-US/docs/Web/CSS/Reference/Properties/break-before) is now an alias for [`page-break-before`](/en-US/docs/Web/CSS/Reference/Properties/page-break-before).
    *   [`break-after`](/en-US/docs/Web/CSS/Reference/Properties/break-after) is now an alias for [`page-break-after`](/en-US/docs/Web/CSS/Reference/Properties/page-break-after).
    *   [`break-inside`](/en-US/docs/Web/CSS/Reference/Properties/break-inside) is now an alias for [`page-break-inside`](/en-US/docs/Web/CSS/Reference/Properties/page-break-inside).
*   The [`overflow-wrap`](/en-US/docs/Web/CSS/Reference/Properties/overflow-wrap) property's `anywhere` value has been implemented ([Firefox bug 1505786](https://bugzil.la/1505786 "External link (opens in new tab)")).
    
*   The new step position keywords `jump-start`, `jump-end`, `jump-none`, and `jump-both` — usable inside the [`steps()` timing function](/en-US/docs/Web/CSS/Reference/Values/easing-function/steps) — have been implemented ([Firefox bug 1496619](https://bugzil.la/1496619 "External link (opens in new tab)")). This also coincides with the removal of the `frames()` timing function, which was the previous way of implementing such functionality, now deprecated.
    
*   Some new [`-webkit-appearance`](/en-US/docs/Web/CSS/Reference/Properties/appearance) values have been added, for compatibility with other browsers. In particular:
    
    *   `meter`, which is now used as the default value for [`<meter>`](/en-US/docs/Web/HTML/Reference/Elements/meter) elements in UA stylesheets. The existing value `meterbar` is now an alias for `meter` ([Firefox bug 1501483](https://bugzil.la/1501483 "External link (opens in new tab)")).
    *   `progress-bar`, which is now used as the default value for [`<progress>`](/en-US/docs/Web/HTML/Reference/Elements/progress) elements in UA stylesheets. The existing value `progressbar` is now an alias for `progress-bar` ([Firefox bug 1501506](https://bugzil.la/1501506 "External link (opens in new tab)")).
    *   `textarea`, which is now used as the default value for [`<textarea>`](/en-US/docs/Web/HTML/Reference/Elements/textarea) elements in UA stylesheets. The existing value `textfield-multiline` is now an alias for `textarea` ([Firefox bug 1507905](https://bugzil.la/1507905 "External link (opens in new tab)")).
*   The behavior of [`user-select`](/en-US/docs/Web/CSS/Reference/Properties/user-select) has been changed to make it align more with other browsers ([Firefox bug 1506547](https://bugzil.la/1506547 "External link (opens in new tab)")). Specifically:
    
    *   `user-select: all` set on an element no longer overrides other values of `user-select` set on children of that element. So for example in the following snippet:
        
        html
        
        ```
        <div style="-webkit-user-select: all">
          All
          <div style="-webkit-user-select: none">None</div>
        </div>
        ```
        
        The `<div>` with `none` set on it is now non-selectable. Previously this value would have been overridden by the `all` value set on the parent element.
        
    *   non-`contenteditable` elements nested inside `contenteditable` elements are now selectable.
        
    *   `user-select` now behaves consistently inside and outside shadow DOM.
        
    *   The proprietary `-moz-text` value has been removed.
        
*   CSS environment variables (the [`env()`](/en-US/docs/Web/CSS/Reference/Values/env) function) have been implemented ([Firefox bug 1462233](https://bugzil.la/1462233 "External link (opens in new tab)")).
    

#### Removals

*   The `layout.css.shape-outside.enabled` pref has been removed; [`shape-outside`](/en-US/docs/Web/CSS/Reference/Properties/shape-outside), [`shape-margin`](/en-US/docs/Web/CSS/Reference/Properties/shape-margin), and [`shape-image-threshold`](/en-US/docs/Web/CSS/Reference/Properties/shape-image-threshold) can no longer be disabled in `about:config` ([Firefox bug 1504387](https://bugzil.la/1504387 "External link (opens in new tab)")).
*   Several Firefox-only values of the [`user-select`](/en-US/docs/Web/CSS/Reference/Properties/user-select) property have been removed — `-moz-all`, `-moz-text`, `tri-state`, `element`, `elements`, and `toggle`. See [Firefox bug 1492958](https://bugzil.la/1492958 "External link (opens in new tab)") and [Firefox bug 1506547](https://bugzil.la/1506547 "External link (opens in new tab)").
*   As mentioned above, the `frames()` timing function has been removed ([Firefox bug 1496619](https://bugzil.la/1496619 "External link (opens in new tab)")).

### [SVG](#svg)

_No changes._

### [JavaScript](#javascript)

*   [`Intl.RelativeTimeFormat`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/RelativeTimeFormat) is now supported ([Firefox bug 1504334](https://bugzil.la/1504334 "External link (opens in new tab)")).
*   Strings now have a maximum [length](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/length) of `2**30 - 2` (~1GB) instead of `2**28 - 1` (~256MB) ([Firefox bug 1509542](https://bugzil.la/1509542 "External link (opens in new tab)")).
*   The [`globalThis`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/globalThis) property, which always refers to the top-level global object, has been implemented ([Firefox bug 1317422](https://bugzil.la/1317422 "External link (opens in new tab)")).

### [APIs](#apis)

#### New APIs

*   [Readable Streams](/en-US/docs/Web/API/Streams_API/Using_readable_streams "Readable Streams") have been enabled by default ([Firefox bug 1505122](https://bugzil.la/1505122 "External link (opens in new tab)")).
*   The [Storage Access API](/en-US/docs/Web/API/Storage_Access_API "Storage Access API") has been enabled by default ([Firefox bug 1513021](https://bugzil.la/1513021 "External link (opens in new tab)")).

#### DOM

*   [`Performance.toJSON()`](/en-US/docs/Web/API/Performance/toJSON) has been exposed to [Web Workers](/en-US/docs/Web/API/Web_Workers_API "Web Workers") ([Firefox bug 1504958](https://bugzil.la/1504958 "External link (opens in new tab)")).
*   [`XMLHttpRequest`](/en-US/docs/Web/API/XMLHttpRequest) requests will now throw a `NetworkError` if the requested content type is a `Blob`, and the request method is not `GET` ([Firefox bug 1502599](https://bugzil.la/1502599 "External link (opens in new tab)")).
*   The `-moz-` prefixed versions of many of the [Fullscreen API](/en-US/docs/Web/API/Fullscreen_API) features have been deprecated, and will now display deprecation warnings in the JavaScript console when encountered ([Firefox bug 1504946](https://bugzil.la/1504946 "External link (opens in new tab)")).
*   [`Window.createImageBitmap()`](/en-US/docs/Web/API/Window/createImageBitmap) and [`WorkerGlobalScope.createImageBitmap()`](/en-US/docs/Web/API/WorkerGlobalScope/createImageBitmap) now supports SVG images ([`SVGImageElement`](/en-US/docs/Web/API/SVGImageElement)) as an image source ([Firefox bug 1500768](https://bugzil.la/1500768 "External link (opens in new tab)")).

#### DOM events

*   Going forward, only one [`Window.open()`](/en-US/docs/Web/API/Window/open) call is allowed per event ([Firefox bug 675574](https://bugzil.la/675574 "External link (opens in new tab)")).
*   The [`keyup`](/en-US/docs/Web/API/Element/keyup_event) and [`keydown`](/en-US/docs/Web/API/Element/keydown_event) events are now fired during IME composition, to improve cross-browser compatibility for CJKT users ([Firefox bug 354358](https://bugzil.la/354358 "External link (opens in new tab)").

#### Web workers

*   [`SharedWorkerGlobalScope.connect`](/en-US/docs/Web/API/SharedWorkerGlobalScope/connect_event "SharedWorkerGlobalScope.connect")'s event object is a [`MessageEvent`](/en-US/docs/Web/API/MessageEvent) instance — its `data` property is now an empty string value rather than `null` ([Firefox bug 1508824](https://bugzil.la/1508824 "External link (opens in new tab)")).

#### Fetch and Service workers

*   The [`Response.redirect()`](/en-US/docs/Web/API/Response/redirect_static "Response.redirect()") method now correctly throws a `TypeError` if a non-valid URL is specified as the first parameter ([Firefox bug 1503276](https://bugzil.la/1503276 "External link (opens in new tab)")).
*   The [`ServiceWorkerContainer.register()`](/en-US/docs/Web/API/ServiceWorkerContainer/register) and [`WorkerGlobalScope.importScripts()`](/en-US/docs/Web/API/WorkerGlobalScope/importScripts) (when used by a service worker) methods will now accept any files with a valid [JavaScript MIME type](/en-US/docs/Web/HTTP/Guides/MIME_types#textjavascript) ([Firefox bug 1354577](https://bugzil.la/1354577 "External link (opens in new tab)")).
*   The `FetchEvent.replacesClientId` and [`FetchEvent.resultingClientId`](/en-US/docs/Web/API/FetchEvent/resultingClientId) properties are now supported ([Firefox bug 1264177](https://bugzil.la/1264177 "External link (opens in new tab)")).
*   The [`ServiceWorkerGlobalScope.onmessageerror`](/en-US/docs/Web/API/ServiceWorkerGlobalScope/messageerror_event "ServiceWorkerGlobalScope.onmessageerror") and [`ServiceWorkerContainer.onmessageerror`](/en-US/docs/Web/API/ServiceWorkerContainer/messageerror_event "ServiceWorkerContainer.onmessageerror") handler properties have been implemented ([Firefox bug 1399446](https://bugzil.la/1399446 "External link (opens in new tab)")).
*   The [`Origin`](/en-US/docs/Web/HTTP/Reference/Headers/Origin) header is no longer set on Fetch requests with a method of [`HEAD`](/en-US/docs/Web/HTTP/Reference/Methods/HEAD) or [`GET`](/en-US/docs/Web/HTTP/Reference/Methods/GET) ([Firefox bug 1508661](https://bugzil.la/1508661 "External link (opens in new tab)")).

#### Media, Web Audio, and WebRTC

*   The [WebRTC](/en-US/docs/Web/API/WebRTC_API "WebRTC") [`RTCIceCandidateStats`](/en-US/docs/Web/API/RTCIceCandidateStats) dictionary has been updated according to the latest spec changes ([Firefox bug 1324788](https://bugzil.la/1324788 "External link (opens in new tab)"), [Firefox bug 1489040](https://bugzil.la/1489040 "External link (opens in new tab)"); RTCIceCandidateStats has been updated to the latest spec for more details on exactly what has changed).
*   The [`MediaRecorder`](/en-US/docs/Web/API/MediaRecorder) `pause` and `resume` events (and their corresponding event handler properties were not previously implemented, even though compatibility tables claimed they had been. They have now been implemented ([Firefox bug 1458538](https://bugzil.la/1458538 "External link (opens in new tab)"), [Firefox bug 1514016](https://bugzil.la/1514016 "External link (opens in new tab)")).

#### Canvas and WebGL

*   The [WebGL](/en-US/docs/Web/API/WebGL_API "WebGL") [`EXT_texture_compression_bptc`](/en-US/docs/Web/API/EXT_texture_compression_bptc) and [`EXT_texture_compression_rgtc`](/en-US/docs/Web/API/EXT_texture_compression_rgtc) texture compression extensions have been exposed to WebGL1 and WebGL2 contexts ([Firefox bug 1507263](https://bugzil.la/1507263 "External link (opens in new tab)")).

#### Removals

*   [Mutation events](/en-US/docs/Web/API/MutationEvent) have been disabled in shadow trees ([Firefox bug 1489858](https://bugzil.la/1489858 "External link (opens in new tab)")).
*   The non-standard [`MediaStream`](/en-US/docs/Web/API/MediaStream) property `currentTime` has been removed ([Firefox bug 1502927](https://bugzil.la/1502927 "External link (opens in new tab)")).
*   The `dom.webcomponents.shadowdom.enabled` and `dom.webcomponents.customelements.enabled` prefs have been removed — Shadow DOM and Custom Elements can no longer be disabled in `about:config` ([Firefox bug 1503019](https://bugzil.la/1503019 "External link (opens in new tab)")).
*   The non-standard DOM `text` event — fired to notify the browser editor UI of IME composition string data and selection range — has been removed ([Firefox bug 1288640](https://bugzil.la/1288640 "External link (opens in new tab)")).
*   The [`keypress`](/en-US/docs/Web/API/Element/keypress_event "keypress") event is no longer fired for [non-printable keys](/en-US/docs/Web/API/KeyboardEvent/keyCode#non-printable_keys_function_keys) ([Firefox bug 968056](https://bugzil.la/968056 "External link (opens in new tab)")), except for the `Enter` key, and the `Shift` + `Enter` and `Ctrl` + `Enter` key combinations (these were kept for cross-browser compatibility purposes).

### [Security](#security)

*   Additional CORS restrictions are now being enforced on allowable request headers ([Firefox bug 1483815](https://bugzil.la/1483815 "External link (opens in new tab)"), see also [whatwg fetch issue 382: CORS-safelisted request headers should be restricted according to RFC 7231](https://github.com/whatwg/fetch/issues/382 "External link (opens in new tab)") for more details).

_No changes._

_No changes._

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

#### API changes

*   `WebDriver:ElementSendKeys` now handles `<input type=file>` more relaxed for interactability checks, and allows those elements to be hidden without raising a `not interactable` error anymore. If a strict interactability check is wanted the capability `strictFileInteractability` can be used ([Firefox bug 1502864](https://bugzil.la/1502864 "External link (opens in new tab)")).

#### Bug fixes

*   The window manipulation commands `WebDriver:FullscreenWindow`, `WebDriver:MinimizeWindow`, `WebDriver:MaximizeWindow`, and `WebDriver:SetWindowRect` have been made more stable ([Firefox bug 1492499](https://bugzil.la/1492499 "External link (opens in new tab)")). It means that under special conditions they don't cause an infinite hang anymore, but instead timeout after 5s if the requested window state cannot be reached ([Firefox bug 1521527](https://bugzil.la/1521527 "External link (opens in new tab)")).
*   `WebDriver:ElementClick` now correctly calculates the center point of the element to click, which allows interactions with dimensions of 1x1 pixels ([Firefox bug 1499360](https://bugzil.la/1499360 "External link (opens in new tab)")).

#### Others

*   For `unexpected alert open` errors more informative messages are provided ([Firefox bug 1502268](https://bugzil.la/1502268 "External link (opens in new tab)")).

### [Other](#other)

*   Support for [WebP](/en-US/docs/Glossary/WebP) images has been added ([Firefox bug 1294490](https://bugzil.la/1294490 "External link (opens in new tab)")).
    
    *   In addition, to facilitate cross-browser compatibility in certain situations the WebP MIMEType (`image/webp`) has been added to the standard HTTP Request [`Accept`](/en-US/docs/Web/HTTP/Reference/Headers/Accept) header for HTML files ([Firefox bug 1507691](https://bugzil.la/1507691 "External link (opens in new tab)")).
*   The AV1 codec is now supported by default on Windows ([Firefox bug 1452146](https://bugzil.la/1452146 "External link (opens in new tab)")).
    

## [Changes for add-on developers](#changes_for_add-on_developers)

### [API changes](#api_changes_2)

#### Tabs

*   The [tabs API](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs) has been enhanced to support tab successors — a tab can have a successor assigned to it, which is the ID of the tab that will be active once it is closed ([Firefox bug 1500479](https://bugzil.la/1500479 "External link (opens in new tab)"), also see [this blog post](https://qiita.com/piroor/items/ea7e727735631c45a366 "External link (opens in new tab)") for more information). In particular:
    *   The [`tabs.Tab`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/Tab) type now has a `successorId` property, which can be used to store/retrieve the ID of the tab's successor.
    *   The [`tabs.onActivated`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/onActivated) event listener's callback has a new parameter available, `previousTabId`, which contains the ID of the previous activated tab, if it is still open.
    *   The [`tabs.update()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/update) function's `updateProperties` object has a new optional property available on it, `successorTabId`, so can be used to update it.
    *   `successorTabId` is also returned by functions like [`tabs.get()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/get) and [`tabs.query()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/query).
    *   The new function `tabs.moveInSuccession()` allows manipulation of tab successors in bulk.
