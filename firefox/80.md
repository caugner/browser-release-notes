# Firefox 80 release notes for developers

This article provides information about the changes in Firefox 80 that will affect developers. Firefox 80 was released on August 25, 2020.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

*   You can now block and unblock network requests using the `:block` and `:unblock` [helper commands](https://firefox-source-docs.mozilla.org/devtools-user/web_console/helpers/index.html "External link (opens in new tab)") in the Web Console ([Firefox bug 1546394](https://bugzil.la/1546394 "External link (opens in new tab)")).
*   When [adding a class](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_css/index.html#viewing-and-changing-classes-on-an-element "External link (opens in new tab)") to an element in the Page Inspector's Rules pane, existing classes are suggested with autocomplete (Refer to [Firefox bug 1492797](https://bugzil.la/1492797 "External link (opens in new tab)")).
*   When the Debugger [breaks on an exception](https://firefox-source-docs.mozilla.org/devtools-user/debugger/how_to/breaking_on_exceptions/index.html "External link (opens in new tab)"), the tooltip in the source pane now shows a disclosure triangle that reveals a stack trace ([Firefox bug 1643633](https://bugzil.la/1643633 "External link (opens in new tab)")).
*   In the [Network Monitor request list](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/request_list/index.html#network-request-columns "External link (opens in new tab)"), a turtle icon is shown for "slow" requests that exceed a configurable threshold for the waiting time ([Firefox bug 1648373](https://bugzil.la/1648373 "External link (opens in new tab)")).

### [HTML](#html)

_No changes._

### [CSS](#css)

*   The standard, unprefixed [`appearance`](/en-US/docs/Web/CSS/Reference/Properties/appearance) property is now supported; existing `-moz-appearance` and `-webkit-appearance` are now aliases of the unprefixed property ([Firefox bug 1620467](https://bugzil.la/1620467 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   The ECMAScript 2021 `export * as namespace` syntax for the [`export`](/en-US/docs/Web/JavaScript/Reference/Statements/export) statement is now supported ([Firefox bug 1496852](https://bugzil.la/1496852 "External link (opens in new tab)")).

### [HTTP](#http)

*   Previously, when the [fullscreen](/en-US/docs/Web/HTTP/Reference/Headers/Permissions-Policy/fullscreen) directive was applied to an [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) (i.e., via the `allow` attribute), it didn't work unless the `allowfullscreen` attribute was also present This has now been fixed ([Firefox bug 1608358](https://bugzil.la/1608358 "External link (opens in new tab)")).

### [APIs](#apis)

#### DOM

*   Web Animations API compositing operations are now enabled — see [`KeyframeEffect.composite`](/en-US/docs/Web/API/KeyframeEffect/composite) and [`KeyframeEffect.iterationComposite`](/en-US/docs/Web/API/KeyframeEffect/iterationComposite) ([Firefox bug 1652676](https://bugzil.la/1652676 "External link (opens in new tab)")).

#### Removals

*   The `outerHeight` and `outerWidth` features of [`Window.open()`](/en-US/docs/Web/API/Window/open) are no longer exposed to web content ([Firefox bug 1623826](https://bugzil.la/1623826 "External link (opens in new tab)")).

### [WebAssembly](#webassembly)

*   Atomic operations are now allowed on non-shared memories ([Firefox bug 1619196](https://bugzil.la/1619196 "External link (opens in new tab)")).

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

*   Using `WebDriver:NewWindow` to open a new tab no longer returns too early when running tests in headless mode ([Firefox bug 1653281](https://bugzil.la/1653281 "External link (opens in new tab)")).
*   We removed the `name` argument for `WebDriver:SwitchToWindow` — it is not supported for W3C-compatible mode, and shouldn't be used anymore ([Firefox bug 1588424](https://bugzil.la/1588424 "External link (opens in new tab)")).
*   We've started to add Fission support for the following commands: `WebDriver:FindElement`, `WebDriver:FindElements`, `WebDriver:GetElementAttribute`, `WebDriver:GetElementProperty`.
*   **Known issue**: Opening a new tab by using `WebDriver:NewWindow`, or via an arbitrary script that calls `window.open()`, now automatically switches to that new window ([Firefox bug 1661495](https://bugzil.la/1661495 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

_No changes._
