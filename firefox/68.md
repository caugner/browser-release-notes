# Firefox 68 release notes for developers

This article provides information about the changes in Firefox 68 that will affect developers. Firefox 68 was released on July 9, 2019.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

#### Browser/web console

*   The Web console now shows [more information about CSS warnings](https://firefox-source-docs.mozilla.org/devtools-user/web_console/console_messages/index.html#css "External link (opens in new tab)"), including a node list of the DOM elements that used the rule ([Firefox bug 1093953](https://bugzil.la/1093953 "External link (opens in new tab)")).
*   You can now filter content in the Web console using regular expressions ([Firefox bug 1441079](https://bugzil.la/1441079 "External link (opens in new tab)")).
*   The Browser console now allows you to show or hide messages from the content process by setting or clearing the checkbox labeled _Show Content Messages_ ([Firefox bug 1260877](https://bugzil.la/1260877 "External link (opens in new tab)")).

#### JavaScript debugger

*   You can now [Search](https://firefox-source-docs.mozilla.org/devtools-user/debugger/how_to/search/index.html#searching-in-all-files "External link (opens in new tab)") in all files in the current project from the debugger by pressing `Shift` + `Ctrl` + `F` (Windows or Linux) or `Shift` + `Cmd` + `F` (macOS) ([Firefox bug 1320325](https://bugzil.la/1320325 "External link (opens in new tab)")).

#### Network monitor

*   The Network monitor [request list](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/request_list/index.html#filtering-requests "External link (opens in new tab)") now allows you to block a specific URL ([Firefox bug 1151368](https://bugzil.la/1151368 "External link (opens in new tab)")).
*   You can now resend a network request without editing the method, URL, parameters, and headers, using the [Resend](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/request_list/index.html#context-menu "External link (opens in new tab)") command on the context menu ([Firefox bug 1422014](https://bugzil.la/1422014 "External link (opens in new tab)")).
*   The context menu of the Network monitor [Headers](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/request_details/index.html#headers "External link (opens in new tab)") tab now allows you to copy all or some of the header information to the clipboard in JSON format ([Firefox bug 1442249](https://bugzil.la/1442249 "External link (opens in new tab)")).

#### Page inspector

*   A button has been added to the [rules panel](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_css/index.html#examine-css-rules "External link (opens in new tab)") of the Page inspector that allows you to toggle the display of any print media queries ([Firefox bug 1534984](https://bugzil.la/1534984 "External link (opens in new tab)")).
*   The [fonts panel](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/edit_fonts/index.html "External link (opens in new tab)") now includes a slider to modify `letter-spacing` ([Firefox bug 1536237](https://bugzil.la/1536237 "External link (opens in new tab)")).
*   A warning icon appears next to unsupported CSS properties or rules that have invalid values, to help you understand why certain styles are not being applied ([Firefox bug 1306054](https://bugzil.la/1306054 "External link (opens in new tab)")).

#### Storage inspector

*   You can now [delete local and session storage](https://firefox-source-docs.mozilla.org/devtools-user/storage_inspector/index.html#local-storage-session-storage "External link (opens in new tab)") entries by selecting the item in the storage inspector and pressing the backspace key ([Firefox bug 1522893](https://bugzil.la/1522893 "External link (opens in new tab)")).

#### Other

*   The [Accessibility Inspector](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html "External link (opens in new tab)") now includes a new _Check for issues_ feature, which will include a number of audit tools to highlight accessibility problems on your web pages. The first available check is _contrast_, for highlighting color contrast problems.
*   The preference that controls the visibility of internal extensions (system add-ons and hidden extensions) on the [about:debugging](https://firefox-source-docs.mozilla.org/devtools-user/about_colon_debugging/index.html "External link (opens in new tab)") page has been changed from `devtools.aboutdebugging.showSystemAddons` to `devtools.aboutdebugging.showHiddenAddons` ([Firefox bug 1544372](https://bugzil.la/1544372 "External link (opens in new tab)")).
*   [Responsive design mode](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html "External link (opens in new tab)") has been redesigned — the _Device Settings_ dialog (device selection menu > _Edit List…_) is now more intuitive and simpler to use ([Firefox bug 1487857](https://bugzil.la/1487857 "External link (opens in new tab)")).

#### Removals

*   The "Enable add-on debugging" checkbox has been removed from the [about:debugging](https://firefox-source-docs.mozilla.org/devtools-user/about_colon_debugging/index.html "External link (opens in new tab)") page ([Firefox bug 1544813](https://bugzil.la/1544813 "External link (opens in new tab)")).

### [HTML](#html)

*   The [`<track>`](/en-US/docs/Web/HTML/Reference/Elements/track) element — represented by [`HTMLTrackElement`](/en-US/docs/Web/API/HTMLTrackElement) — now receives a [`cuechange`](/en-US/docs/Web/API/HTMLTrackElement/cuechange_event "cuechange") event in addition to the [`TextTrack`](/en-US/docs/Web/API/TextTrack) itself, if the text track is a contained by a media element ([Firefox bug 1548731](https://bugzil.la/1548731 "External link (opens in new tab)")).
*   [`<link>`](/en-US/docs/Web/HTML/Reference/Elements/link) elements support the `disabled` attribute again, albeit with different behavior. When `disabled` is set on a `<link>` element along with `rel="stylesheet"`, the referenced stylesheet is not loaded during page load, and will be loaded on demand when the `disabled` attribute is changed to `false` or removed ([Firefox bug 1281135](https://bugzil.la/1281135 "External link (opens in new tab)")).

#### Removals

*   [`<meta http-equiv="set-cookie">`](/en-US/docs/Web/HTML/Reference/Elements/meta) is no longer supported ([Firefox bug 1457503](https://bugzil.la/1457503 "External link (opens in new tab)")).

### [CSS](#css)

*   [CSS Scroll Snapping](/en-US/docs/Web/CSS/Guides/Scroll_snap) has been updated to the latest version of the specification ([Firefox bug 1312163](https://bugzil.la/1312163 "External link (opens in new tab)")) and ([Firefox bug 1544136](https://bugzil.la/1544136 "External link (opens in new tab)")), this includes:
    
    *   The `scroll-padding` property ([Firefox bug 1373832](https://bugzil.la/1373832 "External link (opens in new tab)"))
    *   The `scroll-margin` property ([Firefox bug 1373833](https://bugzil.la/1373833 "External link (opens in new tab)"))
    *   The [`scroll-snap-align`](/en-US/docs/Web/CSS/Reference/Properties/scroll-snap-align) property ([Firefox bug 1373835](https://bugzil.la/1373835 "External link (opens in new tab)"))
*   The [`-webkit-line-clamp`](/en-US/docs/Web/CSS/Reference/Properties/line-clamp) property has been implemented for compatibility with other browsers ([Firefox bug 866102](https://bugzil.la/866102 "External link (opens in new tab)")).
    
*   Support has been added for the [`::marker`](/en-US/docs/Web/CSS/Reference/Selectors/::marker) pseudo-element ([Firefox bug 205202](https://bugzil.la/205202 "External link (opens in new tab)")) and animation for `::marker` pseudos ([Firefox bug 1538618](https://bugzil.la/1538618 "External link (opens in new tab)"))
    
*   We changed [`currentColor`](/en-US/docs/Web/CSS/Reference/Values/color_value#currentcolor_keyword) to be a computed value (except for the [`color`](/en-US/docs/Web/CSS/Reference/Properties/color) property) ([Firefox bug 760345](https://bugzil.la/760345 "External link (opens in new tab)")).
    
*   Support has been fixed for the `ch` length unit so it now matches the spec (fallback for no '0' glyph, vertical metrics) ([Firefox bug 282126](https://bugzil.la/282126 "External link (opens in new tab)"))
    
*   The [`counter-set`](/en-US/docs/Web/CSS/Reference/Properties/counter-set) property has been implemented. ([Firefox bug 1518201](https://bugzil.la/1518201 "External link (opens in new tab)")).
    
*   We now implement list numbering using a built-in "list-item" counter; this fixes list numbering bugs ([Firefox bug 288704](https://bugzil.la/288704 "External link (opens in new tab)")).
    
*   Selector matching and parsing support has been implemented for [`::part()`](/en-US/docs/Web/CSS/Reference/Selectors/::part) ([Firefox bug 1545430](https://bugzil.la/1545430 "External link (opens in new tab)")) and ([Firefox bug 1545425](https://bugzil.la/1545425 "External link (opens in new tab)")).
    
*   [CSS Transforms](/en-US/docs/Web/CSS/Guides/Transforms) are now supported in indirectly rendered things e.g., [`<mask>`](/en-US/docs/Web/SVG/Reference/Element/mask), [`<marker>`](/en-US/docs/Web/SVG/Reference/Element/marker), [`<pattern>`](/en-US/docs/Web/SVG/Reference/Element/pattern), [`<clipPath>`](/en-US/docs/Web/SVG/Reference/Element/clipPath) ([Firefox bug 1323962](https://bugzil.la/1323962 "External link (opens in new tab)")).
    
*   While we're keeping the prefixed versions of the various gradient properties [`linear-gradient()`](/en-US/docs/Web/CSS/Reference/Values/gradient/linear-gradient), [`radial-gradient()`](/en-US/docs/Web/CSS/Reference/Values/gradient/radial-gradient), and [`repeating-radial-gradient()`](/en-US/docs/Web/CSS/Reference/Values/gradient/repeating-radial-gradient) available for compatibility reasons, we have revised how they're parsed so that they're handled much more like the non-prefixed versions. This means that certain existing styles won't work correctly.
    
    In particular, the complicated syntax taking both an angle and a position will no longer work, and the `to` keyword in the `<side-or-corner>` parameter is not required for the prefixed gradient properties. You are encouraged to use the standard, non-prefixed gradient properties instead, as they're now widely supported ([Firefox bug 1547939](https://bugzil.la/1547939 "External link (opens in new tab)")).
    

#### Removals

*   `scroll-snap-coordinate`, `scroll-snap-destination`, `scroll-snap-type-x` and `scroll-snap-type-y` have been removed.
*   The [`scroll-snap-type`](/en-US/docs/Web/CSS/Reference/Properties/scroll-snap-type) property has become a longhand, so the old shorthand syntax like `scroll-snap-type:mandatory` will stop working.

### [SVG](#svg)

_No changes._

### [JavaScript](#javascript)

*   The new [`BigInt`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/BigInt) primitive is enabled by default ([Firefox bug 1527902](https://bugzil.la/1527902 "External link (opens in new tab)")).
*   [String generic methods](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#string_2) have been removed ([Firefox bug 1222552](https://bugzil.la/1222552 "External link (opens in new tab)")).

### [APIs](#apis)

#### CSS Object Model (CSSOM)

*   The legacy [`rules`](/en-US/docs/Web/API/CSSStyleSheet/rules "rules") property and [`addRule()`](/en-US/docs/Web/API/CSSStyleSheet/addRule "addRule()") and [`removeRule()`](/en-US/docs/Web/API/CSSStyleSheet/removeRule "removeRule()") methods have been added to the [`CSSStyleSheet`](/en-US/docs/Web/API/CSSStyleSheet) interface. These were introduced by Internet Explorer 9 and have never managed to quite be stamped out, so they have been added to improve compatibility with the small percentage of sites that still use them ([Firefox bug 1545823](https://bugzil.la/1545823 "External link (opens in new tab)")).

#### DOM

*   The [Visual Viewport API](/en-US/docs/Web/API/VisualViewport) has now been enabled by default on Android ([Firefox bug 1512813](https://bugzil.la/1512813 "External link (opens in new tab)")). Adding this API to desktop versions of Firefox is being tracked in [Firefox bug 1551302](https://bugzil.la/1551302 "External link (opens in new tab)").
*   The [`Window`](/en-US/docs/Web/API/Window) feature [`noreferrer`](/en-US/docs/Web/API/Window/open) is now supported; if specified, the new window's content is loaded without sharing the hostname, IP address, URL, or other identifying information about the host device ([Firefox bug 1527287](https://bugzil.la/1527287 "External link (opens in new tab)")).
*   The [`decode()`](/en-US/docs/Web/API/HTMLImageElement/decode "decode()") method on `HTMLImageElement` is now implemented. This can be used to trigger loading and decoding of an image prior to adding it to the DOM ([Firefox bug 1501794](https://bugzil.la/1501794 "External link (opens in new tab)")).
*   [`XMLHttpRequest`](/en-US/docs/Web/API/XMLHttpRequest) has been updated to no longer accept the non-standard `moz-chunked-arraybuffer` value for [`responseType`](/en-US/docs/Web/API/XMLHttpRequest/responseType "responseType"). Code still using it should be updated to [use the Fetch API as a stream](/en-US/docs/Web/API/Streams_API/Using_readable_streams#consuming_a_fetch_as_a_stream) ([Firefox bug 1120171](https://bugzil.la/1120171 "External link (opens in new tab)")).
*   `XMLHttpRequest` now outputs a warning to console if you perform a synchronous request while handling an [`unload`](/en-US/docs/Web/API/Window/unload_event "unload"), [`beforeunload`](/en-US/docs/Web/API/Window/beforeunload_event "beforeunload"), or [`pagehide`](/en-US/docs/Web/API/Window/pagehide_event "pagehide") event ([Firefox bug 980902](https://bugzil.la/980902 "External link (opens in new tab)")).
*   The [`cookie`](/en-US/docs/Web/API/Document/cookie "cookie") property has moved from the [`HTMLDocument`](/en-US/docs/Web/API/HTMLDocument) interface to the [`Document`](/en-US/docs/Web/API/Document) interface, allowing documents other than [HTML](/en-US/docs/Glossary/HTML) to use cookies ([Firefox bug 144795](https://bugzil.la/144795 "External link (opens in new tab)")).
*   The [`HTMLElement.focus()`](/en-US/docs/Web/API/HTMLElement/focus) and [`SVGElement.focus()`](/en-US/docs/Web/API/SVGElement/focus) methods now accept an optional object that may contain a boolean `preventScroll` option specifying whether or not to block the browser from scrolling the newly-focused element into view ([Firefox bug 1374045](https://bugzil.la/1374045 "External link (opens in new tab)")).

#### DOM events

*   [Firefox for Android](https://firefox-source-docs.mozilla.org/mobile/android/index.html "External link (opens in new tab)") no longer incorrectly sends a [`resize`](/en-US/docs/Web/API/Window/resize_event "resize") event until after the first frame is painted; this improves web compatibility with sites that don't expect this event to occur ([Firefox bug 1528052](https://bugzil.la/1528052 "External link (opens in new tab)")).
*   The dispatching of events for non-primary mouse buttons has been made to more closely follow the specification; the [`click`](/en-US/docs/Web/API/Element/click_event "click") event is no longer sent when non-primary buttons are clicked, instead using [`auxclick`](/en-US/docs/Web/API/Element/auxclick_event "auxclick"). In addition, [`dblclick`](/en-US/docs/Web/API/Element/dblclick_event "dblclick") no longer fires for non-primary buttons ([Firefox bug 1379466](https://bugzil.la/1379466 "External link (opens in new tab)")).
*   The proprietary `mozPressure` property has been deprecated, and will now trigger a warning in the console ([Firefox bug 1165211](https://bugzil.la/1165211 "External link (opens in new tab)")).

#### Media, Web Audio, and WebRTC

*   Due to changes in the Google Play store's policies, starting with Firefox 68 for Android, the OpenH264 codec used to handle AVC/H.264 video in WebRTC connections can no longer be downloaded and installed. Therefore, fresh installs of Firefox on Android devices no longer support AVC in WebRTC calls. If you upgrade from earlier versions of Firefox and already have the codec downloaded, it will continue to work. This does _not_ affect other platforms. For more details, see [this article on SUMO](https://support.mozilla.org/en-US/kb/firefox-android-openh264 "External link (opens in new tab)") or [Firefox bug 1548679](https://bugzil.la/1548679 "External link (opens in new tab)").
    
*   WebRTC has been updated to recognize that a `null` candidate passed into the [`icecandidate`](/en-US/docs/Web/API/RTCPeerConnection/icecandidate_event "icecandidate") event handler, indicating the receipt of a candidate, instead indicates that there are no further candidates coming; when this happens the ICE gathering ([`iceGatheringState`](/en-US/docs/Web/API/RTCPeerConnection/iceGatheringState "iceGatheringState")) state reaches `complete` ([Firefox bug 1318167](https://bugzil.la/1318167 "External link (opens in new tab)")).
    
*   The [`RTCRtpReceiver`](/en-US/docs/Web/API/RTCRtpReceiver) methods [`getContributingSources()`](/en-US/docs/Web/API/RTCRtpReceiver/getContributingSources "getContributingSources()") and [`getSynchronizationSources()`](/en-US/docs/Web/API/RTCRtpReceiver/getSynchronizationSources "getSynchronizationSources()") now support video tracks; previously they only worked on audio ([Firefox bug 1534466](https://bugzil.la/1534466 "External link (opens in new tab)")).
    
*   The Web Audio API [`MediaStreamTrackAudioSourceNode`](/en-US/docs/Web/API/MediaStreamTrackAudioSourceNode) interface is now supported, as is the method [`AudioContext.createMediaStreamTrackSource()`](/en-US/docs/Web/API/AudioContext/createMediaStreamTrackSource) ([Firefox bug 1324548](https://bugzil.la/1324548 "External link (opens in new tab)")).
    
*   [`RTCDataChannel.negotiated`](/en-US/docs/Web/API/RTCDataChannel/negotiated) is now implemented ([Firefox bug 1529695](https://bugzil.la/1529695 "External link (opens in new tab)")).
    
*   The [`MediaStreamAudioSourceNode()`](/en-US/docs/Web/API/MediaStreamAudioSourceNode/MediaStreamAudioSourceNode "MediaStreamAudioSourceNode()") constructor has been updated to match the current specification's definition that the "first audio track" in the stream is the track whose ID comes first in lexicographical order ([Firefox bug 1324548](https://bugzil.la/1324548 "External link (opens in new tab)")).
    
*   [`getUserMedia()`](/en-US/docs/Web/API/MediaDevices/getUserMedia "getUserMedia()") may no longer be used from a non-secure context; attempting to do so now throws a `NotAllowedError` exception. Secure contexts are those loaded using HTTPS, those located using the `file:///` scheme, and those loaded from `localhost`. For now, if you must, you can re-enable the ability to perform insecure calls to `getUserMedia()` by setting the preference `media.getusermedia.insecure.enabled` to `true` ([Firefox bug 1335740](https://bugzil.la/1335740 "External link (opens in new tab)")).
    
    **Note:** In the future, Firefox will also remove the [`navigator.mediaDevices`](/en-US/docs/Web/API/Navigator/mediaDevices) property on insecure contexts, preventing all access to the [`MediaDevices`](/en-US/docs/Web/API/MediaDevices) APIs. **This is already the case in Nightly builds.**
    

#### Removals

*   Removed the non-standard `XMLDocument.load()` method ([Firefox bug 332175](https://bugzil.la/332175 "External link (opens in new tab)")).
*   Removed the non-standard `XMLDocument.async` property ([Firefox bug 1328138](https://bugzil.la/1328138 "External link (opens in new tab)")).
*   The `RTCIceServer.credentialType` `token` value has been removed ([Firefox bug 1529595](https://bugzil.la/1529595 "External link (opens in new tab)")).

### [HTTP](#http)

*   The [HTTP](/en-US/docs/Web/HTTP) [`Clear-Site-Data`](/en-US/docs/Web/HTTP/Reference/Headers/Clear-Site-Data) header no longer supports the `executionContexts` directive. This was removed due to problems with interactions between interconnections among different kinds of data at different points in the navigation process and the way the specification is designed. It [has been proposed](https://github.com/w3c/webappsec-clear-site-data/issues/59 "External link (opens in new tab)") that this directive be removed from the specification for this reason, among others ([Firefox bug 1548034](https://bugzil.la/1548034 "External link (opens in new tab)")).

#### Removals

*   The [`Content-Security-Policy`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy) directive `require-sri-for` is no longer supported due to concerns about its standardization status. It was previously available only behind a preference, which was off by default ([Firefox bug 1386214](https://bugzil.la/1386214 "External link (opens in new tab)")).

### [Security](#security)

*   Due to [CVE-2019-11730: Same-origin policy treats all files in a directory as having the same-origin](https://www.mozilla.org/en-US/security/advisories/mfsa2019-21/#CVE-2019-11730 "External link (opens in new tab)"), changes have been made so that Firefox now treats files in the same directory as being from different origins. This has a number of side-effects on what will work in documents loaded via file:// URLs (see [Firefox bug 1558299](https://bugzil.la/1558299 "External link (opens in new tab)") for useful background research). For example, workers can no longer be loaded.

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

#### Bug fixes

*   If `WebDriver:SwitchToWindow` changes the selection to a different window it now waits for its `focus` and `activate` events before returning ([Firefox bug 1335085](https://bugzil.la/1335085 "External link (opens in new tab)")).
*   Fixed the `TypeError: this.tabModal is null` failure, which sometimes appeared when interacting with modal dialogs or user prompts ([Firefox bug 1538782](https://bugzil.la/1538782 "External link (opens in new tab)"))

#### Other

*   Disabled the feature to force unloading background tabs on low memory conditions, to prevent top-level browser contexts from magically disappearing ([Firefox bug 1553748](https://bugzil.la/1553748 "External link (opens in new tab)")).
*   Disabled privileged content processes that caused HTTP authentication dialogs not to appear when navigating to a website after opening a new tab ([Firefox bug 1558763](https://bugzil.la/1558763 "External link (opens in new tab)")).

### [Plugins](#plugins)

_No changes._

## [Changes for add-on developers](#changes_for_add-on_developers)

### [API changes](#api_changes)

*   The [`proxy.register()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/proxy) and [`proxy.unregister()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/proxy) functions have been deprecated and will be removed from Firefox 71 ([Firefox bug 1545811](https://bugzil.la/1545811 "External link (opens in new tab)")).
*   A `boolean` flag, `incognito`, has been added to the [proxy.RequestDetails](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/proxy/RequestDetails) object. When `true`, it indicates that this was a private browsing request ([Firefox bug 1545163](https://bugzil.la/1545163 "External link (opens in new tab)")).
*   The [webRequest.RequestFilter](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest/RequestFilter) parameters can include an incognito parameter. If provided, requests that do not match the incognito state (`true` or `false`) will be filtered out ([Firefox bug 1548177](https://bugzil.la/1548177 "External link (opens in new tab)")).
*   A `string` value, `cookieStoreId`, representing the cookie store ID of the current context, has been added to the [proxy.RequestDetails](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/proxy/RequestDetails). object ([Firefox bug 1545420](https://bugzil.la/1545420 "External link (opens in new tab)")).
*   When an add-on attempts to add a bookmark folder to the root folder, the resulting error message is now much more intuitive ([Firefox bug 1512171](https://bugzil.la/1512171 "External link (opens in new tab)")).
*   The promise returned by [`browser.tabs.duplicate()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/duplicate) now resolves immediately, before the tabs are completely loaded ([Firefox bug 1394376](https://bugzil.la/1394376 "External link (opens in new tab)")).
*   Support has been added for chrome.storage.managed, allowing web extension settings to be implemented via enterprise policy ([Firefox bug 1230802](https://bugzil.la/1230802 "External link (opens in new tab)")).
*   `proxyAuthorization` and `connectionIsolation` in [`proxy.onRequest`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/proxy/onRequest) now apply only to HTTPS proxies ([Firefox bug 1549368](https://bugzil.la/1549368 "External link (opens in new tab)").

### [Manifest changes](#manifest_changes)

*   Support added for the [`dark_theme` key](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/dark_theme). This key enables a static theme to define its looks when Firefox is using the dark color scheme ([Firefox bug 1525762](https://bugzil.la/1525762 "External link (opens in new tab)")).
