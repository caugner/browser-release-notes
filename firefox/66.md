# Firefox 66 release notes for developers

This article provides information about the changes in Firefox 66 that will affect developers. Firefox 66 was released on March 19, 2019.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   JavaScript getters can now be executed from the auto-completion popup in the [Web Console](https://firefox-source-docs.mozilla.org/devtools-user/web_console/index.html "External link (opens in new tab)") ([Firefox bug 1499289](https://bugzil.la/1499289 "External link (opens in new tab)")).
*   The Window methods [`alert()`](/en-US/docs/Web/API/Window/alert "alert()"), [`prompt()`](/en-US/docs/Web/API/Window/prompt "prompt()"), and [`confirm()`](/en-US/docs/Web/API/Window/confirm "confirm()") now work again in [Responsive Design Mode](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html "External link (opens in new tab)"), after a period of being broken ([Firefox bug 1273997](https://bugzil.la/1273997 "External link (opens in new tab)")).
*   You can copy the output of the console to the clipboard by right-clicking and selecting "**Export visible messages to clipboard**" from the context menu.

### [HTML](#html)

*   UTF-8-encoded HTML (and plain text) files loaded from `file:` URLs are now supported without `<meta charset="utf-8">` or the UTF-8 BOM, making it easier to work on such files locally before uploading them to a server. You still need to make sure that the server sends `charset=utf-8` in the `Content-Type` HTTP header for such files, otherwise the detection mechanism used for local files would break incremental loading in the network case ([Firefox bug 1071816](https://bugzil.la/1071816 "External link (opens in new tab)")).

#### Removals

*   The `x-moz-errormessage` attribute has been removed from the [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) element ([Firefox bug 1513890](https://bugzil.la/1513890 "External link (opens in new tab)")). You should use the [constraint validation](/en-US/docs/Web/HTML/Guides/Constraint_validation) API to implement custom validation messages instead.

### [CSS](#css)

*   [Scroll anchoring](https://drafts.csswg.org/css-scroll-anchoring/ "External link (opens in new tab)") has been implemented in Firefox Desktop (but not mobile yet), which includes the [`overflow-anchor`](/en-US/docs/Web/CSS/Reference/Properties/overflow-anchor) property ([Firefox bug 1305957](https://bugzil.la/1305957 "External link (opens in new tab)")).
    
*   We've implemented the case-sensitive [attribute selector](/en-US/docs/Web/CSS/Reference/Selectors/Attribute_selectors) modifier, `s` ([Firefox bug 1512386](https://bugzil.la/1512386 "External link (opens in new tab)")).
    
*   Several [logical property](/en-US/docs/Web/CSS/Guides/Logical_properties_and_values) shorthands have landed, along with the flow-relative border radius properties:
    
    *   [`padding-block`](/en-US/docs/Web/CSS/Reference/Properties/padding-block) and [`padding-inline`](/en-US/docs/Web/CSS/Reference/Properties/padding-inline) ([Firefox bug 1519847](https://bugzil.la/1519847 "External link (opens in new tab)")).
    *   [`margin-block`](/en-US/docs/Web/CSS/Reference/Properties/margin-block) and [`margin-inline`](/en-US/docs/Web/CSS/Reference/Properties/margin-inline) ([Firefox bug 1519944](https://bugzil.la/1519944 "External link (opens in new tab)")).
    *   [`inset`](/en-US/docs/Web/CSS/Reference/Properties/inset), [`inset-block`](/en-US/docs/Web/CSS/Reference/Properties/inset-block), and [`inset-inline`](/en-US/docs/Web/CSS/Reference/Properties/inset-inline) ([Firefox bug 1520229](https://bugzil.la/1520229 "External link (opens in new tab)")).
    *   [`border-block-color`](/en-US/docs/Web/CSS/Reference/Properties/border-block-color), [`border-block-style`](/en-US/docs/Web/CSS/Reference/Properties/border-block-style), [`border-block-width`](/en-US/docs/Web/CSS/Reference/Properties/border-block-width), [`border-inline-color`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-color), [`border-inline-style`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-style), and [`border-inline-width`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-width) ([Firefox bug 1520236](https://bugzil.la/1520236 "External link (opens in new tab)")).
    *   [`border-block`](/en-US/docs/Web/CSS/Reference/Properties/border-block) and [`border-inline`](/en-US/docs/Web/CSS/Reference/Properties/border-inline) ([Firefox bug 1520396](https://bugzil.la/1520396 "External link (opens in new tab)")).
    *   [`border-start-start-radius`](/en-US/docs/Web/CSS/Reference/Properties/border-start-start-radius), [`border-start-end-radius`](/en-US/docs/Web/CSS/Reference/Properties/border-start-end-radius), [`border-end-start-radius`](/en-US/docs/Web/CSS/Reference/Properties/border-end-start-radius), and [`border-end-end-radius`](/en-US/docs/Web/CSS/Reference/Properties/border-end-end-radius) ([Firefox bug 1520684](https://bugzil.la/1520684 "External link (opens in new tab)")).
*   We implemented the [`overflow-inline`](/en-US/docs/Web/CSS/Reference/At-rules/@media/overflow-inline) and [`overflow-block`](/en-US/docs/Web/CSS/Reference/At-rules/@media/overflow-block) media queries ([Firefox bug 1422235](https://bugzil.la/1422235 "External link (opens in new tab)")).
    
*   [`grid-template-columns`](/en-US/docs/Web/CSS/Reference/Properties/grid-template-columns) and [`grid-template-rows`](/en-US/docs/Web/CSS/Reference/Properties/grid-template-rows) are now animatable, as per the rules set out in their specs ([Firefox bug 1348519](https://bugzil.la/1348519 "External link (opens in new tab)")).
    
*   We now support [`calc()`](/en-US/docs/Web/CSS/Reference/Values/calc) with percentages for table cells and column widths ([Firefox bug 957915](https://bugzil.la/957915 "External link (opens in new tab)")).
    
*   The `min-content` and `max-content` keywords are now available unprefixed ([Firefox bug 1322780](https://bugzil.la/1322780 "External link (opens in new tab)")). These can be set on:
    
    *   [`width`](/en-US/docs/Web/CSS/Reference/Properties/width)
    *   [`height`](/en-US/docs/Web/CSS/Reference/Properties/height)
    *   [`flex-basis`](/en-US/docs/Web/CSS/Reference/Properties/flex-basis)
    *   [`min-width`](/en-US/docs/Web/CSS/Reference/Properties/min-width)
    *   [`max-width`](/en-US/docs/Web/CSS/Reference/Properties/max-width)
    *   [`min-height`](/en-US/docs/Web/CSS/Reference/Properties/min-height)
    *   [`max-height`](/en-US/docs/Web/CSS/Reference/Properties/max-height)
    *   [`min-block-size`](/en-US/docs/Web/CSS/Reference/Properties/min-block-size)
    *   [`min-inline-size`](/en-US/docs/Web/CSS/Reference/Properties/min-inline-size)
    *   [`max-block-size`](/en-US/docs/Web/CSS/Reference/Properties/max-block-size)
    *   [`max-inline-size`](/en-US/docs/Web/CSS/Reference/Properties/max-inline-size)
    *   [`block-size`](/en-US/docs/Web/CSS/Reference/Properties/block-size)
    *   [`inline-size`](/en-US/docs/Web/CSS/Reference/Properties/inline-size)

### [APIs](#apis)

#### New APIs/changes

*   Autoplaying audio will be blocked by default soon after 66 becomes the release version of Firefox ([Firefox bug 1487844](https://bugzil.la/1487844 "External link (opens in new tab)"), see [Firefox bug 1535667](https://bugzil.la/1535667 "External link (opens in new tab)") for rollout details). The feature will be rolled out gradually to users until everyone has it.

#### DOM

*   The [`HTMLSlotElement.assignedElements()`](/en-US/docs/Web/API/HTMLSlotElement/assignedElements) method has been implemented ([Firefox bug 1425685](https://bugzil.la/1425685 "External link (opens in new tab)")).
*   The [`TextEncoder.encodeInto()`](/en-US/docs/Web/API/TextEncoder/encodeInto) method has been implemented ([Firefox bug 1514664](https://bugzil.la/1514664 "External link (opens in new tab)")).

#### DOM events

*   The [`InputEvent.inputType`](/en-US/docs/Web/API/InputEvent/inputType) property has been implemented ([Firefox bug 1447239](https://bugzil.la/1447239 "External link (opens in new tab)")).
*   The [`Window.event`](/en-US/docs/Web/API/Window/event) and [`Event.returnValue`](/en-US/docs/Web/API/Event/returnValue) properties — originally proprietary IE features, then also supported across other browsers for compatibility purposes — have been re-introduced in Firefox 66, after first being added in versions 63 and 64 respectively but then removed again due to compatibility issues.
*   From 66 onwards, when the [`KeyboardEvent.keyCode`](/en-US/docs/Web/API/KeyboardEvent/keyCode) property of the [`keypress`](/en-US/docs/Web/API/Element/keypress_event "keypress") event object is 0, the value will be the same as [`KeyboardEvent.charCode`](/en-US/docs/Web/API/KeyboardEvent/charCode). Conversely, when `charCode` is 0, it will be the same as `keyCode`. This mirroring behavior matches other browsers and is expected to solve most associated compatibility issues, however user agent sniffing might cause further issues in some JavaScript libraries. Note that in spec terms, we've switched from the _split model_ to the _conflated model_ (see [How to determine keyCode for keypress events](https://w3c.github.io/uievents/#determine-keypress-keyCode "External link (opens in new tab)") in the UI Event spec).

#### Media, Web Audio, and WebRTC

*   The new [AV1 video codec](/en-US/docs/Web/Media/Guides/Formats/Video_codecs#av1) is now enabled by default on both macOS and Windows (for Intel processors). Linux support will come in Firefox 67 ([Firefox bug 1521181](https://bugzil.la/1521181 "External link (opens in new tab)"), [Firefox bug 1452146](https://bugzil.la/1452146 "External link (opens in new tab)"), and [Firefox bug 1534814](https://bugzil.la/1534814 "External link (opens in new tab)")).
*   The [`MediaDevices`](/en-US/docs/Web/API/MediaDevices) method [`getDisplayMedia()`](/en-US/docs/Web/API/MediaDevices/getDisplayMedia "getDisplayMedia()"), available as `navigator.mediaDevices.getDisplayMedia()`, has been added and synchronized with the specification. This method lets you capture a screen or part of a screen as a [`MediaStream`](/en-US/docs/Web/API/MediaStream) for manipulation or sharing ([Firefox bug 1321221](https://bugzil.la/1321221 "External link (opens in new tab)")).
*   As a step toward eventually deprecating the Firefox-specific [`getUserMedia()`](/en-US/docs/Web/API/MediaDevices/getUserMedia "getUserMedia()")\-based method for capturing screen and window contents, the non-standard `mediaSource` constraint now treats the values `screen` and `window` identically. Both now present a list of both screens and windows for the user to choose from ([Firefox bug 1474376](https://bugzil.la/1474376 "External link (opens in new tab)")).
*   `RTCOutboundRtpStreamStats.qpSum` has been added. This measures the total of the Quantization Parameter values for every frame sent or received on the video track. The higher this number, the more compressed the stream probably is ([Firefox bug 1347070](https://bugzil.la/1347070 "External link (opens in new tab)")).
*   In a step along the road toward implementing support for Feature Policy in a future Firefox update, [`getUserMedia()`](/en-US/docs/Web/API/MediaDevices/getUserMedia "getUserMedia()") can no longer be used in situations in which there is no proper origin for the content, such as when called from a sandboxed [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) or from a `data` URL entered into the address bar by the user. For more details, see the [Security](/en-US/docs/Web/API/MediaDevices/getUserMedia#security) section on the MediaDevices.getUserMedia() page ([Firefox bug 1371741](https://bugzil.la/1371741 "External link (opens in new tab)")).

#### Removals

*   The legacy WebRTC `PeerConnection.getStats()` method has been removed, along with associated types ([Firefox bug 1328194](https://bugzil.la/1328194 "External link (opens in new tab)")).

### [Networking](#networking)

*   The default value of the [`Accept`](/en-US/docs/Web/HTTP/Reference/Headers/Accept) header has been changed to `*/*` ([Firefox bug 1417463](https://bugzil.la/1417463 "External link (opens in new tab)")).

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

#### API changes

*   `WebDriver:NewWindow` has been added to support opening of a new browsing context, which can be one of either window or tab ([Firefox bug 1504756](https://bugzil.la/1504756 "External link (opens in new tab)")).
    
*   `WebDriver:SwitchToFrame` now raises a `no such element` error if the specified element isn't part of the current browsing context ([Firefox bug 1517196](https://bugzil.la/1517196 "External link (opens in new tab)")).
    
*   `WebDriver:ExecuteScript` and `WebDriver:ExecuteAsyncScript` no longer support the non-spec compliant `scriptTimeout` parameter. Instead, use `WebDriver:SetTimeout` or the `timeouts` capability to define this value ([Firefox bug 1510929](https://bugzil.la/1510929 "External link (opens in new tab)")).
    
    *   In addition, indefinite script timeouts are now supported ([Firefox bug 1128997](https://bugzil.la/1128997 "External link (opens in new tab)")).
*   `WebDriver:SetWindowRect` no longer returns the window state in its response ([Firefox bug 1517587](https://bugzil.la/1517587 "External link (opens in new tab)")).
    

#### Bug fixes

*   `WebDriver:TakeScreenshot` now uses the [`Element.clientWidth`](/en-US/docs/Web/API/Element/clientWidth) and [`Element.clientHeight`](/en-US/docs/Web/API/Element/clientHeight) properties of the [`Document.documentElement`](/en-US/docs/Web/API/Document/documentElement) instead of the viewport dimensions ([Firefox bug 1385706](https://bugzil.la/1385706 "External link (opens in new tab)")).
*   Various fixes have been applied to make window manipulation commands more reliable across platforms ([Firefox bug 1522408](https://bugzil.la/1522408 "External link (opens in new tab)"), [Firefox bug 1478358](https://bugzil.la/1478358 "External link (opens in new tab)"), [Firefox bug 1489955](https://bugzil.la/1489955 "External link (opens in new tab)")).
