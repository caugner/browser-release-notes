# Firefox 142 release notes for developers

This article provides information about the changes in Firefox 142 that affect developers. Firefox 142 was released on [August 19, 2025](https://whattrainisitnow.com/release/?version=142 "External link (opens in new tab)").

## [Changes for web developers](#changes_for_web_developers)

### [HTML](#html)

#### Removals

*   The [`<object>`](/en-US/docs/Web/HTML/Reference/Elements/object) element no longer supports the deprecated `codebase` attribute. Use the [`data`](/en-US/docs/Web/HTML/Reference/Elements/object#data) attribute instead. (See [Firefox bug 1973900](https://bugzil.la/1973900 "External link (opens in new tab)") for more details.)

### [CSS](#css)

*   The [`&` selector](/en-US/docs/Web/CSS/Reference/Selectors/Nesting_selector) inside [`@scope`](/en-US/docs/Web/CSS/Reference/At-rules/@scope) no longer inherits the [specificity of the scope start selector](/en-US/docs/Web/CSS/Reference/At-rules/@scope#specificity_in_scope). This makes `&` selectors in `@scope` consistent with [CSS nesting](/en-US/docs/Web/CSS/Guides/Nesting), avoiding unexpected specificity differences (see [CSS nesting and specificity](/en-US/docs/Web/CSS/Guides/Nesting/Nesting_and_specificity)). ([Firefox bug 1975531](https://bugzil.la/1975531 "External link (opens in new tab)")).

### [JavaScript](#javascript)

No notable changes.

### [APIs](#apis)

*   The [URL Pattern API](/en-US/docs/Web/API/URL_Pattern_API) is fully supported, enabling you to match and parse URLs using a standardized pattern syntax. ([Firefox bug 1731418](https://bugzil.la/1731418 "External link (opens in new tab)")).
*   The [File and Directory Entries API](/en-US/docs/Web/API/File_and_Directory_Entries_API) now fully supports the [`HTMLInputElement.webkitdirectory`](/en-US/docs/Web/API/HTMLInputElement/webkitdirectory) (and corresponding HTML [`webkitdirectory`](/en-US/docs/Web/HTML/Reference/Elements/input/file#webkitdirectory) attribute) and [`File.webkitRelativePath`](/en-US/docs/Web/API/File/webkitRelativePath) properties on Firefox Android. This lets you configure an [`<input type="file">`](/en-US/docs/Web/HTML/Reference/Elements/input/file) element to accept directories instead of files ([Firefox bug 1973726](https://bugzil.la/1973726 "External link (opens in new tab)")).

#### DOM

*   The [`Selection.getComposedRanges()`](/en-US/docs/Web/API/Selection/getComposedRanges) method is now supported, allowing developers to accurately get selected text ranges across shadow DOM boundaries. In addition, the methods [`setBaseAndExtent()`](/en-US/docs/Web/API/Selection/setBaseAndExtent "setBaseAndExtent()"), [`collapse()`](/en-US/docs/Web/API/Selection/collapse "collapse()"), and [`extend()`](/en-US/docs/Web/API/Selection/extend "extend()") of the [`Selection`](/en-US/docs/Web/API/Selection) interface have been modified to accept nodes inside a shadow root. ([Firefox bug 1903870](https://bugzil.la/1903870 "External link (opens in new tab)")).
*   The [`Animation.overallProgress`](/en-US/docs/Web/API/Animation/overallProgress) property is now supported, allowing developers to track and display progress through an animation. ([Firefox bug 1834878](https://bugzil.la/1834878 "External link (opens in new tab)")).
*   The [`Animation.commitStyles()`](/en-US/docs/Web/API/Animation/commitStyles) method no longer requires [`fill`](/en-US/docs/Web/API/KeyframeEffect/KeyframeEffect#fill) to be set on an animation to commit the computed styles after the animation has finished. Note that until more browsers support this change, you should continue to set `fill`. ([Firefox bug 1973203](https://bugzil.la/1973203 "External link (opens in new tab)")).
*   The [Prioritized Task Scheduling API](/en-US/docs/Web/API/Prioritized_Task_Scheduling_API) is now supported, providing a standardized mechanism to assign and manage task priorities for an application. The supported interfaces include: [`Scheduler`](/en-US/docs/Web/API/Scheduler), [`TaskController`](/en-US/docs/Web/API/TaskController), [`TaskSignal`](/en-US/docs/Web/API/TaskSignal), [`TaskPriorityChangeEvent`](/en-US/docs/Web/API/TaskPriorityChangeEvent) (and the [`prioritychange`](/en-US/docs/Web/API/TaskSignal/prioritychange_event "prioritychange") event), and the properties [`Window.scheduler`](/en-US/docs/Web/API/Window/scheduler) and [`WorkerGlobalScope.scheduler`](/en-US/docs/Web/API/WorkerGlobalScope/scheduler). The [`Scheduling`](/en-US/docs/Web/API/Scheduling) interface and the [`Navigator.scheduling`](/en-US/docs/Web/API/Navigator/scheduling) property are not supported. ([Firefox bug 1966997](https://bugzil.la/1966997 "External link (opens in new tab)")).

#### Media, WebRTC, and Web Audio

*   The [`currentRoundTripTime`](/en-US/docs/Web/API/RTCIceCandidatePairStats/currentRoundTripTime "currentRoundTripTime"), [`totalRoundTripTime`](/en-US/docs/Web/API/RTCIceCandidatePairStats/totalRoundTripTime "totalRoundTripTime"), and [`responsesReceived`](/en-US/docs/Web/API/RTCIceCandidatePairStats/responsesReceived "responsesReceived") properties of the [`RTCIceCandidatePairStats`](/en-US/docs/Web/API/RTCIceCandidatePairStats) dictionary are now supported. These return the current round trip time (RTT) and the information needed to calculate the average RTT for the connection. ([Firefox bug 1371391](https://bugzil.la/1371391 "External link (opens in new tab)")).
*   The [`setParameters()`](/en-US/docs/Web/API/RTCRtpSender/setParameters "setParameters()") and [`getParameters()`](/en-US/docs/Web/API/RTCRtpSender/getParameters "getParameters()") methods of the [`RTCRtpSender`](/en-US/docs/Web/API/RTCRtpSender) interface now support setting and getting the specific [`codec`](/en-US/docs/Web/API/RTCRtpSender/setParameters#codecs) used for each `encoding`. You can also set a `codec` for each encoding in the [`init.sendEncodings`](/en-US/docs/Web/API/RTCPeerConnection/addTransceiver#sendencodings) array that's passed to the [`addTransceiver()`](/en-US/docs/Web/API/RTCPeerConnection/addTransceiver "addTransceiver()") method of the [`RTCPeerConnection`](/en-US/docs/Web/API/RTCPeerConnection) interface. ([Firefox bug 1894137](https://bugzil.la/1894137 "External link (opens in new tab)")).
*   The [`estimatedPlayoutTimestamp`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/estimatedPlayoutTimestamp "estimatedPlayoutTimestamp"), [`framesAssembledFromMultiplePackets`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/framesAssembledFromMultiplePackets "framesAssembledFromMultiplePackets"), [`freezeCount`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/freezeCount "freezeCount"), [`jitterBufferMinimumDelay`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/jitterBufferMinimumDelay "jitterBufferMinimumDelay"), [`jitterBufferTargetDelay`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/jitterBufferTargetDelay "jitterBufferTargetDelay"), [`keyFramesDecoded`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/keyFramesDecoded "keyFramesDecoded"), [`pauseCount`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/pauseCount "pauseCount"), [`totalAssemblyTime`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/totalAssemblyTime "totalAssemblyTime"), [`totalFreezesDuration`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/totalFreezesDuration "totalFreezesDuration") and [`totalPausesDuration`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/totalPausesDuration "totalPausesDuration") properties of the [`RTCInboundRtpStreamStats`](/en-US/docs/Web/API/RTCInboundRtpStreamStats) interface are now supported. ([Firefox bug 1926622](https://bugzil.la/1926622 "External link (opens in new tab)")).

### [WebDriver conformance (WebDriver BiDi, Marionette)](#webdriver_conformance_webdriver_bidi_marionette)

#### General

*   Removed FTP proxy support from WebDriver capabilities ([Firefox bug 1972670](https://bugzil.la/1972670 "External link (opens in new tab)")).
*   Updated the expiry value of all the cookies set via WebDriver BiDi and WebDriver classic (Marionette) to be limited to 400 days ([Firefox bug 1974394](https://bugzil.la/1974394 "External link (opens in new tab)")).

#### WebDriver BiDi

*   Implemented the new `emulation.setLocaleOverride` command which allows clients to override a locale in JavaScript APIs ([Firefox bug 1968952](https://bugzil.la/1968952 "External link (opens in new tab)")).
*   Improved setting a proxy with `browsingContext.createUserContext`: added support for host patterns like `.mozilla.org` in `noProxy` property ([Firefox bug 1977180](https://bugzil.la/1977180 "External link (opens in new tab)")) and fixed a bug where setting an HTTP proxy did not allow navigation to HTTPS URLs ([Firefox bug 1977168](https://bugzil.la/1977168 "External link (opens in new tab)")).
*   Fixed a bug where `browsingContext.create` would fail after a `browsingContext.print` command was interrupted by closing a tab with the `browsingContext.close` command ([Firefox bug 1841125](https://bugzil.la/1841125 "External link (opens in new tab)")).
*   Updated the `session.end` command to resume all requests which were blocked by network interceptions ([Firefox bug 1974426](https://bugzil.la/1974426 "External link (opens in new tab)")).

#### Marionette

*   Updated the `WebDriver:AddCookie` command to throw an error when a target cookie has `sameSite=none` and `secure=false` attributes ([Firefox bug 1977205](https://bugzil.la/1977205 "External link (opens in new tab)")).
*   Removed the dialog text value from the `unexpected alert open` error message, since the dialog text is available now via the `data` field ([Firefox bug 1948236](https://bugzil.la/1948236 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

*   Cookies created with [`cookies.set()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/cookies/set) in Nightly are now validated, and invalid cookies are rejected. The implementation in Nightly is to enable monitoring for any issues. The intention is to enforce validation in all channels in a future release. ([Firefox bug 1976197](https://bugzil.la/1976197 "External link (opens in new tab)"))
*   The [`cookies`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/cookies) methods now accept and return milliseconds in the fractional part of `expirationDate`. ([Firefox bug 1972757](https://bugzil.la/1972757 "External link (opens in new tab)"))
*   Adds the [`browserAction.onUserSettingsChanged`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserAction/onUserSettingsChanged) and [`action.onUserSettingsChanged`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/action/onUserSettingsChanged) events that listen for changes in the user-specified settings that affect an extension's action. ([Firefox bug 1828220](https://bugzil.la/1828220 "External link (opens in new tab)"))
*   Adds [`browserSettings.verticalTabs`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings/verticalTabs), which enables extensions to control whether the browser displays the tab bar horizontally or vertically. ([Firefox bug 1946600](https://bugzil.la/1946600 "External link (opens in new tab)"))
*   Enabled the Firefox built-in data collection consent feature for Firefox for Android. See the Extension Workshop article [Firefox built-in consent for data collection and transmission](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/ "External link (opens in new tab)"). ([Firefox bug 1954524](https://bugzil.la/1954524 "External link (opens in new tab)"))

## [Experimental web features](#experimental_web_features)

*   **`anchor-size()`** (Nightly): `layout.css.anchor-positioning.enabled`
    
    The CSS [`anchor-size()`](/en-US/docs/Web/CSS/Reference/Values/anchor-size) function enables setting anchor-positioned element's size, position, and margins relative to the dimensions of anchor elements. ([Firefox bug 1972610](https://bugzil.la/1972610 "External link (opens in new tab)")).
    
*   **`:heading`** and **`:heading()`**: `layout.css.heading-selector.enabled`
    
    The CSS [`:heading`](/en-US/docs/Web/CSS/Reference/Selectors/:heading) pseudo-class allows you to style all [heading elements](/en-US/docs/Web/HTML/Reference/Elements/Heading_Elements) (`<h1>`\-`<h6>`) at once rather than targeting them individually. The [`:heading()`](/en-US/docs/Web/CSS/Reference/Selectors/:heading_function) functional pseudo-class allows you to style heading elements that match the given heading levels. ([Firefox bug 1974386](https://bugzil.la/1974386 "External link (opens in new tab)")).
    
*   **`view-transition-name: match-element`** (Nightly): `dom.viewTransitions.enabled`
    
    The [`match-element`](/en-US/docs/Web/CSS/Reference/Properties/view-transition-name#match-element) value of the CSS [`view-transition-name`](/en-US/docs/Web/CSS/Reference/Properties/view-transition-name) property [automatically](/en-US/docs/Web/CSS/Reference/Properties/view-transition-name#specifying_view-transition-name_values_automatically) assigns a unique internal `view-transition-name` to each selected element, rather than having to name them individually. ([Firefox bug 1956141](https://bugzil.la/1956141 "External link (opens in new tab)")).
    
*   **`Integrity-Policy` and `Integrity-Policy-Report-Only`** for scripts (Nightly): `security.integrity_policy.enabled`
    
    The [`Integrity-Policy`](/en-US/docs/Web/HTTP/Reference/Headers/Integrity-Policy) and [`Integrity-Policy-Report-Only`](/en-US/docs/Web/HTTP/Reference/Headers/Integrity-Policy-Report-Only) HTTP headers are now supported for script resources. These allow websites to either enforce [subresource integrity guarantees](/en-US/docs/Web/Security/Defenses/Subresource_Integrity) for scripts or only report violations of the policy, respectively. ([Firefox bug 1976656](https://bugzil.la/1976656 "External link (opens in new tab)")).
    
*   **`Integrity-Policy` and `Integrity-Policy-Report-Only`** for stylesheets: `security.integrity_policy.stylesheet.enabled`
    
    The [`Integrity-Policy`](/en-US/docs/Web/HTTP/Reference/Headers/Integrity-Policy) and [`Integrity-Policy-Report-Only`](/en-US/docs/Web/HTTP/Reference/Headers/Integrity-Policy-Report-Only) HTTP headers are now supported for stylesheet resources. These allow websites to either enforce or only report violations of the policy, respectively. ([Firefox bug 1974247](https://bugzil.la/1974247 "External link (opens in new tab)")).
    

These features are shipping in Firefox 142 but are disabled by default. To experiment with them, search for the appropriate preference on the `about:config` page and set it to `true`. You can find more such features on the [Experimental features](/en-US/docs/Mozilla/Firefox/Experimental_features) page.
