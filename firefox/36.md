# Firefox 36 release notes for developers

Firefox 36 was released on February 24th, 2015. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

Highlights:

*   [eval sources now appear in the Debugger](https://firefox-source-docs.mozilla.org/devtools-user/debugger/index.html#debug-eval-sources "External link (opens in new tab)")
*   [Simpler process for connecting to Firefox for Android](https://web.archive.org/web/20220410035837/https://firefox-source-docs.mozilla.org/devtools-user/remote_debugging/debugging_firefox_for_android_with_webide/index.html "External link (opens in new tab)")
*   Box Model Highlighter works on remote targets
*   ["Invert the call tree" option in the Profiler](https://firefox-source-docs.mozilla.org/devtools-user/performance/index.html#inverting-the-call-tree "External link (opens in new tab)")
*   [Inspect DOM promises in the console](https://firefox-source-docs.mozilla.org/devtools-user/web_console/index.html#type-specific-rich-output "External link (opens in new tab)")
*   [Extra "Paste" commands in the Inspector](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/index.html#element-popup-menu-2 "External link (opens in new tab)")

[All devtools bugs fixed between Firefox 35 and Firefox 36](https://bugzilla.mozilla.org/buglist.cgi?resolution=FIXED&classification=Client%20Software&chfieldto=2014-11-28&chfield=resolution&query_format=advanced&chfieldfrom=2014-10-13&chfieldvalue=FIXED&bug_status=RESOLVED&bug_status=VERIFIED&component=Developer%20Tools&component=Developer%20Tools%3A%203D%20View&component=Developer%20Tools%3A%20Canvas%20Debugger&component=Developer%20Tools%3A%20Console&component=Developer%20Tools%3A%20Debugger&component=Developer%20Tools%3A%20Framework&component=Developer%20Tools%3A%20Graphic%20Commandline%20and%20Toolbar&component=Developer%20Tools%3A%20Inspector&component=Developer%20Tools%3A%20Memory&component=Developer%20Tools%3A%20Netmonitor&component=Developer%20Tools%3A%20Object%20Inspector&component=Developer%20Tools%3A%20Profiler&component=Developer%20Tools%3A%20Responsive%20Mode&component=Developer%20Tools%3A%20Scratchpad&component=Developer%20Tools%3A%20Source%20Editor&component=Developer%20Tools%3A%20Storage%20Inspector&component=Developer%20Tools%3A%20Style%20Editor&component=Developer%20Tools%3A%20Timeline&component=Developer%20Tools%3A%20User%20Stories&component=Developer%20Tools%3A%20Web%20Audio%20Editor&component=Developer%20Tools%3A%20WebGL%20Shader%20Editor&component=Developer%20Tools%3A%20WebIDE&product=Firefox&list_id=11736454 "External link (opens in new tab)").

### [CSS](#css)

*   The [`will-change`](/en-US/docs/Web/CSS/Reference/Properties/will-change) property has been enabled by default ([Firefox bug 961871](https://bugzil.la/961871 "External link (opens in new tab)")).
*   The [`white-space`](/en-US/docs/Web/CSS/Reference/Properties/white-space) property is now working on [`<textarea>`](/en-US/docs/Web/HTML/Reference/Elements/textarea) HTML elements ([Firefox bug 82711](https://bugzil.la/82711 "External link (opens in new tab)")).
*   The [`unicode-range`](/en-US/docs/Web/CSS/Reference/At-rules/@font-face/unicode-range) descriptor is now supported by [`@font-face`](/en-US/docs/Web/CSS/Reference/At-rules/@font-face) ([Firefox bug 475891](https://bugzil.la/475891 "External link (opens in new tab)")), but not enabled by default.
*   The properties [`text-decoration-color`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-color), [`text-decoration-line`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-line), and [`text-decoration-style`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-style) are unprefixed ([Firefox bug 825004](https://bugzil.la/825004 "External link (opens in new tab)")). The prefixed version are still available for some time to ease transition ([Firefox bug 1097922](https://bugzil.la/1097922 "External link (opens in new tab)")).
*   The [`text-decoration`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration) property is turned into shorthand property ([Firefox bug 1039488](https://bugzil.la/1039488 "External link (opens in new tab)")).
*   The properties [`object-fit`](/en-US/docs/Web/CSS/Reference/Properties/object-fit) and [`object-position`](/en-US/docs/Web/CSS/Reference/Properties/object-position) are now supported ([Firefox bug 624647](https://bugzil.la/624647 "External link (opens in new tab)"))
*   The `contents` value of the [`display`](/en-US/docs/Web/CSS/Reference/Properties/display) property has been experimentally implemented. It is preffed off by default ([Firefox bug 907396](https://bugzil.la/907396 "External link (opens in new tab)")).
*   In [Quirks mode](/en-US/docs/Web/HTML/Guides/Quirks_mode_and_standards_mode), the [`:active` and `:hover` quiver quirk](https://web.archive.org/web/20210414153205/https://developer.mozilla.org/en-US/docs/Mozilla/Mozilla_quirks_mode_behavior#Miscellaneous_.26_Style "External link (opens in new tab)") has been altered to be applied less often: it is now used only on links, only if there are no pseudo-element or other pseudo-class in the element and if it isn't part of a pseudo-class element ([Firefox bug 783213](https://bugzil.la/783213 "External link (opens in new tab)")).
*   The [`isolation`](/en-US/docs/Web/CSS/Reference/Properties/isolation) property has been implemented ([Firefox bug 1077872](https://bugzil.la/1077872 "External link (opens in new tab)")).
*   CSS [`<gradient>`](/en-US/docs/Web/CSS/Reference/Values/gradient) now applies on the premultiplied colors, matching the spec and other browsers, and getting rid of unexpected gray colors appearing in them ([Firefox bug 591600](https://bugzil.la/591600 "External link (opens in new tab)")).
*   Interpolation hint syntax has been added to [`<gradient>`](/en-US/docs/Web/CSS/Reference/Values/gradient) ([Firefox bug 1074056](https://bugzil.la/1074056 "External link (opens in new tab)")).
*   The [`scroll-behavior`](/en-US/docs/Web/CSS/Reference/Properties/scroll-behavior) property has been implemented ([Firefox bug 1010538](https://bugzil.la/1010538 "External link (opens in new tab)")).

### [HTML](#html)

*   Support for [`<meta name="referrer">`](/en-US/docs/Web/HTML/Reference/Elements/meta) has been added ([Firefox bug 704320](https://bugzil.la/704320 "External link (opens in new tab)")).
*   In Firefox, [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) filters specified in the [`accept`](/en-US/docs/Web/HTML/Reference/Elements/input#accept) attribute will always be selected by default, unless there is an unknown value, that is an unknown mime type or badly formatted value in the [`accept`](/en-US/docs/Web/HTML/Reference/Elements/input#accept) attribute. Previously specified filters were only selected by default for `image/*`, `video/*` and `audio/*` values ([Firefox bug 826185](https://bugzil.la/826185 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   The [ECMAScript 2015](https://web.archive.org/web/20210612110055/https://developer.mozilla.org/en-US/docs/Archive/Web/JavaScript/New_in_JavaScript/ECMAScript_2015_support_in_Mozilla "External link (opens in new tab)") Symbol data type has been enabled by default (was available in the Nightly channel since version 33) ([Firefox bug 1066322](https://bugzil.la/1066322 "External link (opens in new tab)")):
    
    *   [`Symbol`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol)
    *   [`Symbol.for()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/for)
    *   [`Symbol.keyFor()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/keyFor)
    *   [`Object.getOwnPropertySymbols()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/getOwnPropertySymbols)
*   The old placeholder string `"@@iterator"` has been replaced with the real ES2015 well-known symbol [`Symbol.iterator`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/iterator) for the [iterable](/en-US/docs/Web/JavaScript/Reference/Iteration_protocols) interface property key ([Firefox bug 918828](https://bugzil.la/918828 "External link (opens in new tab)")).
    
*   The spec-internal abstract operation `ToNumber(string)` now supports binary (`0b`) and octal (`0o`) literals, this is a potentially breaking change from ES5 ([Firefox bug 1079120](https://bugzil.la/1079120 "External link (opens in new tab)")).
    
    *   `Number("0b11")` now returns `3`, not `NaN`.
    *   `"0o11" == 9` now returns `true`, not `false`.
*   The [`const`](/en-US/docs/Web/JavaScript/Reference/Statements/const) declaration is now block-scoped and requires an initializer ([Firefox bug 611388](https://bugzil.la/611388 "External link (opens in new tab)")). It also cannot be redeclared anymore ([Firefox bug 1095439](https://bugzil.la/1095439 "External link (opens in new tab)")).
    
    *   `{const a=1}; a;` now throws a [`ReferenceError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/ReferenceError) and does not return `1` anymore due to block-scoping.
    *   `const a;` now throws a [`SyntaxError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/SyntaxError) ("missing = in const declaration"): An initializer is required.
    *   `const a = 1; a = 2;` now also throws a [`SyntaxError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/SyntaxError) ("invalid assignment to const a").
*   The ES2016 method [`Array.prototype.includes`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/includes) has been implemented, but for now, it is only enabled in Nightly builds ([Firefox bug 1069063](https://bugzil.la/1069063 "External link (opens in new tab)")).
    
*   The [`delete`](/en-US/docs/Web/JavaScript/Reference/Operators/delete) operator now triggers the "[temporal dead zone](/en-US/docs/Web/JavaScript/Reference/Statements/let#temporal_dead_zone_tdz)" when using with [`let`](/en-US/docs/Web/JavaScript/Reference/Statements/let) and [`const`](/en-US/docs/Web/JavaScript/Reference/Statements/const) ([Firefox bug 1074571](https://bugzil.la/1074571 "External link (opens in new tab)")).
    
*   The non-standard [`let` blocks and `let` expressions](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#statements_2) are deprecated and will now log a warning in the console. Do not use them anymore, they will be removed in the future.
    
*   [WeakMap](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap) constructor now handles optional iterable argument ([Firefox bug 1092537](https://bugzil.la/1092537 "External link (opens in new tab)")).
    

### [Interfaces/APIs/DOM](#interfacesapisdom)

*   The [`CanvasRenderingContext2D.resetTransform()`](/en-US/docs/Web/API/CanvasRenderingContext2D/resetTransform) method of the Canvas API has been implemented ([Firefox bug 1099148](https://bugzil.la/1099148 "External link (opens in new tab)")).
    
*   ECDSA is now supported in the Web Crypto API ([Firefox bug 1034854](https://bugzil.la/1034854 "External link (opens in new tab)")).
    
*   Our experimental implementation of WebGL 2.0 is going forward!
    
    *   The [`WebGLQuery`](/en-US/docs/Web/API/WebGLQuery) interface is available ([Firefox bug 1048719](https://bugzil.la/1048719 "External link (opens in new tab)")).
    *   The [`WebGL2RenderingContext.invalidateFrameBuffer()`](/en-US/docs/Web/API/WebGL2RenderingContext/invalidateFramebuffer) method has been implemented ([Firefox bug 1076456](https://bugzil.la/1076456 "External link (opens in new tab)")).
*   The [`MediaDevices`](/en-US/docs/Web/API/MediaDevices) interface, containing the [`Promise`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)\-based version of [`getUserMedia()`](/en-US/docs/Web/API/MediaDevices/getUserMedia "getUserMedia()"), has been added. It is available via [`Navigator.mediaDevices`](/en-US/docs/Web/API/Navigator/mediaDevices) ([Firefox bug 1033885](https://bugzil.la/1033885 "External link (opens in new tab)")).
    
*   The EME-related [`Navigator.requestMediaKeySystemAccess()`](/en-US/docs/Web/API/Navigator/requestMediaKeySystemAccess) method, and the related [`MediaKeySystemAccess`](/en-US/docs/Web/API/MediaKeySystemAccess), is now supported ([Firefox bug 1095257](https://bugzil.la/1095257 "External link (opens in new tab)")).
    
*   The [`keyschange`](/en-US/docs/Web/API/MediaKeySession/keystatuseschange_event "keyschange") event is now sent when an EME-related CDM change keys in a session ([Firefox bug 1081755](https://bugzil.la/1081755 "External link (opens in new tab)")).
    
*   The default values of the options for [`MutationObserver.observe()`](/en-US/docs/Web/API/MutationObserver/observe) have been updated to match the latest specification ([Firefox bug 973638](https://bugzil.la/973638 "External link (opens in new tab)")).
    
*   Experimental support for virtual reality devices has landed behind the `dom.vr.enabled` preference, off by default ([Firefox bug 1036604](https://bugzil.la/1036604 "External link (opens in new tab)")).
    
*   The function associated with [`RTCPeerConnection.onsignalingstatechange`](/en-US/docs/Web/API/RTCPeerConnection/signalingstatechange_event "RTCPeerConnection.onsignalingstatechange") now receives an event as parameter, as per spec ([Firefox bug 1075133](https://bugzil.la/1075133 "External link (opens in new tab)")).
    
*   The experimental implementation of Web Animations make progress: the method [`AnimationPlayer.play()`](/en-US/docs/Web/API/Animation/play "AnimationPlayer.play()") and [`AnimationPlayer.pause()`](/en-US/docs/Web/API/Animation/pause "AnimationPlayer.pause()") are now supported ([Firefox bug 1070745](https://bugzil.la/1070745 "External link (opens in new tab)")), as well as [`AnimationPlayer.playState`](/en-US/docs/Web/API/Animation/playState "AnimationPlayer.playState") ([Firefox bug 1037321](https://bugzil.la/1037321 "External link (opens in new tab)")).
    
*   The non-standard `DOMRequest` interface has now a `DOMRequest.then()` method ([Firefox bug 839838](https://bugzil.la/839838 "External link (opens in new tab)")).
    
*   The CSSOM View scroll behavior controlling methods, [`Element.scroll()`](/en-US/docs/Web/API/Element/scroll), [`Element.scrollTo()`](/en-US/docs/Web/API/Element/scrollTo), [`Element.scrollBy()`](/en-US/docs/Web/API/Element/scrollBy), and [`Element.scrollIntoView()`](/en-US/docs/Web/API/Element/scrollIntoView), have been implemented or extended ([Firefox bug 1045754](https://bugzil.la/1045754 "External link (opens in new tab)") and [Firefox bug 1087559](https://bugzil.la/1087559 "External link (opens in new tab)")).
    
*   Assigning to [`Element.innerHTML`](/en-US/docs/Web/API/Element/innerHTML) on an [`SVGElement`](/en-US/docs/Web/API/SVGElement) now create elements in the SVG namespace ([Firefox bug 886390](https://bugzil.la/886390 "External link (opens in new tab)")).
    
*   The `nsIWebBrowserPersist.saveURI()` method now requires 8 arguments, in an order incompatible with previous releases.
    
*   Support for Media Source Extensions (MSE) is activated by default in non-build releases (Nightly and Developer Edition only) ([Firefox bug 1000686](https://bugzil.la/1000686 "External link (opens in new tab)")). It keeps being preffed off on Beta and Release version.

## [Networking](#networking)

*   Support for SPDY/3 has been removed; support for SPDY/3.1 is still available ([Firefox bug 1097944](https://bugzil.la/1097944 "External link (opens in new tab)")).

## [Security](#security)

*   RC4 is now considered as insecure and all UI indicators will react as such; SSLv3 has been disabled by default in Firefox 34, but the UI has been changed to help the user better understand what is happening ([Firefox bug 1093595](https://bugzil.la/1093595 "External link (opens in new tab)")).
*   Also, RC4 is no longer offered in the initial handshake of TLS ([Firefox bug 1088915](https://bugzil.la/1088915 "External link (opens in new tab)")).
*   The [`form-action`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/form-action) directive of CSP 1.1 is now supported ([Firefox bug 529697](https://bugzil.la/529697 "External link (opens in new tab)")).
*   In the preferences of Firefox, The [Do not track](/en-US/docs/Web/HTTP/Reference/Headers/DNT) selection widget is again an on/off switch ([Firefox bug 1071747](https://bugzil.la/1071747 "External link (opens in new tab)")).

### [Interfaces](#interfaces)

#### nsIContentPolicy

New constants have been added to `nsIContentPolicy` to allow Gecko internals and add-on code to better differentiate different types of requests. These are:

[`TYPE_FETCH`](#type_fetch)

Indicates a content load request initiated by the [`fetch()`](/en-US/docs/Web/API/Window/fetch "fetch()") method.

[`TYPE_IMAGESET`](#type_imageset)

Indicates a request to load an [`<img>`](/en-US/docs/Web/HTML/Reference/Elements/img) (with the [`srcset`](/en-US/docs/Web/HTML/Reference/Elements/img#srcset) attribute or [`<picture>`](/en-US/docs/Web/HTML/Reference/Elements/picture) element.
