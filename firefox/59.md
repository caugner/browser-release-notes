# Firefox 59 release notes for developers

This article provides information about the changes in Firefox 59 that will affect developers. Firefox 59 was released on March 13, 2018.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   The [Network Monitor](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html "External link (opens in new tab)") Response tab now shows a [preview of the rendered HTML](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html#html-preview "External link (opens in new tab)") — if the response is HTML ([Firefox bug 1353319](https://bugzil.la/1353319 "External link (opens in new tab)")).
*   Cookie information shown in the Storage Inspector (see [Cookies](https://firefox-source-docs.mozilla.org/devtools-user/storage_inspector/index.html#cookies "External link (opens in new tab)")) now includes a _sameSite_ column showing what the same-site status of each cookie is ([Firefox bug 1298370](https://bugzil.la/1298370 "External link (opens in new tab)")).
*   The [Rulers](https://firefox-source-docs.mozilla.org/devtools-user/rulers/index.html "External link (opens in new tab)") tool now includes a readout showing the current dimensions of the viewport ([Firefox bug 1402633](https://bugzil.la/1402633 "External link (opens in new tab)")).
*   In [Responsive Design Mode](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html "External link (opens in new tab)"), you can now set the screen dimensions using the cursor keys ([Firefox bug 1421663](https://bugzil.la/1421663 "External link (opens in new tab)")). See the [Setting screen size](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html#setting-screen-size "External link (opens in new tab)") section for more details.
*   The _Raw headers_ display in the [Network Monitor](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html "External link (opens in new tab)") _Headers_ tab now includes the response's status code ([Firefox bug 1419401](https://bugzil.la/1419401 "External link (opens in new tab)")).

### [HTML](#html)

*   The [`<textarea>`](/en-US/docs/Web/HTML/Reference/Elements/textarea) element's [`autocomplete`](/en-US/docs/Web/HTML/Reference/Elements/textarea#autocomplete) attribute has been implemented. This lets you enable or disable form auto-fill for the element.

### [CSS](#css)

*   The [`overscroll-behavior`](/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior) property and its associated longhand properties — [`overscroll-behavior-x`](/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior-x) and [`overscroll-behavior-y`](/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior-y) — have been implemented ([Firefox bug 951793](https://bugzil.la/951793 "External link (opens in new tab)")), and it has been enabled by default on all releases ([Firefox bug 1428879](https://bugzil.la/1428879 "External link (opens in new tab)")).
*   The behavior of "unusual elements" (elements that aren't rendered purely by CSS box concepts such as replaced elements) when given a [`display`](/en-US/docs/Web/CSS/Reference/Properties/display) value of `contents` has been updated as per spec ([Firefox bug 1427292](https://bugzil.la/1427292 "External link (opens in new tab)")). See [Appendix B: Effects of display: contents on Unusual Elements](https://drafts.csswg.org/css-display/#unbox "External link (opens in new tab)") for exactly what the specified behaviors are.
*   [`position`](/en-US/docs/Web/CSS/Reference/Properties/position) `sticky` is now supported on appropriate [HTML table](/en-US/docs/Learn_web_development/Core/Structuring_content/HTML_table_basics) parts (e.g., [`<th>`](/en-US/docs/Web/HTML/Reference/Elements/th) elements) ([Firefox bug 975644](https://bugzil.la/975644 "External link (opens in new tab)")).
*   [`calc()`](/en-US/docs/Web/CSS/Reference/Values/calc) is now supported in [`<color>`](/en-US/docs/Web/CSS/Reference/Values/color_value) values — `rgb()`, `rgba()`, `hsl()`, and `hsla()` ([Firefox bug 984021](https://bugzil.la/984021 "External link (opens in new tab)")).
*   [`calc()`](/en-US/docs/Web/CSS/Reference/Values/calc) in [media query](/en-US/docs/Web/CSS/Guides/Media_queries) values is now supported [Firefox bug 1396057](https://bugzil.la/1396057 "External link (opens in new tab)").
*   The [`@document`](/en-US/docs/Web/CSS/Reference/At-rules/@document) at-rule has been limited to use only in user and UA sheets ([Firefox bug 1035091](https://bugzil.la/1035091 "External link (opens in new tab)")).
*   Implement the [`font-optical-sizing`](/en-US/docs/Web/CSS/Reference/Properties/font-optical-sizing) property ([Firefox bug 1435692](https://bugzil.la/1435692 "External link (opens in new tab)")).

### [APIs](#apis)

#### New APIs

*   [`PointerEvents`](/en-US/docs/Web/API/PointerEvent "PointerEvents") have been enabled in Firefox Desktop ([Firefox bug 1411467](https://bugzil.la/1411467 "External link (opens in new tab)")).

#### DOM

*   The [`EventTarget()`](/en-US/docs/Web/API/EventTarget/EventTarget "EventTarget()") constructor has been implemented ([Firefox bug 1379688](https://bugzil.la/1379688 "External link (opens in new tab)")).
*   The [`Response()`](/en-US/docs/Web/API/Response/Response "Response()") constructor can now accept a `null` value for its `body` parameter, as per spec ([Firefox bug 1303025](https://bugzil.la/1303025 "External link (opens in new tab)")).

#### DOM events

*   The [`Event.composedPath()`](/en-US/docs/Web/API/Event/composedPath) method has been implemented ([Firefox bug 1412775](https://bugzil.la/1412775 "External link (opens in new tab)")).

#### Service workers

*   The service worker [Clients API](/en-US/docs/Web/API/Clients) can now find and communicate with windows in a separate browser process ([Firefox bug 1293277](https://bugzil.la/1293277 "External link (opens in new tab)")).
*   Nested about:blank and about:srcdoc iframes will now inherit their parent's controlling service worker. Fixed in ([Firefox bug 1293277](https://bugzil.la/1293277 "External link (opens in new tab)")) and ([Firefox bug 1426979](https://bugzil.la/1426979 "External link (opens in new tab)")).
*   When a service worker provides a [`Response`](/en-US/docs/Web/API/Response) to [`FetchEvent.respondWith()`](/en-US/docs/Web/API/FetchEvent/respondWith), the [`Response.url`](/en-US/docs/Web/API/Response/url) value will now be propagated to the intercepted network request as the final resolved URL. In the past the [`FetchEvent.request.url`](/en-US/docs/Web/API/Request/url "FetchEvent.request.url") was used for this instead. This means, for example, if a service worker intercepts a stylesheet or worker script, then the provided `Response.url` will be used to resolve any relative [`@import`](/en-US/docs/Web/CSS/Reference/At-rules/@import) or [`importScripts()`](/en-US/docs/Web/API/WorkerGlobalScope/importScripts "importScripts()") subresource loads ([Firefox bug 1222008](https://bugzil.la/1222008 "External link (opens in new tab)")).
*   `FetchEvent.respondWith()` will now trigger a network error if the [`FetchEvent.request.mode`](/en-US/docs/Web/API/Request/mode "FetchEvent.request.mode") is `"same-origin"` and the provided [`Response.type`](/en-US/docs/Web/API/Response/type) is `"cors"`. ([Firefox bug 1222008](https://bugzil.la/1222008 "External link (opens in new tab)"))

#### Media and WebRTC

*   The [`MediaStreamTrack`](/en-US/docs/Web/API/MediaStreamTrack) property [`MediaStreamTrack.muted`](/en-US/docs/Web/API/MediaStreamTrack/muted), along with the events [`mute`](/en-US/docs/Web/API/MediaStreamTrack/mute_event "mute") and [`unmute`](/en-US/docs/Web/API/MediaStreamTrack/unmute_event "unmute") and the corresponding event handlers, [`onmute`](/en-US/docs/Web/API/MediaStreamTrack/mute_event "onmute") and [`onunmute`](/en-US/docs/Web/API/MediaStreamTrack/unmute_event "onunmute"), have been implemented. A track's `muted` state indicates that the track is not currently able to provide media data.
    
    **Note:** The `muted` state of a track isn't useful for what's typically thought of as muting and unmuting a track. Instead, use the [`enabled`](/en-US/docs/Web/API/MediaStreamTrack/enabled "enabled") property; setting `enabled` to `false` causes the track to output only empty frames.
    
*   Firefox 59 on Android now supports Apple's HTTPS Live Streaming (HLS) protocol for both audio and video. This non-standard protocol is being supported on mobile to improve compatibility with sites that require it for mobile streaming. There is not currently any plan to implement it on Firefox Desktop.
    
*   The [`RTCRtpReceiver`](/en-US/docs/Web/API/RTCRtpReceiver) methods [`getContributingSources()`](/en-US/docs/Web/API/RTCRtpReceiver/getContributingSources "getContributingSources()") and [`getSynchronizationSources()`](/en-US/docs/Web/API/RTCRtpReceiver/getSynchronizationSources "getSynchronizationSources()") have been implemented to provide information about the sources of each RTP stream. However, a specification change occurred before release and we have disabled these by default behind the preference `media.peerconnection.rtpsourcesapi.enable` ([Firefox bug 1363667](https://bugzil.la/1363667 "External link (opens in new tab)"), [Firefox bug 1430213](https://bugzil.la/1430213 "External link (opens in new tab)"), and [Firefox bug 1433236](https://bugzil.la/1433236 "External link (opens in new tab)").
    
*   The [`RTCRtpTransceiver`](/en-US/docs/Web/API/RTCRtpTransceiver) interface has now been implemented, since the Firefox implementation of WebRTC now supports transceivers, with `RTCPeerConnection` and other interfaces updated to use them per the latest specification.
    
*   The [`RTCPeerConnection.addTransceiver()`](/en-US/docs/Web/API/RTCPeerConnection/addTransceiver) method has been added. In addition, the behavior of [`addTrack()`](/en-US/docs/Web/API/RTCPeerConnection/addTrack "addTrack()") has been updated to create a transceiver as required.
    
*   Support for [WebVTT](/en-US/docs/Web/API/WebVTT_API) regions was implemented in Firefox 58 but disabled by default. They're now available by default ([Firefox bug 1415805](https://bugzil.la/1415805 "External link (opens in new tab)")).
    
*   Firefox now supports WebVTT `REGION` definition blocks whose settings list has one setting per line instead of all of the settings being on the same line of the WebVTT file ([Firefox bug 1415821](https://bugzil.la/1415821 "External link (opens in new tab)").

### [CSSOM](#cssom)

The [`CSSNamespaceRule`](/en-US/docs/Web/API/CSSNamespaceRule) interface and its `namespaceURL` and `prefix` properties have been implemented ([Firefox bug 1326514](https://bugzil.la/1326514 "External link (opens in new tab)")).

### [HTTP](#http)

_No changes._

### [Security](#security)

*   Top-level navigation to `data:` URLs has been blocked [Firefox bug 1401895](https://bugzil.la/1401895 "External link (opens in new tab)"). See [Blocking Top-Level Navigations to data URLs for Firefox 59](https://blog.mozilla.org/security/2017/11/27/blocking-top-level-navigations-data-urls-firefox-59/ "External link (opens in new tab)") for more details.
*   The `SAMEORIGIN` directive of the [`X-Frame-Options`](/en-US/docs/Web/HTTP/Reference/Headers/X-Frame-Options) header has been changed so that it checks not only the top-level IFrame is in the same origin, but all its ancestors as well ([Firefox bug 725490](https://bugzil.la/725490 "External link (opens in new tab)")).
*   Image resources loaded from different origins to the current document are no longer able to trigger HTTP authentication dialogs ([Firefox bug 1423146](https://bugzil.la/1423146 "External link (opens in new tab)")).
*   HTTP authentication now uses `utf-8` encoding for usernames and passwords (rather than `ISO-8859-1`) for parity with other browsers, and to avoid potential problems as described in [Firefox bug 1419658](https://bugzil.la/1419658 "External link (opens in new tab)").
*   Everyday the [HSTS preload list](https://searchfox.org/firefox-main/source/security/manager/ssl/nsSTSPreloadList.inc "External link (opens in new tab)") is updated from Google. Normally this doesn't warrant a note, but in this release new TLDs were included, notably `.app` and `.dev`. While they are new TLDs developers might have used them for local development and be surprised by this change. Note that [reserved TLDs](https://datatracker.ietf.org/doc/html/rfc2606 "External link (opens in new tab)") should be used for local development instead.

## [Removals from the web platform](#removals_from_the_web_platform)

### [HTML](#html_2)

The non-standard `version` parameter of the [`<script>`](/en-US/docs/Web/HTML/Reference/Elements/script) element's [`type`](/en-US/docs/Web/HTML/Reference/Elements/script/type) attribute (e.g., `type="application/javascript;version=1.8"`) has been removed ([Firefox bug 1428745](https://bugzil.la/1428745 "External link (opens in new tab)")).

### [CSS](#css_2)

*   The proprietary `mozmm` [`<length>`](/en-US/docs/Web/CSS/Reference/Values/length) unit has been removed ([Firefox bug 1416564](https://bugzil.la/1416564 "External link (opens in new tab)")).
*   The proprietary `-moz-border-top-colors`, `-moz-border-right-colors`, `-moz-border-bottom-colors`, and `-moz-border-left-colors` properties have been limited to usage in chrome code only ([Firefox bug 1417200](https://bugzil.la/1417200 "External link (opens in new tab)")).

### [JavaScript](#javascript_2)

*   Non-standard conditional catch clauses have been removed ([Firefox bug 1228841](https://bugzil.la/1228841 "External link (opens in new tab)")).

### [APIs](#apis_2)

*   The non-standard method `Event.getPreventDefault()` has been removed. You should instead use the [`Event.defaultPrevented`](/en-US/docs/Web/API/Event/defaultPrevented) property to determine whether or not [`preventDefault()`](/en-US/docs/Web/API/Event/preventDefault "preventDefault()") was called on the [`Event`](/en-US/docs/Web/API/Event).
*   The proprietary `Navigator.mozNotification` property and `DesktopNotification` interface have been removed, in favor of the standard [Notifications API](/en-US/docs/Web/API/Notifications_API) ([Firefox bug 952453](https://bugzil.la/952453 "External link (opens in new tab)")).
*   The proprietary `window.external.addSearchEngine()` method has been removed ([Firefox bug 862147](https://bugzil.la/862147 "External link (opens in new tab)")). Also see [`Window.external`](/en-US/docs/Web/API/Window/external) for more details.
*   The non-standard Firefox-only [`HTMLMediaElement`](/en-US/docs/Web/API/HTMLMediaElement) property `mozAutoplayEnabled` has been removed.

### [SVG](#svg_2)

Support for SMIL's `accessKey` feature has been removed ([Firefox bug 1423098](https://bugzil.la/1423098 "External link (opens in new tab)")).

### [Other](#other_2)

Support for the non-standard `pcast:` and `feed:` protocols has been removed from Firefox ([Firefox bug 1420622](https://bugzil.la/1420622 "External link (opens in new tab)")).

## [Changes for add-on and Mozilla developers](#changes_for_add-on_and_mozilla_developers)

### [WebExtensions](#webextensions)

*   [Theme](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/theme) updates:
    
    *   new properties: `colors.background_tab_text`, `colors.toolbar_field_border`
    *   all color properties now support both Chrome-style arrays and CSS color values.
*   New [browser settings](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings):
    
    *   [`contextMenuShowEvent`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings/contextMenuShowEvent)
    *   [`openBookmarksInNewTabs`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings/openBookmarksInNewTabs)
    *   [`openSearchResultsInNewTabs`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings/openSearchResultsInNewTabs)
    *   [`proxyConfig`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/proxy/settings)
*   New [`tabs`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs) APIs:
    
    *   [`tabs.captureTab()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/captureTab)
    *   [`tabs.hide()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/hide)
    *   [`tabs.show()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/show)
*   The `contextMenus` API now supports a ["bookmark" context](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus/ContextType).
    
*   New [`contentScripts`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/contentScripts) API enables runtime registration of content scripts.
    
*   New [`pageAction`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/pageAction), [`browserAction`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserAction), [`SidebarAction`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/sidebarAction) APIs:
    
    *   `browserAction/pageAction/sidebarAction.set*` functions now accept `null` to undo changes.
    *   [`browserAction.isEnabled()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserAction/isEnabled), [`pageAction.isShown()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/pageAction/isShown), [`sidebarAction.isOpen()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/sidebarAction/isOpen) functions.
*   New option in [`page_action`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/page_action) to show page actions by default.
    
*   New values for `protocol_handlers`:
    
    *   "ssb" for Secure Scuttlebutt communications
    *   "dat" for DATproject
    *   "ipfs", "ipns", "dweb" for IPFS
*   New [`privacy.websites`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/privacy/websites) setting "cookieConfig".
    
*   Support in [`cookies`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/cookies) API for [first-party isolation](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/cookies#first-party_isolation).
    
*   New option `upgradeToSecure` in [`webRequest`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest).
