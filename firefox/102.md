# Firefox 102 release notes for developers

This article provides information about the changes in Firefox 102 that will affect developers. Firefox 102 was released on June 28, 2022.

## [Changes for web developers](#changes_for_web_developers)

### [HTML](#html)

No notable changes.

### [CSS](#css)

The [`update`](/en-US/docs/Web/CSS/Reference/At-rules/@media/update) media feature that can be used to query the ability of the output device to modify the appearance of content after it is rendered is now available by default ([Firefox bug 1422312](https://bugzil.la/1422312 "External link (opens in new tab)")).

### [JavaScript](#javascript)

No notable changes.

### [APIs](#apis)

*   The non-standard interfaces `IDBMutableFile`, `IDBFileHandle`, `IDBFileRequest`, and the method `IDBDatabase.createMutableFile()` have been disabled by default in preparation for removal in a future release ([Firefox bug 1764771](https://bugzil.la/1764771 "External link (opens in new tab)")).
    
*   [Transform streams](/en-US/docs/Web/API/TransformStream) are now supported, allowing you to pipe from [`ReadableStream`](/en-US/docs/Web/API/ReadableStream) to a [`WritableStream`](/en-US/docs/Web/API/WritableStream), executing a transformation on the chunks. The update includes the new interfaces [`TransformStream`](/en-US/docs/Web/API/TransformStream) and [`TransformStreamDefaultController`](/en-US/docs/Web/API/TransformStreamDefaultController) and the method [`ReadableStream.pipeThrough()`](/en-US/docs/Web/API/ReadableStream/pipeThrough) ([Firefox bug 1767507](https://bugzil.la/1767507 "External link (opens in new tab)")).
    
*   [Readable byte streams](/en-US/docs/Web/API/Streams_API/Using_readable_byte_streams) are now supported, allowing efficient zero-byte transfer of data from an underlying byte source to a consumer (bypassing the stream's internal queues). The new interfaces are [`ReadableStreamBYOBReader`](/en-US/docs/Web/API/ReadableStreamBYOBReader), [`ReadableByteStreamController`](/en-US/docs/Web/API/ReadableByteStreamController) and [`ReadableStreamBYOBRequest`](/en-US/docs/Web/API/ReadableStreamBYOBRequest) ([Firefox bug 1767342](https://bugzil.la/1767342 "External link (opens in new tab)")).
    

### [Security](#security)

*   Support of the [`wasm-unsafe-eval`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src#unsafe_webassembly_execution) CSP policy directive has been implemented. A document with a CSP that restricts scripts will no longer load and execute WebAssembly unless the CSP uses `'wasm-unsafe-eval'` or the existing `'unsafe-eval'` keyword ([Firefox bug 1740263](https://bugzil.la/1740263 "External link (opens in new tab)")).

#### DOM

*   The Firefox-only property [`Window.sidebar`](/en-US/docs/Web/API/Window/external "Window.sidebar") has been moved behind a preference (and permanently removed in version 119) ([Firefox bug 1768486](https://bugzil.la/1768486 "External link (opens in new tab)")).

### [WebDriver conformance](#webdriver_conformance)

#### WebDriver BiDi

*   There are some improvements to Webdriver BiDi's `browsingContext.navigate`
    *   Fixed edge cases where the navigation could incorrectly timeout ([Firefox bug 1766217](https://bugzil.la/1766217 "External link (opens in new tab)")).
    *   Added support for hash changes ([Firefox bug 1763127](https://bugzil.la/1763127 "External link (opens in new tab)")).
    *   Added support navigation to error pages ([Firefox bug 1763124](https://bugzil.la/1763124 "External link (opens in new tab)")).

#### Marionette

*   Allow marionette to connect to a windowless instance of Firefox ([Firefox bug 1726465](https://bugzil.la/1726465 "External link (opens in new tab)")).
*   Fixed issue where `WebDriver:Navigate` with a PageLoadStrategy of "none" returns before navigation has started ([Firefox bug 1754132](https://bugzil.la/1754132 "External link (opens in new tab)")).
*   Fixed a potential race condition in `WebDriver:SwitchToWindow` when switching to a different tab ([Firefox bug 1749666](https://bugzil.la/1749666 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

*   The [`scripting`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/scripting) API, which provides features to execute script, insert and remove CSS, and manage the registration of content scripts is available to Manifest V2 extensions ([Firefox bug 1766615](https://bugzil.la/1766615 "External link (opens in new tab)")).
*   The `nonPersistentCookies` option of the [`privacy.websites`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/privacy/websites) `cookieConfig` property has been deprecated ([Firefox bug 1754924](https://bugzil.la/1754924 "External link (opens in new tab)")).
*   Manifest V3 [preview](https://blog.mozilla.org/addons/2022/06/08/manifest-v3-firefox-developer-preview-how-to-get-involved/ "External link (opens in new tab)") features:
    *   With the introduction of support for the 'wasm-unsafe-eval' CSP keyword in Firefox ([Firefox bug 1740263](https://bugzil.la/1740263 "External link (opens in new tab)")), Manifest V3 extensions are now required to specify this keyword in the [content\_security\_policy](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/content_security_policy) manifest key to use [WebAssembly](/en-US/docs/WebAssembly). For backwards-compatibility, Manifest V2 extensions can still use WebAssembly without the keyword ([Firefox bug 1766027](https://bugzil.la/1766027 "External link (opens in new tab)")).
