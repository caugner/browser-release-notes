# Firefox 29 release notes for developers

Firefox 29 was released on April 29, 2014. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

Major changes include:

*   Vastly improved web console - Arrays are shown inline without clicking to bring up in the right inspector, window objects show their URL, etc.
*   Added the [console API](/en-US/docs/Web/API/Console_API) to Web Workers ([bug 620935](https://bugzil.la/620935 "External link (opens in new tab)")). Now you can log messages to the Web Console from Web Workers.
*   The [Network Monitor](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html "External link (opens in new tab)") tool now shows performance statistics using pie charts ([Firefox bug 846601](https://bugzil.la/846601 "External link (opens in new tab)")).
*   On the [Inspector](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/index.html "External link (opens in new tab)"), preview tooltips of CSS transforms are now available ([Firefox bug 726427](https://bugzil.la/726427 "External link (opens in new tab)")).
*   DOM elements seen in the debugger and console can be removed or inspected directly, via the new buttons to the right of the variable listing.
*   A CSS source map is now supported by the [Style Editor](https://firefox-source-docs.mozilla.org/devtools-user/style_editor/index.html "External link (opens in new tab)") ([Firefox bug 926014](https://bugzil.la/926014 "External link (opens in new tab)")).
*   Autocompletion of CSS properties and values has been added to the [Style Editor](https://firefox-source-docs.mozilla.org/devtools-user/style_editor/index.html "External link (opens in new tab)") ([Firefox bug 717369](https://bugzil.la/717369 "External link (opens in new tab)")).

_See the [Mozilla Hacks blog post](https://hacks.mozilla.org/2014/02/css-source-map-support-network-performance-analysis-more-firefox-developer-tools-episode-29/ "External link (opens in new tab)") for details and other smaller changes._

### [CSS](#css)

*   [CSS variables](/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties) have been implemented ([Firefox bug 773296](https://bugzil.la/773296 "External link (opens in new tab)")). The [CSS Variables in Firefox Nightly](https://hacks.mozilla.org/2013/12/css-variables-in-firefox-nightly/ "External link (opens in new tab)") on Mozilla Hacks contains more details. They are enabled by default only for non-release builds (on release builds flip the pref `layout.css.variables.enabled` to `true` if you want to play with them).
*   Flexboxes now support [`visibility: collapse`](/en-US/docs/Web/CSS/Reference/Properties/visibility) ([Firefox bug 783470](https://bugzil.la/783470 "External link (opens in new tab)")).
*   The [`box-sizing`](/en-US/docs/Web/CSS/Reference/Properties/box-sizing) property has been unprefixed ([Firefox bug 243412](https://bugzil.la/243412 "External link (opens in new tab)")).
*   The [`will-change`](/en-US/docs/Web/CSS/Reference/Properties/will-change) property, a hint to that something will animate has been added. The preference `layout.css.will-change.enabled` must be switched to `true` to enable it. ([Firefox bug 940842](https://bugzil.la/940842 "External link (opens in new tab)"))
*   Scientific exponential notation, like `3e1` or `10e+0`, is now supported for [`<number>`](/en-US/docs/Web/CSS/Reference/Values/number) values and derivatives, like [`<percentage>`](/en-US/docs/Web/CSS/Reference/Values/percentage) and unit values, but not [`<integer>`](/en-US/docs/Web/CSS/Reference/Values/integer) ([Firefox bug 964529](https://bugzil.la/964529 "External link (opens in new tab)")).
*   Images of type [`<gradient>`](/en-US/docs/Web/CSS/Reference/Values/gradient) are now supported in [`border-image`](/en-US/docs/Web/CSS/Reference/Properties/border-image) ([Firefox bug 709587](https://bugzil.la/709587 "External link (opens in new tab)")).
*   The [`touch-action`](/en-US/docs/Web/CSS/Reference/Properties/touch-action) property has been implemented. It is not activated by default; the `layout.css.touch_action.enabled` pref controls it. ([Firefox bug 795567](https://bugzil.la/795567 "External link (opens in new tab)"))
*   Remove redundant default style for <pre> element from quirk.css ([Firefox bug 948914](https://bugzil.la/948914 "External link (opens in new tab)")).
*   CSS Variables fallback incorrectly implemented (primary cycles) ([Firefox bug 950497](https://bugzil.la/950497 "External link (opens in new tab)")).
*   @supports conditions with tokens after a declaration's priority should evaluate to false ([Firefox bug 909170](https://bugzil.la/909170 "External link (opens in new tab)")).

### [HTML](#html)

*   `<input type=color>` and `<input type=number>` are available by default.
*   Support for the non standard `<pre cols>` has been removed, as well as the layout effect of `<pre wrap>`. Both effects can, and should, be achieved using CSS. ([Firefox bug 949879](https://bugzil.la/949879 "External link (opens in new tab)"))

### [JavaScript](#javascript)

*   New ECMAScript 2015 String methods: [`String.prototype.codePointAt()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/codePointAt) and [`String.prototype.fromCodePoint()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/fromCodePoint) have been implemented ([Firefox bug 918879](https://bugzil.la/918879 "External link (opens in new tab)")).
    
*   The [ECMAScript Internationalization API (ECMA-402)](https://402.ecma-international.org/1.0/ "External link (opens in new tab)") has been implemented and is now enabled by default in Firefox Desktop ([Firefox bug 853301](https://bugzil.la/853301 "External link (opens in new tab)")):
    
    *   New objects in the new [`Intl`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl) object namespace:
        
        *   [`Intl.Collator`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Collator)
        *   [`Intl.DateTimeFormat`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat)
        *   [`Intl.NumberFormat`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat)
    *   The following methods of [`String`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String), [`Number`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number) and [`Date`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date) have been updated to include the `locales` and `options` arguments per ECMA-402:
        
        *   [`String.prototype.localeCompare()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/localeCompare)
        *   [`Number.prototype.toLocaleString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/toLocaleString)
        *   [`Date.prototype.toLocaleString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/toLocaleString)
        *   [`Date.prototype.toLocaleDateString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/toLocaleDateString)
        *   [`Date.prototype.toLocaleTimeString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/toLocaleTimeString)
*   To match the updated ECMAScript 2015 draft specification, the [`Map`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map) and [`Set`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set) objects now treat `-0` and `+0` as the same when checking for key and value equality.
    
*   `Promise` has been enabled by default ([Firefox bug 918806](https://bugzil.la/918806 "External link (opens in new tab)")).
    
*   Completed [generators](/en-US/docs/Web/JavaScript/Reference/Statements/function*) now return an `IteratorResult` object instead of throwing ([Firefox bug 958951](https://bugzil.la/958951 "External link (opens in new tab)")).
    
*   A malformed JSON string parsed by [`JSON.parse()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/parse) now yields a more detailed error message containing the line and column number that caused the parsing error. This is useful when debugging large JSON data.
    
*   The [`ArrayBuffer.isView()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/ArrayBuffer/isView) method has been added ([Firefox bug 896105](https://bugzil.la/896105 "External link (opens in new tab)")).
    

### [Interfaces/APIs/DOM](#interfacesapisdom)

*   A new type of workers, [`SharedWorker`](/en-US/docs/Web/API/SharedWorker), is now available by default ([Firefox bug 924089](https://bugzil.la/924089 "External link (opens in new tab)")).
*   The [`URL`](/en-US/docs/Web/API/URL) interface now supports the [`searchParams`](/en-US/docs/Web/API/URL/searchParams "searchParams") property returning a [`URLSearchParams`](/en-US/docs/Web/API/URLSearchParams) object, allowing you to modify the search params of a URL ([Firefox bug 887836](https://bugzil.la/887836 "External link (opens in new tab)")). The [`URLSearchParams()`](/en-US/docs/Web/API/URLSearchParams/URLSearchParams "URLSearchParams()") constructor allows easier parsing of query strings.
*   The [`navigator.onLine`](/en-US/docs/Web/API/WorkerNavigator/onLine "navigator.onLine") property is now supported on [`WorkerNavigator`](/en-US/docs/Web/API/WorkerNavigator), allowing you to know the online/offline status in workers ([Firefox bug 925437](https://bugzil.la/925437 "External link (opens in new tab)")).
*   As part of the implementation of Web Components, the `HTMLShadowElement` interface has been implemented behind the `dom.webcomponents.enabled`. Flip it to `true` if you want to use it. ([Firefox bug 887538](https://bugzil.la/887538 "External link (opens in new tab)"))
*   The read-only property [`HTMLIFrameElement.sandbox`](/en-US/docs/Web/API/HTMLIFrameElement/sandbox) is no longer a string but a [`DOMTokenList`](/en-US/docs/Web/API/DOMTokenList) ([Firefox bug 845057](https://bugzil.la/845057 "External link (opens in new tab)")).
*   On [`HTMLCanvasElement.getContext()`](/en-US/docs/Web/API/HTMLCanvasElement/getContext), the value `moz-webgl` is no longer supported. Use the standard `webgl` value ([Firefox bug 913597](https://bugzil.la/913597 "External link (opens in new tab)")).
*   The constructor for [`ImageData`](/en-US/docs/Web/API/ImageData) has been added. This interface can be used in a [`Worker`](/en-US/docs/Web/API/Worker). ([Firefox bug 959958](https://bugzil.la/959958 "External link (opens in new tab)"))
*   The property [`location.origin`](/en-US/docs/Web/API/WorkerLocation/origin "location.origin") is now available in workers (via [`WorkerLocation`](/en-US/docs/Web/API/WorkerLocation)) ([Firefox bug 964148](https://bugzil.la/964148 "External link (opens in new tab)")).
*   The [`ValidityState.badInput`](/en-US/docs/Web/API/ValidityState/badInput) property has been implemented ([Firefox bug 827161](https://bugzil.la/827161 "External link (opens in new tab)")).
*   The deprecated `Window.pkcs11` property has been removed; it was returning `null` since Firefox 3.0.14. ([Firefox bug 964964](https://bugzil.la/964964 "External link (opens in new tab)"))
*   The [`Node.cloneNode()`](/en-US/docs/Web/API/Node/cloneNode) and [`Document.importNode()`](/en-US/docs/Web/API/Document/importNode) methods take the Boolean `deep` argument. Until now, if omitted, these methods acted as if the value of `deep` was `true`. But this behavior has been changed as per the latest spec, and if omitted, the methods will act as if the value was `false`. ([Firefox bug 937461](https://bugzil.la/937461 "External link (opens in new tab)"))
*   `Window._content` is no longer available to Web content ([Firefox bug 946564](https://bugzil.la/946564 "External link (opens in new tab)")).
*   [`URLUtils.port`](/en-US/docs/Web/API/HTMLAnchorElement/port "URLUtils.port") behavior has been slightly changed: set to `''` will set it to the default port associated with the protocol, and `0` to `0`. ([Firefox bug 930450](https://bugzil.la/930450 "External link (opens in new tab)"))
*   [`Document.referrer`](/en-US/docs/Web/API/Document/referrer) is now based on the incumbent script ([Firefox bug 887928](https://bugzil.la/887928 "External link (opens in new tab)")).
*   The [Gamepad API](/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API) is enabled by default ([Firefox bug 878828](https://bugzil.la/878828 "External link (opens in new tab)")).
*   The `CanvasRenderingContext2D.drawSystemFocusRing()` method got renamed to [`CanvasRenderingContext2D.drawFocusIfNeeded()`](/en-US/docs/Web/API/CanvasRenderingContext2D/drawFocusIfNeeded) ([Firefox bug 959820](https://bugzil.la/959820 "External link (opens in new tab)")).

### [MathML](#mathml)

_No change._

### [SVG](#svg)

_No change._

## [Security](#security)

*   The CSP 1.1 experimental `hash-source` directive has been implemented. The preference `security.csp.experimentalEnabled` should be set to `true` to enable this functionality ([Firefox bug 883975](https://bugzil.la/883975 "External link (opens in new tab)")).

## [Changes for add-on and Mozilla developers](#changes_for_add-on_and_mozilla_developers)

*   Major Firefox theme changes affect most extensions that interact with the Firefox user interface.
*   `nsISecurityCheckedComponent` has been removed ([Firefox bug 794943](https://bugzil.la/794943 "External link (opens in new tab)")). Most consumers can remove `nsISecurityCheckedComponent` from their interface definition and they will continue to work.
