# Firefox 70 release notes for developers

This article provides information about the changes in Firefox 70 that will affect developers. Firefox 70 was released on October 22, 2019.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

#### Debugger updates

*   In the [Debugger](https://firefox-source-docs.mozilla.org/devtools-user/debugger/index.html "External link (opens in new tab)") you can now set breakpoints for [DOM Mutation](https://firefox-source-docs.mozilla.org/devtools-user/debugger/break_on_dom_mutation/index.html "External link (opens in new tab)"), so execution will pause when a node or its attributes are changed or when a node is removed from the DOM ([Firefox bug 1576219](https://bugzil.la/1576219 "External link (opens in new tab)")).
*   The Debugger now shows an overlay on the page when it is paused, with basic stepping buttons to let you step and continue ([Firefox bug 1574646](https://bugzil.la/1574646 "External link (opens in new tab)")).
*   The Debugger now shows sources that already got discarded by the engine (usually scripts that execute once during page load), so you can properly set breakpoints to debug when they execute next ([Firefox bug 1572280](https://bugzil.la/1572280 "External link (opens in new tab)")).
*   The Debugger's [scopes panel](https://firefox-source-docs.mozilla.org/devtools-user/debugger/using_the_debugger_map_scopes_feature/index.html "External link (opens in new tab)") grouping has been simplified, consolidating additional scopes previously shown above the top level function (e.g., blocks created by [`let`](/en-US/docs/Web/JavaScript/Reference/Statements/let), [`with`](/en-US/docs/Web/JavaScript/Reference/Statements/with), or [`if`/`else`](/en-US/docs/Web/JavaScript/Reference/Statements/if...else)) ([Firefox bug 1448166](https://bugzil.la/1448166 "External link (opens in new tab)"))
*   The Debugger now retains the currently selected and expanded variables in the [scopes panel](https://firefox-source-docs.mozilla.org/devtools-user/debugger/using_the_debugger_map_scopes_feature/index.html "External link (opens in new tab)") while stepping ([Firefox bug 1405402](https://bugzil.la/1405402 "External link (opens in new tab)")).
*   The Debugger now handles stepping over async functions correctly, making [asynchronous function](/en-US/docs/Web/JavaScript/Reference/Statements/async_function) debugging easier ([Firefox bug 1570178](https://bugzil.la/1570178 "External link (opens in new tab)")).
*   When debugging in [Container sessions](https://support.mozilla.org/en-US/kb/containers "External link (opens in new tab)") (useful for testing different logins), the sources in the debugger are now shown correctly ([Firefox bug 1375036](https://bugzil.la/1375036 "External link (opens in new tab)")).
*   [`debugger`](/en-US/docs/Web/JavaScript/Reference/Statements/debugger) statements can be now disabled in the Debugger by setting a breakpoint on them and switching the breakpoints to "Never pause here" ([Firefox bug 925269](https://bugzil.la/925269 "External link (opens in new tab)")).
*   WebExtensions developers can inspect `browser.storage.local` from the Extension Storage item under the Storage tab ([Firefox bug 1585499](https://bugzil.la/1585499 "External link (opens in new tab)")).

#### Other updates

*   An icon will be displayed next to inactive CSS properties in the [Rules view](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/ui_tour/index.html#rules-view "External link (opens in new tab)") of the [Page Inspector](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/index.html "External link (opens in new tab)"), which you can hover over to get information on why it is inactive ([Firefox bug 1306054](https://bugzil.la/1306054 "External link (opens in new tab)")).
*   In the [CSS Rules view](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/ui_tour/index.html#rules-view "External link (opens in new tab)"), the [color picker](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/inspect_and_select_colors/index.html "External link (opens in new tab)") on foreground colors now tells you whether its contrast with the background color meets accessibility conformance criteria ([Firefox bug 1478156](https://bugzil.la/1478156 "External link (opens in new tab)")).
*   The [Accessibility inspector](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html "External link (opens in new tab)")'s [Check for issues](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html#check-for-accessibility-issues "External link (opens in new tab)") dropdown now includes keyboard accessibility checks ([Firefox bug 1564968](https://bugzil.la/1564968 "External link (opens in new tab)")).

### [HTML](#html)

*   Firefox can now suggest securely-generated passwords to the user in the following situations:
    *   An [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) element has the `autocomplete="new-password"` attribute value.
    *   The user opens the context menu on any password input element, even if it is not intended for new passwords.

### [CSS](#css)

*   Opacity values like for [`opacity`](/en-US/docs/Web/CSS/Reference/Properties/opacity) or [`stop-opacity`](/en-US/docs/Web/SVG/Reference/Attribute/stop-opacity) can now be percentages ([Firefox bug 1562086](https://bugzil.la/1562086 "External link (opens in new tab)")).
    
*   [`grid-auto-columns`](/en-US/docs/Web/CSS/Reference/Properties/grid-auto-columns) and [`grid-auto-rows`](/en-US/docs/Web/CSS/Reference/Properties/grid-auto-rows) now accept multiple track-size values ([Firefox bug 1339672](https://bugzil.la/1339672 "External link (opens in new tab)")).
    
*   A number of text-related CSS properties have been enabled by default ([Firefox bug 1573631](https://bugzil.la/1573631 "External link (opens in new tab)")):
    
    *   [`text-decoration-thickness`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-thickness).
    *   [`text-underline-offset`](/en-US/docs/Web/CSS/Reference/Properties/text-underline-offset).
    *   [`text-decoration-skip-ink`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-skip-ink). The default value is `auto`, which means that by default underlines and overlines are now interrupted where they would otherwise cross over a [glyph](/en-US/docs/Glossary/Glyph).
*   The [`display`](/en-US/docs/Web/CSS/Reference/Properties/display) property now accepts two keyword values representing the inner and outer display type ([Firefox bug 1038294](https://bugzil.la/1038294 "External link (opens in new tab)"), [WebKit bug 1105868](https://bugzil.la/1105868 "External link (opens in new tab)") and [WebKit bug 1557825](https://bugzil.la/1557825 "External link (opens in new tab)")).
    
*   The [`font-size`](/en-US/docs/Web/CSS/Reference/Properties/font-size) property now accepts the new keyword value `xxx-large`. ([Firefox bug 1553545](https://bugzil.la/1553545 "External link (opens in new tab)")).
    
*   The [`:visited`](/en-US/docs/Web/CSS/Reference/Selectors/:visited) pseudo-class no longer matches [`<link>`](/en-US/docs/Web/HTML/Reference/Elements/link) elements, for logic and performance reasons ([Firefox bug 1572246](https://bugzil.la/1572246 "External link (opens in new tab)"); see [Intent to ship: Make <link> elements always unvisited](https://groups.google.com/forum/#!msg/mozilla.dev.platform/1NP6oJzK6zg/ftAz_TajAAAJ "External link (opens in new tab)") and [\[selectors\] :link and <link>](https://github.com/w3c/csswg-drafts/issues/3817 "External link (opens in new tab)") for more reasoning as to why).
    
*   We now support an `auto` value for the [`quotes`](/en-US/docs/Web/CSS/Reference/Properties/quotes) property ([Firefox bug 1421938](https://bugzil.la/1421938 "External link (opens in new tab)")).
    
*   Stylesheets contained in [`<style>`](/en-US/docs/Web/HTML/Reference/Elements/style) elements are now cached for reuse, to improve performance ([Firefox bug 1480146](https://bugzil.la/1480146 "External link (opens in new tab)")). Note that this currently doesn't include stylesheets that contain `@import` rules.
    
*   The `<ratio>` type now accepts `<number>/<number>` or a single `<number>` as a value. ([Firefox bug 1565562](https://bugzil.la/1565562 "External link (opens in new tab)")).
    

#### Removals

*   We have retired support for 3-valued <position> (excluding background)([Firefox bug 1559276](https://bugzil.la/1559276 "External link (opens in new tab)")).
*   The `none` value is now invalid in [`counter()`](/en-US/docs/Web/CSS/Reference/Values/counter) / [`counters()`](/en-US/docs/Web/CSS/Reference/Values/counters) — a change which makes the Level 3 spec match CSS 2.1 ([Firefox bug 1576821](https://bugzil.la/1576821 "External link (opens in new tab)")).

### [SVG](#svg)

*   Cut, copy, and paste events are now dispatched to SVG graphics elements ([Firefox bug 1569474](https://bugzil.la/1569474 "External link (opens in new tab)")).

### [MathML](#mathml)

*   The deprecated `mode` attribute on [`<math>`](/en-US/docs/Web/MathML/Reference/Element/math "<math>") elements has been removed ([Firefox bug 1573438](https://bugzil.la/1573438 "External link (opens in new tab)")).
*   Non-zero unitless length values, such as `5` for `500%`, are no longer supported.
*   Length values ending with a dot, such as `2.` or `34.px`, are also unsupported now.

### [JavaScript](#javascript)

*   [Numeric separators](/en-US/docs/Web/JavaScript/Reference/Lexical_grammar#numeric_separators) are now supported ([Firefox bug 1435818](https://bugzil.la/1435818 "External link (opens in new tab)")).
*   The [`Intl.RelativeTimeFormat.formatToParts()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/RelativeTimeFormat/formatToParts) method has been implemented ([Firefox bug 1473229](https://bugzil.la/1473229 "External link (opens in new tab)")).
*   The [`BigInt.prototype.toLocaleString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/BigInt/toLocaleString) method has been updated to work with the `locales` and `options` parameters per the ECMAScript 402 Intl API. Also, [`Intl.NumberFormat.format()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/format) and [`Intl.NumberFormat.formatToParts()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/formatToParts) now accept [`BigInt`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/BigInt) values ([Firefox bug 1543677](https://bugzil.la/1543677 "External link (opens in new tab)")).
*   Per the latest ECMAScript specification, a leading zero is now never allowed for [BigInt literals](/en-US/docs/Web/JavaScript/Reference/Lexical_grammar#bigint_literal), making `08n` and `09n` invalid similar to the existing error when legacy octal numbers like `07n` are used. Always use a leading zero with the letter "o" (lowercase or uppercase) for octal `BigInt` numbers (i.e., `0o755n` instead of `0755n`). See [Firefox bug 1568619](https://bugzil.la/1568619 "External link (opens in new tab)").
*   The Unicode extension key "nu" is now supported for the [`Intl.RelativeTimeFormat`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/RelativeTimeFormat) constructor and the [`Intl.RelativeTimeFormat.resolvedOptions()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/RelativeTimeFormat/resolvedOptions) method now also returns `numberingSystem` ([Firefox bug 1521819](https://bugzil.la/1521819 "External link (opens in new tab)")).

### [APIs](#apis)

#### DOM

*   The [`back()`](/en-US/docs/Web/API/History/back "back()"), [`forward()`](/en-US/docs/Web/API/History/forward "forward()"), and [`go()`](/en-US/docs/Web/API/History/go "go()") methods are now asynchronous. Add a listener to the [`popstate`](/en-US/docs/Web/API/Window/popstate_event "popstate") event to get notification that navigation has completed [Firefox bug 1563587](https://bugzil.la/1563587 "External link (opens in new tab)").
*   We've added support [`DOMMatrix`](/en-US/docs/Web/API/DOMMatrix), [`DOMPoint`](/en-US/docs/Web/API/DOMPoint), etc. in web workers ([Firefox bug 1420580](https://bugzil.la/1420580 "External link (opens in new tab)")).
*   A few more members have been moved from [`HTMLDocument`](/en-US/docs/Web/API/HTMLDocument) to [`Document`](/en-US/docs/Web/API/Document), including [`Document.all`](/en-US/docs/Web/API/Document/all), [`Document.clear`](/en-US/docs/Web/API/Document/clear), `Document.captureEvents`, and [`Document.clear`](/en-US/docs/Web/API/Document/clear) ([Firefox bug 1558570](https://bugzil.la/1558570 "External link (opens in new tab)"), [Firefox bug 1558571](https://bugzil.la/1558571 "External link (opens in new tab)")).
*   [Notification](/en-US/docs/Web/API/Notifications_API) permission can no longer be requested from inside a cross-origin [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) ([Firefox bug 1560741](https://bugzil.la/1560741 "External link (opens in new tab)")).

#### Media, Web Audio, and WebRTC

*   The [`RTCPeerConnection.restartIce()`](/en-US/docs/Web/API/RTCPeerConnection/restartIce) method has been added. This is one of the four changes needed to implement the new "perfect negotiation" mechanism; the rest will come in future Firefox updates ([Firefox bug 1551316](https://bugzil.la/1551316 "External link (opens in new tab)")).
*   The [`RTCPeerConnection.setRemoteDescription()`](/en-US/docs/Web/API/RTCPeerConnection/setRemoteDescription) method can now be called with no parameters. This is another "perfect negotiation" update ([Firefox bug 1568292](https://bugzil.la/1568292 "External link (opens in new tab)")).
*   [`MediaTrackSupportedConstraints.groupId`](/en-US/docs/Web/API/MediaDevices/getSupportedConstraints#groupid) is now supported, and returns `true` since the [`MediaTrackConstraints.groupId`](/en-US/docs/Web/API/MediaTrackConstraints/groupId) property is now supported ([Firefox bug 1561254](https://bugzil.la/1561254 "External link (opens in new tab)")).
*   Several new Web Audio API features have been implemented/updated:
    *   [`AudioContext.getOutputTimestamp()`](/en-US/docs/Web/API/AudioContext/getOutputTimestamp) implemented ([Firefox bug 1324545](https://bugzil.la/1324545 "External link (opens in new tab)")).
    *   [`AudioContext.baseLatency`](/en-US/docs/Web/API/AudioContext/baseLatency) and [`AudioContext.outputLatency`](/en-US/docs/Web/API/AudioContext/outputLatency) implemented ([Firefox bug 1324552](https://bugzil.la/1324552 "External link (opens in new tab)")).
    *   [`MediaElementAudioSourceNode.mediaElement`](/en-US/docs/Web/API/MediaElementAudioSourceNode/mediaElement) and [`MediaStreamAudioSourceNode.mediaStream`](/en-US/docs/Web/API/MediaStreamAudioSourceNode/mediaStream) implemented ([Firefox bug 1350973](https://bugzil.la/1350973 "External link (opens in new tab)")).
    *   The [`ChannelMergerNode()`](/en-US/docs/Web/API/ChannelMergerNode/ChannelMergerNode "ChannelMergerNode()") constructor now throws errors if you try to set `channelCount` and `channelCountMode` to invalid values ([Firefox bug 1456263](https://bugzil.la/1456263 "External link (opens in new tab)")).

#### Canvas and WebGL

*   We now support [`CanvasRenderingContext2D.getTransform()`](/en-US/docs/Web/API/CanvasRenderingContext2D/getTransform), and the newer variant of [`CanvasRenderingContext2D.setTransform()`](/en-US/docs/Web/API/CanvasRenderingContext2D/setTransform) that accepts a matrix object as a parameter rather than multiple parameters representing the individual components of the matrix ([Firefox bug 928150](https://bugzil.la/928150 "External link (opens in new tab)")).

### [HTTP](#http)

*   The default referrer policy for third-party tracking resources is now `strict-origin-when-cross-origin` when [Enhanced Tracking Protection](/en-US/docs/Web/Privacy/Guides/Firefox_tracking_protection) is turned on ([Firefox bug 1569996](https://bugzil.la/1569996 "External link (opens in new tab)")).
*   The size of the [`Referer`](/en-US/docs/Web/HTTP/Reference/Headers/Referer) request header is now limited to 4 KB (4,096 bytes). If an overly long referer exceeds the defined limit, only the origin part will be sent ([Firefox bug 1557346](https://bugzil.la/1557346 "External link (opens in new tab)")).
*   The [HTTP cache](/en-US/docs/Web/HTTP/Guides/Caching) is now partitioned per the top-level document's origin ([Firefox bug 1536058](https://bugzil.la/1536058 "External link (opens in new tab)")).

#### Removals

*   The [`X-Frame-Options`](/en-US/docs/Web/HTTP/Reference/Headers/X-Frame-Options) `allow-from uri` directive has been removed. Use the [`Content-Security-Policy`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy) header with the [`frame-ancestors`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors) directive instead ([Firefox bug 1301529](https://bugzil.la/1301529 "External link (opens in new tab)")).

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

*   Updated the `WebDriver:TakeScreenshot` command to be [Fission](https://wiki.mozilla.org/Project_Fission "External link (opens in new tab)") compatible. It means that content from [cross-origin](/en-US/docs/Web/Security/Defenses/Same-origin_policy) iframes is now included in a page's screenshot. Or when using it from chrome scope that the active tab's content is visible now inside the browser window. ([Firefox bug 1559592](https://bugzil.la/1559592 "External link (opens in new tab)")).
*   `WebDriver:TakeScreenshot` no longer accepts a list of DOM elements as used for highlighting ([Firefox bug 1575511](https://bugzil.la/1575511 "External link (opens in new tab)")).
*   `WebDriver:ExecuteScript` and `WebDriver:ExecuteAsyncScript` no longer sets `window.onunload` in ways that are web-exposed ([Firefox bug 1568991](https://bugzil.la/1568991 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

### [API changes](#api_changes)

*   Added a new parameter to the [`topSites.get()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/topSites/get) method that causes the method to return the list of pages that appear when the user opens a new tab ([Firefox bug 1568617](https://bugzil.la/1568617 "External link (opens in new tab)")).
*   The [`privacy.network`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/privacy/network) property's `webRTCIPHandlingPolicy` sub-property's permitted values have been amended (in [Firefox bug 1452713](https://bugzil.la/1452713 "External link (opens in new tab)")) to match the behavior seen in Chrome as follows:
    *   `disable_non_proxied_udp` previously prevented the use of WebRTC if no proxy was configured. Now a proxy is always used if one is configured, but otherwise a non-proxied connection is permitted.
    *   `proxy_only` can be used to provide the old behavior; this has the effect of only allowing ICE negotiation over TURN on TCP using a proxy; no other connections are allowed.

### [Manifest changes](#manifest_changes)

#### Removals

The following [theme](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/theme) key properties, which provided aliases for theme keys used in chromium-based browsers, were removed:

*   `images` property `headerURL`, themes should now use `theme_frame`.
*   `colors` properties:
    *   `accentcolor`, themes should now use `frame`.
    *   `textcolor`, themes should now use `tab_background_text`.
