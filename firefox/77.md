# Firefox 77 release notes for developers

This article provides information about the changes in Firefox 77 that will affect developers. Firefox 77 was released on [June 2, 2020](https://wiki.mozilla.org/RapidRelease/Calendar "External link (opens in new tab)").

**See also the accompanying hacks post — [New in Firefox 77: DevTool improvements and web platform updates](https://hacks.mozilla.org/2020/06/new-in-firefox-77-devtool-improvements-and-web-platform-updates/ "External link (opens in new tab)").**

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   Firefox Developer Edition offers a [Compatibility panel](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/ui_tour/index.html#compatibility-view "External link (opens in new tab)") in the Page Inspector, to show the browsers supported by the CSS properties used on the page. ([Firefox bug 1625134](https://bugzil.la/1625134 "External link (opens in new tab)"))
    
*   The Debugger has a [Settings menu in its toolbar](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/ui_tour/index.html#toolbar "External link (opens in new tab)"); the only menu option (yet) is **Disable JavaScript**. ([Firefox bug 1630957](https://bugzil.la/1630957 "External link (opens in new tab)"))
    
*   The [Network Monitor toolbar](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/toolbar/index.html "External link (opens in new tab)") has an **Actions** menu for managing log data ([Firefox bug 1459175](https://bugzil.la/1459175 "External link (opens in new tab)")):
    
    *   **Persist Logs**
    *   **Import HAR File**
    *   **Save All as HAR**
    *   **Copy All as HAR**
*   The [Request Blocking panel](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/request_list/index.html#blocking-specific-urls "External link (opens in new tab)") of the Network Monitor has a context menu for enabling, disabling or removing all request block items. ([Firefox bug 1588076](https://bugzil.la/1588076 "External link (opens in new tab)"))
    
*   If you change the selected source line in the Debugger by clicking a frame in the [Call Stack](https://firefox-source-docs.mozilla.org/devtools-user/debugger/ui_tour/index.html#call-stack "External link (opens in new tab)"), and then click **Step over** (`F10`), the debugger executes until reaching the line following the newly-selected line (disregarding whatever line the debugger originally stopped at). ([Firefox bug 1630642](https://bugzil.la/1630642 "External link (opens in new tab)"))
    
*   You can set a watchpoint that pauses execution when a value is [either read or assigned ("get or set")](https://firefox-source-docs.mozilla.org/devtools-user/debugger/how_to/use_watchpoints/index.html#set-a-watchpoint "External link (opens in new tab)"), as well as just read ("get") or just assigned ("set"). ([Firefox bug 1580585](https://bugzil.la/1580585 "External link (opens in new tab)")
    

### [HTML](#html)

*   Firefox now displays the [label value](/en-US/docs/Web/HTML/Reference/Elements/option#browser_compatibility) on an [`<option>`](/en-US/docs/Web/HTML/Reference/Elements/option) element when the element's content is empty. ([Firefox bug 40545](https://bugzil.la/40545 "External link (opens in new tab)"))

### [SVG](#svg)

*   Firefox now supports the [`transform-origin`](/en-US/docs/Web/SVG/Reference/Attribute/transform-origin) presentation attribute ([Firefox bug 1581691](https://bugzil.la/1581691 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   [`String.prototype.replaceAll()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/replaceAll) is now supported ([Firefox bug 1608168](https://bugzil.la/1608168 "External link (opens in new tab)")).

### [APIs](#apis)

#### IndexedDB

*   The [`IDBCursor.request`](/en-US/docs/Web/API/IDBCursor/request) property has been implemented ([Firefox bug 1536540](https://bugzil.la/1536540 "External link (opens in new tab)")).

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

*   Certain commands could have caused a hang of Marionette when the currently selected top-level browsing context gets removed (e.g., closing the window by a click) ([Firefox bug 1619481](https://bugzil.la/1619481 "External link (opens in new tab)")).
*   Known issue: Because of changes in Firefox 77 an open user prompt could be closed too early when navigating away from the current page. This problem will be fixed in Firefox 78 ([Firefox bug 1631362](https://bugzil.la/1631362 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

### [API changes](#api_changes)

*   [`tabs.goBack`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/goBack) and [`tabs.goForward`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/goForward) are now supported. ([Firefox bug 1603796](https://bugzil.la/1603796 "External link (opens in new tab)"))
*   [`browsingData.remove`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browsingData/remove) with type `serviceWorkers` and `indexedDB` now supports deleting by hostname. ([Firefox bug 1632990](https://bugzil.la/1632990 "External link (opens in new tab)") and [Firefox bug 1551301](https://bugzil.la/1551301 "External link (opens in new tab)"))
*   The [`tabs.duplicate`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/duplicate) API now supports `duplicateProperties`, enabling the position and active status of a duplicated tab to be specified. ([Firefox bug 1560218](https://bugzil.la/1560218 "External link (opens in new tab)"))
*   The [`permissions`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/permissions) API events [`permissions.onAdded`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/permissions/onAdded) and [`permissions.onRemoved`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/permissions/onRemoved) are now supported. ([Firefox bug 1444294](https://bugzil.la/1444294 "External link (opens in new tab)"))
*   Multiple `Content-Security-Policy` header changes requested in [`webRequest.onHeadersReceived`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest/onHeadersReceived) are merged. ([Firefox bug 1462989](https://bugzil.la/1462989 "External link (opens in new tab)"))
*   [`webRequest`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest) events will no longer be triggered for `data:` URLs. ([Firefox bug 1631933](https://bugzil.la/1631933 "External link (opens in new tab)"))

### [Manifest changes](#manifest_changes)

*   The following permissions are now optional, they can be specified in the [`optional_permissions`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/optional_permissions) manifest key and requested using the [`permissions`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/permissions) API:
    *   `browsingData` ([Firefox bug 1630417](https://bugzil.la/1630417 "External link (opens in new tab)"))
    *   `devtools` ([Firefox bug 1606862](https://bugzil.la/1606862 "External link (opens in new tab)")) – by setting this permission, an extension can introduce developer tools panels in an update without the extension being disabled (in Chrome) or blocked from updating (in Firefox).
    *   `pkcs11` ([Firefox bug 1630418](https://bugzil.la/1630418 "External link (opens in new tab)"))
    *   `proxy` ([Firefox bug 1548011](https://bugzil.la/1548011 "External link (opens in new tab)"))
    *   `sessions` ([Firefox bug 1630414](https://bugzil.la/1630414 "External link (opens in new tab)")).

### [Other](#other)

*   Use of the `unlimitedStorage` permission no longer results in a prompt during extension installation or update. See [Requesting the right permissions](https://extensionworkshop.com/documentation/develop/request-the-right-permissions/ "External link (opens in new tab)") for more information. ([Firefox bug 1630413](https://bugzil.la/1630413 "External link (opens in new tab)"))
*   Changes related to [`SameSite` cookies](/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie#samesitesamesite-value) mean that when setting [host permissions](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/permissions#host_permissions) to bypass tracking protection for extension pages hosts must be specified as a full domain or with wildcards. However, for Content scripts tracking protection can only be bypassed for hosts specified with a full domain.
