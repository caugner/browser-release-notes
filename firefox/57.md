# Firefox 57 (Quantum) for developers

This article provides information about the changes in Firefox 57 (a.k.a. Firefox Quantum) that will affect developers. Firefox 57 was released on November 14, 2017.

## [Firefox 57 === Firefox Quantum](#firefox_57_firefox_quantum)

Firefox 57 has been given the release name **Quantum**, after the [Firefox Quantum](https://wiki.mozilla.org/Quantum "External link (opens in new tab)") engineering project that has aimed to rebuild Firefox from the ground up, bringing with it major performance, stability, and visual improvements. This is the first version of Firefox to ship some of these improvements, so we wanted to mark the occasion.

**Note:** To read more about the Quantum features in this release, see [Firefox Quantum Developer Edition: the fastest Firefox ever with Photon UI and better tooling](https://hacks.mozilla.org/2017/09/firefox-quantum-developer-edition-fastest-firefox-ever/ "External link (opens in new tab)") by Dan Callahan.

[Firefox's new parallel CSS engine](https://hacks.mozilla.org/2017/08/inside-a-super-fast-css-engine-quantum-css-aka-stylo/ "External link (opens in new tab)") — also known as **Quantum CSS** or **Stylo** — is enabled by default in Firefox 57 for desktop, with Mobile versions of Firefox to follow later on. Developers shouldn't notice anything significantly different, aside from a whole host of performance improvements. There are however a number of minor functional differences in Stylo, implemented to fix non-standard Gecko behavior that should be eliminated. We will report on such differences on reference pages and in the release notes as appropriate (see [Quantum CSS notes](#quantum_css_notes)).

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

_No changes._

### [HTML](#html)

*   The [date](/en-US/docs/Web/HTML/Reference/Elements/input/date) and [time](/en-US/docs/Web/HTML/Reference/Elements/input/time) [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) types are now enabled in all builds ([Firefox bug 1399036](https://bugzil.la/1399036 "External link (opens in new tab)")).

### [CSS](#css)

*   The `minimal-ui` and `standalone` values of the [`display-mode`](/en-US/docs/Web/CSS/Reference/At-rules/@media/display-mode) media query are now supported ([Firefox bug 1369815](https://bugzil.la/1369815 "External link (opens in new tab)")). See also the [Web app manifest `display` field](/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/display).
*   The `grid-row-gap` and `grid-column-gap` properties are no longer reset by the [`grid`](/en-US/docs/Web/CSS/Reference/Properties/grid) shorthand ([Firefox bug 1387410](https://bugzil.la/1387410 "External link (opens in new tab)")).
*   The `layout.css.clip-path-shapes.enabled` preference has been removed ([Firefox bug 1399767](https://bugzil.la/1399767 "External link (opens in new tab)")). This preference allowed disabling the [`<basic-shape>`](/en-US/docs/Web/CSS/Reference/Values/basic-shape) support in [`clip-path`](/en-US/docs/Web/CSS/Reference/Properties/clip-path). This support was shipped in Firefox 54 and can no longer be disabled.

#### Quantum CSS notes

Following bugs have been fixed in Quantum:

*   Radial gradient values like `radial-gradient(circle gold,red)` will work in the old Gecko style system, even though they shouldn't because of the missing comma between `circle` and `gold` ([Firefox bug 1383323](https://bugzil.la/1383323 "External link (opens in new tab)")).
*   When you animate an offscreen element onscreen but specify a delay, Gecko does not repaint on some platforms, e.g., Windows ([Firefox bug 1383239](https://bugzil.la/1383239 "External link (opens in new tab)")).
*   In Gecko, [`<details>`](/en-US/docs/Web/HTML/Reference/Elements/details) elements can't be made open by default using the `open` attribute if they have an [`animation`](/en-US/docs/Web/CSS/Reference/Properties/animation) active on them ([Firefox bug 1382124](https://bugzil.la/1382124 "External link (opens in new tab)")).
*   In Gecko, [`transitions`](/en-US/docs/Web/CSS/Reference/Properties/transition) will not work when transitioning from a [`text-shadow`](/en-US/docs/Web/CSS/Reference/Properties/text-shadow) with a color specified to a `text-shadow` without a color specified ([Firefox bug 726550](https://bugzil.la/726550 "External link (opens in new tab)")).
*   In Gecko, canceling a filling animation (e.g., with `animation-fill-mode: forwards` set) can trigger a transition set on the same element, although only once (see [Firefox bug 1192592](https://bugzil.la/1192592 "External link (opens in new tab)") and [these test cases](https://bug1192592.bmoattachments.org/attachment.cgi?id=8843824 "External link (opens in new tab)") for more information). In general declarative animations should not trigger transitions.
*   Animations using em units are not affected by changes to the [`font-size`](/en-US/docs/Web/CSS/Reference/Properties/font-size) on the animated element's parent in Gecko, whereas they should be ([Firefox bug 1254424](https://bugzil.la/1254424 "External link (opens in new tab)")).
*   Gecko also deals with `font-size` inheritance differently from Quantum CSS, meaning that for some language settings inherited font sizes end up being smaller than expected (see [Firefox bug 1391341](https://bugzil.la/1391341 "External link (opens in new tab)")).
*   Gecko reuses the same mechanism used when parsing a url-token when parsing the `domain()` or `url-prefix()` URL matching functions for a [`@-moz-document`](/en-US/docs/Web/CSS/Reference/At-rules/@document) rule. Quantum CSS does not use the same mechanism and it does not consider tokens invalid when they contain brackets or quotes ([Firefox bug 1362333](https://bugzil.la/1362333 "External link (opens in new tab)")).
*   In Gecko, when you set a system font as the value of a canvas 2D context's [`font`](/en-US/docs/Web/API/CanvasRenderingContext2D/font "font") (e.g., `menu`), getting the font value fails to return the expected font (it returns nothing). This has been fixed in Quantum. ([Firefox bug 1374885](https://bugzil.la/1374885 "External link (opens in new tab)")).
*   In Gecko, when you create a detached subtree (e.g., a [`<div>`](/en-US/docs/Web/HTML/Reference/Elements/div) created using [`createElement()`](/en-US/docs/Web/API/Document/createElement "createElement()") that is not yet inserted into the DOM), the subtree's root element is set as a block-level element. In Quantum CSS this is set as inline, as per spec ([Firefox bug 1374994](https://bugzil.la/1374994 "External link (opens in new tab)")).
*   In Gecko, [`calc()`](/en-US/docs/Web/CSS/Reference/Values/calc) expressions are rejected — causing the value to be invalid — when used as the radius component of a [`radial-gradient()`](/en-US/docs/Web/CSS/Reference/Values/gradient/radial-gradient) function ([Firefox bug 1376019](https://bugzil.la/1376019 "External link (opens in new tab)")).
*   In Gecko, `calc(1*2*3)` is not parsed successfully; Quantum CSS fixes this ([Firefox bug 1379467](https://bugzil.la/1379467 "External link (opens in new tab)")).
*   In Quantum CSS, [`calc()` is supported everywhere that the spec explains it should be](https://drafts.csswg.org/css-values-3/#calc-notation "External link (opens in new tab)") ([Firefox bug 1350857](https://bugzil.la/1350857 "External link (opens in new tab)")). In Gecko it is not.
*   Gecko has a bug whereby the [`::before`](/en-US/docs/Web/CSS/Reference/Selectors/::before) and [`::after`](/en-US/docs/Web/CSS/Reference/Selectors/::after) pseudo-elements are still generated even if the [`content`](/en-US/docs/Web/CSS/Reference/Properties/content) property value is set to `normal` or `none`. As per spec, they shouldn't be ([Firefox bug 1387931](https://bugzil.la/1387931 "External link (opens in new tab)")).
*   Another Gecko bug means that the [`background-position`](/en-US/docs/Web/CSS/Reference/Properties/background-position) property can't be transitioned between two values containing different numbers of [`<position>`](/en-US/docs/Web/CSS/Reference/Values/position_value) values, for example `background-position: 10px 10px;` and `background-position: 20px 20px, 30px 30px;` (see [Firefox bug 1390446](https://bugzil.la/1390446 "External link (opens in new tab)")).

### [SVG](#svg)

_No changes._

### [JavaScript](#javascript)

*   The non-standard [`for each...in`](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#statements_2) loop, originally part of ECMAScript for XML (E4X), has been removed. Please use [`for...of`](/en-US/docs/Web/JavaScript/Reference/Statements/for...of) instead. ([Firefox bug 1083470](https://bugzil.la/1083470 "External link (opens in new tab)")).
*   The [`Object.prototype.watch()` and `Object.prototype.unwatch()`](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#object_2) methods are deprecated, will now throw a warning when used, and will be removed soon ([Firefox bug 934669](https://bugzil.la/934669 "External link (opens in new tab)")).
*   The non-standard `Iterator` and `StopIteration` objects as well as the [legacy iteration protocol](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#legacy_generator_and_iterator) have been removed ([Firefox bug 1098412](https://bugzil.la/1098412 "External link (opens in new tab)")).
*   Async generator is now enabled ([Firefox bug 1352312](https://bugzil.la/1352312 "External link (opens in new tab)")).
*   for await (... of ...) syntax is now enabled ([Firefox bug 1352312](https://bugzil.la/1352312 "External link (opens in new tab)")).

### [APIs](#apis)

#### New APIs

*   The [`PerformanceObserver`](/en-US/docs/Web/API/PerformanceObserver) API is now enabled by default ([Firefox bug 1386021](https://bugzil.la/1386021 "External link (opens in new tab)")).
*   The [`AbortController`](/en-US/docs/Web/API/AbortController) and [`AbortSignal`](/en-US/docs/Web/API/AbortSignal) interfaces (known as the Abort API) have been added, allowing DOM requests (such as [fetch requests](/en-US/docs/Web/API/Window/fetch)) to be aborted if desired ([Firefox bug 1378342](https://bugzil.la/1378342 "External link (opens in new tab)")).
*   \[2\] The [Storage API](/en-US/docs/Web/API/Storage_API) is implemented and enabled by default ([Firefox bug 1399038](https://bugzil.la/1399038 "External link (opens in new tab)")).

#### DOM

*   The [`Selection.type`](/en-US/docs/Web/API/Selection/type) property of the [Selection API](/en-US/docs/Web/API/Selection) is now implemented ([Firefox bug 1359157](https://bugzil.la/1359157 "External link (opens in new tab)")).
*   [`Document.createEvent('FocusEvent')`](/en-US/docs/Web/API/Document/createEvent "Document.createEvent('FocusEvent')") is now supported ([Firefox bug 1388069](https://bugzil.la/1388069 "External link (opens in new tab)")).
*   The `files` property of the [`HTMLInputElement`](/en-US/docs/Web/API/HTMLInputElement) interface is now settable ([Firefox bug 1384030](https://bugzil.la/1384030 "External link (opens in new tab)")).
*   The `HTMLDocument.getSelection()` method has been moved to the [`Document`](/en-US/docs/Web/API/Document/getSelection "Document") interface so it is available to XML documents ([Firefox bug 718711](https://bugzil.la/718711 "External link (opens in new tab)")).
*   The `messageerror` event is now implemented, and can have code run in response to it firing via event handlers implemented on message targets — see the `messageerror` event of [`MessagePort`](/en-US/docs/Web/API/MessagePort/messageerror_event "MessagePort"), [`DedicatedWorkerGlobalScope`](/en-US/docs/Web/API/DedicatedWorkerGlobalScope/messageerror_event "DedicatedWorkerGlobalScope"), [`Worker`](/en-US/docs/Web/API/Worker/messageerror_event "Worker"), [`BroadcastChannel`](/en-US/docs/Web/API/BroadcastChannel/messageerror_event "BroadcastChannel"), and [`Window`](/en-US/docs/Web/API/Window/messageerror_event "Window") ([Firefox bug 1359017](https://bugzil.la/1359017 "External link (opens in new tab)")).
*   When [`Headers`](/en-US/docs/Web/API/Headers) values are iterated over, they are automatically sorted in lexicographical order, and values from duplicate header names are combined ([Firefox bug 1396848](https://bugzil.la/1396848 "External link (opens in new tab)")).

#### DOM events

_No changes._

#### Media and WebRTC

*   Support for messages of arbitrary size (up to 1GiB, although 256kiB is more interoperable) is now supported on [`RTCDataChannel`](/en-US/docs/Web/API/RTCDataChannel) through use of the end-of-record (EOR) flag on SCTP messages. See [Understanding message size limits](/en-US/docs/Web/API/WebRTC_API/Using_data_channels#understanding_message_size_limits) for more information ([Firefox bug 979417](https://bugzil.la/979417 "External link (opens in new tab)")).
    
    **Note:** Because Firefox doesn't yet support the SCTP Stream Schedulers and User Message Interleaving protocol that provides the ability to interleave SCTP messages from multiple sources, sending large data objects can cause significant delays on all other SCTP traffic. See [Firefox bug 1381145](https://bugzil.la/1381145 "External link (opens in new tab)") to track progress on implementing and deploying stream schedulers support in Firefox.
    
*   The [`RTCDataChannel.send()`](/en-US/docs/Web/API/RTCDataChannel/send) method can now throw a `TypeError` exception if the size of the message you're trying to send is not compatible with the receiving [user agent](/en-US/docs/Glossary/User_agent) (this is implemented as part of [Firefox bug 979417](https://bugzil.la/979417 "External link (opens in new tab)")).
    
*   The [MediaStream Recording API](/en-US/docs/Web/API/MediaStream_Recording_API) has been updated so that [`error`](/en-US/docs/Web/API/MediaRecorder/error_event "error") events sent to report problems that occur while recording are now of type [`MediaRecorderErrorEvent`](/en-US/docs/Web/API/MediaRecorderErrorEvent) rather than being generic events.
    
*   Updated the documentation around [`OfflineAudioContext`](/en-US/docs/Web/API/OfflineAudioContext) since its constructor's inputs can now be specified in an object rather than as a list of parameters ([Firefox bug 1388591](https://bugzil.la/1388591 "External link (opens in new tab)")).
    
*   The Web Audio API now properly supports multi-channel output ([Firefox bug 1378070](https://bugzil.la/1378070 "External link (opens in new tab)")).
    

### [Security](#security)

*   `resource://` URLs no longer leak information ([Firefox bug 863246](https://bugzil.la/863246 "External link (opens in new tab)"))
*   Data URLs are now treated as unique opaque origins, rather than inheriting the origin of the settings object responsible for the navigation ([Firefox bug 1324406](https://bugzil.la/1324406 "External link (opens in new tab)")).

### [Plugins](#plugins)

_No changes._

### [Other](#other)

*   Firefox [headless mode](https://web.archive.org/web/20210604151145/https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Headless_mode "External link (opens in new tab)") now includes a `-screenshot` flag that allows you to take website screenshots directly from the command line ([Firefox bug 1378010](https://bugzil.la/1378010 "External link (opens in new tab)")).

## [Removals from the web platform](#removals_from_the_web_platform)

### [HTML](#html_2)

*   `<link rel="preload">` (see [Preloading content with rel="preload"](/en-US/docs/Web/HTML/Reference/Attributes/rel/preload)) has been disabled in Firefox 57 because of various web compatibility issues (e.g., [Firefox bug 1405761](https://bugzil.la/1405761 "External link (opens in new tab)")). An improved version that works for non-cacheable resources is expected to land in Firefox 58.

### [APIs](#apis_2)

*   Mozilla's proprietary [Social API](https://web.archive.org/web/20210509145412/https://developer.mozilla.org/en-US/docs/Archive/Social_API "External link (opens in new tab)") has been completely removed ([Firefox bug 1388902](https://bugzil.la/1388902 "External link (opens in new tab)")).

### [SVG](#svg_2)

_No changes._

## [Changes for add-on and Mozilla developers](#changes_for_add-on_and_mozilla_developers)

**Note:** Starting in Firefox 57, all support for XPCOM-based add-ons has been removed. All extensions must be converted into the new [browser extensions](/en-US/docs/Mozilla/Add-ons/WebExtensions) (also known as WebExtensions) or they will not work.
