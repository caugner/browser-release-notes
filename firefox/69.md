# Firefox 69 release notes for developers

This article provides information about the changes in Firefox 69 that will affect developers. Firefox 69 was released on September 3, 2019.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

#### Debugger

*   [Event Listener Breakpoints](https://firefox-source-docs.mozilla.org/devtools-user/debugger/set_event_listener_breakpoints/index.html "External link (opens in new tab)") let you diagnose which code a page executes in response to browser events. You can pick specific types, such as `click` or `keydown`, or whole categories of events, like all mouse input events. ([Firefox bug 1526082](https://bugzil.la/1526082 "External link (opens in new tab)")).
*   Scripts shown in the debugger's [source list pane](https://firefox-source-docs.mozilla.org/devtools-user/debugger/ui_tour/index.html#source-list-pane "External link (opens in new tab)") can now be saved via the _Download file_ context menu option ([Firefox bug 888161](https://bugzil.la/888161 "External link (opens in new tab)")).
*   In the debugger's source list pane, loaded extensions are listed with their name, rather than just their [UUID](/en-US/docs/Glossary/UUID) ([Firefox bug 1486416](https://bugzil.la/1486416 "External link (opens in new tab)")), making it much easier to find the extension code you want to debug.
*   The debugger now loads significantly faster via lazy-loading scripts ([Firefox bug 1527488](https://bugzil.la/1527488 "External link (opens in new tab)")).

#### Console

*   [Browser Console](https://firefox-source-docs.mozilla.org/devtools-user/browser_console/index.html "External link (opens in new tab)") messages from [tracking protection errors](/en-US/docs/Web/Privacy/Guides/Firefox_tracking_protection), [CSP errors](/en-US/docs/Web/HTTP/Guides/CSP), and [CORS errors](/en-US/docs/Web/HTTP/Guides/CORS/Errors) are grouped automatically to reduce noise from repeated blocked resources and storage access ([Firefox bug 1522396](https://bugzil.la/1522396 "External link (opens in new tab)")).
*   All visible logs in the console can be shared by saving to a file or copying to clipboard via a new _Export visible messages to_ context menu item ([Firefox bug 1517728](https://bugzil.la/1517728 "External link (opens in new tab)")).
*   The console's toolbar now responsively reduces its height into a single row to save vertical space ([Firefox bug 972530](https://bugzil.la/972530 "External link (opens in new tab)")).
*   Messages from content can now be hidden in the console to focus on logs from the Firefox UI ([Firefox bug 1523842](https://bugzil.la/1523842 "External link (opens in new tab)")).

#### Network

*   Resources that got blocked because of [CSP](/en-US/docs/Web/HTTP/Guides/CSP) or [Mixed Content](/en-US/docs/Web/Security/Defenses/Mixed_content) are now shown in the Network panel, with details of the reason ([Firefox bug 1556451](https://bugzil.la/1556451 "External link (opens in new tab)")).
*   A new optional _URL_ column in the Network panel can be enabled to show the full URL for resources ([Firefox bug 1341155](https://bugzil.la/1341155 "External link (opens in new tab)")).

#### Inspector

*   When you hover over an element in the [Page Inspector](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/index.html "External link (opens in new tab)"), the infobar that appears now includes the fact that an element is a flex container, or flex item ([Firefox bug 1521188](https://bugzil.la/1521188 "External link (opens in new tab)")).
*   When inspecting a page containing a grid with a subgrid, the parent grid's overlay lines are displayed whenever the subgrid's lines are displayed; if the parent grid's overlay checkbox is unselected, then its lines are translucent ([Firefox bug 1550519](https://bugzil.la/1550519 "External link (opens in new tab)")).

#### Remote debugging

*   For our mobile web developers, we have migrated remote debugging from the old WebIDE into a re-designed [about:debugging](https://firefox-source-docs.mozilla.org/devtools-user/about_colon_debugging/index.html "External link (opens in new tab)"), making the experience of debugging [GeckoView](https://hacks.mozilla.org/2019/06/geckoview-in-2019/ "External link (opens in new tab)") on remote devices via USB much better ([Firefox bug 1462208](https://bugzil.la/1462208 "External link (opens in new tab)")).

#### General

*   The DevTools panel order has been changed to reflect popularity ([Firefox bug 1558630](https://bugzil.la/1558630 "External link (opens in new tab)")).

### [HTML](#html)

*   In order to align more closely to the specification, the text track associated with a [`<track>`](/en-US/docs/Web/HTML/Reference/Elements/track) element no longer loads the WebVTT file containing the text cues if the element is created in its default `disabled` [`mode`](/en-US/docs/Web/API/TextTrack/mode "mode"). To access or manipulate the cues when the `mode` is `disabled`, change the `mode` to either `started` or `hidden`; this will trigger loading of the WebVTT data ([Firefox bug 1550633](https://bugzil.la/1550633 "External link (opens in new tab)")).

#### Removals

*   The HTML `<keygen>` element has been removed from Firefox. It was deprecated some time ago, and its purpose has generally been supplanted by other technologies ([Firefox bug 1315460](https://bugzil.la/1315460 "External link (opens in new tab)")).

### [CSS](#css)

*   We implemented the `break-spaces` value of the [`white-space`](/en-US/docs/Web/CSS/Reference/Properties/white-space) property ([Firefox bug 1351432](https://bugzil.la/1351432 "External link (opens in new tab)")).
*   The SVG geometry attributes (such as [`width`](/en-US/docs/Web/SVG/Reference/Attribute/width) and [`height`](/en-US/docs/Web/SVG/Reference/Attribute/height)) can now also be defined as CSS properties ([Firefox bug 1383650](https://bugzil.la/1383650 "External link (opens in new tab)")).
*   The [`::cue`](/en-US/docs/Web/CSS/Reference/Selectors/::cue) selector — used to style the captions ("cues") displayed by [WebVTT](/en-US/docs/Web/API/WebVTT_API) — now enforces the limitations on which CSS properties may be used within cues, as per the specification ([Firefox bug 1321488](https://bugzil.la/1321488 "External link (opens in new tab)")).
*   We've restricted the properties that may apply to [`::marker`](/en-US/docs/Web/CSS/Reference/Selectors/::marker) as per the specification ([Firefox bug 1552578](https://bugzil.la/1552578 "External link (opens in new tab)"))
*   The [`overflow-block`](/en-US/docs/Web/CSS/Reference/Properties/overflow-block) and [`overflow-inline`](/en-US/docs/Web/CSS/Reference/Properties/overflow-inline) properties have been implemented ([Firefox bug 1470695](https://bugzil.la/1470695 "External link (opens in new tab)")).
*   We added the ability to test for support of a selector when using CSS Feature Queries ([`@supports`](/en-US/docs/Web/CSS/Reference/At-rules/@supports)), with the `selector()` method ([Firefox bug 1513643](https://bugzil.la/1513643 "External link (opens in new tab)")).
*   The [`user-select`](/en-US/docs/Web/CSS/Reference/Properties/user-select) property — which specifies whether or not the user is able to select text in the affected element — has been unprefixed ([Firefox bug 1492739](https://bugzil.la/1492739 "External link (opens in new tab)")).
*   We implemented local-specific casing behavior for Lithuanian ([Firefox bug 1322992](https://bugzil.la/1322992 "External link (opens in new tab)")), [as seen in this example](/en-US/docs/Web/CSS/Reference/Properties/text-transform#example_using_lowercase_lithuanian).
*   We've implemented the [`line-break`](/en-US/docs/Web/CSS/Reference/Properties/line-break) property of CSS Text ([Firefox bug 1011369](https://bugzil.la/1011369 "External link (opens in new tab)") and [Firefox bug 1531715](https://bugzil.la/1531715 "External link (opens in new tab)")).
*   The [`contain`](/en-US/docs/Web/CSS/Reference/Properties/contain) property — which allows developers to define that an element and its contents are mostly independent of the rest of the DOM tree — got implemented [Firefox bug 1487493](https://bugzil.la/1487493 "External link (opens in new tab)").

### [SVG](#svg)

*   We've added support for gzip-compressed SVG-in-OpenType ([Firefox bug 1359240](https://bugzil.la/1359240 "External link (opens in new tab)")).
*   The [`SVGGeometryElement.isPointInFill()`](/en-US/docs/Web/API/SVGGeometryElement/isPointInFill) and [`SVGGeometryElement.isPointInStroke()`](/en-US/docs/Web/API/SVGGeometryElement/isPointInStroke) methods have been implemented ([Firefox bug 1325319](https://bugzil.la/1325319 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   [Public class fields](/en-US/docs/Web/JavaScript/Reference/Classes#field_declarations) are enabled by default ([Firefox bug 1555464](https://bugzil.la/1555464 "External link (opens in new tab)")). See also [Class fields](/en-US/docs/Web/JavaScript/Reference/Classes/Public_class_fields) for more information.
*   The promise rejection events [`unhandledrejection`](/en-US/docs/Web/API/Window/unhandledrejection_event) and [`rejectionhandled`](/en-US/docs/Web/API/Window/rejectionhandled_event) are now enabled by default ([Firefox bug 1362272](https://bugzil.la/1362272 "External link (opens in new tab)")). To learn more about how these work, see [Promise rejection events](/en-US/docs/Web/JavaScript/Guide/Using_promises#promise_rejection_events).

### [HTTP](#http)

*   The HTTP headers [`Access-Control-Expose-Headers`](/en-US/docs/Web/HTTP/Reference/Headers/Access-Control-Expose-Headers), [`Access-Control-Allow-Methods`](/en-US/docs/Web/HTTP/Reference/Headers/Access-Control-Allow-Methods), and [`Access-Control-Allow-Headers`](/en-US/docs/Web/HTTP/Reference/Headers/Access-Control-Allow-Headers) now accept a wildcard value `*` for requests without credentials ([Firefox bug 1309358](https://bugzil.la/1309358 "External link (opens in new tab)")). This change has also been uplifted to Firefox 68 ESR.

### [APIs](#apis)

#### New APIs

*   The [Resize Observer API](/en-US/docs/Web/API/Resize_Observer_API) is supported by default ([Firefox bug 1543839](https://bugzil.la/1543839 "External link (opens in new tab)")).
*   The Microtask API ([`Window.queueMicrotask()`](/en-US/docs/Web/API/Window/queueMicrotask) and [`WorkerGlobalScope.queueMicrotask()`](/en-US/docs/Web/API/WorkerGlobalScope/queueMicrotask)) has been implemented ([Firefox bug 1480236](https://bugzil.la/1480236 "External link (opens in new tab)")).

#### DOM

*   The [`DOMMatrix`](/en-US/docs/Web/API/DOMMatrix), [`DOMPoint`](/en-US/docs/Web/API/DOMPoint), and related objects are now supported in workers ([Firefox bug 1420580](https://bugzil.la/1420580 "External link (opens in new tab)")).
*   The `pageX` and `pageY` properties have been moved from [`UIEvent`](/en-US/docs/Web/API/UIEvent) to [`MouseEvent`](/en-US/docs/Web/API/MouseEvent), for better spec compliance ([Firefox bug 1178763](https://bugzil.la/1178763 "External link (opens in new tab)")). These properties are no longer exposed to the [`CompositionEvent`](/en-US/docs/Web/API/CompositionEvent), [`FocusEvent`](/en-US/docs/Web/API/FocusEvent), [`InputEvent`](/en-US/docs/Web/API/InputEvent), [`KeyboardEvent`](/en-US/docs/Web/API/KeyboardEvent), and [`TouchEvent`](/en-US/docs/Web/API/TouchEvent) interfaces, which all inherit from `UIEvent`.
*   The [`Blob.text()`](/en-US/docs/Web/API/Blob/text), [`Blob.arrayBuffer()`](/en-US/docs/Web/API/Blob/arrayBuffer), and [`Blob.stream()`](/en-US/docs/Web/API/Blob/stream) methods are now implemented ([Firefox bug 1557121](https://bugzil.la/1557121 "External link (opens in new tab)")).
*   `DOMMatrixReadOnly.fromMatrix()` has been implemented ([Firefox bug 1560462](https://bugzil.la/1560462 "External link (opens in new tab)")).
*   We now support the six-parameter version of the [`DOMMatrixReadOnly.scale()`](/en-US/docs/Web/API/DOMMatrixReadOnly/scale) method ([Firefox bug 1397945](https://bugzil.la/1397945 "External link (opens in new tab)")).
*   The arguments for [`DOMMatrixReadOnly.translate()`](/en-US/docs/Web/API/DOMMatrixReadOnly/translate), [`DOMMatrixReadOnly.skewX()`](/en-US/docs/Web/API/DOMMatrixReadOnly/skewX), and [`DOMMatrixReadOnly.skewY()`](/en-US/docs/Web/API/DOMMatrixReadOnly/skewY) are now all optional, as per spec ([Firefox bug 1397949](https://bugzil.la/1397949 "External link (opens in new tab)")).
*   The [`Navigator.userAgent`](/en-US/docs/Web/API/Navigator/userAgent), [`Navigator.platform`](/en-US/docs/Web/API/Navigator/platform), and [`Navigator.oscpu`](/en-US/docs/Web/API/Navigator/oscpu) properties no longer reveal whether a user is running 32-bit Firefox on a 64-bit OS ([Firefox bug 1559747](https://bugzil.la/1559747 "External link (opens in new tab)")). They now say `Linux x86_64` instead of `Linux i686 on x86_64`, and `Win64` instead of `WOW64`.
*   The remaining methods of [`HTMLDocument`](/en-US/docs/Web/API/HTMLDocument) have been moved to [`Document`](/en-US/docs/Web/API/Document). This should have no appreciable impact on your work in most cases. In particular, the [`close()`](/en-US/docs/Web/API/Document/close "close()"), [`open()`](/en-US/docs/Web/API/Document/open "open()"), and [`write()`](/en-US/docs/Web/API/Document/write "write()") methods have been moved. So have the various editor related methods, including [`execCommand()`](/en-US/docs/Web/API/Document/execCommand "execCommand()") as well as various properties ([Firefox bug 1549560](https://bugzil.la/1549560 "External link (opens in new tab)")).
*   We have implemented [`AbstractRange`](/en-US/docs/Web/API/AbstractRange) and [`StaticRange`](/en-US/docs/Web/API/StaticRange) ([Firefox bug 1444847](https://bugzil.la/1444847 "External link (opens in new tab)")).

#### Media, Web Audio, and WebRTC

*   For improved user security, and in-keeping with the latest versions of the [Media Capture and Streams](/en-US/docs/Web/API/Media_Capture_and_Streams_API) specification, the [`navigator.mediaDevices`](/en-US/docs/Web/API/Navigator/mediaDevices) property is no longer present if the context is insecure. To use [`getUserMedia()`](/en-US/docs/Web/API/MediaDevices/getUserMedia "getUserMedia()"), [`getDisplayMedia()`](/en-US/docs/Web/API/MediaDevices/getDisplayMedia "getDisplayMedia()"), [`enumerateDevices()`](/en-US/docs/Web/API/MediaDevices/enumerateDevices "enumerateDevices()"), and so forth, be sure your content is loaded using [HTTPS](/en-US/docs/Glossary/HTTPS) ([Firefox bug 1528031](https://bugzil.la/1528031 "External link (opens in new tab)")).
*   The Web Audio API's [`AudioParam.value`](/en-US/docs/Web/API/AudioParam/value) property now returns the actual value of the property at the current time, taking into account all scheduled or graduated value changes. Previously, Firefox only returned the most recent explicitly-set value (as through using the `value` setter) ([Firefox bug 893020](https://bugzil.la/893020 "External link (opens in new tab)")).
*   We've updated [`MediaStreamAudioSourceNode`](/en-US/docs/Web/API/MediaStreamAudioSourceNode) to use the new, lexicographical, ordering for tracks. Previously, track ordering was up to the individual browser, and could even change arbitrarily. In addition, attempting to create a `MediaStreamAudioSourceNode` using a stream that has no audio tracks now throws an `InvalidStateError` exception ([Firefox bug 1553215](https://bugzil.la/1553215 "External link (opens in new tab)")).
*   The [`facingMode`](/en-US/docs/Web/API/MediaStreamTrack/getSettings#facingmode), [`deviceId`](/en-US/docs/Web/API/MediaStreamTrack/getSettings#deviceid), and [`groupId`](/en-US/docs/Web/API/MediaStreamTrack/getSettings#groupid) settings are now included as members of the object returned by calls to [`MediaStreamTrack.getSettings()`](/en-US/docs/Web/API/MediaStreamTrack/getSettings) ([Firefox bug 1537986](https://bugzil.la/1537986 "External link (opens in new tab)")).

#### Removals

*   The `DOMMatrix.scaleNonUniformSelf()` method has been removed ([Firefox bug 1560119](https://bugzil.la/1560119 "External link (opens in new tab)")).

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

#### Other

*   Marionette now dynamically handles the opening and closing of modal dialogs and user prompts ([Firefox bug 1477977](https://bugzil.la/1477977 "External link (opens in new tab)")), which also means that multiple open prompts will be handled ([Firefox bug 1487358](https://bugzil.la/1487358 "External link (opens in new tab)")).
*   Tracking protection and DOM push features are now disabled by default to avoid the removal of parts of the DOM, and extra notifications ([Firefox bug 1542244](https://bugzil.la/1542244 "External link (opens in new tab)")).
*   Automatic unloading of background tabs if Firefox runs into a low memory condition is now disabled — this badly interacts with automation when switching between tabs ([Firefox bug 1553748](https://bugzil.la/1553748 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

### [API changes](#api_changes)

*   The [UserScripts API](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/userScripts) is now enabled by default.
*   The [`topSites.get()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/topSites/get) method now has new options available — `includePinned` and `includeSearchShortcuts` ([Firefox bug 1547669](https://bugzil.la/1547669 "External link (opens in new tab)")).

### [Other changes](#other_changes)

*   There are now [Group Policy options](https://github.com/mozilla/policy-templates/blob/master/README.md#extensionsettings "External link (opens in new tab)") to blacklist all extensions except the ones that have been whitelisted ([Firefox bug 1522823](https://bugzil.la/1522823 "External link (opens in new tab)")).
