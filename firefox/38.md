# Firefox 38 release notes for developers

Firefox 38 was released on May 12th, 2015. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

*   [Highlight and filter XmlHttpRequests in Web Console](https://firefox-source-docs.mozilla.org/devtools-user/web_console/index.html#xhr "External link (opens in new tab)")

### [CSS](#css)

*   Support for [`ruby-position`](/en-US/docs/Web/CSS/Reference/Properties/ruby-position) and [`ruby-align`](/en-US/docs/Web/CSS/Reference/Properties/ruby-align) have been added and is available by default ([Firefox bug 1055676](https://bugzil.la/1055676 "External link (opens in new tab)") [Firefox bug 1123917](https://bugzil.la/1123917 "External link (opens in new tab)") and [Firefox bug 1039006](https://bugzil.la/1039006 "External link (opens in new tab)")).
    
*   The `:unresolved` pseudo-class has been implemented for custom elements ([Firefox bug 1111633](https://bugzil.la/1111633 "External link (opens in new tab)")).
    
*   The predefined style [`ethiopic-numeric`](/en-US/docs/Web/CSS/Reference/Properties/list-style-type) now uses a space, instead of a dot, as the suffix to match a recent change to the spec ([Firefox bug 1120721](https://bugzil.la/1120721 "External link (opens in new tab)")).
    
*   CSS transitions on generated content (with [`::before`](/en-US/docs/Web/CSS/Reference/Selectors/::before) and [`::after`](/en-US/docs/Web/CSS/Reference/Selectors/::after)) on both an inline and the block that splits them now start as expected by the specification ([Firefox bug 1110277](https://bugzil.la/1110277 "External link (opens in new tab)")).
    
*   The implementation of CSS Logical Properties made big progress. The following properties are available behind the `layout.css.vertical-text.enabled` flag (`false` by default):
    
    *   Direction-independent equivalents of [`width`](/en-US/docs/Web/CSS/Reference/Properties/width) and [`height`](/en-US/docs/Web/CSS/Reference/Properties/height): [`block-size`](/en-US/docs/Web/CSS/Reference/Properties/block-size) and [`inline-size`](/en-US/docs/Web/CSS/Reference/Properties/inline-size) ([Firefox bug 1117983](https://bugzil.la/1117983 "External link (opens in new tab)")).
    *   Direction-independent equivalents of [`min-width`](/en-US/docs/Web/CSS/Reference/Properties/min-width) and [`min-height`](/en-US/docs/Web/CSS/Reference/Properties/min-height): [`min-block-size`](/en-US/docs/Web/CSS/Reference/Properties/min-block-size) and [`min-inline-size`](/en-US/docs/Web/CSS/Reference/Properties/min-inline-size) ([Firefox bug 1117983](https://bugzil.la/1117983 "External link (opens in new tab)")).
    *   Direction-independent equivalents of [`max-width`](/en-US/docs/Web/CSS/Reference/Properties/max-width) and [`max-height`](/en-US/docs/Web/CSS/Reference/Properties/max-height): [`max-block-size`](/en-US/docs/Web/CSS/Reference/Properties/max-block-size) and [`max-block-size`](/en-US/docs/Web/CSS/Reference/Properties/max-block-size) ([Firefox bug 1117983](https://bugzil.la/1117983 "External link (opens in new tab)")).
    *   Direction-independent equivalents of [`margin-top`](/en-US/docs/Web/CSS/Reference/Properties/margin-top), [`margin-right`](/en-US/docs/Web/CSS/Reference/Properties/margin-right), [`margin-bottom`](/en-US/docs/Web/CSS/Reference/Properties/margin-bottom) and [`margin-left`](/en-US/docs/Web/CSS/Reference/Properties/margin-left): [`margin-block-start`](/en-US/docs/Web/CSS/Reference/Properties/margin-block-start), [`margin-block-end`](/en-US/docs/Web/CSS/Reference/Properties/margin-block-end), [`margin-inline-start`](/en-US/docs/Web/CSS/Reference/Properties/margin-inline-start) and [`margin-inline-end`](/en-US/docs/Web/CSS/Reference/Properties/margin-inline-end) ([Firefox bug 649142](https://bugzil.la/649142 "External link (opens in new tab)")).
    *   Direction-independent equivalents of [`padding-top`](/en-US/docs/Web/CSS/Reference/Properties/padding-top), [`padding-right`](/en-US/docs/Web/CSS/Reference/Properties/padding-right), [`padding-bottom`](/en-US/docs/Web/CSS/Reference/Properties/padding-bottom) and [`padding-left`](/en-US/docs/Web/CSS/Reference/Properties/padding-left): [`padding-block-start`](/en-US/docs/Web/CSS/Reference/Properties/padding-block-start), [`padding-block-end`](/en-US/docs/Web/CSS/Reference/Properties/padding-block-end), [`padding-inline-start`](/en-US/docs/Web/CSS/Reference/Properties/padding-inline-start) and [`padding-inline-end`](/en-US/docs/Web/CSS/Reference/Properties/padding-inline-end) ([Firefox bug 649142](https://bugzil.la/649142 "External link (opens in new tab)")).
    *   Direction-independent equivalents of [`border-top`](/en-US/docs/Web/CSS/Reference/Properties/border-top), [`border-right`](/en-US/docs/Web/CSS/Reference/Properties/border-right), [`border-bottom`](/en-US/docs/Web/CSS/Reference/Properties/border-bottom) and [`border-left`](/en-US/docs/Web/CSS/Reference/Properties/border-left) and their longhands for width, style and color: [`border-block-start`](/en-US/docs/Web/CSS/Reference/Properties/border-block-start), [`border-block-start-width`](/en-US/docs/Web/CSS/Reference/Properties/border-block-start-width), [`border-block-start-style`](/en-US/docs/Web/CSS/Reference/Properties/border-block-start-style), [`border-block-start-color`](/en-US/docs/Web/CSS/Reference/Properties/border-block-start-color), [`border-block-end`](/en-US/docs/Web/CSS/Reference/Properties/border-block-end), [`border-block-end-width`](/en-US/docs/Web/CSS/Reference/Properties/border-block-end-width), [`border-block-end-style`](/en-US/docs/Web/CSS/Reference/Properties/border-block-end-style), [`border-block-end-color`](/en-US/docs/Web/CSS/Reference/Properties/border-block-end-color), [`border-inline-start`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-start), [`border-inline-start-width`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-start-width), [`border-inline-start-style`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-start-style), [`border-inline-start-color`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-start-color), [`border-inline-end`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-end), [`border-inline-end-width`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-end-width), [`border-inline-end-style`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-end-style) and [`border-inline-end-color`](/en-US/docs/Web/CSS/Reference/Properties/border-inline-end-color) ([Firefox bug 649142](https://bugzil.la/649142 "External link (opens in new tab)")).
    *   Direction-independent equivalents of [`top`](/en-US/docs/Web/CSS/Reference/Properties/top), [`right`](/en-US/docs/Web/CSS/Reference/Properties/right), [`bottom`](/en-US/docs/Web/CSS/Reference/Properties/bottom) and [`left`](/en-US/docs/Web/CSS/Reference/Properties/left): [`inset-block-start`](/en-US/docs/Web/CSS/Reference/Properties/inset-block-start), `offset-block-end`, `offset-inline-start` and `offset-inline-end` ([Firefox bug 1120283](https://bugzil.la/1120283 "External link (opens in new tab)")).
*   How [CSS transitions](/en-US/docs/Web/CSS/Guides/Transitions/Using) start has been modified to match a recent change of the specifications, aiming at having an interoperable behavior between browsers ([Firefox bug 960465](https://bugzil.la/960465 "External link (opens in new tab)")).
    

### [HTML](#html)

*   The [`<label>`](/en-US/docs/Web/HTML/Reference/Elements/label) element no longer dispatches events to the label target element if interactive content is found between the event target and the label ([Firefox bug 229925](https://bugzil.la/229925 "External link (opens in new tab)")).
*   The [`<picture>`](/en-US/docs/Web/HTML/Reference/Elements/picture) element has been activated by default ([Firefox bug 1017875](https://bugzil.la/1017875 "External link (opens in new tab)")).
*   The `<meta name="referrer">` is supported for navigations from the context menu or via a middle-click ([Firefox bug 1113431](https://bugzil.la/1113431 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   [`Generator.prototype.return()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Generator/return) is implemented ([Firefox bug 1115868](https://bugzil.la/1115868 "External link (opens in new tab)")).
    
*   [`Setter`](/en-US/docs/Web/JavaScript/Reference/Functions/set) with a [rest parameter](/en-US/docs/Web/JavaScript/Reference/Functions/rest_parameters) is now a [`SyntaxError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/SyntaxError) ([Firefox bug 1089632](https://bugzil.la/1089632 "External link (opens in new tab)")).
    
*   The [`name`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/name) property of functions is configurable now ([Firefox bug 1084019](https://bugzil.la/1084019 "External link (opens in new tab)")).
    
*   Several [`Array`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array) methods have been implemented for [typed arrays](/en-US/docs/Web/JavaScript/Guide/Typed_arrays) as well:
    
    *   The [`of()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/of) and [`from()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/from) methods ([Firefox bug 896608](https://bugzil.la/896608 "External link (opens in new tab)")).
    *   The [`forEach()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/forEach) method ([Firefox bug 1107645](https://bugzil.la/1107645 "External link (opens in new tab)")).
    *   The [`filter()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/filter) and [`map()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/map) methods ([Firefox bug 1121936](https://bugzil.la/1121936 "External link (opens in new tab)")).
    *   The [`slice()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/slice) method ([Firefox bug 1121935](https://bugzil.la/1121935 "External link (opens in new tab)")).
*   Duplicated parameter name is no longer allowed when rest-parameter is present ([Firefox bug 1096376](https://bugzil.la/1096376 "External link (opens in new tab)")).
    
*   Duplicated parameter name is no longer allowed in arrow functions ([Firefox bug 1096377](https://bugzil.la/1096377 "External link (opens in new tab)")).
    
*   Duplicated parameter name is no longer allowed in concise method definitions ([Firefox bug 1096378](https://bugzil.la/1096378 "External link (opens in new tab)")).
    
*   Warning is shown when [`Map`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map)/[`Set`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set)/[`WeakMap`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap) constructor is called without [`new`](/en-US/docs/Web/JavaScript/Reference/Operators/new) ([Firefox bug 1108930](https://bugzil.la/1108930 "External link (opens in new tab)")).
    
*   The [`get`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap/get), [`has`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap/has), and [`delete`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap/delete) methods of [`WeakMap`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap) objects no longer throw when the `key` parameter is not an object ([Firefox bug 1127827](https://bugzil.la/1127827 "External link (opens in new tab)")).
    
*   The optional and non-standard second `fallback` parameter for [`WeakMap.prototype.get()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap/get) has been removed ([Firefox bug 1127827](https://bugzil.la/1127827 "External link (opens in new tab)")).
    
*   When defining a [generator method](/en-US/docs/Web/JavaScript/Reference/Functions/Method_definitions), `set` and `get` are no longer invalid names ([Firefox bug 1073809](https://bugzil.la/1073809 "External link (opens in new tab)")).
    
*   [`RegExp.prototype.source`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/source) now returns "(?:)" instead of an empty string for empty regular expressions ([Firefox bug 1130798](https://bugzil.la/1130798 "External link (opens in new tab)")).
    
*   [`RegExp.prototype.source`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/source) and [`RegExp.prototype.toString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/toString) now escape regular expression patterns properly (e.g., line terminators, "\\n") ([Firefox bug 1130860](https://bugzil.la/1130860 "External link (opens in new tab)")).
    
*   The [`RegExp`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp) [`global`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/global), [`ignoreCase`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/ignoreCase), [`multiline`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/multiline), and [`sticky`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/sticky) properties are now prototype accessor properties rather than own data properties of `RegExp` instances ([Firefox bug 1120169](https://bugzil.la/1120169 "External link (opens in new tab)")).
    
*   The [`RegExp.prototype.source`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/source) property is now prototype accessor property rather than own data property of `RegExp` instances ([Firefox bug 1120169](https://bugzil.la/1120169 "External link (opens in new tab)")). Available only in non-Release version, due to [Firefox bug 1150297](https://bugzil.la/1150297 "External link (opens in new tab)").
    
*   [`Function.prototype.toString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/toString) now throws for [`Proxy`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy) objects ([Firefox bug 1100936](https://bugzil.la/1100936 "External link (opens in new tab)")).
    

### [Interfaces/APIs/DOM](#interfacesapisdom)

*   The Fetch API [`fetch()`](/en-US/docs/Web/API/Window/fetch "fetch()") method has been implemented ([Firefox bug 1039846](https://bugzil.la/1039846 "External link (opens in new tab)")).
*   [`BroadcastChannel`](/en-US/docs/Web/API/BroadcastChannel) API has been implemented and is available in [Web Workers](/en-US/docs/Web/API/Web_Workers_API) ([Firefox bug 966439](https://bugzil.la/966439 "External link (opens in new tab)") and [Firefox bug 1121420](https://bugzil.la/1121420 "External link (opens in new tab)")).
*   The Console API is now available in [Web Workers](/en-US/docs/Web/API/Web_Workers_API).
*   `CanvasRenderingContext2D.clearHitRegions()` has been implemented ([Firefox bug 1119527](https://bugzil.la/1119527 "External link (opens in new tab)")).
*   Constants of [`KeyboardEvent.location`](/en-US/docs/Web/API/KeyboardEvent/location), `DOM_KEY_LOCATION_MOBILE` and DOM\_KEY\_LOCATION\_JOYSTICK, have been removed, since they were removed from the DOM Level 3 Spec ([Firefox bug 936313](https://bugzil.la/936313 "External link (opens in new tab)").
*   [`KeyboardEvent.code`](/en-US/docs/Web/API/KeyboardEvent/code) is now available; previously it was only available in prerelease builds. ([Firefox bug 1126673](https://bugzil.la/1126673 "External link (opens in new tab)"))
*   [`KeyboardEvent.code`](/en-US/docs/Web/API/KeyboardEvent/code) now supports special keys on Sun keyboards on Linux, Android, and Firefox OS. ([Firefox bug 1020139](https://bugzil.la/1020139 "External link (opens in new tab)"))
*   The [`TextEncoder()`](/en-US/docs/Web/API/TextEncoder/TextEncoder "TextEncoder()") constructor has been changed to match the spec: when an invalid parameter is passed, the [`RangeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RangeError) is now raised, rather than the erroneous [`TypeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypeError) ([Firefox bug 1125766](https://bugzil.la/1125766 "External link (opens in new tab)")).
*   The User Timing API, adding [`Performance.mark()`](/en-US/docs/Web/API/Performance/mark), [`Performance.clearMarks()`](/en-US/docs/Web/API/Performance/clearMarks), [`Performance.measure()`](/en-US/docs/Web/API/Performance/measure), and [`Performance.clearMeasures()`](/en-US/docs/Web/API/Performance/clearMeasures) has been implemented ([Firefox bug 782751](https://bugzil.la/782751 "External link (opens in new tab)")).
*   The prefixed version of [`Window.indexedDB`](/en-US/docs/Web/API/Window/indexedDB), `mozIndexedDB`, has been removed ([Firefox bug 975699](https://bugzil.la/975699 "External link (opens in new tab)")).
*   The [`DOMContentLoaded`](/en-US/docs/Web/API/Document/DOMContentLoaded_event "DOMContentLoaded") event is no longer cancelable ([Firefox bug 1134559](https://bugzil.la/1134559 "External link (opens in new tab)")).
*   You can now use [WebSockets](/en-US/docs/Web/API/WebSockets_API) in [Workers](/en-US/docs/Web/API/Web_Workers_API) ([Firefox bug 504553](https://bugzil.la/504553 "External link (opens in new tab)")).
*   The [`XMLHttpRequest.responseType`](/en-US/docs/Web/API/XMLHttpRequest/responseType) and [`XMLHttpRequest.withCredentials`](/en-US/docs/Web/API/XMLHttpRequest/withCredentials) properties can now be set before calling [`XMLHttpRequest.open()`](/en-US/docs/Web/API/XMLHttpRequest/open) ([Firefox bug 707484](https://bugzil.la/707484 "External link (opens in new tab)")).

## [Security](#security)

*   In Firefox, the [`autocomplete=false`](/en-US/docs/Web/HTML/Reference/Elements/input#autocomplete) attribute is now ignored when dealing with a login form ([Firefox bug 1025703](https://bugzil.la/1025703 "External link (opens in new tab)")). This is intended to encourage the use of more secure passwords by allowing password manager tools to work more reliably.
*   RC4 is now disabled when using TLS, except for a few specifically allowed websites. This whitelist is an interim measure until those sites are fixed ([Firefox bug 1124039](https://bugzil.la/1124039 "External link (opens in new tab)")). This fallback is controlled by the `security.tls.unrestricted_rc4_fallback` preference, `true` by default for the moment ([Firefox bug 1138882](https://bugzil.la/1138882 "External link (opens in new tab)")).
*   Websites needing to fall back to an insecure version of TLS in order to work are now in a hardcoded whitelist which will shrink over time ([Firefox bug 1114816](https://bugzil.la/1114816 "External link (opens in new tab)")). The whitelist can be disabled by setting `security.tls.insecure_fallback_hosts.use_static_list` to `false`.
