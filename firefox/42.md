# Firefox 42 release notes for developers

[To test the latest developer features of Firefox, install Firefox Developer Edition](https://www.firefox.com/en-US/channel/desktop/developer/ "External link (opens in new tab)") Firefox 42 was released on November 3, 2015. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

Highlights:

*   [Debugging Firefox for Android over Wi-Fi](https://firefox-source-docs.mozilla.org/devtools-user/about_colon_debugging/index.html#connecting-over-the-network "External link (opens in new tab)")
*   _Firefox OS Simulator configuration in WebIDE_
*   [CSS filter presets](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/edit_css_filters/index.html#saving-filter-presets "External link (opens in new tab)")

### [CSS](#css)

*   Vertical [`writing-mode`](/en-US/docs/Web/CSS/Reference/Properties/writing-mode) is now supported with rtl scripts ([Firefox bug 1131451](https://bugzil.la/1131451 "External link (opens in new tab)")).
*   The values of [`caption-side`](/en-US/docs/Web/CSS/Reference/Properties/caption-side) are now relative to the table, and changing actual meaning according to its [`writing-mode`](/en-US/docs/Web/CSS/Reference/Properties/writing-mode) value [Firefox bug 1202993](https://bugzil.la/1202993 "External link (opens in new tab)").
*   Non-standard properties like `-moz-margin-start` are now aliases of their standard counterpart ([`margin-inline-start`](/en-US/docs/Web/CSS/Reference/Properties/margin-inline-start), …). Previously, it was the opposite. This affects the value returned by [`CSSStyleDeclaration.cssText`](/en-US/docs/Web/API/CSSStyleDeclaration/cssText) and iteration of the properties in a style rule, which both use the canonical form ([Firefox bug 1118103](https://bugzil.la/1118103 "External link (opens in new tab)")).
*   The prefixed version of CSS gradients can be turned off by setting the `layout.css.prefixes.gradients` preference to `false`.
*   Several old bugs with [`float`](/en-US/docs/Web/CSS/Reference/Properties/float) and margin collapsing behavior have been fixed ([Firefox bug 478834](https://bugzil.la/478834 "External link (opens in new tab)"), [Firefox bug 538194](https://bugzil.la/538194 "External link (opens in new tab)"), and [Firefox bug 451791](https://bugzil.la/451791 "External link (opens in new tab)")).

### [HTML](#html)

*   Experimental support for the `referrer` attribute of the [`<img>`](/en-US/docs/Web/HTML/Reference/Elements/img) ([Firefox bug 1166910](https://bugzil.la/1166910 "External link (opens in new tab)")), [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) ([Firefox bug 1175736](https://bugzil.la/1175736 "External link (opens in new tab)")), [`<a>`](/en-US/docs/Web/HTML/Reference/Elements/a) and [`<area>`](/en-US/docs/Web/HTML/Reference/Elements/area) ([Firefox bug 1174913](https://bugzil.la/1174913 "External link (opens in new tab)")) has been added. There is no effect by default, the `network.http.enablePerElementReferrer` being `false` by default.

### [JavaScript](#javascript)

*   The [`Reflect`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Reflect) object has been implemented ([Firefox bug 987514](https://bugzil.la/987514 "External link (opens in new tab)")).
*   The implementation of the [`Proxy`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy) [`handler.ownKeys()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/ownKeys) trap has been updated to match the final ES2015 specification ([Firefox bug 1049662](https://bugzil.la/1049662 "External link (opens in new tab)")).
*   Calling [`Map`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map), [`Set`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set), or [`WeakMap`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap) without [`new`](/en-US/docs/Web/JavaScript/Reference/Operators), will now throw a [`TypeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypeError) ([Firefox bug 1083752](https://bugzil.la/1083752 "External link (opens in new tab)")).

### [Interfaces/APIs/DOM](#interfacesapisdom)

#### DOM & HTML DOM

*   Images with an [`id`](/en-US/docs/Web/HTML/Reference/Global_attributes/id) are no more listed as property of the [`Window`](/en-US/docs/Web/API/Window) interface: `<img id="login">` isn't accessible as `window.login` anymore. This behavior was introduced in Firefox 26 and has been removed to match a later change in the spec. ([Firefox bug 959992](https://bugzil.la/959992 "External link (opens in new tab)"))
    
*   [`MouseEvent.offsetX`](/en-US/docs/Web/API/MouseEvent/offsetX) and [`MouseEvent.offsetY`](/en-US/docs/Web/API/MouseEvent/offsetY) have been added ([Firefox bug 69787](https://bugzil.la/69787 "External link (opens in new tab)")).
    
*   The [`HTMLInputElement`](/en-US/docs/Web/API/HTMLInputElement) interface has been experimentally extended to handle the upload of directories ([Firefox bug 1164310](https://bugzil.la/1164310 "External link (opens in new tab)")). These four members can be exposed by setting the `dom.input.dirpicker` preference to `true`:
    
    *   `HTMLInputElement.directory`
    *   `HTMLInputElement.isFilesAndDirectoriesSupported`
    *   `HTMLInputElement.getFilesAndDirectories()`
    *   `HTMLInputElement.chooseDirectory()`
*   The `Directory` interface has been experimentally extended ([Firefox bug 1177688](https://bugzil.la/1177688 "External link (opens in new tab)")). The two members `Directory.path` and `Directory.getContents` can be exposed by setting the `dom.input.dirpicker` preference to `true`.
    
*   The `HTMLMediaElement.mozSrcObject` has been renamed in [`HTMLMediaElement.srcObject`](/en-US/docs/Web/API/HTMLMediaElement/srcObject) ([Firefox bug 1175523](https://bugzil.la/1175523 "External link (opens in new tab)")).
    

#### Service Workers

*   `Request.context` has been removed ([Firefox bug 1188062](https://bugzil.la/1188062 "External link (opens in new tab)")).
*   The [Push API](/en-US/docs/Web/API/Push_API) has been activated by default on Firefox for Desktop ([Firefox bug 1153499](https://bugzil.la/1153499 "External link (opens in new tab)")), but only on the Nightly/Dev Edition/Beta channels. It is being deactivated by default in the Release channel until consumer UX and debugging features have been properly implemented ([Firefox bug 1207875](https://bugzil.la/1207875 "External link (opens in new tab)").) You can still activate it by enabling the `dom.push.enabled` pref in `about:config`.
*   The [`PushManager.hasPermission()`](/en-US/docs/Web/API/PushManager/hasPermission) method has been deprecated in the spec, and replaced with the [`PushManager.permissionState()`](/en-US/docs/Web/API/PushManager/permissionState) method. Firefox has updated its implementation to reflect this ([Firefox bug 1183853](https://bugzil.la/1183853 "External link (opens in new tab)").)
*   Service-worker-related additions to the [Notifications API](/en-US/docs/Web/API/Notifications_API) have been implemented ([Firefox bug 1114554](https://bugzil.la/1114554 "External link (opens in new tab)")), but are disabled in this release.

#### Web Animations API

Our experimental implementation of [Web Animations API](/en-US/docs/Web/API/Web_Animations_API) have been extended to support:

*   The [`AnimationPlayer.playbackRate`](/en-US/docs/Web/API/Animation/playbackRate "AnimationPlayer.playbackRate") property ([Firefox bug 1127380](https://bugzil.la/1127380 "External link (opens in new tab)")).
*   The [`CSSAnimation`](/en-US/docs/Web/API/CSSAnimation) and [`CSSTransition`](/en-US/docs/Web/API/CSSTransition) interfaces ([Firefox bug 1178186](https://bugzil.la/1178186 "External link (opens in new tab)")).
*   The [`Animation.reverse()`](/en-US/docs/Web/API/Animation/reverse) method ([Firefox bug 1150808](https://bugzil.la/1150808 "External link (opens in new tab)")).
*   The [`AnimationPlaybackEvent`](/en-US/docs/Web/API/AnimationPlaybackEvent) interface has been added and [`cancel`](/en-US/docs/Web/API/Animation/cancel_event "cancel") and [`finish`](/en-US/docs/Web/API/Animation/finish_event "finish") are now fired on [`Animation`](/en-US/docs/Web/API/Animation) ([Firefox bug 1178664](https://bugzil.la/1178664 "External link (opens in new tab)")).

#### Web Components

Our experimental implementation of the [Shadow DOM](/en-US/docs/Web/API/Web_components/Using_shadow_DOM) has been modified:

*   When trying to invoke [`Node.cloneNode()`](/en-US/docs/Web/API/Node/cloneNode) on a [`ShadowRoot`](/en-US/docs/Web/API/ShadowRoot), throws a `DataCloneError` exception ([Firefox bug 1176757](https://bugzil.la/1176757 "External link (opens in new tab)")).
*   When invoking [`Document.importNode()`](/en-US/docs/Web/API/Document/importNode) with a [`ShadowRoot`](/en-US/docs/Web/API/ShadowRoot) as an argument, we now throws a `NotSupportedError` [`DOMException`](/en-US/docs/Web/API/DOMException) ([Firefox bug 1177914](https://bugzil.la/1177914 "External link (opens in new tab)")).
*   When invoking [`Document.adoptNode()`](/en-US/docs/Web/API/Document/adoptNode) with a [`ShadowRoot`](/en-US/docs/Web/API/ShadowRoot) as an argument, we now throws a `HierarchyRequestError` [`DOMException`](/en-US/docs/Web/API/DOMException) ([Firefox bug 1177991](https://bugzil.la/1177991 "External link (opens in new tab)")).

#### WebGL

*   WebGL2 [`WebGLTransformFeedback`](/en-US/docs/Web/API/WebGLTransformFeedback) has been implemented ([Firefox bug 1048724](https://bugzil.la/1048724 "External link (opens in new tab)")).
*   To obtain a WebGL2 context, [`HTMLCanvasElement.getContext()`](/en-US/docs/Web/API/HTMLCanvasElement/getContext) now takes `webgl2` instead of `experimental-webgl2` ([Firefox bug 1187174](https://bugzil.la/1187174 "External link (opens in new tab)")).

#### WebRTC

*   The [`RTCPeerConnection.createOffer()`](/en-US/docs/Web/API/RTCPeerConnection/createOffer)'s options data type, `RTCOfferOptions`, has been updated to more closely match the specification. Among other changes, it is now based upon the `RTCOfferAnswerOptions` dictionary, which provides the `voiceActivityDetection` option.
*   The `RTCAnswerOptions` dictionary has been added. This is the type used for the `options` parameter to [`createAnswer()`](/en-US/docs/Web/API/RTCPeerConnection/createAnswer "createAnswer()").
*   The `RTCICECandidatePairStats.mozPriority` has been renamed to [`RTCICECandidatePairStats.priority`](/en-US/docs/Web/API/RTCIceCandidatePairStats/priority) ([Firefox bug 1184426](https://bugzil.la/1184426 "External link (opens in new tab)")).

#### New APIs

*   The [`ImageBitmap`](/en-US/docs/Web/API/ImageBitmap) interface, the [`Window.createImageBitmap()`](/en-US/docs/Web/API/Window/createImageBitmap) and [`WorkerGlobalScope.createImageBitmap()`](/en-US/docs/Web/API/WorkerGlobalScope/createImageBitmap) method have been implemented. They are available on regular window scripts and in Web workers and allow efficient posting of images between window and worker contexts ([Firefox bug 1044102](https://bugzil.la/1044102 "External link (opens in new tab)")).

#### Miscellaneous

*   The [`IDBCursorWithValue`](/en-US/docs/Web/API/IDBCursorWithValue) interface is now available in [Web workers](/en-US/docs/Web/API/Web_Workers_API) ([Firefox bug 1188115](https://bugzil.la/1188115 "External link (opens in new tab)")).
*   Error events sent in [Web workers](/en-US/docs/Web/API/Web_Workers_API) doesn't bubble anymore ([Firefox bug 1188141](https://bugzil.la/1188141 "External link (opens in new tab)")).
*   [Media Source Extensions](/en-US/docs/Web/API/Media_Source_Extensions_API) (MSE) has been activated for all websites, and no more for a white list of sites ([Firefox bug 1185611](https://bugzil.la/1185611 "External link (opens in new tab)")).
*   The non-standard and deprecated `Window.mozRequestAnimationFrame()` has been removed ([Firefox bug 909154](https://bugzil.la/909154 "External link (opens in new tab)")). Use the standard [`Window.requestAnimationFrame()`](/en-US/docs/Web/API/Window/requestAnimationFrame) instead.
*   Speech synthesis (text-to-speech) has been implemented in Firefox Desktop for Windows, hidden behind the `media.webspeech.synth.enabled` flag in `about:config` ([Firefox bug 1003457](https://bugzil.la/1003457 "External link (opens in new tab)").) See [Web Speech API](/en-US/docs/Web/API/Web_Speech_API) for more information.

## [HTTP](#http)

*   Firefox 41 and earlier versions were incorrectly accepting undefined or invalid pseudo-header fields in HTTP/2 responses. This is now fixed and the only pseudo-header field accepted from Firefox 42 is the _:status_ as per the specification. Response headers containing arbitrary fields are considered malformed. ([Firefox bug 1136727](https://bugzil.la/1136727 "External link (opens in new tab)"))

## [Networking](#networking)

*   The CSP [`upgrade-insecure-requests`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/upgrade-insecure-requests) directive has been implemented ([Firefox bug 1139297](https://bugzil.la/1139297 "External link (opens in new tab)")).

## [Security](#security)

*   EV certificates with a validity greater than 39 months are now considered and handled as DV certificates ([Firefox bug 1145679](https://bugzil.la/1145679 "External link (opens in new tab)")).

## [Changes for add-on and Mozilla developers](#changes_for_add-on_and_mozilla_developers)

### [Interfaces](#interfaces)

#### nsIContentPolicy

*   The `TYPE_EMBED` constant has been added to `nsIContentPolicy` to allow Gecko internals and add-on code to better differentiate different types of requests. Previously, `TYPE_OBJECT` was used for these cases ([Firefox bug 1148030](https://bugzil.la/1148030 "External link (opens in new tab)")).
*   Similarly, the `TYPE_SUBDOCUMENT` constants has been split into `TYPE_FRAME` and `TYPE_IFRAME` ([Firefox bug 1148044](https://bugzil.la/1148044 "External link (opens in new tab)")).
