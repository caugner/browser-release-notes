# Firefox 75 release notes for developers

This article provides information about the changes in Firefox 75 that will affect developers. Firefox 75 was released on April 7, 2020.

**See also the accompanying hacks post — [Firefox 75: Ambitions for April](https://hacks.mozilla.org/2020/04/firefox-75-ambitions-for-april/ "External link (opens in new tab)").**

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   It is now possible to resize the rectangle of the [Measuring Tool](https://firefox-source-docs.mozilla.org/devtools-user/measure_a_portion_of_the_page/index.html "External link (opens in new tab)") ([Firefox bug 1152321](https://bugzil.la/1152321 "External link (opens in new tab)")).
*   In the [inspector](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/index.html "External link (opens in new tab)"), you can now use [XPath](/en-US/docs/Web/XML/XPath) expressions to locate elements, in addition to locating elements using CSS selectors as before ([Firefox bug 963933](https://bugzil.la/963933 "External link (opens in new tab)")).
*   You can now filter [WebSocket](/en-US/docs/Web/API/WebSockets_API) messages using [regular expressions](/en-US/docs/Web/JavaScript/Guide/Regular_expressions), in addition to plain text search, by writing the regular expression in slashes ([Firefox bug 1593837](https://bugzil.la/1593837 "External link (opens in new tab)")).

### [HTML](#html)

*   The [`loading`](/en-US/docs/Web/HTML/Reference/Elements/img#loading) attribute of the [`<img>`](/en-US/docs/Web/HTML/Reference/Elements/img) element has now been implemented. This string value can be used to specify that the image should be [lazily loaded](/en-US/docs/Web/Performance/Guides/Lazy_loading), by setting its value to `lazy` ([Firefox bug 1542784](https://bugzil.la/1542784 "External link (opens in new tab)")).
*   The value of the [`<style>`](/en-US/docs/Web/HTML/Reference/Elements/style) element's `type` attribute is now restricted to `text/css` only, as per the spec ([Firefox bug 1614329](https://bugzil.la/1614329 "External link (opens in new tab)")).

### [CSS](#css)

*   Support for the [`min()`](/en-US/docs/Web/CSS/Reference/Values/min), [`max()`](/en-US/docs/Web/CSS/Reference/Values/max), and [`clamp()`](/en-US/docs/Web/CSS/Reference/Values/clamp) functions has been implemented ([Firefox bug 1519519](https://bugzil.la/1519519 "External link (opens in new tab)")).
*   The `all` value of the [`text-decoration-skip-ink`](/en-US/docs/Web/CSS/Reference/Properties/text-decoration-skip-ink) property has been added ([Firefox bug 1611965](https://bugzil.la/1611965 "External link (opens in new tab)"))

### [Accessibility](#accessibility)

New [ARIA](/en-US/docs/Web/Accessibility/ARIA) roles and attributes are now exposed in Firefox, on Windows and Linux (bear in mind that these still won't be usable until screen readers start to support them):

*   `aria-description` ([Firefox bug 1608961](https://bugzil.la/1608961 "External link (opens in new tab)")).
*   [`role="mark"`](/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/mark_role) and [`role="suggestion"`](/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/suggestion_role) ([Firefox bug 1608965](https://bugzil.la/1608965 "External link (opens in new tab)")).
*   [`role="comment"`](/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/comment_role) ([Firefox bug 1608969](https://bugzil.la/1608969 "External link (opens in new tab)")).
*   Multiple IDs on `aria-details` ([Firefox bug 1608883](https://bugzil.la/1608883 "External link (opens in new tab)")).

**Note:** On macOS, we are first waiting for Apple to define what Safari will expose as Apple-dialect attributes to VoiceOver, and will then follow suit.

### [JavaScript](#javascript)

*   [Public static class fields](/en-US/docs/Web/JavaScript/Reference/Classes/static) are now supported ([Firefox bug 1535804](https://bugzil.la/1535804 "External link (opens in new tab)")).
*   The [`Intl.Locale`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Locale) class is now supported ([Firefox bug 1613713](https://bugzil.la/1613713 "External link (opens in new tab)")).
*   The [`Function.caller`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/caller) property has been updated to be aligned with the latest [ECMAScript spec proposal](https://github.com/claudepache/es-legacy-function-reflection "External link (opens in new tab)"). Previously throwing a `TypeError`, it now returns `null` if the caller is a strict, async, or generator function ([Firefox bug 1610206](https://bugzil.la/1610206 "External link (opens in new tab)")).

### [APIs](#apis)

#### DOM

*   The [`HTMLFormElement`](/en-US/docs/Web/API/HTMLFormElement) interface has a new method, [`requestSubmit()`](/en-US/docs/Web/API/HTMLFormElement/requestSubmit "requestSubmit()"). Unlike the old (and still available) [`submit()`](/en-US/docs/Web/API/HTMLFormElement/submit "submit()") method, `requestSubmit()` acts as if a specified submit button has been clicked, rather than just sending the form data to the recipient. Thus the [`submit`](/en-US/docs/Web/API/HTMLFormElement/submit_event "submit") event is delivered and the form is checked for validity prior to the data being submitted ([Firefox bug 1613360](https://bugzil.la/1613360 "External link (opens in new tab)")).
*   The [`submit`](/en-US/docs/Web/API/HTMLFormElement/submit_event "submit") event is now represented by an object of type [`SubmitEvent`](/en-US/docs/Web/API/SubmitEvent) rather than a simple [`Event`](/en-US/docs/Web/API/Event). `SubmitEvent` includes a new [`submitter`](/en-US/docs/Web/API/SubmitEvent/submitter "submitter") property, which is the [`Element`](/en-US/docs/Web/API/Element) that was invoked to trigger the form submission. With this event, you can have a single handler for submit events that can discern which of multiple submit buttons or links was used to submit the form ([Firefox bug 1588715](https://bugzil.la/1588715 "External link (opens in new tab)")).
*   Calling the [`click()`](/en-US/docs/Web/API/HTMLElement/click "click()") method on a detached element (one not part of a DOM tree) now functions normally, leading to a `click` event being sent to it ([Firefox bug 1610821](https://bugzil.la/1610821 "External link (opens in new tab)")).

#### Web animations API

Firefox 75 sees numerous additions to the [Web Animations API](/en-US/docs/Web/API/Web_Animations_API):

*   [Implicit to/from keyframes](/en-US/docs/Web/API/Web_Animations_API/Keyframe_Formats#implicit_tofrom_keyframes) are now supported, as is automatically removing filling animations that have been replaced by other indefinitely filling animations ([Firefox bug 1618773](https://bugzil.la/1618773 "External link (opens in new tab)")). This includes enabling of support for:
    
    *   [`Animation.commitStyles()`](/en-US/docs/Web/API/Animation/commitStyles)
    *   [`Animation.onremove`](/en-US/docs/Web/API/Animation/remove_event)
    *   [`Animation.persist()`](/en-US/docs/Web/API/Animation/persist)
    *   [`Animation.replaceState`](/en-US/docs/Web/API/Animation/replaceState)
*   The [`Animation.timeline`](/en-US/docs/Web/API/Animation/timeline) getter, [`Document.timeline`](/en-US/docs/Web/API/Document/timeline), [`DocumentTimeline`](/en-US/docs/Web/API/DocumentTimeline), and [`AnimationTimeline`](/en-US/docs/Web/API/AnimationTimeline) features are now enabled by default ([Firefox bug 1619178](https://bugzil.la/1619178 "External link (opens in new tab)")).
    
*   The [`Document.getAnimations()`](/en-US/docs/Web/API/Document/getAnimations) and [`Element.getAnimations()`](/en-US/docs/Web/API/Element/getAnimations) methods are now enabled by default ([Firefox bug 1619821](https://bugzil.la/1619821 "External link (opens in new tab)")).
    

#### Media, Web Audio, and WebRTC

*   The [`RTCPeerConnection.setLocalDescription()`](/en-US/docs/Web/API/RTCPeerConnection/setLocalDescription) method can now be called without arguments, in which case the WebRTC runtime will try to create the new local session description itself ([Firefox bug 1568292](https://bugzil.la/1568292 "External link (opens in new tab)")).

### [HTTP](#http)

_No changes._

### [Security](#security)

*   [CSP](/en-US/docs/Web/HTTP/Guides/CSP) [nonces](/en-US/docs/Glossary/Nonce) from non-script sources, such as CSS selectors, and `.getAttribute("nonce")` calls, are now hidden. Instead, check the [`.nonce`](/en-US/docs/Web/API/HTMLElement/nonce) property to access nonces from scripts ([Firefox bug 1374612](https://bugzil.la/1374612 "External link (opens in new tab)")).

### [Plugins](#plugins)

_No changes._

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

*   Fixed a bug that always caused Marionette to initialize when Firefox starts-up. It has been limited to the command-line argument and environment variable now ([Firefox bug 1622012](https://bugzil.la/1622012 "External link (opens in new tab)")).
*   Fixed `WebDriver:Print` to no longer add extra margins to the document ([Firefox bug 1616932](https://bugzil.la/1616932 "External link (opens in new tab)")).
*   Changed the preference value for `network.http.speculative-parallel-limit` to `0`, to no longer force-disable speculative connections ([Firefox bug 1617869](https://bugzil.la/1617869 "External link (opens in new tab)")).

### [Other](#other)

_No changes._

## [Changes for add-on developers](#changes_for_add-on_developers)

### [API changes](#api_changes)

*   We've added some new settings in [`browserSettings`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings) ([Firefox bug 1286953](https://bugzil.la/1286953 "External link (opens in new tab)")):
    
    *   [`browserSettings.zoomSiteSpecific`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings/zoomSiteSpecific) to control whether zooming is on a per-site or per-tab basis
    *   [`browserSettings.zoomFullPage`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings/zoomFullPage) to control whether zoom is applied to the entire page or to text only.
*   The name of the file used when saving a PDF with [`tabs.saveAsPDF`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/saveAsPDF) can be specified using `toFileName` in the type `tabs.PageSettings`.([Firefox bug 1483590](https://bugzil.la/1483590 "External link (opens in new tab)"))
    

### [Manifest changes](#manifest_changes)

*   The "privacy" permission is now optional. ([Firefox bug 1618399](https://bugzil.la/1618399 "External link (opens in new tab)"))
