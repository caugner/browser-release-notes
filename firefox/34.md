# Firefox 34 release notes for developers

Firefox 34 was released on December 1st, 2014. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

Highlights:

*   [Storage Inspector: a new tool enabling you to view data stored by web pages](https://firefox-source-docs.mozilla.org/devtools-user/storage_inspector/index.html "External link (opens in new tab)")
*   [Performance tool: revamped Profiler UI and frame rate timeline](https://firefox-source-docs.mozilla.org/devtools-user/performance/index.html "External link (opens in new tab)")
*   [Frame switching: point the developer tools at a specific iframe in the page](https://firefox-source-docs.mozilla.org/devtools-user/working_with_iframes/index.html "External link (opens in new tab)")
*   [console.table support](/en-US/docs/Web/API/console/table_static)
*   [jQuery events are visible in the Page Inspector](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_event_listeners/index.html "External link (opens in new tab)")

[All devtools bugs fixed between Firefox 33 and Firefox 34](https://bugzilla.mozilla.org/buglist.cgi?resolution=FIXED&chfieldto=2014-09-02&chfield=resolution&query_format=advanced&chfieldfrom=2014-07-21&chfieldvalue=FIXED&component=Developer%20Tools&component=Developer%20Tools%3A%203D%20View&component=Developer%20Tools%3A%20Canvas%20Debugger&component=Developer%20Tools%3A%20Console&component=Developer%20Tools%3A%20Debugger&component=Developer%20Tools%3A%20Framework&component=Developer%20Tools%3A%20Graphic%20Commandline%20and%20Toolbar&component=Developer%20Tools%3A%20Inspector&component=Developer%20Tools%3A%20Memory&component=Developer%20Tools%3A%20Netmonitor&component=Developer%20Tools%3A%20Object%20Inspector&component=Developer%20Tools%3A%20Profiler&component=Developer%20Tools%3A%20Responsive%20Mode&component=Developer%20Tools%3A%20Scratchpad&component=Developer%20Tools%3A%20Source%20Editor&component=Developer%20Tools%3A%20Storage%20Inspector&component=Developer%20Tools%3A%20Style%20Editor&component=Developer%20Tools%3A%20Timeline&component=Developer%20Tools%3A%20User%20Stories&component=Developer%20Tools%3A%20Web%20Audio%20Editor&component=Developer%20Tools%3A%20WebGL%20Shader%20Editor&component=Developer%20Tools%3A%20WebIDE&component=Simulator&product=Firefox&product=Firefox%20OS&list_id=11184176 "External link (opens in new tab)").

### [CSS](#css)

*   Our experimental implementation of CSS Fonts Level 3 progresses. Newly implemented features are:
    
    *   the fallback algorithm of [`font-variant-position`](/en-US/docs/Web/CSS/Reference/Properties/font-variant-position), creating synthetic alternates for missing glyphs, based on the subscript and superscript metrics supplied by the font ([Firefox bug 1024804](https://bugzil.la/1024804 "External link (opens in new tab)")).
    *   The `layout.css.font-features.enabled` preference has been removed, meaning the following properties have been activated by default:
        *   The CSS Font Level 3 version of [`font-variant`](/en-US/docs/Web/CSS/Reference/Properties/font-variant) which is now a shorthand property.
        *   The longhand properties [`font-variant-caps`](/en-US/docs/Web/CSS/Reference/Properties/font-variant-caps), [`font-variant-numeric`](/en-US/docs/Web/CSS/Reference/Properties/font-variant-numeric), [`font-variant-position`](/en-US/docs/Web/CSS/Reference/Properties/font-variant-position), [`font-variant-east-asian`](/en-US/docs/Web/CSS/Reference/Properties/font-variant-east-asian), [`font-variant-ligatures`](/en-US/docs/Web/CSS/Reference/Properties/font-variant-ligatures), and [`font-variant-alternates`](/en-US/docs/Web/CSS/Reference/Properties/font-variant-alternates).
        *   The properties [`font-kerning`](/en-US/docs/Web/CSS/Reference/Properties/font-kerning) and [`font-synthesis`](/en-US/docs/Web/CSS/Reference/Properties/font-synthesis)
        *   The properties [`font-feature-settings`](/en-US/docs/Web/CSS/Reference/Properties/font-feature-settings) and [`font-language-override`](/en-US/docs/Web/CSS/Reference/Properties/font-language-override) are unprefixed. The prefixed version are still available for some time to ease transition.
*   The value `auto` has been added to [`min-width`](/en-US/docs/Web/CSS/Reference/Properties/min-width) and [`min-height`](/en-US/docs/Web/CSS/Reference/Properties/min-height) with a different behavior than the last time ([Firefox bug 984711](https://bugzil.la/984711 "External link (opens in new tab)") and [Firefox bug 1015474](https://bugzil.la/1015474 "External link (opens in new tab)")).
    
*   An experimental implementation, disabled by default, of the filter functional values of the [`filter`](/en-US/docs/Web/CSS/Reference/Properties/filter) property have been implemented. It is controlled by the `layout.css.filters.enabled` pref ([Firefox bug 948265](https://bugzil.la/948265 "External link (opens in new tab)")).
    
*   Fixed starting of CSS transitions that start together with changes to [`display`](/en-US/docs/Web/CSS/Reference/Properties/display), [`position`](/en-US/docs/Web/CSS/Reference/Properties/position), [`overflow`](/en-US/docs/Web/CSS/Reference/Properties/overflow), and similar properties ([Firefox bug 625289](https://bugzil.la/625289 "External link (opens in new tab)"))

### [JavaScript](#javascript)

*   The ES2015 syntax for [computed property names on object literals](/en-US/docs/Web/JavaScript/Reference/Operators/Object_initializer#computed_property_names) has been implemented ([Firefox bug 924688](https://bugzil.la/924688 "External link (opens in new tab)")).
    
    *   This includes [getter](/en-US/docs/Web/JavaScript/Reference/Functions/get) and [setter](/en-US/docs/Web/JavaScript/Reference/Functions/set) method names as well ([Firefox bug 1048384](https://bugzil.la/1048384 "External link (opens in new tab)")) and can also be used with [destructuring](/en-US/docs/Web/JavaScript/Reference/Operators/Destructuring#computed_object_property_names_and_destructuring).
*   The ES2015 [shorthand syntax for defining methods](/en-US/docs/Web/JavaScript/Reference/Functions/Method_definitions) on objects has been implemented ([Firefox bug 924672](https://bugzil.la/924672 "External link (opens in new tab)")).
    
*   The ES2015 `Object` method [`Object.assign()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/assign) has been implemented ([Firefox bug 937855](https://bugzil.la/937855 "External link (opens in new tab)")).
    
*   ES2015 [template strings](/en-US/docs/Web/JavaScript/Reference/Template_literals) and the [`String.raw()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/raw) method are now supported ([Firefox bug 1038259](https://bugzil.la/1038259 "External link (opens in new tab)"), [Firefox bug 1039774](https://bugzil.la/1039774 "External link (opens in new tab)")).
    
*   A new ES2015 object [`WeakSet`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakSet) has been added ([Firefox bug 792439](https://bugzil.la/792439 "External link (opens in new tab)")).
    
*   ES2015 [Symbols](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol) (only available in the Nightly channel) have been updated to conform with recent specification changes ([Firefox bug 1042602](https://bugzil.la/1042602 "External link (opens in new tab)")):
    
    *   When trying to convert a symbol to a number, a [`TypeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypeError) will be thrown now.
    *   When using loose equality, `Object(sym) == sym` returns `true` now.
*   The experimental `TypedArray.prototype.move()` method (only available in former Nightly and Aurora channels) has been replaced with the now implemented standard ES2015 [`TypedArray.prototype.copyWithin()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray/copyWithin) method ([Firefox bug 1021379](https://bugzil.la/1021379 "External link (opens in new tab)")).
    
*   In [strict mode](/en-US/docs/Web/JavaScript/Reference/Strict_mode), setting a [duplicate property name in object literals](/en-US/docs/Web/JavaScript/Reference/Operators/Object_initializer#duplicate_property_names) will no longer throw a `SyntaxError` as per ES2015 specification ([Firefox bug 1041128](https://bugzil.la/1041128 "External link (opens in new tab)")).
    
*   In regular expressions (including `String.replace`), the matched text for a capturing group is now `undefined` instead of the empty string when that capturing group didn't get consulted because quantifiers prevented its exercise (see [Firefox bug 369778](https://bugzil.la/369778 "External link (opens in new tab)") and [this example code](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp#firefox-specific_notes)). Note that due to web compatibility, RegExp.$N will still return an empty string ([Firefox bug 1053944](https://bugzil.la/1053944 "External link (opens in new tab)")).
    
*   The ES2015 [spread operator](/en-US/docs/Web/JavaScript/Reference/Operators/Spread_syntax) is now supported in [destructuring](/en-US/docs/Web/JavaScript/Reference/Operators/Destructuring) ([Firefox bug 933276](https://bugzil.la/933276 "External link (opens in new tab)")).
    
*   [Destructuring](/en-US/docs/Web/JavaScript/Reference/Operators/Destructuring) now uses iterator protocol instead of array-like protocol ([Firefox bug 933276](https://bugzil.la/933276 "External link (opens in new tab)")).
    
*   [`Proxy.revocable()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/revocable) has been implemented ([Firefox bug 978279](https://bugzil.la/978279 "External link (opens in new tab)")).
    

### [Interfaces/APIs/DOM](#interfacesapisdom)

*   The [`Element.matches()`](/en-US/docs/Web/API/Element/matches) method has been added; it does what the non-standard `mozMatchesSelector()` was doing ([Firefox bug 886308](https://bugzil.la/886308 "External link (opens in new tab)")).
    
*   The [`Performance.now()`](/en-US/docs/Web/API/Performance/now) method is now available to Web workers ([Firefox bug 908390](https://bugzil.la/908390 "External link (opens in new tab)")).
    
*   The non-standard interface `MozNamedAttrMap` has been renamed to the standard [`NamedNodeMap`](/en-US/docs/Web/API/NamedNodeMap) and [`Element.attributes`](/en-US/docs/Web/API/Element/attributes) has been adapted to use it ([Firefox bug 1055467](https://bugzil.la/1055467 "External link (opens in new tab)")).
    
*   The [`Path2D.addPath()`](/en-US/docs/Web/API/Path2D/addPath) method has been added ([Firefox bug 985801](https://bugzil.la/985801 "External link (opens in new tab)")).
    
*   The non-standard Device Storage API is now also enabled for privileged apps installed on Android ([Firefox bug 886627](https://bugzil.la/886627 "External link (opens in new tab)")).
    
*   Web Crypto API has been enabled by default ([Firefox bug 1074001](https://bugzil.la/1074001 "External link (opens in new tab)")).
    
*   The [`MediaStreamTrack.stop()`](/en-US/docs/Web/API/MediaStreamTrack/stop) method has been added ([Firefox bug 1057955](https://bugzil.la/1057955 "External link (opens in new tab)")).
    
*   Our experimental implementation of EME continues. The `MediaKeySession.getUsableKeyIds()` method has been added ([Firefox bug 1057171](https://bugzil.la/1057171 "External link (opens in new tab)")).
    
*   Regarding [WebRTC](/en-US/docs/Web/API/WebRTC_API):
    
    *   an experiment implementation of `RTPSender` and `RTPReceiver` working with [`RTCPeerConnection`](/en-US/docs/Web/API/RTCPeerConnection) has landed ([Firefox bug 1032835](https://bugzil.la/1032835 "External link (opens in new tab)")).
    *   application window sharing has been added to [`Navigator.getUserMedia()`](/en-US/docs/Web/API/Navigator/getUserMedia) ([Firefox bug 1036653](https://bugzil.la/1036653 "External link (opens in new tab)")) and `MediaTrackConstraintSet` now supports `browserWindow` and `scrollWithPage` allowing you to chose the tab of a window that has to be shared without showing the tab chooser dialog ([Firefox bug 1041700](https://bugzil.la/1041700 "External link (opens in new tab)")).
    *   `"browser"` is now an accepted value of MediaSourceEnum, used to define constraints ([Firefox bug 1041493](https://bugzil.la/1041493 "External link (opens in new tab)")).
*   For Web Components, event retargeting is now implemented ([Firefox bug 887541](https://bugzil.la/887541 "External link (opens in new tab)")).
    
*   The [`Headers`](/en-US/docs/Web/API/Headers) interface has been implemented ([Firefox bug 1029620](https://bugzil.la/1029620 "External link (opens in new tab)")). It is controlled by the `dom.fetch.enabled` preference which is set to `false` by default.
    
*   Regarding our experimental implementation of Web Animations, the [`AnimationEffect`](/en-US/docs/Web/API/AnimationEffect) interface has been added, with the single `AnimationEffect.name` property ([Firefox bug 1045993](https://bugzil.la/1045993 "External link (opens in new tab)")). Web Animations is not activated by default and is controlled by the `dom.animations-api.core.enabled` preference.
    
*   CSSOM View smooth scrolling methods have been added: [`Window.scroll()`](/en-US/docs/Web/API/Window/scroll), [`Window.scrollTo()`](/en-US/docs/Web/API/Window/scrollTo), and [`Window.scrollBy()`](/en-US/docs/Web/API/Window/scrollBy) ([Firefox bug 1022818](https://bugzil.la/1022818 "External link (opens in new tab)")).
    
*   The non-standard `MozSmsSegmentInfo` is no more visible on the global object [Firefox bug 916607](https://bugzil.la/916607 "External link (opens in new tab)").

### [Add-on SDK](#add-on_sdk)

#### Highlights

*   New API: [dev/panel](https://web.archive.org/web/20210517043357/https://developer.mozilla.org/en-US/docs/Archive/Add-ons/Add-on_SDK/Low-Level_APIs/dev_panel "External link (opens in new tab)") enables you to extend the Firefox Developer Tools.
*   [jpm](https://web.archive.org/web/20210221222338/https://developer.mozilla.org/en-US/docs/Archive/Add-ons/Add-on_SDK/Tools/jpm "External link (opens in new tab)") beta released.
*   `"./my-file"` introduced everywhere as an alias for `require("sdk/self").data.url("my-file")`
*   Added the ability to [attach stylesheets to individual tabs](/en-US/docs/Mozilla/Add-ons/WebExtensions/Working_with_the_Tabs_API#manipulating_a_tabs_css).
