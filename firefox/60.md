# Firefox 60 release notes for developers

This article provides information about the changes in Firefox 60 that will affect developers. Firefox 60 was released on May 9, 2018.

## [Stylo comes to Firefox for Android in 60](#stylo_comes_to_firefox_for_android_in_60)

[Firefox's new parallel CSS engine](https://hacks.mozilla.org/2017/08/inside-a-super-fast-css-engine-quantum-css-aka-stylo/ "External link (opens in new tab)") — also known as **Quantum CSS** or **Stylo** — which was [first enabled by default in Firefox 57 for desktop](/en-US/docs/Mozilla/Firefox/Releases/57#firefox_57_firefox_quantum), has now been enabled in Firefox for Android.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   In the CSS Pane rules view (see [Examine and edit CSS](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_css/index.html "External link (opens in new tab)")), the keyboard shortcuts for precise value increments (increase/decrease by 0.1) have changed from `Alt` + `Up`/`Down` to `Ctrl` + `Up`/`Down` on Linux and Windows, to avoid clashes with default OS-level shortcuts (see [Firefox bug 1413314](https://bugzil.la/1413314 "External link (opens in new tab)")).
*   Also in the CSS Pane rules view, [CSS variable names](/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties) will now auto-complete ([Firefox bug 1422635](https://bugzil.la/1422635 "External link (opens in new tab)")). If you enter `var(` into a property value and then type a dash (`-`), any variables you have declared in your CSS will then appear in an autocomplete list.
*   In [Responsive Design Mode](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html "External link (opens in new tab)"), a _Reload when…_ dropdown has been added to allow users to enable/disable automatic page reloads when touch simulation is toggled, or simulated user agent is changed. See [Controlling page reload behavior](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html#controlling-page-reload-behavior "External link (opens in new tab)") for more details ([Firefox bug 1428816](https://bugzil.la/1428816 "External link (opens in new tab)")).
*   The `view_source.tab` preference has been removed so you can no longer toggle [View Source](https://firefox-source-docs.mozilla.org/devtools-user/view_source/index.html "External link (opens in new tab)") mode between appearing in a new tab or new window. Page sources will always appear in new tabs from now on ([Firefox bug 1418403](https://bugzil.la/1418403 "External link (opens in new tab)")).

### [HTML](#html)

Pressing the Enter key in `designMode` and `contenteditable` now inserts `<div>` elements when the caret is in an inline element or text node which is a child of a block level editing host — instead of inserting `<br>` elements like it used to. If you want to use the old behavior on your app, you can do it with `document.execCommand()` ([Firefox bug 1430551](https://bugzil.la/1430551 "External link (opens in new tab)")).

### [CSS](#css)

*   The [`align-content`](/en-US/docs/Web/CSS/Reference/Properties/align-content), [`align-items`](/en-US/docs/Web/CSS/Reference/Properties/align-items), [`align-self`](/en-US/docs/Web/CSS/Reference/Properties/align-self), [`justify-content`](/en-US/docs/Web/CSS/Reference/Properties/justify-content), and [`place-content`](/en-US/docs/Web/CSS/Reference/Properties/place-content) property values have been updated as per the latest [CSS Box Alignment Module Level 3](https://drafts.csswg.org/css-align-3/ "External link (opens in new tab)") spec ([Firefox bug 1430817](https://bugzil.la/1430817 "External link (opens in new tab)")).
*   The [`paint-order`](/en-US/docs/Web/CSS/Reference/Properties/paint-order) property has been implemented ([Firefox bug 1426146](https://bugzil.la/1426146 "External link (opens in new tab)")).

### [SVG](#svg)

_No changes._

### [JavaScript](#javascript)

*   ECMAScript 2015 modules have been enabled by default in ([Firefox bug 1438139](https://bugzil.la/1438139 "External link (opens in new tab)")). See [ES6 In Depth: Modules](https://hacks.mozilla.org/2015/08/es6-in-depth-modules/ "External link (opens in new tab)") and [ES modules: A cartoon deep dive](https://hacks.mozilla.org/2018/03/es-modules-a-cartoon-deep-dive/ "External link (opens in new tab)") for more information, or consult MDN reference docs:
    
    *   [`<script src="main.js" type="module">`](/en-US/docs/Web/HTML/Reference/Elements/script/type) and [`<script nomodule src="fallback.js">`](/en-US/docs/Web/HTML/Reference/Elements/script#nomodule)
    *   [`import`](/en-US/docs/Web/JavaScript/Reference/Statements/import) and [`export`](/en-US/docs/Web/JavaScript/Reference/Statements/export) statements.
*   The [`Array.prototype.values()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/values) method has been added again ([Firefox bug 1420101](https://bugzil.la/1420101 "External link (opens in new tab)")). Make sure your code doesn't have any custom implementation of this method.
    

### [APIs](#apis)

#### New APIs

*   The [Web Authentication API](/en-US/docs/Web/API/Web_Authentication_API) has been enabled in ([Firefox bug 1432542](https://bugzil.la/1432542 "External link (opens in new tab)")).

#### DOM

*   In the [Web Authentication API](/en-US/docs/Web/API/Web_Authentication_API), the `MakePublicKeyCredentialOptions` dictionary object has been renamed `PublicKeyCredentialCreationOptions`; this change has been made in Firefox ([Firefox bug 1436473](https://bugzil.la/1436473 "External link (opens in new tab)")).
*   The `dom.workers.enabled` pref has been removed, meaning workers can no longer be disabled since ([Firefox bug 1434934](https://bugzil.la/1434934 "External link (opens in new tab)")).
*   The [`body`](/en-US/docs/Web/API/Document/body "body") property is now implemented on the [`Document`](/en-US/docs/Web/API/Document) interface, rather than the [`HTMLDocument`](/en-US/docs/Web/API/HTMLDocument) interface ([Firefox bug 1276438](https://bugzil.la/1276438 "External link (opens in new tab)")).
*   [`PerformanceResourceTiming`](/en-US/docs/Web/API/PerformanceResourceTiming) is now available in workers ([Firefox bug 1425458](https://bugzil.la/1425458 "External link (opens in new tab)")).
*   The [`PerformanceObserver.takeRecords()`](/en-US/docs/Web/API/PerformanceObserver/takeRecords) method has been implemented ([Firefox bug 1436692](https://bugzil.la/1436692 "External link (opens in new tab)")).
*   The [`KeyboardEvent.keyCode`](/en-US/docs/Web/API/KeyboardEvent/keyCode) attribute of punctuation key becomes non-zero even if the active keyboard layout doesn't produce ASCII characters. See [these notes for more detail](/en-US/docs/Web/API/KeyboardEvent/keyCode#printable_keys_in_standard_position). Please do **not** use `KeyboardEvent.keyCode` in new applications — use [`KeyboardEvent.key`](/en-US/docs/Web/API/KeyboardEvent/key) or [`KeyboardEvent.code`](/en-US/docs/Web/API/KeyboardEvent/code) instead.
*   The [`Animation.updatePlaybackRate()`](/en-US/docs/Web/API/Animation/updatePlaybackRate) method has been implemented ([Firefox bug 1436659](https://bugzil.la/1436659 "External link (opens in new tab)")).
*   New rules have been included for determining [keyCode values of punctuation keys](/en-US/docs/Web/API/KeyboardEvent/keyCode#printable_keys_in_standard_position) ([Firefox bug 1036008](https://bugzil.la/1036008 "External link (opens in new tab)")).
*   The Gecko-only options object `storage` option of the [`IDBFactory.open()`](/en-US/docs/Web/API/IDBFactory/open) method has been deprecated ([Firefox bug 1442560](https://bugzil.la/1442560 "External link (opens in new tab)")).
*   [Promises](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) can now be used within [IndexedDB](/en-US/docs/Web/API/IndexedDB_API) code ([Firefox bug 1193394](https://bugzil.la/1193394 "External link (opens in new tab)")).

#### DOM events

_No changes._

#### Service workers

_No changes._

#### Media and WebRTC

*   When recording or sharing media obtained using [`getUserMedia()`](/en-US/docs/Web/API/MediaDevices/getUserMedia "getUserMedia()"), muting the camera by setting the corresponding track's [`MediaStreamTrack.enabled`](/en-US/docs/Web/API/MediaStreamTrack/enabled) property to `false` now turns off the camera's "in use" indicator light, to help the user more easily see that the camera is not in use ([Firefox bug 1299515](https://bugzil.la/1299515 "External link (opens in new tab)")). See [User privacy](/en-US/docs/Web/API/MediaDevices/getUserMedia#user_privacy) for more details. See also [this blog post](https://blog.mozilla.org/webrtc/better-privacy-on-camera-mute-in-firefox-60/ "External link (opens in new tab)").
*   Removing a track from an [`RTCPeerConnection`](/en-US/docs/Web/API/RTCPeerConnection) using [`removeTrack()`](/en-US/docs/Web/API/RTCPeerConnection/removeTrack "removeTrack()") no longer removes the track's [`RTCRtpSender`](/en-US/docs/Web/API/RTCRtpSender) from the peer connection's list of senders as reported by [`getSenders()`](/en-US/docs/Web/API/RTCPeerConnection/getSenders "getSenders()") ([Firefox bug 1290949](https://bugzil.la/1290949 "External link (opens in new tab)")).
*   The `RTCRtpContributingSource` and `RTCRtpSynchronizationSource` objects' timestamps were previously being reported based on values returned by [`Date.getTime()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime). In Firefox 60, these have been fixed to correctly use the [Performance Timing API](/en-US/docs/Web/API/Performance_API) instead ([Firefox bug 1433576](https://bugzil.la/1433576 "External link (opens in new tab)")).
*   As per spec, the [`ConvolverNode()`](/en-US/docs/Web/API/ConvolverNode/ConvolverNode "ConvolverNode()") constructor now throws a `NotSupportedError` [`DOMException`](/en-US/docs/Web/API/DOMException) if the referenced [`AudioBuffer`](/en-US/docs/Web/API/AudioBuffer) does not have 1, 2, or 4 channels ([Firefox bug 1443228](https://bugzil.la/1443228 "External link (opens in new tab)")).
*   The obsolete [`RTCPeerConnection`](/en-US/docs/Web/API/RTCPeerConnection) event handler [`RTCPeerConnection.onremovestream`](/en-US/docs/Web/API/RTCPeerConnection/removestream_event "RTCPeerConnection.onremovestream") has been removed; by now you should be using [`removetrack`](/en-US/docs/Web/API/MediaStream/removetrack_event "removetrack") events instead ([Firefox bug 1442385](https://bugzil.la/1442385 "External link (opens in new tab)")).
*   The primary name for [`RTCDataChannel`](/en-US/docs/Web/API/RTCDataChannel) is now in fact `RTCDataChannel`, instead of being an alias for `DataChannel`. The name `DataChannel` is no longer supported ([Firefox bug 1173851](https://bugzil.la/1173851 "External link (opens in new tab)")).

#### Canvas and WebGL

*   If the `privacy.resistFingerprinting` preference is set to `true`, the [`WEBGL_debug_renderer_info`](/en-US/docs/Web/API/WEBGL_debug_renderer_info) WebGL extension will be disabled from now on ([Firefox bug 1337157](https://bugzil.la/1337157 "External link (opens in new tab)")).

### [CSSOM](#cssom)

_No changes._

### [HTTP](#http)

*   `SameSite` cookies are now supported ([Firefox bug 795346](https://bugzil.la/795346 "External link (opens in new tab)")). See [`Set-Cookie`](/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie) for more information.

### [Security](#security)

The [`X-Content-Type-Options`](/en-US/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options) header, when set to `no-sniff`, now follows the specification for JavaScript MIME types. In particular, `text/json` and `application/json` are no longer valid values ([Firefox bug 1431095](https://bugzil.la/1431095 "External link (opens in new tab)")).

### [Plugins](#plugins)

_No changes._

### [Other](#other)

Fetches that include credentials can now share connections with fetches that don't include credentials. For example, if the same origin requests some web fonts as well as some credentialed user data from the same CDN, both could share a connection, potentially leading to a quicker turnaround ([Firefox bug 1363284](https://bugzil.la/1363284 "External link (opens in new tab)")).

## [Removals from the web platform](#removals_from_the_web_platform)

### [HTML](#html_2)

_No changes._

### [CSS](#css_2)

*   The proprietary [`-moz-user-input`](/en-US/docs/Web/CSS/Reference/Properties/-moz-user-input) property's `enabled` and `disabled` values are no longer available ([Firefox bug 1405087](https://bugzil.la/1405087 "External link (opens in new tab)")).
*   The proprietary `-moz-border-top-colors`, `-moz-border-right-colors`, `-moz-border-bottom-colors`, and `-moz-border-left-colors` properties have been removed from the platform completely ([Firefox bug 1429723](https://bugzil.la/1429723 "External link (opens in new tab)")).

### [JavaScript](#javascript_2)

The non-standard [expression closure](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#statements_2) syntax has been removed ([Firefox bug 1426519](https://bugzil.la/1426519 "External link (opens in new tab)")).

### [APIs](#apis_2)

_No changes._

### [SVG](#svg_2)

_No changes._

### [Other](#other_2)

_No changes._

## [Changes for add-on and Mozilla developers](#changes_for_add-on_and_mozilla_developers)

### [WebExtensions](#webextensions)

Theme API:

*   headerURL is now optional
*   When creating a browser [theme](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/theme), any [`text-shadow`](/en-US/docs/Web/CSS/Reference/Properties/text-shadow) applied to the header text is removed if no `headerURL` is specified (see [Firefox bug 1404688](https://bugzil.la/1404688 "External link (opens in new tab)")).
*   New properties are supported:
    *   **tab\_line**
    *   **tab\_selected**
    *   **popup**
    *   **popup\_border**
    *   **popup\_text**
    *   **tab\_loading**
    *   **icons**
    *   **icons\_attention**
    *   **frame\_inactive**
    *   **button\_background\_active**
    *   **button\_background\_hover**
