# Firefox 63 release notes for developers

This article provides information about the changes in Firefox 63 that will affect developers. Firefox 63 was released on October 23, 2018.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   The Fonts tab in the [Page Inspector](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/index.html "External link (opens in new tab)") now includes an editor that makes it easy to view and edit the settings of the fonts on your page. See [Edit fonts](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/edit_fonts/index.html "External link (opens in new tab)") for details.
*   The [Accessibility inspector](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html "External link (opens in new tab)") is now enabled by default ([Firefox bug 1482454](https://bugzil.la/1482454 "External link (opens in new tab)")).
*   When you hover over an object in the [Accessibility Inspector](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html "External link (opens in new tab)"), [the item is highlighted](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html#highlighting-of-ui-items "External link (opens in new tab)") and its role and name will be shown in an information bar on the page ([Firefox bug 1473030](https://bugzil.la/1473030 "External link (opens in new tab)")).
*   The command line in the [Web Console](https://firefox-source-docs.mozilla.org/devtools-user/web_console/index.html "External link (opens in new tab)") is now shown immediately following the console output ([Firefox bug 1136299](https://bugzil.la/1136299 "External link (opens in new tab)")).
*   A new icon has been added to the content in the [Network Monitor](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html "External link (opens in new tab)") to indicate when a URL belongs to a known tracker — see [security icons](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/request_list/index.html#network-monitor-request-list-security-icons "External link (opens in new tab)") ([Firefox bug 1333994](https://bugzil.la/1333994 "External link (opens in new tab)")).
*   The default value of `devtools.aboutdebugging.showSystemAddons` is now `false`, meaning that system add-ons will not be listed on the `about:debugging` page. You can change the settings by navigating to `about:config` ([Firefox bug 1425347](https://bugzil.la/1425347 "External link (opens in new tab)")).
*   The [Responsive Design Mode](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html "External link (opens in new tab)") toolbar was simplified, and we added the option to left-align the viewport.
*   The Page Inspector includes a [link to the class definition](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_html/index.html#custom-element-definition "External link (opens in new tab)") for a custom element. ([Firefox bug 1443923](https://bugzil.la/1443923 "External link (opens in new tab)")).

### [HTML](#html)

*   Support for the [`<img>`](/en-US/docs/Web/HTML/Reference/Elements/img) element's `decoding` attribute has been added ([Firefox bug 1416328](https://bugzil.la/1416328 "External link (opens in new tab)")); see also [`HTMLImageElement.decoding`](/en-US/docs/Web/API/HTMLImageElement/decoding).

#### Removals

*   Support for the `sidebar` link type (`rel="sidebar"`) has been removed. If an anchor tag includes this attribute, it will be ignored ([Firefox bug 1452645](https://bugzil.la/1452645 "External link (opens in new tab)")).

### [CSS](#css)

*   Support for the [`:defined`](/en-US/docs/Web/CSS/Reference/Selectors/:defined) pseudo-class has been added ([Firefox bug 1331334](https://bugzil.la/1331334 "External link (opens in new tab)")).
*   Support for [`row-gap`](/en-US/docs/Web/CSS/Reference/Properties/row-gap), [`column-gap`](/en-US/docs/Web/CSS/Reference/Properties/column-gap) and [`gap`](/en-US/docs/Web/CSS/Reference/Properties/gap) have been added in [Flexbox layout](/en-US/docs/Web/CSS/Guides/Box_alignment/In_flexbox#the_gap_properties) ([Firefox bug 1398483](https://bugzil.la/1398483 "External link (opens in new tab)")).
*   Re-enabled support for [webkit-prefixed pixel-density @media queries](/en-US/docs/Web/CSS/Reference/At-rules/@media/-webkit-device-pixel-ratio) ([Firefox bug 1444139](https://bugzil.la/1444139 "External link (opens in new tab)")).
*   Support added for the [CSS Flexible Box Layout](/en-US/docs/Web/CSS/Guides/Flexible_box_layout) (Flexbox) properties [`align-self`](/en-US/docs/Web/CSS/Reference/Properties/align-self), [`align-content`](/en-US/docs/Web/CSS/Reference/Properties/align-content), and [`align-items`](/en-US/docs/Web/CSS/Reference/Properties/align-items) as well as the [`justify-content`](/en-US/docs/Web/CSS/Reference/Properties/justify-content) property ([Firefox bug 1472843](https://bugzil.la/1472843 "External link (opens in new tab)")).
*   Implemented the `path()` function for [`offset-path`](/en-US/docs/Web/CSS/Reference/Properties/offset-path) ([Firefox bug 1429298](https://bugzil.la/1429298 "External link (opens in new tab)")).
*   Implemented syntax improvements from the Media Queries Level 4 specification, notably [nested boolean expressions](/en-US/docs/Web/CSS/Guides/Media_queries/Using#creating_complex_media_queries) and the [range syntax](/en-US/docs/Web/CSS/Guides/Media_queries/Using#targeting_media_features) ([Firefox bug 1422225](https://bugzil.la/1422225 "External link (opens in new tab)")).
*   Renamed `offset-*` properties to [`inset-block-start`](/en-US/docs/Web/CSS/Reference/Properties/inset-block-start), [`inset-block-end`](/en-US/docs/Web/CSS/Reference/Properties/inset-block-end), [`inset-inline-start`](/en-US/docs/Web/CSS/Reference/Properties/inset-inline-start), and [`inset-inline-end`](/en-US/docs/Web/CSS/Reference/Properties/inset-inline-end) ([Firefox bug 1464782](https://bugzil.la/1464782 "External link (opens in new tab)")).
*   Added support for the [prefers-reduced-motion](/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion) media feature ([Firefox bug 1365045](https://bugzil.la/1365045 "External link (opens in new tab)"), [Firefox bug 1475462](https://bugzil.la/1475462 "External link (opens in new tab)")).
*   Added flow relative values (`block`, `inline`) for the [`resize`](/en-US/docs/Web/CSS/Reference/Properties/resize) property ([Firefox bug 1464786](https://bugzil.la/1464786 "External link (opens in new tab)")).
*   Implemented flexbox layout for `safe` & `unsafe` values in [`align-self`](/en-US/docs/Web/CSS/Reference/Properties/align-self), [`align-content`](/en-US/docs/Web/CSS/Reference/Properties/align-content), and [`justify-content`](/en-US/docs/Web/CSS/Reference/Properties/justify-content) ([Firefox bug 1297774](https://bugzil.la/1297774 "External link (opens in new tab)")).
*   The [logical properties](/en-US/docs/Web/CSS/Guides/Logical_properties_and_values) (where appropriate) are now animatable ([Firefox bug 1309752](https://bugzil.la/1309752 "External link (opens in new tab)")).

#### Removals

*   Removed `offset-block-start`, `offset-block-end`, `offset-inline-start`, and `offset-inline-end`; these have been renamed to `inset-*`, as described above ([Firefox bug 1464782](https://bugzil.la/1464782 "External link (opens in new tab)")).

### [SVG](#svg)

_No changes._

### [JavaScript](#javascript)

*   The [`Symbol.prototype.description`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/description) property has been implemented ([Firefox bug 1472170](https://bugzil.la/1472170 "External link (opens in new tab)")).
*   The [`Object.fromEntries()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/fromEntries) method has been added ([Firefox bug 1469019](https://bugzil.la/1469019 "External link (opens in new tab)")).
*   When you try to access a property of an undefined object, the error message is now much improved. Considering the case where `x` is undefined and you try to access `x.y`, instead of "TypeError: x is undefined" the console now returns the more descriptive [x is undefined; can't access its "y" property](/en-US/docs/Web/JavaScript/Reference/Errors/Unexpected_type) ([Firefox bug 1259822](https://bugzil.la/1259822 "External link (opens in new tab)")).

#### Removals

*   Experimental WebAssembly Module IndexedDB serialization support has been removed ([Firefox bug 1469395](https://bugzil.la/1469395 "External link (opens in new tab)")).

### [APIs](#apis)

#### New APIs

*   The Shadow DOM ([Firefox bug 1471947](https://bugzil.la/1471947 "External link (opens in new tab)")) and Custom Elements ([Firefox bug 1471948](https://bugzil.la/1471948 "External link (opens in new tab)")) APIs have been enabled by default; see [Web components](/en-US/docs/Web/API/Web_components) for more details.
*   The [Media Capabilities API](/en-US/docs/Web/API/Media_Capabilities_API "Media Capabilities API") has been implemented ([Firefox bug 1409664](https://bugzil.la/1409664 "External link (opens in new tab)")).
*   The [Async Clipboard API](/en-US/docs/Web/API/Clipboard "Async Clipboard API") has been implemented and enabled by default for all channels ([Firefox bug 1461465](https://bugzil.la/1461465 "External link (opens in new tab)")). As is the case with Chrome, Firefox currently implements only the [`writeText()`](/en-US/docs/Web/API/Clipboard/writeText "writeText()") and [`readText()`](/en-US/docs/Web/API/Clipboard/readText "readText()") methods; however, unlike Chrome, `readText()` is only available in [browser extensions](/en-US/docs/Mozilla/Add-ons/WebExtensions).
*   The [`SecurityPolicyViolationEvent`](/en-US/docs/Web/API/SecurityPolicyViolationEvent) interface is now supported. It allows sending events when the [`Content-Security-Policy`](/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy) is violated ([Firefox bug 1472661](https://bugzil.la/1472661 "External link (opens in new tab)")).

#### DOM

*   The following portions of the [Web Animations API](/en-US/docs/Web/API/Web_Animations_API "Web Animations API") have been enabled by default (see [Firefox bug 1476158](https://bugzil.la/1476158 "External link (opens in new tab)")):
    
    *   The [`Animation`](/en-US/docs/Web/API/Animation) properties [`ready`](/en-US/docs/Web/API/Animation/ready "ready") and [`finished`](/en-US/docs/Web/API/Animation/finished "finished"), specifying the `Animation` object's `ready` and `finished` [`Promise`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)s.
    *   The [`Animation`](/en-US/docs/Web/API/Animation) object's [`effect`](/en-US/docs/Web/API/Animation/effect "effect") property.
    *   The interfaces [`KeyframeEffect`](/en-US/docs/Web/API/KeyframeEffect) and [`AnimationEffect`](/en-US/docs/Web/API/AnimationEffect).
*   The [`Element.toggleAttribute()`](/en-US/docs/Web/API/Element/toggleAttribute) method has been implemented ([Firefox bug 1469592](https://bugzil.la/1469592 "External link (opens in new tab)")).
    
*   The historical, previously non-standard, [`Event.returnValue`](/en-US/docs/Web/API/Event/returnValue) property is now supported for compatibility purposes ([Firefox bug 1452569](https://bugzil.la/1452569 "External link (opens in new tab)")).
    
*   We implemented the [`Window.event`](/en-US/docs/Web/API/Window/event) property to improve web compatibility, now that it's become standard ([Firefox bug 218415](https://bugzil.la/218415 "External link (opens in new tab)")). However, due to some web compat issues (e.g., [Firefox bug 1479964](https://bugzil.la/1479964 "External link (opens in new tab)")), this was quickly disabled in non-Nightly channels, hidden behind the `dom.window.event.enabled` pref ([Firefox bug 1493869](https://bugzil.la/1493869 "External link (opens in new tab)")).
    
*   To bring Firefox into alignment with Edge and Chrome, the [`navigator.platform`](/en-US/docs/Web/API/Navigator/platform "navigator.platform") property now returns `"Win32"` even when running on 64-bit Windows ([Firefox bug 1472618](https://bugzil.la/1472618 "External link (opens in new tab)")).
    
*   Prior to Firefox 63, links that open new windows that had `rel="noopener"`, as well as calls to [`Window.open()`](/en-US/docs/Web/API/Window/open) with the [`noopener`](/en-US/docs/Web/API/Window/open) window feature enabled would default to having all window features disabled so that you had to explicitly re-enable any standard features you wanted. Now, these windows have the same set of features enabled like any other window, and you need to explicitly turn off any you don't want ([Firefox bug 1419960](https://bugzil.la/1419960 "External link (opens in new tab)")).
    

#### DOM events

*   Handling of the `Alt` key _on the right side_ of the keyboard has been improved on Windows. If the user's current keyboard layout maps the `Alt` key to the `AltGr` modifier key, the value of [`KeyboardEvent.key`](/en-US/docs/Web/API/KeyboardEvent/key) is now reported as `"AltGraph"`. This behavior matches the behavior recently introduced in Chrome ([Firefox bug 900750](https://bugzil.la/900750 "External link (opens in new tab)")).

#### Media, Web Audio, and WebRTC

*   Microphone access now works simultaneously in multiple tabs, even within the same content process ([Firefox bug 1404977](https://bugzil.la/1404977 "External link (opens in new tab)")).
*   [`RTCDataChannel`](/en-US/docs/Web/API/RTCDataChannel) has been updated to support the sctp-sdp-21 data format for the data, in addition to the older sctp-sdp-05 format previously supported.
*   The [`ConstantSourceNode`](/en-US/docs/Web/API/ConstantSourceNode) node type for Web Audio API now has a default channel count of 2 rather than 1, in order to match the specification ([Firefox bug 1413283](https://bugzil.la/1413283 "External link (opens in new tab)")).
*   The [Web Audio API](/en-US/docs/Web/API/Web_Audio_API "Web Audio API") interface [`AudioScheduledSourceNode`](/en-US/docs/Web/API/AudioScheduledSourceNode) (and by extension, all the other node types based on it) now throw the correct exception when a negative value is specified for the node start time. That error is `RangeError` ([Firefox bug 1413284](https://bugzil.la/1413284 "External link (opens in new tab)")).
*   The minimum and maximum permitted values for an [`AudioParam`](/en-US/docs/Web/API/AudioParam) object's [`value`](/en-US/docs/Web/API/AudioParam/value "value") have been changed to the minimum negative single-precision floating-point value (-340,282,346,638,528,859,811,704,183,484,516,925,440) and the maximum positive single-precision floating-point value (+340,282,346,638,528,859,811,704,183,484,516,925,440) respectively ([Firefox bug 1476695](https://bugzil.la/1476695 "External link (opens in new tab)")).
*   The [`SourceBuffer.changeType`](/en-US/docs/Web/API/SourceBuffer/changeType) method, which allows you to change codecs during an active stream, has been enabled by default. This is part of the [Media Source Extensions API](/en-US/docs/Web/API/Media_Source_Extensions_API "Media Source Extensions API") ([Firefox bug 1481166](https://bugzil.la/1481166 "External link (opens in new tab)")).
*   The [`AudioParam.setValueCurveAtTime()`](/en-US/docs/Web/API/AudioParam/setValueCurveAtTime) method has been updated to correctly accept an array of floating-point values to indicate the parameter's values to change to over time. Previously, it required a [`Float32Array`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Float32Array) ([Firefox bug 1421091](https://bugzil.la/1421091 "External link (opens in new tab)")).
*   [`AudioParam.setValueCurveAtTime()`](/en-US/docs/Web/API/AudioParam/setValueCurveAtTime) has also been updated to correctly return a proper `TypeError` when a non-finite value is found in the `values` array ([Firefox bug 1472095](https://bugzil.la/1472095 "External link (opens in new tab)")).
*   In addition, `setValueCurveAtTime()` has been updated to ensure that, when the parameter finishes following the specified value curve after the duration elapses, the value of the parameter is set to the last value in the list of values to curve through ([Firefox bug 1308436](https://bugzil.la/1308436 "External link (opens in new tab)")).
*   The `RTCRTPStreamStats` dictionary has been renamed to `RTCRtpStreamStats` for consistency with other WebRTC dictionaries and the specification ([Firefox bug 1480498](https://bugzil.la/1480498 "External link (opens in new tab)")).
*   Support for the `RTCRtpStreamStats` dictionary's `kind` property has been added ([Firefox bug 1481851](https://bugzil.la/1481851 "External link (opens in new tab)")).
*   The `RTCRtpStreamStats` dictionary's `isRemote` property is deprecated and will be removed in Firefox 65. A warning is now output to console when this property is accessed. See [this blog post on the Advancing WebRTC blog](https://blog.mozilla.org/webrtc/getstats-isremote-65/ "External link (opens in new tab)") for details ([Firefox bug 1393306](https://bugzil.la/1393306 "External link (opens in new tab)")).

#### Canvas and WebGL

*   A new `powerPreference` context attribute has been added to [`HTMLCanvasElement.getContext()`](/en-US/docs/Web/API/HTMLCanvasElement/getContext). On macOS this allows WebGL non-performance-critical applications and applets to request the low-power GPU instead of the high-power GPU in multi-GPU systems ([Firefox bug 1349799](https://bugzil.la/1349799 "External link (opens in new tab)")).

#### Removals

*   The obsolete and non-standard Firefox-only methods `Window.back()` and `Window.forward()` have been removed. Please use the [`window.history.back()`](/en-US/docs/Web/API/History/back "window.history.back()") and [`window.history.forward()`](/en-US/docs/Web/API/History/forward "window.history.forward()") methods instead ([Firefox bug 1479486](https://bugzil.la/1479486 "External link (opens in new tab)")).
*   The [`URL.createObjectURL()`](/en-US/docs/Web/API/URL/createObjectURL_static "URL.createObjectURL()") and [`URL.revokeObjectURL()`](/en-US/docs/Web/API/URL/revokeObjectURL_static "URL.revokeObjectURL()") methods are no longer available on [`ServiceWorker`](/en-US/docs/Web/API/ServiceWorker) instances due to the potential they introduced for memory leaks to occur ([Firefox bug 1264182](https://bugzil.la/1264182 "External link (opens in new tab)")).
*   Since it was deprecated in the specification anyway, the limited support for Doppler effects on [`PannerNode`](/en-US/docs/Web/API/PannerNode) has been removed from the Web Audio API. The [`AudioListener`](/en-US/docs/Web/API/AudioListener) properties `dopplerFactor` and `speedOfSound` have been removed, along with the `PannerNode` method `setVelocity()` ([Firefox bug 1148354](https://bugzil.la/1148354 "External link (opens in new tab)")).

### [Security](#security)

*   Site favicons are now subject to [Content Security Policy](/en-US/docs/Web/HTTP/Guides/CSP) if one is configured for the site ([Firefox bug 1297156](https://bugzil.la/1297156 "External link (opens in new tab)")).
*   CSP `script-src` directive's `'report-sample'` expression now recognized when generating violation reports. This directive indicates that a short sample of where the violation occurred should be included in the report. Previously, Firefox always included this sample ([Firefox bug 1473218](https://bugzil.la/1473218 "External link (opens in new tab)")).
*   Firefox now uses NSS 3.39 ([Firefox bug 1470914](https://bugzil.la/1470914 "External link (opens in new tab)")).

_No changes._

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

#### New features

*   Marionette now returns a `setWindowRect` [capability](/en-US/docs/Web/WebDriver/Reference/Capabilities) in the `WebDriver:NewSession` response that is true if the browser window can be repositioned and resized, which e.g., is the case for Firefox but not any mobile applications ([Firefox bug 1470659](https://bugzil.la/1470659 "External link (opens in new tab)")).
*   Added support for the `unhandledPromptBehavior` capability, which allows you to define a specific [prompt behavior](https://w3c.github.io/webdriver/#dfn-user-prompt-handler "External link (opens in new tab)") of the WebDriver specification ([Firefox bug 1264259](https://bugzil.la/1264259 "External link (opens in new tab)")).
*   Handling of user prompts has been added to the `WebDriver:ExecuteScript` and `WebDriver:ExecuteAsyncScript` commands ([Firefox bug 1439995](https://bugzil.la/1439995 "External link (opens in new tab)")).

#### API changes

*   Deprecated command end-points without the `WebDriver:` prefix have been removed ([Firefox bug 1451725](https://bugzil.la/1451725 "External link (opens in new tab)")).
*   The `WebDriver:NewSession` command returns recommended strings (`linux`, `mac`, `windows`) for `platformName` as defined in the WebDriver specification ([Firefox bug 1470646](https://bugzil.la/1470646 "External link (opens in new tab)")).

#### Bug fixes

*   Focus related events were missing on element interaction when Firefox was not running as the top-most application ([Firefox bug 1398111](https://bugzil.la/1398111 "External link (opens in new tab)")).
*   Performing a `pointerDown` and `pointerUp` action in a subsequent action sequence could trigger a double click because `WebDriver:ReleaseActions` didn't reset the double click tracker ([Firefox bug 1422583](https://bugzil.la/1422583 "External link (opens in new tab)")).
*   Executing `pause` actions repeatedly could cause an infinite hang ([Firefox bug 1447449](https://bugzil.la/1447449 "External link (opens in new tab)")).
*   Fixed a bug where returning an element collection from `WebDriver:ExecuteScript` and `WebDriver:ExecuteAsyncScript` would cause a cyclic reference error ([Firefox bug 1447977](https://bugzil.la/1447977 "External link (opens in new tab)")).
*   To prevent a race condition both the `WebDriver:AcceptAlert` and `WebDriver:DismissAlert` commands now wait until the user prompt has been closed ([Firefox bug 1479368](https://bugzil.la/1479368 "External link (opens in new tab)")).
*   Log entries as emitted by the frame script were no longer limited by `MarionettePrefs.logLevel` but logged everything ([Firefox bug 1482829](https://bugzil.la/1482829 "External link (opens in new tab)")).
*   `WebDriver:TakeScreenshot` raised an error when taking a screenshot of a window larger than 32767 pixels in width or height ([Firefox bug 1485730](https://bugzil.la/1485730 "External link (opens in new tab)")).
*   `WebDriver:SendAlertText` didn't replace default user prompt value if text to send is an empty string ([Firefox bug 1486485](https://bugzil.la/1486485 "External link (opens in new tab)")).

### [Other](#other)

*   Corrected the behavior of [`PerformanceObserver.observe()`](/en-US/docs/Web/API/PerformanceObserver/observe) to do nothing if no valid entry types are found in the specified array of entry types to observe, or if the array is empty or missing. Previously, Firefox was incorrectly throwing a `TypeError` ([Firefox bug 1403027](https://bugzil.la/1403027 "External link (opens in new tab)")).
*   In [OpenSearch](/en-US/docs/Web/XML/Guides/OpenSearch), Firefox now accepts `application/json` as a search URL type, as an alias of `application/x-suggestions+json` ([Firefox bug 1425827](https://bugzil.la/1425827 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

### [API changes](#api_changes_2)

#### Theming

*   The default text color for [`browserAction`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserAction) badges is now automatically set to black or white, to maximize contrast with the background ([Firefox bug 1474110](https://bugzil.la/1474110 "External link (opens in new tab)")).
    
*   The `accentcolor` and `textcolor` properties of the [`theme`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/theme) manifest key are now optional ([Firefox bug 1413144](https://bugzil.la/1413144 "External link (opens in new tab)")).
    
*   [`browserAction.getBadgeTextColor()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserAction/getBadgeTextColor) and [`browserAction.setBadgeTextColor()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserAction/setBadgeTextColor) enable you to get and set the text color of browser action badges ([Firefox bug 1424620](https://bugzil.la/1424620 "External link (opens in new tab)")).
    
*   The theme `colors` key in `manifest.json` now supports the `ntp_text` property to set the text color in a new tab, and the `ntp_background` property to set the color of a new tab ([Firefox bug 1347204](https://bugzil.la/1347204 "External link (opens in new tab)")).
    
*   Themes can now define the colors for sidebars, such as the bookmarks sidebar ([Firefox bug 1418602](https://bugzil.la/1418602 "External link (opens in new tab)")). The relevant properties include:
    
    *   `sidebar`: The background color for sidebars.
    *   `sidebar_text`: The text color for sidebars.
    *   `sidebar_highlight`: The background color of a selected item in a sidebar.
    *   `sidebar_highlight_text`: The text color of a selected item in a sidebar.
*   The method [`management.install()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/management/install) allows web extensions to install and enable signed browser themes ([Firefox bug 1369209](https://bugzil.la/1369209 "External link (opens in new tab)")).
    
*   The manifest key [theme\_experiment](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/theme_experiment) was introduced ([Firefox bug 1472740](https://bugzil.la/1472740 "External link (opens in new tab)")). This key enables the definition of experimental [`theme`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/theme) key properties for the Firefox interface.
    

#### Search

*   The new [`search`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/search) API enables you to retrieve the list of installed search engines and perform searches with them ([Firefox bug 1352598](https://bugzil.la/1352598 "External link (opens in new tab)")).
*   [`topSites.get()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/topSites/get) now takes an `options` parameter enabling you to set various options for the list of sites returned ([Firefox bug 1445836](https://bugzil.la/1445836 "External link (opens in new tab)")).

#### Tabs

*   [`tabs.onHighlighted`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/onHighlighted) now supports multi-select ([Firefox bug 1474440](https://bugzil.la/1474440 "External link (opens in new tab)")).
*   [`tabs.highlight`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/highlight) now includes an optional field in the `highlightInfo` object — `populate` — which defaults to `true`. Setting it to `false` prevents the returned `windows.Window` object from being populated with a list of tabs, to improve performance ([Firefox bug 1489814](https://bugzil.la/1489814 "External link (opens in new tab)")).
*   [`tabs.update`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/update) now supports changing the selection status of a tab by including `highlighted: true` in the `updateProperties` parameter ([Firefox bug 1479129](https://bugzil.la/1479129 "External link (opens in new tab)")).
*   [`tabs.update`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/update) now supports changing the selection status of a tab without changing the focused tab ([Firefox bug 1486050](https://bugzil.la/1486050 "External link (opens in new tab)")) by including both `highlighted: true` and `active: false` in the `updateProperties` parameter.
*   [`tabs.query`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/query) now returns an array of [`tabs.Tab`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/Tab) objects if multiple tabs are selected ([Firefox bug 1465170](https://bugzil.la/1465170 "External link (opens in new tab)")).
*   The [`tabs.Tab`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/Tab) property now properly reflects which tabs in a browser window are selected (highlighted) and [`tabs.highlight`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/highlight) supports changing the highlighted status of multiple tabs ([Firefox bug 1464862](https://bugzil.la/1464862 "External link (opens in new tab)")).
*   The `isarticle` property in the `filter` object passed into [`tabs.onUpdated`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/onUpdated) has been renamed to `isArticle`. The old name is retained but deprecated. This change was uplifted to Firefox 62 ([Firefox bug 1461695](https://bugzil.la/1461695 "External link (opens in new tab)")).
*   The [`tabs.onUpdated`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/onUpdated) event can be used to track when a tab is drawing the user's attention with `attention` property of the `changeInfo` object ([Firefox bug 1396684](https://bugzil.la/1396684 "External link (opens in new tab)")).

#### Menus

*   Added [`menus.getTargetElement()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus/getTargetElement) to the [`menus`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus) API. The method returns the element referenced by the `targetElementId` parameter that identifies the clicked element. If the `targetElementId` is no longer valid, the method returns null ([Firefox bug 1325814](https://bugzil.la/1325814 "External link (opens in new tab)")).
*   [`menus.create()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus/create) now enables you to create invisible menu items, and [`menus.update()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus/update) enables you to toggle menu item visibility ([Firefox bug 1482529](https://bugzil.la/1482529 "External link (opens in new tab)")).
*   Items created using the [`menus`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus) API now support access keys ([Firefox bug 1320462](https://bugzil.la/1320462 "External link (opens in new tab)")).
*   The `targetUrlPatterns` parameter of [`menus.create()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus/create) and [`menus.update()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus/update) now supports any URL scheme, even those that are usually not allowed in a match pattern ([Firefox bug 1280370](https://bugzil.la/1280370 "External link (opens in new tab)")).
*   When a tab context menu item is clicked, the [`activeTab` permission](/en-US/docs/Mozilla/Add-ons/WebExtensions/activeTab_permission) is now granted for that tab, even if that's not the currently active tab ([Firefox bug 1446956](https://bugzil.la/1446956 "External link (opens in new tab)")).

#### Other

*   [`commands.onCommand`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/commands/onCommand) is now treated as [user input](/en-US/docs/Mozilla/Add-ons/WebExtensions/User_actions) ([Firefox bug 1408129](https://bugzil.la/1408129 "External link (opens in new tab)")).
*   The [`webRequest`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest) API now enables you to filter for speculative connections ([Firefox bug 1479565](https://bugzil.la/1479565 "External link (opens in new tab)")).
*   [`webRequest.SecurityInfo`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest/SecurityInfo) adds two new properties, `keaGroupName`, and `signatureSchemeName`. This change was uplifted to Firefox 62 ([Firefox bug 1471959](https://bugzil.la/1471959 "External link (opens in new tab)")).
*   [`cookies.Cookie`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/cookies/Cookie) now includes a property indicating the SameSite state of the cookie. The [`cookies.SameSiteStatus`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/cookies/SameSiteStatus) enumeration defines SameSite state values ([Firefox bug 1351663](https://bugzil.la/1351663 "External link (opens in new tab)")).
*   Match patterns for URLs now explicitly match the "data" URL scheme ([Firefox bug 1280370](https://bugzil.la/1280370 "External link (opens in new tab)")).
