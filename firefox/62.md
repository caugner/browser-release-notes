# Firefox 62 release notes for developers

This article provides information about the changes in Firefox 62 that will affect developers. Firefox 62 was released on September 5, 2018.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   The Shape Path Editor is now available by default — see [Edit Shape Paths in CSS](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/edit_css_shapes/index.html "External link (opens in new tab)") for more information.
    
*   You can now split the Rules view out into its own pane, separate from the other tabs on the CSS pane. See [Page inspector 3-pane mode](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/3-pane_mode/index.html "External link (opens in new tab)") for more details.
    
*   The Grid inspector has updated features, and all new documentation — see [CSS Grid Inspector: Examine grid layouts](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_grid_layouts/index.html "External link (opens in new tab)").
    
*   You now have four options for the location of the Developer Tools. In addition to the default location on the bottom of the window, you can choose to locate the tools on either the left or right sides of the main window or in a separate window ([Firefox bug 1192642](https://bugzil.la/1192642 "External link (opens in new tab)")).
    
*   A close button has been added to the [split console](https://firefox-source-docs.mozilla.org/devtools-user/web_console/split_console/index.html "External link (opens in new tab)") toolbar.
    
*   If the option to "Select an iframe as the currently targeted document" is checked, the icon will appear in the toolbar while the Settings tab is displayed, even if the current page doesn't include any iframes ([Firefox bug 1456069](https://bugzil.la/1456069 "External link (opens in new tab)")).
    
*   The [Network Monitor](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html "External link (opens in new tab)")'s [Cookies tab](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html#cookies "External link (opens in new tab)") now shows the cookie `samesite` attribute ([Firefox bug 1452715](https://bugzil.la/1452715 "External link (opens in new tab)")).
    
*   [Responsive design mode](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html "External link (opens in new tab)") now works inside container tabs ([Firefox bug 1306975](https://bugzil.la/1306975 "External link (opens in new tab)")).
    
*   When [CORS](/en-US/docs/Glossary/CORS) errors occur and are reported on the console, Firefox now provides a link to the corresponding page in our [CORS error documentation](/en-US/docs/Web/HTTP/Guides/CORS/Errors) ([Firefox bug 1475391](https://bugzil.la/1475391 "External link (opens in new tab)")).
    
*   Create a screenshot of the current page (with an optional filename) from the Console tab ([Firefox bug 1464461](https://bugzil.la/1464461 "External link (opens in new tab)")) using the following command:
    
    bash
    
    ```
    :screenshot <filename.png> --fullpage
    ```
    
    where `<filename.png>` is the desired filename. The file will be saved to your downloads folder. The `--fullpage` parameter is optional, but if included, it will save the full web page. This option also adds `-fullpage` to the name of the file. For a list of all options available for this command, enter: `:screenshot --help`
    

#### Removals

*   The _Developer Toolbar/GCLI_ (accessed with `Shift` + `F2`), **has been removed** from Firefox ([Firefox bug 1461970](https://bugzil.la/1461970 "External link (opens in new tab)")). Both the Developer Toolbar UI and the GCLI upstream library have become unmaintained, some of its features are broken (some ever since e10s), it is blocking the `unsafeSetInnerHTML` work, usage numbers are very low, alternatives exist for the most used commands.

### [HTML](#html)

_No changes._

### [CSS](#css)

*   `:-moz-selection` has been unprefixed to [`::selection`](/en-US/docs/Web/CSS/Reference/Selectors/::selection) ([Firefox bug 509958](https://bugzil.la/509958 "External link (opens in new tab)")).
*   `x` is now supported as a unit for the [`<resolution>`](/en-US/docs/Web/CSS/Reference/Values/resolution) type ([Firefox bug 1460655](https://bugzil.la/1460655 "External link (opens in new tab)")).
*   [`shape-margin`](/en-US/docs/Web/CSS/Reference/Properties/shape-margin), [`shape-outside`](/en-US/docs/Web/CSS/Reference/Properties/shape-outside), and [`shape-image-threshold`](/en-US/docs/Web/CSS/Reference/Properties/shape-image-threshold) are now enabled by default ([Firefox bug 1457297](https://bugzil.la/1457297 "External link (opens in new tab)")).

#### Removals

*   All XUL `display` values with the exception of `-moz-box` and `-moz-inline-box` have been removed from non-XUL documents in [Firefox bug 1288572](https://bugzil.la/1288572 "External link (opens in new tab)").

### [SVG](#svg)

_No changes._

### [JavaScript](#javascript)

*   The [`WebAssembly.Global()`](/en-US/docs/WebAssembly/Reference/JavaScript_interface/Global) constructor is now supported, along with global variables in WebAssembly ([Firefox bug 1464656](https://bugzil.la/1464656 "External link (opens in new tab)")).
*   The [`Array.prototype.flat()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/flat) and [`Array.prototype.flatMap()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/flatMap) methods are now enabled by default ([Firefox bug 1435813](https://bugzil.la/1435813 "External link (opens in new tab)")).
*   The [`import.meta`](/en-US/docs/Web/JavaScript/Reference/Operators/import.meta) property has been implemented to expose context-specific metadata to a JavaScript module ([Firefox bug 1427610](https://bugzil.la/1427610 "External link (opens in new tab)")).
*   JavaScript [string literals](/en-US/docs/Web/JavaScript/Reference/Lexical_grammar#string_literals) may now directly contain the U+2028 LINE SEPARATOR and U+2029 PARAGRAPH SEPARATOR characters. As a consequence, [`JSON`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON) syntax is now a subset of JavaScript literal syntax (see [Firefox bug 1435828](https://bugzil.la/1435828 "External link (opens in new tab)") and the TC39 proposal [json-superset](https://github.com/tc39/proposal-json-superset "External link (opens in new tab)")).
*   For out-of-bounds [typed array](/en-US/docs/Web/JavaScript/Guide/Typed_arrays) indexes, [`Reflect.defineProperty()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Reflect/defineProperty) and [`Reflect.set()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Reflect/set) will now return `false` instead of `true` ([Firefox bug 1308735](https://bugzil.la/1308735 "External link (opens in new tab)")).

#### Removals

*   The `DOMPoint` and `DOMPointReadOnly` constructors no longer support an input parameter of type `DOMPointInit`; the values of the properties must be specified using the `x`, `y`, `z`, and `w` parameters ([Firefox bug 1186265](https://bugzil.la/1186265 "External link (opens in new tab)")).
*   The [`URL.createObjectURL()`](/en-US/docs/Web/API/URL/createObjectURL_static "URL.createObjectURL()") method no longer supports creating object URLs to represent a [`MediaStream`](/en-US/docs/Web/API/MediaStream). This capability has been obsolete for some time, since you can now set [`HTMLMediaElement.srcObject`](/en-US/docs/Web/API/HTMLMediaElement/srcObject) to the `MediaStream` directly ([Firefox bug 1454889](https://bugzil.la/1454889 "External link (opens in new tab)")).

### [APIs](#apis)

#### New APIs

*   The [Speech Synthesis API (Text-to-Speech)](/en-US/docs/Web/API/Web_Speech_API "Speech Synthesis API (Text-to-Speech)") is now enabled by default on Firefox for Android ([Firefox bug 1463496](https://bugzil.la/1463496 "External link (opens in new tab)")).

#### DOM

*   The [`DOMPointReadOnly`](/en-US/docs/Web/API/DOMPointReadOnly) interface now supports the static function [`DOMPointReadOnly.fromPoint()`](/en-US/docs/Web/API/DOMPointReadOnly/fromPoint_static "DOMPointReadOnly.fromPoint()"), which creates a new point object from a dictionary that's compatible with `DOMPointInit`, which includes any [`DOMPoint`](/en-US/docs/Web/API/DOMPoint) object. This function is also available on [`DOMPoint`](/en-US/docs/Web/API/DOMPoint) ([Firefox bug 1186265](https://bugzil.la/1186265 "External link (opens in new tab)")).
*   For compatibility purposes, the [`Event.srcElement`](/en-US/docs/Web/API/Event/srcElement) property is now supported. It is an alias for [`Event.target`](/en-US/docs/Web/API/Event/target) ([Firefox bug 453968](https://bugzil.la/453968 "External link (opens in new tab)")).
*   [`Navigator.registerProtocolHandler()`](/en-US/docs/Web/API/Navigator/registerProtocolHandler) now must only be called from a secure context ([Firefox bug 1460506](https://bugzil.la/1460506 "External link (opens in new tab)")).
*   The `Navigator.registerContentHandler()` method has been disabled by default in preparation for being removed entirely, as it's been obsolete for some time ([Firefox bug 1460481](https://bugzil.la/1460481 "External link (opens in new tab)")).
*   The [`DataTransfer()`](/en-US/docs/Web/API/DataTransfer/DataTransfer "DataTransfer()") constructor has been implemented ([Firefox bug 1351193](https://bugzil.la/1351193 "External link (opens in new tab)")).
*   [`Document.domain`](/en-US/docs/Web/API/Document/domain) can no longer return `null` ([Firefox bug 819475](https://bugzil.la/819475 "External link (opens in new tab)")). If the domain cannot be identified, then `domain` returns an empty string instead of `null`.
*   Added the [`console.timeLog()`](/en-US/docs/Web/API/console/timeLog_static "console.timeLog()") method to display the current value of a console timer while continuing to track the time ([Firefox bug 1458466](https://bugzil.la/1458466 "External link (opens in new tab)")).
*   Added [`console.countReset()`](/en-US/docs/Web/API/console/countReset_static "console.countReset()") to reset a console counter value ([Firefox bug 1459279](https://bugzil.la/1459279 "External link (opens in new tab)")).

#### DOM events

_No changes._

#### Service workers

_No changes._

#### Media, Web Audio, and WebRTC

*   The `"media.autoplay.enabled"` preference now controls automatic playback of both audio and video media, instead of just video media ([Firefox bug 1413098](https://bugzil.la/1413098 "External link (opens in new tab)")).
*   The [`ChannelSplitterNode`](/en-US/docs/Web/API/ChannelSplitterNode) has been fixed to correctly default to having 6 channels with the `channelInterpretation` set to `"discrete"` and the `channelCountMode` set to `"explicit"`, as per the specification ([Firefox bug 1456265](https://bugzil.la/1456265 "External link (opens in new tab)")).

#### Removals

*   The `userproximity` and `deviceproximity` events, as well as the `UserProximityEvent` and `DeviceProximityEvent` interfaces, have been disabled by default behind the `device.sensors.proximity.enabled` preference ([Firefox bug 1462308](https://bugzil.la/1462308 "External link (opens in new tab)")).
*   The `devicelight` event of type `DeviceLightEvent` has been disabled by default behind the `device.sensors.ambientLight.enabled` preference ([Firefox bug 1462308](https://bugzil.la/1462308 "External link (opens in new tab)")).
*   The `DOMSubtreeModified` and `DOMAttrModified` [mutation events](/en-US/docs/Web/API/MutationEvent) are no longer thrown when the [`style`](/en-US/docs/Web/HTML/Reference/Global_attributes/style) attribute is changed via the CSSOM ([Firefox bug 1460295](https://bugzil.la/1460295 "External link (opens in new tab)").
*   Support for [`CSSStyleDeclaration.getPropertyCSSValue()`](/en-US/docs/Web/API/CSSStyleDeclaration/getPropertyCSSValue) has been removed ([Firefox bug 1408301](https://bugzil.la/1408301 "External link (opens in new tab)")).
*   Support for [`CSSValue`](/en-US/docs/Web/API/CSSValue), [`CSSPrimitiveValue`](/en-US/docs/Web/API/CSSPrimitiveValue), and [`CSSValueList`](/en-US/docs/Web/API/CSSValueList) has been removed ([Firefox bug 1459871](https://bugzil.la/1459871 "External link (opens in new tab)")).
*   [`window.getComputedStyle()`](/en-US/docs/Web/API/Window/getComputedStyle) no longer returns `null` when called on a `Window` which has no presentation ([Firefox bug 1467722](https://bugzil.la/1467722 "External link (opens in new tab)")).

### [HTTP](#http)

#### Removals

*   The deprecated CSP `referrer` directive has been removed. Please use the [`Referrer-Policy`](/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy) header instead ([Firefox bug 1302449](https://bugzil.la/1302449 "External link (opens in new tab)")).

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

#### New features

*   Command `WebDriver:ElementSendKeys` has been made WebDriver conforming for file uploads ([Firefox bug 1448792](https://bugzil.la/1448792 "External link (opens in new tab)")).
*   User prompts as raised by `beforeunload` events are automatically dismissed for `WebDriver:Get`, `WebDriver:Back`, `WebDriver:Forward`, `WebDriver:Refresh`, and `WebDriver:Close` commands ([Firefox bug 1434872](https://bugzil.la/1434872 "External link (opens in new tab)")).
*   `WebDriver:PerformActions` for `Ctrl` + `Click` synthesizes a [`contextmenu`](/en-US/docs/Web/API/Element/contextmenu_event "contextmenu") event ([Firefox bug 1421323](https://bugzil.la/1421323 "External link (opens in new tab)")).

#### API changes

*   Removed obsolete endpoints including `getWindowPosition`, `setWindowPosition`, `getWindowSize`, and `setWindowSize` ([Firefox bug 1348145](https://bugzil.la/1348145 "External link (opens in new tab)")).
*   WebDriver commands which return success with data `null` now return an empty dictionary ([Firefox bug 1461463](https://bugzil.la/1461463 "External link (opens in new tab)")).

#### Bug fixes

*   `WebDriver:ExecuteScript` caused cyclic reference error for WebElement collections ([Firefox bug 1447977](https://bugzil.la/1447977 "External link (opens in new tab)")).
*   Dispatching a `pointerMove` or `pause` action primitive could cause a hang, and the command to never send a reply ([Firefox bug 1467743](https://bugzil.la/1467743 "External link (opens in new tab)"), [Firefox bug 1447449](https://bugzil.la/1447449 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

### [API changes](#api_changes_2)

*   Added the [`webRequest.getSecurityInfo()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest/getSecurityInfo) API to examine details of TLS connections ([Firefox bug 1322748](https://bugzil.la/1322748 "External link (opens in new tab)")).
*   Added the [`browserSettings.newTabPosition`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings/newTabPosition) to customize where new tabs open ([Firefox bug 1344749](https://bugzil.la/1344749 "External link (opens in new tab)")).
*   `windowTypes` has been deprecated in [`windows.get()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/windows/get), [`windows.getCurrent()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/windows/getCurrent), and [`windows.getLastFocused()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/windows/getLastFocused) ([Firefox bug 1419132](https://bugzil.la/1419132 "External link (opens in new tab)")).
*   It's now possible to modify a browser action on a per-window basis ([Firefox bug 1419893](https://bugzil.la/1419893 "External link (opens in new tab)")).

### [Manifest changes](#manifest_changes)

*   New `open_at_install` property of the [`sidebar_action`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/sidebar_action) manifest key enables extensions to control whether their sidebars should open automatically on install or not ([Firefox bug 1460910](https://bugzil.la/1460910 "External link (opens in new tab)")).
*   Changes to the `browser_style` property of various manifest keys:
    *   In [`page_action`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/page_action) and [`browser_action`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/browser_action) it defaults to `false`.
    *   In [`sidebar_action`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/sidebar_action) and [`options_ui`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/options_ui) it defaults to `true`.

### [Theme changes](#theme_changes)

*   New `tab_background_separator` property of the [`theme`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/theme) manifest key enables extensions to change the color of the tab separator ([Firefox bug 1459455](https://bugzil.la/1459455 "External link (opens in new tab)")).

### [Removals](#removals_6)

*   Support for unpacked sideloaded extensions has been removed ([Firefox bug 1385057](https://bugzil.la/1385057 "External link (opens in new tab)")).
*   The warning about `browser_style` displayed when temporarily loading an extension for testing is no longer displayed ([Firefox bug 1404724](https://bugzil.la/1404724 "External link (opens in new tab)")).
