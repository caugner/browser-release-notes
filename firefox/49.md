# Firefox 49 release notes for developers

[To test the latest developer features of Firefox, install Firefox Developer Edition](https://www.firefox.com/en-US/channel/desktop/developer/ "External link (opens in new tab)") Firefox 49 was released on September 20, 2016. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

*   JavaScript errors logged into the console [now provide a \[Learn more\] link](https://hacks.mozilla.org/2016/06/helping-web-developers-with-javascript-errors/ "External link (opens in new tab)") for additional debugging help ([Firefox bug 1179876](https://bugzil.la/1179876 "External link (opens in new tab)")).
    
*   CSS autocomplete: show more suggestions in autocomplete popup ([Firefox bug 1260419](https://bugzil.la/1260419 "External link (opens in new tab)")).
    
*   The Animation Inspector now [exposes animation performance information](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/work_with_animations/index.html#further-information-about-animation-compositing "External link (opens in new tab)") in DevTools ([Firefox bug 1254408](https://bugzil.la/1254408 "External link (opens in new tab)")).
    
*   The [Inspector's context menu](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_html/index.html#element-popup-context-menu "External link (opens in new tab)") has been reorganized to be cleaner and easier to use ([Firefox bug 1211613](https://bugzil.la/1211613 "External link (opens in new tab)")).
    
*   The Inspector now supports `#RRGGBBAA` and `#RGBA` syntax for color values ([Firefox bug 1271191](https://bugzil.la/1271191 "External link (opens in new tab)")).
    
*   The developer tools no longer display self-closing tags (such as [`<br>`](/en-US/docs/Web/HTML/Reference/Elements/br) and [`<img>`](/en-US/docs/Web/HTML/Reference/Elements/img) as if they have a closing tag on HTML pages; the behavior is unchanged for XHTML pages ([Firefox bug 820926](https://bugzil.la/820926 "External link (opens in new tab)")).
    
*   Accessibility improvements!
    
    *   The toolbox does a better job of ensuring that keyboard focus is more visible ([Firefox bug 1242851](https://bugzil.la/1242851 "External link (opens in new tab)")).
    *   Accessibility labels have been added to unlabeled controls ([Firefox bug 1242715](https://bugzil.la/1242715 "External link (opens in new tab)")).
    *   Added proper tree view semantics and keyboard navigation to the Inspector's markup view ([Firefox bug 1242694](https://bugzil.la/1242694 "External link (opens in new tab)")).
*   The [Network Monitor](https://firefox-source-docs.mozilla.org/devtools-user/network_monitor/index.html "External link (opens in new tab)") now shows a Cause column, which provides an indication of what caused each particular network request ([Firefox bug 1134073](https://bugzil.la/1134073 "External link (opens in new tab)")).
    
*   In the _about:debugging_ Add-ons page, the Reload button is only enabled for temporary add-ons. It will be disabled for all other add-ons ([Firefox bug 1273184](https://bugzil.la/1273184 "External link (opens in new tab)")).
    
*   In the _about:debugging_ Workers page, a warning message will be displayed in the Service Workers section if [service workers are incompatible](https://firefox-source-docs.mozilla.org/devtools-user/about_colon_debugging/index.html#service-workers-not-compatible "External link (opens in new tab)") with the current browser configuration ([Firefox bug 1266415](https://bugzil.la/1266415 "External link (opens in new tab)")).
    
*   _about:debugging_ now has a [new Tabs page](https://firefox-source-docs.mozilla.org/devtools-user/about_colon_debugging/index.html#tabs "External link (opens in new tab)") available, which provides a complete list of all the debuggable tabs open in the current Firefox instance ([Firefox bug 1266128](https://bugzil.la/1266128 "External link (opens in new tab)")).
    
*   The _Disable Cache_ option in the [Toolbox Advanced settings](https://firefox-source-docs.mozilla.org/devtools-user/settings/index.html#advanced-settings "External link (opens in new tab)") has been renamed to Disable HTTP Cache, to make it clearer that this affects the HTTP cache, and not [Service Workers](/en-US/docs/Web/API/Service_Worker_API)/the [Cache API](/en-US/docs/Web/API/Cache) (bug(1253018)).
    
*   The [Storage Inspector now allows IndexedDB databases to be deleted](https://firefox-source-docs.mozilla.org/devtools-user/storage_inspector/index.html#indexeddb "External link (opens in new tab)") via their own context menus ([Firefox bug 1205123](https://bugzil.la/1205123 "External link (opens in new tab)")), and will display warning messages if the IndexedDB cannot be deleted for some reason (if there are still active connections, for example) ([Firefox bug 1268460](https://bugzil.la/1268460 "External link (opens in new tab)")).
    

### [HTML](#html)

*   Added support for the [`<details>`](/en-US/docs/Web/HTML/Reference/Elements/details) and [`<summary>`](/en-US/docs/Web/HTML/Reference/Elements/summary) elements ([Firefox bug 1226455](https://bugzil.la/1226455 "External link (opens in new tab)")).
*   The [`pattern`](/en-US/docs/Web/HTML/Reference/Elements/input#pattern) attribute of the [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) element now uses the `'u'` parameter in the underlying JavaScript [`RegExp`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp) ([Firefox bug 1227906](https://bugzil.la/1227906 "External link (opens in new tab)")).
*   To match a spec change, an invalid value of the [`kind`](/en-US/docs/Web/HTML/Reference/Elements/track#kind) attribute of the [`<track>`](/en-US/docs/Web/HTML/Reference/Elements/track) element is now treated like `"metadata"` instead of `"subtitles"` ([Firefox bug 1269712](https://bugzil.la/1269712 "External link (opens in new tab)")).
*   The [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) element's [`sandbox`](/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox) attribute now supports the `'allow-popups-to-escape-sandbox'` and `'allow-modals'` values ([Firefox bug 1190641](https://bugzil.la/1190641 "External link (opens in new tab)")).
*   Support for microdata attributes and the Microdata API have been removed ([Firefox bug 909633](https://bugzil.la/909633 "External link (opens in new tab)")).
*   The [`referrerpolicy`](/en-US/docs/Web/HTML/Reference/Elements/a#referrerpolicy) attribute on the [`<a>`](/en-US/docs/Web/HTML/Reference/Elements/a) element now supports the `'no-referrer-when-downgrade'` and `'origin-when-cross-origin'` ([Firefox bug 1178337](https://bugzil.la/1178337 "External link (opens in new tab)")).
*   The `form` content attribute of the [`<label>`](/en-US/docs/Web/HTML/Reference/Elements/label) element has been removed. The [`HTMLLabelElement.form`](/en-US/docs/Web/API/HTMLLabelElement/form) property still exists, but now returns the form with which the label's control is associated, if there is a control (and if that control is associated with a form) ([Firefox bug 1268852](https://bugzil.la/1268852 "External link (opens in new tab)")).

### [CSS](#css)

*   Added [`background-position-x`](/en-US/docs/Web/CSS/Reference/Properties/background-position-x) and [`background-position-y`](/en-US/docs/Web/CSS/Reference/Properties/background-position-y), which allow separately specifying the horizontal and vertical offsets at which to draw a background image; these are components of [`background-position`](/en-US/docs/Web/CSS/Reference/Properties/background-position) ([Firefox bug 550426](https://bugzil.la/550426 "External link (opens in new tab)")).
    
*   Added support for the `round` and `space` keywords to [`background-repeat`](/en-US/docs/Web/CSS/Reference/Properties/background-repeat) ([Firefox bug 548372](https://bugzil.la/548372 "External link (opens in new tab)")).
    
*   On [`background-clip`](/en-US/docs/Web/CSS/Reference/Properties/background-clip), the keyword `text` is now activated by default ([Firefox bug 1264905](https://bugzil.la/1264905 "External link (opens in new tab)")).
    
*   Added support for specifying colors with an alpha channel using 4- and 8-digit CSS hex [color](/en-US/docs/Web/CSS/Reference/Values/color_value) values (#RRGGBBAA and #RGBA) ([Firefox bug 567283](https://bugzil.la/567283 "External link (opens in new tab)")).
    
*   The pseudo-class [`:dir`](/en-US/docs/Web/CSS/Reference/Selectors/:dir) has been unprefixed ([Firefox bug 859301](https://bugzil.la/859301 "External link (opens in new tab)")).
    
*   In our experimental implementation (not yet activated by default) of [`clip-path`](/en-US/docs/Web/CSS/Reference/Properties/clip-path), we can now interpolate between [`<basic-shape>`](/en-US/docs/Web/CSS/Reference/Values/basic-shape) values ([Firefox bug 1110460](https://bugzil.la/1110460 "External link (opens in new tab)")).
    
*   Added the [`q` length unit](/en-US/docs/Web/CSS/Reference/Values/length#q) ([Firefox bug 1274526](https://bugzil.la/1274526 "External link (opens in new tab)")).
    
*   The property [`text-align-last`](/en-US/docs/Web/CSS/Reference/Properties/text-align-last) has been unprefixed ([Firefox bug 1039541](https://bugzil.la/1039541 "External link (opens in new tab)")).
    
*   Added support for [`overflow-wrap`](/en-US/docs/Web/CSS/Reference/Properties/overflow-wrap), replacing `word-wrap` that is still supported as an alternative name ([Firefox bug 955857](https://bugzil.la/955857 "External link (opens in new tab)")).
    
*   Our experimental [CSS Grids](/en-US/docs/Web/CSS/Guides/Grid_layout) implementation has been improved:
    
    *   Implemented [`<percentage>`](/en-US/docs/Web/CSS/Reference/Values/percentage) for the `grid-gap`, `grid-row-gap`, and `grid-column-gap` properties ([Firefox bug 1266268](https://bugzil.la/1266268 "External link (opens in new tab)")).
    *   Implemented grid layout support for [`align-self`](/en-US/docs/Web/CSS/Reference/Properties/align-self), [`justify-self`](/en-US/docs/Web/CSS/Reference/Properties/justify-self) values `baseline` and `last-baseline` (aka "baseline self-alignment") ([Firefox bug 1221525](https://bugzil.la/1221525 "External link (opens in new tab)")).
    *   Implemented grid item baseline content alignment ([Firefox bug 1256429](https://bugzil.la/1256429 "External link (opens in new tab)")).
*   Our experimental [CSS Masks](/en-US/docs/Web/CSS/Guides/Masking) implementation has been improved:
    
    *   The [`mask-origin`](/en-US/docs/Web/CSS/Reference/Properties/mask-origin) property now uses `border-box` instead of `padding-box` as initial value, to match the spec ([Firefox bug 1258286](https://bugzil.la/1258286 "External link (opens in new tab)")).
    *   The [`mask-repeat`](/en-US/docs/Web/CSS/Reference/Properties/mask-repeat) property now supports the `space` and `round` values ([Firefox bug 1258626](https://bugzil.la/1258626 "External link (opens in new tab)")).
    *   Fixed an issue preventing the [`mask-position`](/en-US/docs/Web/CSS/Reference/Properties/mask-position) attribute from being animated ([Firefox bug 1273804](https://bugzil.la/1273804 "External link (opens in new tab)")).
*   The preference controlling [`text-emphasis`](/en-US/docs/Web/CSS/Reference/Properties/text-emphasis) has been removed, so support for this property can no longer be disabled ([Firefox bug 1229609](https://bugzil.la/1229609 "External link (opens in new tab)")).
    

### [JavaScript](#javascript)

*   The ES2015 [`getPrototypeOf()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/getPrototypeOf) and [`setPrototypeOf()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/setPrototypeOf) [`Proxy`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy) traps have been implemented ([Firefox bug 888969](https://bugzil.la/888969 "External link (opens in new tab)")).
*   The ES2015 [`RegExp.prototype[Symbol.match]()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/Symbol.match), [`RegExp.prototype[Symbol.replace]()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/Symbol.replace), [`RegExp.prototype[Symbol.search]()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/Symbol.search), and [`RegExp.prototype[Symbol.split]()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/Symbol.split) methods, and [`RegExp[Symbol.species]`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/Symbol.species) getter have been implemented ([Firefox bug 887016](https://bugzil.la/887016 "External link (opens in new tab)")).
*   The deprecated, non-standard `flags` argument of [`String.prototype.match`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/match)/[`search`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/search)/[`replace`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/replace) has been removed ([Firefox bug 1108382](https://bugzil.la/1108382 "External link (opens in new tab)")).
*   The behavior of the [`Date.parse()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/parse) method when parsing 2-digit years has been changed to be more interoperable with the Google Chrome browser ([Firefox bug 1265136](https://bugzil.la/1265136 "External link (opens in new tab)")).

### [Interfaces/APIs/DOM](#interfacesapisdom)

#### DOM & HTML DOM

*   The method [`DOMTokenList.supports()`](/en-US/docs/Web/API/DOMTokenList/supports) has been added ([Firefox bug 1257849](https://bugzil.la/1257849 "External link (opens in new tab)")).
*   The [`DOMTokenList.replace()`](/en-US/docs/Web/API/DOMTokenList/replace) method has been added ([Firefox bug 1224186](https://bugzil.la/1224186 "External link (opens in new tab)")).
*   Leading `'?'` characters are now ignored in the parameter of the [`URLSearchParams()`](/en-US/docs/Web/API/URLSearchParams/URLSearchParams "URLSearchParams()") constructor ([Firefox bug 1268361](https://bugzil.la/1268361 "External link (opens in new tab)")).
*   The value returned by [`URL.origin`](/en-US/docs/Web/API/URL/origin), [`HTMLAnchorElement.origin`](/en-US/docs/Web/API/HTMLAnchorElement/origin "HTMLAnchorElement.origin"), and [`HTMLAreaElement.origin`](/en-US/docs/Web/API/HTMLAnchorElement/origin "HTMLAreaElement.origin") for URL using the `blob:` scheme is no longer incorrectly `null` but is instead the origin of the URL formed by removing the leading `blob:` ([Firefox bug 1270451](https://bugzil.la/1270451 "External link (opens in new tab)")).
*   In prerendering mode, the [`Document.visibilityState`](/en-US/docs/Web/API/Document/visibilityState) property now returns `'prerender'` ([Firefox bug 1069772](https://bugzil.la/1069772 "External link (opens in new tab)")).
*   The [`Window.isSecureContext`](/en-US/docs/Web/API/Window/isSecureContext) property has been implemented ([Firefox bug 1162772](https://bugzil.la/1162772 "External link (opens in new tab)")).
*   The DOM4 [`Element.before`](/en-US/docs/Web/API/Element/before), [`Element.after`](/en-US/docs/Web/API/Element/after), [`Element.replaceWith`](/en-US/docs/Web/API/Element/replaceWith), [`Element.append`](/en-US/docs/Web/API/Element/append) and [`Element.prepend`](/en-US/docs/Web/API/Element/prepend) methods have been implemented ([Firefox bug 911477](https://bugzil.la/911477 "External link (opens in new tab)")).
*   The `TouchList.identifiedTouch()` method has been removed ([Firefox bug 1188539](https://bugzil.la/1188539 "External link (opens in new tab)")).
*   By default, the `scrollbars` [`Window`](/en-US/docs/Web/API/Window) feature is enabled when calling [`Window.open()`](/en-US/docs/Web/API/Window/open). In the past, while it was strongly recommended to enable it, it wasn't the default ([Firefox bug 1257887](https://bugzil.la/1257887 "External link (opens in new tab)")).
*   Added the _experimental_ and _non-standard_ [`HTMLMediaElement.seekToNextFrame()`](/en-US/docs/Web/API/HTMLMediaElement/seekToNextFrame) method, which allows seeking frame-by-frame through video content ([Firefox bug 1235301](https://bugzil.la/1235301 "External link (opens in new tab)")). While you're encouraged to experiment with this method to help us understand how useful it is, _do not use it in production code!_
*   The [`HTMLLabelElement.form`](/en-US/docs/Web/API/HTMLLabelElement/form) property now returns the form with which the label's control is associated, if there is a control (and if that control is associated with a form). Previously, labels were directly associated with forms using this property ([Firefox bug 1268852](https://bugzil.la/1268852 "External link (opens in new tab)")).
*   Support for the third parameter of [`EventTarget.addEventListener()`](/en-US/docs/Web/API/EventTarget/addEventListener), either a [`Boolean`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Boolean) or an `EventListenerOptions` has been added ([Firefox bug 1266164](https://bugzil.la/1266164 "External link (opens in new tab)") and [Firefox bug 1266066](https://bugzil.la/1266066 "External link (opens in new tab)")).
*   The audio volume related values for [`KeyboardEvent.key`](/en-US/docs/Web/API/KeyboardEvent/key) have been renamed. `"VolumeDown"` is now `"AudioVolumeDown"`, `"VolumeUp"` is now `"AudioVolumeUp"`, and `"VolumeMute"` is now `"AudioVolumeMute"`. This brings Firefox into alignment with the latest draft of the UI Events specification ([Firefox bug 1272578](https://bugzil.la/1272578 "External link (opens in new tab)")). See [Code values for keyboard events](/en-US/docs/Web/API/UI_Events/Keyboard_event_code_values) for a full list of available key codes.
*   The keys previously referred to as `"MozHomeScreen"`, `"MozCameraFocusAdjust"`, and `"MozPhoneCall"` now have official names in the UI Events specification: `"GoHome"`, `"CameraFocus"`, and `"Call"`. Firefox 49 has been updated to use the new names ([Firefox bug 1272599](https://bugzil.la/1272599 "External link (opens in new tab)")). See [Code values for keyboard events](/en-US/docs/Web/API/UI_Events/Keyboard_event_code_values) for a full list of available key codes.
*   The key values `"Separator"` and `"MediaSkip"` have been removed, as they were deprecated and unused ([Firefox bug 1232919](https://bugzil.la/1232919 "External link (opens in new tab)")).
*   Key values and the corresponding key codes `"Hyper"` and `"Super"` have been added to represent these legacy modifier keys ([Firefox bug 1232919](https://bugzil.la/1232919 "External link (opens in new tab)")).
*   Two key values for multimedia numeric keypad keys have been added: `"Key11"` and `"Key12"` ([Firefox bug 1232919](https://bugzil.la/1232919 "External link (opens in new tab)")).
*   The following new key values have been added for audio control keys: `"AudioBassBoostToggle"`, `"AudioTrebleDown"`, and `"AudioTrebleUp"` ([Firefox bug 123919](https://bugzil.la/123919 "External link (opens in new tab)")).
*   Key values have been added for these microphone control keys: `MicrophoneToggle`, `MicrophoneVolumeDown`, `MicrophoneVolumeUp`, and `MicrophoneVolumeMute` ([Firefox bug 123919](https://bugzil.la/123919 "External link (opens in new tab)")).
*   New key values have been added to support speech recognition devices: `SpeechCorrectionList` and `SpeechInputToggle` ([Firefox bug 1232919](https://bugzil.la/1232919 "External link (opens in new tab)")).
*   New key values have been added to support special buttons on phones: `AppSwitch`, `Call`, `CameraFocus`, `EndCall`, `GoBack`, `GoHome`, `HeadsetHook`, `LastNumberRedial`, `Notification`, `MannerMode`, and `VoiceDial` ([Firefox bug 1232919](https://bugzil.la/1232919 "External link (opens in new tab)")).
*   These new application key values have been added: `LaunchContacts` and `LaunchPhone` ([Firefox bug 1232919](https://bugzil.la/1232919 "External link (opens in new tab)")).
*   New key values have been added to support television devices: `TV3DMode`, `TVAntennaCable`, `TVAudioDescription`, `TVAudioDescriptionMixDown`, `TVAudioDescriptionMixUp`, `TVContentsMenu`, `TVDataService`, `TVInput`, `TVInputComponent1`, `TVInputComponent2`, `TVInputComposite1`, `TVInputComposite2`, `TVInputHDMI1`, `TVInputHDMI2`, `TVInputHDMI3`, `TVInputHDMI4`, `TVInputVGA1`, `TVMediaContext`, `TVNetwork`, `TVNumberEntry`, `TVRadioService`, `TVSatellite`, `TVSatelliteBS`, `TVSatelliteCS`, `TVSatelliteToggle`, `TVTerrestrialAnalog`, `TVTerrestrialDigital`, `TVTimer`, and `DVR` ([Firefox bug 1232919](https://bugzil.la/1232919 "External link (opens in new tab)")).
*   The key value `MediaSelect` has been replaced with the standard `LaunchMediaPlayer` key value ([Firefox bug 1272592](https://bugzil.la/1272592 "External link (opens in new tab)")).
*   Additional media player key values have been added as well. These are `MediaAudioTrack`, `MediaSkipBackward`, `MediaSkipForward`, `MediaStepBackward`, `MediaStepForward`, `MediaTopMenu`, `NavigateIn`, `NavigateNext`, `NavigateOut`, and `NavigatePrevious` ([Firefox bug 1232919](https://bugzil.la/1232919 "External link (opens in new tab)")).

#### Canvas

*   The [`CanvasRenderingContext2D.filter`](/en-US/docs/Web/API/CanvasRenderingContext2D/filter) property, which provides support for adding filters to a canvas, is now activated by default and no longer needs to be enabled using a preference ([Firefox bug 1173545](https://bugzil.la/1173545 "External link (opens in new tab)")).

#### WebGL

*   The [`EXT_color_buffer_float`](/en-US/docs/Web/API/EXT_color_buffer_float) [WebGL 2](/en-US/docs/Web/API/WebGL2RenderingContext "WebGL 2") extension has been implemented ([Firefox bug 1129332](https://bugzil.la/1129332 "External link (opens in new tab)")).
*   The [`webglcontextcreationerror`](/en-US/docs/Web/API/HTMLCanvasElement/webglcontextcreationerror_event "webglcontextcreationerror") event, which is sent when a WebGL context creation attempt fails, has been implemented ([Firefox bug 1271478](https://bugzil.la/1271478 "External link (opens in new tab)")). Use this to help understand what went wrong, both for debugging and for production error handling.

#### IndexedDB

*   You can now rename IndexedDB indexes; the [`IDBIndex.name`](/en-US/docs/Web/API/IDBIndex/name) property is no longer read-only ([Firefox bug 1118028](https://bugzil.la/1118028 "External link (opens in new tab)")).
*   You can also now rename [`IDBObjectStore`](/en-US/docs/Web/API/IDBObjectStore)s; the [`IDBObjectStore.name`](/en-US/docs/Web/API/IDBObjectStore/name) property is no longer read-only ([Firefox bug 1118028](https://bugzil.la/1118028 "External link (opens in new tab)")).

#### Service Workers and related

*   The [Fetch API](/en-US/docs/Web/API/Fetch_API)'s [`Response`](/en-US/docs/Web/API/Response) object now implements the [`redirected`](/en-US/docs/Web/API/Response/redirected "redirected") property, which indicates whether or not the response is for a request which was redirected. Please review the security related notes in the documentation before using this property ([Firefox bug 1243792](https://bugzil.la/1243792 "External link (opens in new tab)")).
*   In the [Permissions API](/en-US/docs/Web/API/Permissions_API), Firefox no longer supports the 'push' `PermissionDescriptor` dictionary type (referred to in the spec as `PushPermissionDescriptor`); this is because Firefox relies on a quota system for controlling the `userVisibleOnly` status instead, and was throwing an error when it encountered a `PushPermissionDescriptor` instance ([Firefox bug 1266821](https://bugzil.la/1266821 "External link (opens in new tab)")). With this dictionary removed, Firefox now ignores it.

#### Media Streams

*   In the past, it was possible for a call to [`MediaDevices.getUserMedia()`](/en-US/docs/Web/API/MediaDevices/getUserMedia) which requests both audio and video to succeed in cases where the user has only one of the two types of hardware available. This has been fixed ([Firefox bug 802326](https://bugzil.la/802326 "External link (opens in new tab)")).
*   In prior versions of Firefox, it was possible for a call to [`MediaDevices.getUserMedia()`](/en-US/docs/Web/API/MediaDevices/getUserMedia) which requests both audio and video to succeed even though the user denied access to one but not both of the matching devices. This has been fixed ([Firefox bug 802326](https://bugzil.la/802326 "External link (opens in new tab)")). This involves minor user interface changes as well, to remove the options to choose "No audio" or "No video" when the user is prompted for permissions.
*   The [`MediaStream.getTrackById()`](/en-US/docs/Web/API/MediaStream/getTrackById) method has been implemented ([Firefox bug 1208390](https://bugzil.la/1208390 "External link (opens in new tab)")).

#### WebRTC

*   The [`RTCPeerConnection.addTrack()`](/en-US/docs/Web/API/RTCPeerConnection/addTrack) method has been updated to allow tracks which are not components of the specified streams to be added to the connection. Instead, the streams are used to group tracks on the receiving end of the connection ([Firefox bug 1271669](https://bugzil.la/1271669 "External link (opens in new tab)")).

#### New APIs

*   The [`PerformanceObserver`](/en-US/docs/Web/API/PerformanceObserver) API is now activated by default on Nightly. It is not available by default in other versions of Firefox 49 ([Firefox bug 1271487](https://bugzil.la/1271487 "External link (opens in new tab)")).

#### Others

*   [`XMLHttpRequest.getResponseHeader()`](/en-US/docs/Web/API/XMLHttpRequest/getResponseHeader) and [`XMLHttpRequest.getAllResponseHeaders()`](/en-US/docs/Web/API/XMLHttpRequest/getAllResponseHeaders) return empty headers in case the preference `network.http.keep_empty_response_headers_as_empty_string` is set to `true` ([Firefox bug 669259](https://bugzil.la/669259 "External link (opens in new tab)")).
*   The Firefox OS-only Data Store API has been removed ([Firefox bug 1261009](https://bugzil.la/1261009 "External link (opens in new tab)")).
*   The [Fullscreen API](/en-US/docs/Web/API/Fullscreen_API) event handlers `Document.onfullscreenchange` and `Document.onfullscreenerror` have been removed from [`Element`](/en-US/docs/Web/API/Element) as they were never fired there; the prefixed versions of these event handlers have been kept there for compatibility purposes, however ([Firefox bug 1270386](https://bugzil.la/1270386 "External link (opens in new tab)")). Note that this is not yet activated by default, but is behind the `full-screen-api.unprefix.enabled` preference ([Firefox bug 1268749](https://bugzil.la/1268749 "External link (opens in new tab)")).
*   The obsolete `Document.mozFullScreen` property has been unprefixed to [`Document.fullscreen`](/en-US/docs/Web/API/Document/fullscreen) [Firefox bug 1269157](https://bugzil.la/1269157 "External link (opens in new tab)"). Note that this is not yet activated by default by behind the `full-screen-api.unprefix.enabled` preference ([Firefox bug 1268749](https://bugzil.la/1268749 "External link (opens in new tab)")).
*   The read-only properties [`Document.fullscreenElement`](/en-US/docs/Web/API/Document/fullscreenElement "Document.fullscreenElement") and [`Document.fullscreenEnabled`](/en-US/docs/Web/API/Document/fullscreenEnabled) no longer throw an exception if an attempt is made to change their values; instead, the new value is silently ignored and the setter function is a no-op ([Firefox bug 1269798](https://bugzil.la/1269798 "External link (opens in new tab)")).
*   Any kind of data can now be retrieved from the clipboard using [`DataTransfer.getData()`](/en-US/docs/Web/API/DataTransfer/getData): previously, only data of certain MIME types were supported [Firefox bug 860857](https://bugzil.la/860857 "External link (opens in new tab)").
*   Our implementation of the Frame Timing API, consisting of the two interfaces `PerformanceCompositeTiming` and `PerformanceRenderTiming`, has been removed as the spec has been completely rewritten ([Firefox bug 1271846](https://bugzil.la/1271846 "External link (opens in new tab)")).
*   To match the spec, the [`VTTCue.positionAlign`](/en-US/docs/Web/API/VTTCue/positionAlign) property now returns a `PositionAlign` enum instead of an `Align` enum ([Firefox bug 1276129](https://bugzil.la/1276129 "External link (opens in new tab)")).
*   The speech synthesis part of [Web Speech API](/en-US/docs/Web/API/Web_Speech_API#speech_synthesis) is now activated by default ([Firefox bug 1268633](https://bugzil.la/1268633 "External link (opens in new tab)")).
*   The [Performance Timeline API](/en-US/docs/Web/API/Performance_API) is now available by default in Nightly (though not in Aurora, Beta or Release).
*   The [`install`](/en-US/docs/Web/API/ServiceWorkerGlobalScope/install_event "install") event, and the [`Window.oninstall`](/en-US/docs/Web/API/Window/appinstalled_event "Window.oninstall") event handler, are now supported for [Web Manifests](/en-US/docs/Web/Progressive_web_apps/Manifest) ([Firefox bug 1265279](https://bugzil.la/1265279 "External link (opens in new tab)")).
*   When using the [`AudioContext.createPeriodicWave()`](/en-US/docs/Web/API/BaseAudioContext/createPeriodicWave "AudioContext.createPeriodicWave()") method of the [Web Audio API](/en-US/docs/Web/API/Web_Audio_API), you can now specify whether the resulting periodic wave should be normalized by including a dictionary object as the third parameter, which includes a single parameter — `{disableNormalization: true}` ([Firefox bug 1265405](https://bugzil.la/1265405 "External link (opens in new tab)")).
*   In the WebVTT API, [`VTTCue.positionAlign`](/en-US/docs/Web/API/VTTCue/positionAlign) now correctly returns a `PositionAlignSetting` enum as per spec; previously it returned an `AlignSetting` enum ([Firefox bug 1276129](https://bugzil.la/1276129 "External link (opens in new tab)")).
*   The Speech Synthesis part of the Web Speech API is now enabled by default across all desktop browsers ([Firefox bug 1268633](https://bugzil.la/1268633 "External link (opens in new tab)")).
*   The [`Animation()`](/en-US/docs/Web/API/Animation/Animation "Animation()") constructor of the [Web Animations API](/en-US/docs/Web/API/Web_Animations_API) now accepts a null timeline ([Firefox bug 1096776](https://bugzil.la/1096776 "External link (opens in new tab)")).
*   The [`KeyframeEffect`](/en-US/docs/Web/API/KeyframeEffect) property [`target`](/en-US/docs/Web/API/KeyframeEffect/target "target") is now supported in Firefox, if you have enabled [Web Animations](/en-US/docs/Web/API/Web_Animations_API) ([Firefox bug 1067769](https://bugzil.la/1067769 "External link (opens in new tab)")).

### [Plugins and Flash](#plugins_and_flash)

Beginning in Firefox 49, Firefox, by default, blocks certain kinds of Flash content that aren't necessary for sites to function well. This behavior, controlled by the preference `browser.safebrowsing.blockedURIs.enabled`, helps to improve the performance of sites and Firefox in general without having significant impact on site usability. It also helps improve stability of the browsing experience by eliminating a major cause of crashes. The blocked Flash modules include several used just for fingerprinting purposes, as well as a number of "supercookie" modules, and in the future may be expanded to include more types of blocked modules. See [Firefox bug 1275591](https://bugzil.la/1275591 "External link (opens in new tab)") for details.

This marks the next step in the journey toward a plugin-free future. HTML is very close to the point where plugins will no longer be needed to get the job done.

Now `weekdayRange`, `dateRange`, and `timeRange` support "reversed ranges", for example, `weekdayRange("SAT", "MON")` will evaluate `true` if the current day is Saturday, Sunday, or Monday ([Firefox bug 1251332](https://bugzil.la/1251332 "External link (opens in new tab)")).

    *   `-webkit-box-flex`
    *   `-webkit-box-ordinal-group`
    *   `-webkit-box-orient`
    *   `-webkit-box-align`
    *   `-webkit-box-pack`

    *   The outdated `-webkit-gradient` is supported (and translated to a regular gradient)
*   The following [`display`](/en-US/docs/Web/CSS/Reference/Properties/display) values are translated:
    
    *   `-webkit-box` to `-moz-box`
    *   `-webkit-flex` to `flex`
    *   `-webkit-inline-box` to `inline-flex`
    *   `-webkit-inline-flex` to `-moz-inline-flex`
*   The following properties are supported (and don't map to any unprefixed equivalent):
    
    *   [`-webkit-text-fill-color`](/en-US/docs/Web/CSS/Reference/Properties/-webkit-text-fill-color)
    *   [`-webkit-text-stroke-color`](/en-US/docs/Web/CSS/Reference/Properties/-webkit-text-stroke-color)
    *   [`-webkit-text-stroke-width`](/en-US/docs/Web/CSS/Reference/Properties/-webkit-text-stroke-width)
    *   [`-webkit-text-stroke`](/en-US/docs/Web/CSS/Reference/Properties/-webkit-text-stroke)
*   The `WebKitCSSMatrix` interface is an alias of [`DOMMatrix`](/en-US/docs/Web/API/DOMMatrix)
    
*   The following media query features have been implemented:
    
    *   `-webkit-min-device-pixel-ratio` as an alias of [`min-resolution`](/en-US/docs/Web/CSS/Reference/At-rules/@media/resolution) with the same value (in `dppx)`, though this feature is [disabled by default](https://bugzil.la/1237720 "External link (opens in new tab)") (behind about:config pref `layout.css.prefixes.device-pixel-ratio-webkit`)
    *   `-webkit-max-device-pixel-ratio` as an alias of [`max-resolution`](/en-US/docs/Web/CSS/Reference/At-rules/@media/resolution) of the same value (in `dppx`); this feature is also disabled by default, behind the same about:config pref.
    *   [`-webkit-transform-3d`](/en-US/docs/Web/CSS/Reference/At-rules/@media/-webkit-transform-3d) always matching, indicating 3d transform support.
