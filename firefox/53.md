# Firefox 53 release notes for developers

Firefox 53 was released on April 19, 2017. This article lists key changes that are useful not only for web developers but also for Firefox and Gecko developers, as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

*   Avoid scrolling latency on highlighters given by APZ ([Firefox bug 1312103](https://bugzil.la/1312103 "External link (opens in new tab)")).
*   Added option to [copy the full CSS path](https://firefox-source-docs.mozilla.org/devtools-user/page_inspector/how_to/examine_and_edit_html/index.html#copy-css-path "External link (opens in new tab)") of an element ([Firefox bug 1323700](https://bugzil.la/1323700 "External link (opens in new tab)")).
*   DevTools support for css-color-4 ([Firefox bug 1310681](https://bugzil.la/1310681 "External link (opens in new tab)")).
*   Markup view: add a visual hint between opening and closing tags of a collapsed node ([Firefox bug 1323193](https://bugzil.la/1323193 "External link (opens in new tab)")).

### [CSS](#css)

#### New features

*   The `mask-*` longhand properties (see [CSS Masks](/en-US/docs/Web/CSS/Guides/Masking)) are all supported and available by default (see [Firefox bug 1251161](https://bugzil.la/1251161 "External link (opens in new tab)")).
*   Added [`caret-color`](/en-US/docs/Web/CSS/Reference/Properties/caret-color) property ([Firefox bug 1063162](https://bugzil.la/1063162 "External link (opens in new tab)")).
*   Implemented the [`place-items`](/en-US/docs/Web/CSS/Reference/Properties/place-items)/[`place-self`](/en-US/docs/Web/CSS/Reference/Properties/place-self)/[`place-content`](/en-US/docs/Web/CSS/Reference/Properties/place-content) shorthands ([Firefox bug 1319958](https://bugzil.la/1319958 "External link (opens in new tab)")).
*   Added `flow-root` value to [`display`](/en-US/docs/Web/CSS/Reference/Properties/display) property ([Firefox bug 1322191](https://bugzil.la/1322191 "External link (opens in new tab)")).
*   [`-moz-tab-size`](/en-US/docs/Web/CSS/Reference/Properties/tab-size) now accepts [`<length>`](/en-US/docs/Web/CSS/Reference/Values/length) values ([Firefox bug 943918](https://bugzil.la/943918 "External link (opens in new tab)")), and is now animatable ([Firefox bug 1308110](https://bugzil.la/1308110 "External link (opens in new tab)")).
*   [`mask-mode`](/en-US/docs/Web/CSS/Reference/Properties/mask-mode):luminance doesn't work on gradient masks ([Firefox bug 1346265](https://bugzil.la/1346265 "External link (opens in new tab)")).
*   \[css-grid\] FR Unit in [`grid-template-rows`](/en-US/docs/Web/CSS/Reference/Properties/grid-template-rows) not filling viewport ([Firefox bug 1346699](https://bugzil.la/1346699 "External link (opens in new tab)")).
*   flex items aren't sorted according to "order", if they're separated by an abspos sibling ([Firefox bug 1345873](https://bugzil.la/1345873 "External link (opens in new tab)")).

#### Other changes

*   Enable mask longhands on SVG elements ([Firefox bug 1319667](https://bugzil.la/1319667 "External link (opens in new tab)")).
*   \[css-grid\] Fixed: `align-self`/`justify-self:stretch`/`normal` doesn't work on `<table>` grid items ([Firefox bug 1316051](https://bugzil.la/1316051 "External link (opens in new tab)")).
*   Fixed: `clip-path: circle()` with large reference box and percentage radius does not render correctly ([Firefox bug 1324713](https://bugzil.la/1324713 "External link (opens in new tab)").
*   When applying a [`text-transform`](/en-US/docs/Web/CSS/Reference/Properties/text-transform) value of `uppercase` to Greek text, the accent on the disjunctive eta (ή) is no longer removed (see [Firefox bug 1322989](https://bugzil.la/1322989 "External link (opens in new tab)")).
*   The availability of the `contents` value of [`display`](/en-US/docs/Web/CSS/Reference/Properties/display) was controlled through the `layout.css.display-contents.enabled` pref. In Firefox 53, this pref has been removed altogether, so the value will always be available and can no longer be disabled ([Firefox bug 1295788](https://bugzil.la/1295788 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   ECMAScript 2015 semantics for the [`Function.name`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/name) properties have been implemented. This includes inferred names on anonymous functions (`var foo = function() {}`) ([Firefox bug 883377](https://bugzil.la/883377 "External link (opens in new tab)")).
*   ECMAScript 2015 semantics for closing iterators have been implemented. This affects the [`for...of`](/en-US/docs/Web/JavaScript/Reference/Statements/for...of) loop, for example ([Firefox bug 1147371](https://bugzil.la/1147371 "External link (opens in new tab)")).
*   The [Template Literal Revision proposal](https://tc39.es/proposal-template-literal-revision/ "External link (opens in new tab)") that [lifts escape sequence restrictions on tagged template literals](/en-US/docs/Web/JavaScript/Reference/Template_literals#tagged_templates_and_escape_sequences) has been implemented ([Firefox bug 1317375](https://bugzil.la/1317375 "External link (opens in new tab)")).
*   The static `length` property of [`TypedArray`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray) objects was changed from 3 to 0 as per ES2016 ([Firefox bug 1317306](https://bugzil.la/1317306 "External link (opens in new tab)")).
*   [`SharedArrayBuffer`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/SharedArrayBuffer) can now be used in [`DataView`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/DataView) objects ([Firefox bug 1246597](https://bugzil.la/1246597 "External link (opens in new tab)")).
*   In earlier versions of the specification, [`SharedArrayBuffer`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/SharedArrayBuffer) objects needed to be explicitly transferred during [structured cloning](/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm). In the new specification, they aren't [transferable objects](/en-US/docs/Web/API/Web_Workers_API/Transferable_objects) anymore and thus must not be in the transfer list. The new behavior used to present a console warning only, but will now throw an error ([Firefox bug 1302037](https://bugzil.la/1302037 "External link (opens in new tab)")).
*   The [`ArrayBuffer`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/ArrayBuffer) length is now limited to [`Number.MAX_SAFE_INTEGER`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER) (>= 2 \*\* 53) ([Firefox bug 1255128](https://bugzil.la/1255128 "External link (opens in new tab)")).
*   [`Error`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error) and other native error object prototypes like [`RangeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RangeError) etc. are now ordinary objects instead of proper Error objects. (In particular, `Object.prototype.toString.call(Error.prototype)` is now `"[object Object]"` instead of `"[object Error]"`.) ([Firefox bug 1213341](https://bugzil.la/1213341 "External link (opens in new tab)")).

### [Events](#events)

*   CSS Transitions: The [`transitionstart`](/en-US/docs/Web/API/Element/transitionstart_event "transitionstart"), [`transitionrun`](/en-US/docs/Web/API/Element/transitionrun_event "transitionrun"), and [`transitioncancel`](/en-US/docs/Web/API/Element/transitioncancel_event "transitioncancel") events have been implemented (see [Firefox bug 1264125](https://bugzil.la/1264125 "External link (opens in new tab)") and [Firefox bug 1287983](https://bugzil.la/1287983 "External link (opens in new tab)")).
*   The [`CompositionEvent`](/en-US/docs/Web/API/CompositionEvent/CompositionEvent "CompositionEvent") constructor has been implemented (see [Firefox bug 1002256](https://bugzil.la/1002256 "External link (opens in new tab)")).
*   The [`MouseEvent.x`](/en-US/docs/Web/API/MouseEvent/x) and [`MouseEvent.y`](/en-US/docs/Web/API/MouseEvent/y) aliases of [`MouseEvent.clientX`](/en-US/docs/Web/API/MouseEvent/clientX)/[`MouseEvent.clientY`](/en-US/docs/Web/API/MouseEvent/clientY) have been implemented (see [Firefox bug 424390](https://bugzil.la/424390 "External link (opens in new tab)")).
*   The [`auxclick`](/en-US/docs/Web/API/Element/auxclick_event "auxclick") event and corresponding event handler have been implemented (see [Firefox bug 1304044](https://bugzil.la/1304044 "External link (opens in new tab)")).
*   The [`transitioncancel`](/en-US/docs/Web/API/Element/transitioncancel_event "transitioncancel") event is now fired after a [transition](/en-US/docs/Web/CSS/Guides/Transitions) is canceled.

### [DOM](#dom)

*   The [`pathname`](/en-US/docs/Web/API/HTMLAnchorElement/pathname "pathname") and [`search`](/en-US/docs/Web/API/HTMLAnchorElement/search "search") properties of links (like for [`<a>`](/en-US/docs/Web/HTML/Reference/Elements/a) and [`<link>`](/en-US/docs/Web/HTML/Reference/Elements/link) elements' interfaces) previously returned the wrong parts of the URL. For example, for a URL of `http://z.com/x?a=true&b=false`, `pathname` would return `"/x?a=true&b=false"` and `search` would return `""`, rather than `"/x"` and `"?a=true&b=false"` respectively. This has now been fixed ([Firefox bug 1310483](https://bugzil.la/1310483 "External link (opens in new tab)")).
*   The [`URLSearchParams()`](/en-US/docs/Web/API/URLSearchParams/URLSearchParams "URLSearchParams()") constructor now accepts a string or sequence of strings as an init object ([Firefox bug 1330678](https://bugzil.la/1330678 "External link (opens in new tab)")).
*   The [`Selection.setBaseAndExtent()`](/en-US/docs/Web/API/Selection/setBaseAndExtent) method of the [Selection API](/en-US/docs/Web/API/Selection) is now implemented (see [Firefox bug 1321623](https://bugzil.la/1321623 "External link (opens in new tab)")).
*   The ["fakepath"](https://html.spec.whatwg.org/multipage/forms.html#fakepath-srsly "External link (opens in new tab)") addition to `file` type [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) `values` has been implemented in Gecko, giving it parity with other browsers (see [Firefox bug 1274596](https://bugzil.la/1274596 "External link (opens in new tab)")).
*   [`Node.getRootNode()`](/en-US/docs/Web/API/Node/getRootNode) has been implemented, replacing the deprecated `Node.rootNode` property ([Firefox bug 1269155](https://bugzil.la/1269155 "External link (opens in new tab)")).
*   Own properties of [`Plugin`](/en-US/docs/Web/API/Plugin) and [`PluginArray`](/en-US/docs/Web/API/PluginArray) objects are no longer enumerable ([Firefox bug 1270366](https://bugzil.la/1270366 "External link (opens in new tab)")).
*   Named properties of [`MimeTypeArray`](/en-US/docs/Web/API/MimeTypeArray) objects are no longer enumerable ([Firefox bug 1270364](https://bugzil.la/1270364 "External link (opens in new tab)")).
*   The [Permissions API](/en-US/docs/Web/API/Permissions_API) now has a new permission name available — `persistent-storage` — as used when making a [`Permissions.query()`](/en-US/docs/Web/API/Permissions/query) (see [Firefox bug 1270038](https://bugzil.la/1270038 "External link (opens in new tab)")). This allows an origin to use a persistent box (i.e., [persistent storage](https://storage.spec.whatwg.org/#persistence "External link (opens in new tab)")) for its storage, as per the [Storage API](https://storage.spec.whatwg.org/ "External link (opens in new tab)").
*   The [`Performance.timeOrigin`](/en-US/docs/Web/API/Performance/timeOrigin) property has been implemented ([Firefox bug 1313420](https://bugzil.la/1313420 "External link (opens in new tab)")).

### [Workers and service workers](#workers_and_service_workers)

*   The [Network Information API](/en-US/docs/Web/API/Network_Information_API) is now available in workers (see [Firefox bug 1323172](https://bugzil.la/1323172 "External link (opens in new tab)")).
*   [Server-sent events](/en-US/docs/Web/API/Server-sent_events) can now be used in workers (see [Firefox bug 1267903](https://bugzil.la/1267903 "External link (opens in new tab)")).
*   [`ExtendableEvent.waitUntil()`](/en-US/docs/Web/API/ExtendableEvent/waitUntil "ExtendableEvent.waitUntil()") can now be called asynchronously (see [Firefox bug 1263304](https://bugzil.la/1263304 "External link (opens in new tab)")).

### [WebGL](#webgl)

*   The [`WEBGL_compressed_texture_astc`](/en-US/docs/Web/API/WEBGL_compressed_texture_astc) WebGL extension has been implemented ([Firefox bug 1250077](https://bugzil.la/1250077 "External link (opens in new tab)")).
*   The [`WEBGL_debug_renderer_info`](/en-US/docs/Web/API/WEBGL_debug_renderer_info) WebGL extension is now enabled by default ([Firefox bug 1336645](https://bugzil.la/1336645 "External link (opens in new tab)")).

### [Audio, video, and media](#audio_video_and_media)

#### General

*   Beginning in **Firefox 53 for Android**, decoding of media is handled out-of-process for improved performance on multi-core systems ([Firefox bug 1333323](https://bugzil.la/1333323 "External link (opens in new tab)")).

#### Media elements

*   The [`HTMLMediaElement.play()`](/en-US/docs/Web/API/HTMLMediaElement/play) method, used to begin playback of media in any media element, now returns a [`Promise`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) which is fulfilled when playback begins and is rejected if an error occurs ([Firefox bug 1244768](https://bugzil.la/1244768 "External link (opens in new tab)")).

#### Web Audio API

*   The [`AudioScheduledSourceNode`](/en-US/docs/Web/API/AudioScheduledSourceNode) interface has been added and the [`AudioBufferSourceNode`](/en-US/docs/Web/API/AudioBufferSourceNode), [`ConstantSourceNode`](/en-US/docs/Web/API/ConstantSourceNode), and [`OscillatorNode`](/en-US/docs/Web/API/OscillatorNode) interfaces are now based on it ([Firefox bug 1324568](https://bugzil.la/1324568 "External link (opens in new tab)")).
*   All the different audio node types have had constructors added to them ([Firefox bug 1322883](https://bugzil.la/1322883 "External link (opens in new tab)")).

#### WebRTC

*   The [`RTCPeerConnection`](/en-US/docs/Web/API/RTCPeerConnection) methods [`createOffer()`](/en-US/docs/Web/API/RTCPeerConnection/createOffer "createOffer()") and [`createAnswer()`](/en-US/docs/Web/API/RTCPeerConnection/createAnswer "createAnswer()") now return a [`Promise`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) that returns an object conforming to the `RTCSessionDescriptionInit` dictionary instead of returning an [`RTCSessionDescription`](/en-US/docs/Web/API/RTCSessionDescription) directly. Existing code will continue to work, but new code can be written more simply.
*   Similarly, the [`RTCPeerConnection`](/en-US/docs/Web/API/RTCPeerConnection) methods [`setLocalDescription()`](/en-US/docs/Web/API/RTCPeerConnection/setLocalDescription "setLocalDescription()") and [`setRemoteDescription()`](/en-US/docs/Web/API/RTCPeerConnection/setRemoteDescription "setRemoteDescription()") now accept as input an object conforming to the dictionary `RTCSessionDescriptionInit` dictionary. Existing code continues to work, but can be simplified.
*   [`RTCPeerConnection.addIceCandidate()`](/en-US/docs/Web/API/RTCPeerConnection/addIceCandidate) now accepts as input an initialization object. This is compatible with existing code but allows new code to be written slightly more simply when used in tandem with the changes listed above ([Firefox bug 1263312](https://bugzil.la/1263312 "External link (opens in new tab)")).
*   [DTMF](/en-US/docs/Glossary/DTMF) support is now enabled by default using [`RTCDTMFSender`](/en-US/docs/Web/API/RTCDTMFSender). See [Using DTMF with WebRTC](/en-US/docs/Web/API/WebRTC_API/Using_DTMF) for more information on how this works.

### [HTTP/Networking](#httpnetworking)

*   Gecko now has a pref available in `about:config` to allow users to set their default [`Referrer-Policy`](/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy) — `network.http.referer.userControlPolicy` ([Firefox bug 1304623](https://bugzil.la/1304623 "External link (opens in new tab)")). Possible values are:
    
    *   0 — `no-referrer`
    *   1 — `same-origin`
    *   2 — `strict-origin-when-cross-origin`
    *   3 — `no-referrer-when-downgrade` (the default)
*   Support for Next Protocol Negotiation (NPN) has been removed in favor of [Application-Layer Protocol Negotiation](https://en.wikipedia.org/wiki/Application-Layer_Protocol_Negotiation "External link (opens in new tab)") (ALPN) — see [Firefox bug 1248198](https://bugzil.la/1248198 "External link (opens in new tab)").
    
*   The `Large-Allocation` HTTP header is now available by default, and no longer hidden behind a pref ([Firefox bug 1331083](https://bugzil.la/1331083 "External link (opens in new tab)")).
    

### [SVG](#svg)

*   Partly implemented [`SVGGeometryElement`](/en-US/docs/Web/API/SVGGeometryElement) interface ([Firefox bug 1239100](https://bugzil.la/1239100 "External link (opens in new tab)")).

## [Removals from the web platform](#removals_from_the_web_platform)

### [HTML/XML](#htmlxml)

*   The `dom.details_element.enabled` pref — which controlled enabling/disabling [`<details>`](/en-US/docs/Web/HTML/Reference/Elements/details) and [`<summary>`](/en-US/docs/Web/HTML/Reference/Elements/summary) element support in Firefox — has now been removed from `about:config`. These elements (first enabled by default in Firefox 49) can no longer be disabled. See [Firefox bug 1271549](https://bugzil.la/1271549 "External link (opens in new tab)").
*   The `mozapp` attribute of the [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) element /[`HTMLIFrameElement`](/en-US/docs/Web/API/HTMLIFrameElement) interface has been removed — this was used to enable a Firefox OS app to be embedded in a mozilla-prefixed Browser API `<iframe>` ([Firefox bug 1310845](https://bugzil.la/1310845 "External link (opens in new tab)")).
*   The `HTMLIFrameElement.setInputMethodActive()` method and `InputMethod` interface (used to set and manage IMEs on Firefox OS apps) has been removed ([Firefox bug 1313169](https://bugzil.la/1313169 "External link (opens in new tab)")).

### [CSS](#css_2)

*   Removed `-moz` prefixed variant of [`:dir()`](/en-US/docs/Web/CSS/Reference/Selectors/:dir) pseudo-class ([Firefox bug 1270406](https://bugzil.la/1270406 "External link (opens in new tab)")).
*   The `-moz` prefixed version of [`text-align-last`](/en-US/docs/Web/CSS/Reference/Properties/text-align-last) got removed ([Firefox bug 1276808](https://bugzil.la/1276808 "External link (opens in new tab)")).
*   Removed `-moz` prefixed variant of [`calc()`](/en-US/docs/Web/CSS/Reference/Values/calc) method ([Firefox bug 1331296](https://bugzil.la/1331296 "External link (opens in new tab)")).
*   The proprietary `-moz-samplesize` media fragment (added to aid in delivery of downsampled images to low memory Firefox OS devices; see [Firefox bug 854795](https://bugzil.la/854795 "External link (opens in new tab)")) has been removed ([Firefox bug 1311246](https://bugzil.la/1311246 "External link (opens in new tab)")).

### [JavaScript](#javascript_2)

*   The non-standard [`ArrayBuffer.slice()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/ArrayBuffer/slice) method has been removed (but the standardized version [`ArrayBuffer.prototype.slice()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/ArrayBuffer/slice) is kept, see [Firefox bug 1313112](https://bugzil.la/1313112 "External link (opens in new tab)")).

### [APIs](#apis)

*   The Wi-Fi information API, Speaker Manager API, and Tethering API, and Settings API\] have been removed from the platform (see [Firefox bug 1313788](https://bugzil.la/1313788 "External link (opens in new tab)"), [Firefox bug 1317853](https://bugzil.la/1317853 "External link (opens in new tab)"), [Firefox bug 1313789](https://bugzil.la/1313789 "External link (opens in new tab)"), and [Firefox bug 1313155](https://bugzil.la/1313155 "External link (opens in new tab)") respectively).

### [Other](#other)

*   The `legacycaller` has been removed from the [`HTMLEmbedElement`](/en-US/docs/Web/API/HTMLEmbedElement) and [`HTMLObjectElement`](/en-US/docs/Web/API/HTMLObjectElement) interfaces ([Firefox bug 909656](https://bugzil.la/909656 "External link (opens in new tab)")).

## [Changes for add-on and Mozilla developers](#changes_for_add-on_and_mozilla_developers)

### [WebExtensions](#webextensions)

New APIs:

*   [`browsingData`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browsingData)
*   [`identity`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/identity)
*   [`contextualIdentities`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/contextualIdentities)

Enhanced APIs:

*   [`storage.sync`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/sync)
*   `page_action`, `browser_action`, `password`, `tab` [context types](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus/ContextType) in [`contextMenus`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/menus)
*   [`webRequest.onBeforeRequest`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest/onBeforeRequest) now supports `requestBody`
*   [`tabs.insertCSS`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/insertCSS) now supports `cssOrigin`, enabling you to insert user style sheets.

### [JavaScript code modules](#javascript_code_modules)

*   The asynchronous [AddonManager APIs](https://firefox-source-docs.mozilla.org/toolkit/mozapps/extensions/addon-manager/AddonManager.html "External link (opens in new tab)") now support [`Promises`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) as well as callbacks ([Firefox bug 987512](https://bugzil.la/987512 "External link (opens in new tab)").
