# Firefox 54 release notes for developers

Firefox 54 was released on June 13, 2017. This article lists key changes that are useful for web developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

*   The network request summary now includes the amount of data actually transferred ("transferred size"), as does the performance analysis view ([Firefox bug 1168376](https://bugzil.la/1168376 "External link (opens in new tab)")).
*   The network request headers view now links to the related documentation on MDN ([Firefox bug 1320233](https://bugzil.la/1320233 "External link (opens in new tab)")).

### [CSS](#css)

*   [`clip-path`](/en-US/docs/Web/CSS/Reference/Properties/clip-path) now supports [basic shapes](/en-US/docs/Web/CSS/Guides/Shapes) ([Firefox bug 1247229](https://bugzil.la/1247229 "External link (opens in new tab)")).
*   Firefox's implementations of CSS Flexbox and CSS alignment now implement updated spec language for interactions between the properties [`align-items`](/en-US/docs/Web/CSS/Reference/Properties/align-items) and [`align-self`](/en-US/docs/Web/CSS/Reference/Properties/align-self) as well as between [`justify-items`](/en-US/docs/Web/CSS/Reference/Properties/justify-items) and [`justify-self`](/en-US/docs/Web/CSS/Reference/Properties/justify-self) ([Firefox bug 1340309](https://bugzil.la/1340309 "External link (opens in new tab)")).
*   [`<input>`](/en-US/docs/Web/HTML/Reference/Elements/input) elements of types `checkbox` and `radio` with [`-moz-appearance: none`](/en-US/docs/Web/CSS/Reference/Properties/appearance) set on them are now non-replaced elements, for compatibility with other browsers ([Firefox bug 605985](https://bugzil.la/605985 "External link (opens in new tab)")).
*   Previously, an element styled with [`display`](/en-US/docs/Web/CSS/Reference/Properties/display): `inline-block` with a child element of type [`HTMLInputElement`](/en-US/docs/Web/API/HTMLInputElement) styled with `display:block` had a wrong baseline ([Firefox bug 1330962](https://bugzil.la/1330962 "External link (opens in new tab)")). This is now fixed.
*   When Mozilla introduced dedicated content threads to Firefox (through the Electrolysis or e10s project), support for styling [`<option>`](/en-US/docs/Web/HTML/Reference/Elements/option) elements was removed temporarily. Starting in Firefox 54, you can apply foreground and background colors to `<option>` elements again, using the [`color`](/en-US/docs/Web/CSS/Reference/Properties/color) and [`background-color`](/en-US/docs/Web/CSS/Reference/Properties/background-color) attributes. See [Firefox bug 910022](https://bugzil.la/910022 "External link (opens in new tab)") for more information. Note that this is still disabled in Linux due to lack of contrast (see [Firefox bug 1338283](https://bugzil.la/1338283 "External link (opens in new tab)") for progress on this).
*   [CSS Animations](/en-US/docs/Web/CSS/Guides/Animations) now send the [`animationcancel`](/en-US/docs/Web/API/Element/animationcancel_event "animationcancel") event as expected when an animation aborts prematurely ([Firefox bug 1302648](https://bugzil.la/1302648 "External link (opens in new tab)")).
*   Transparent colors (i.e., those with an alpha channel of 0) were being serialized to the [`transparent` color keyword](/en-US/docs/Web/CSS/Reference/Values/color_value) in certain situations; this has been fixed so that Firefox follows the spec (as well as other browsers' implementations). See ([Firefox bug 1339394](https://bugzil.la/1339394 "External link (opens in new tab)") for further information.
*   The proprietary `:-moz-table-border-nonzero` pseudo-class is no longer available to web content; it is now restricted to Firefox's internal UA stylesheet ([Firefox bug 1341925](https://bugzil.la/1341925 "External link (opens in new tab)")).
*   \[css-grid\] Intrinsic content with overflow:auto overlaps in grid ([Firefox bug 1348857](https://bugzil.la/1348857 "External link (opens in new tab)")).
*   \[css-grid\] Transferred min-size contribution of percentage size grid item with an intrinsic ratio ([Firefox bug 1349320](https://bugzil.la/1349320 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   `\b` and `\B` in [`RegExp`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp) with the `"u"` (Unicode) and `"i"` (case insensitive) flags now treat U+017F (LATIN SMALL LETTER LONG S) and U+212A (KELVIN SIGN) as word characters ([Firefox bug 1338373](https://bugzil.la/1338373 "External link (opens in new tab)")).
*   The [`DataView`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/DataView) constructor now throws a [`RangeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RangeError) if the `byteOffset` parameter is out of [`Number.MAX_SAFE_INTEGER`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER) (>= 2 \*\* 53) ([Firefox bug 1317382](https://bugzil.la/1317382 "External link (opens in new tab)")).
*   The [`Date.UTC()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/UTC) method has been updated to conform to ECMAScript 2017 when fewer than two arguments are provided ([Firefox bug 1050755](https://bugzil.la/1050755 "External link (opens in new tab)")).
*   The [`Function.prototype.toString()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/toString) method has been updated to match the latest [proposed specification](https://tc39.es/Function-prototype-toString-revision/ "External link (opens in new tab)") ([Firefox bug 1317400](https://bugzil.la/1317400 "External link (opens in new tab)")).

### [DOM & HTML DOM](#dom_html_dom)

*   The [`URL.toJSON()`](/en-US/docs/Web/API/URL/toJSON) method has been implemented ([Firefox bug 1337702](https://bugzil.la/1337702 "External link (opens in new tab)")).
*   The [`URLSearchParams()`](/en-US/docs/Web/API/URLSearchParams/URLSearchParams "URLSearchParams()") constructor now accepts a record containing strings as an init object ([Firefox bug 1331580](https://bugzil.la/1331580 "External link (opens in new tab)")).
*   Values returned in [`KeyboardEvent.key`](/en-US/docs/Web/API/KeyboardEvent/key) for printable keys when the control key is also pressed have been corrected on macOS (except when the Command key is pressed) ([Firefox bug 1342865](https://bugzil.la/1342865 "External link (opens in new tab)")).
*   The `dom.workers.latestJSVersion` preference, which was mainly implemented to work around problems using [`let`](/en-US/docs/Web/JavaScript/Reference/Statements/let) in workers (due to [Firefox bug 855665](https://bugzil.la/855665 "External link (opens in new tab)"), which has since been fixed) has been removed (see [Firefox bug 1219523](https://bugzil.la/1219523 "External link (opens in new tab)")).
*   The [`event.timeStamp`](/en-US/docs/Web/API/Event/timeStamp) property now returns a high-resolution monotonic time ([`DOMHighResTimeStamp`](/en-US/docs/Web/API/DOMHighResTimeStamp)) instead of a value representing [Unix time](/en-US/docs/Glossary/Unix_time) in milliseconds.

### [Web Workers and Service Workers](#web_workers_and_service_workers)

*   `WorkerGlobalScope.close` is now available on [`DedicatedWorkerGlobalScope`](/en-US/docs/Web/API/DedicatedWorkerGlobalScope/close "DedicatedWorkerGlobalScope") and [`SharedWorkerGlobalScope`](/en-US/docs/Web/API/SharedWorkerGlobalScope/close "SharedWorkerGlobalScope") instead. This change was made to stop `close()` being available on service workers, as it isn't supposed to be used there and always throws an exception when called (see [Firefox bug 1336043](https://bugzil.la/1336043 "External link (opens in new tab)")).
*   The [`Window.origin`](/en-US/docs/Web/API/Window/origin) property and the [`WorkerGlobalScope.origin`](/en-US/docs/Web/API/WorkerGlobalScope/origin) has been implemented (see [Firefox bug 1306170](https://bugzil.la/1306170 "External link (opens in new tab)")).
*   The [`Client.type`](/en-US/docs/Web/API/Client/type) property has been implemented (see [Firefox bug 1339844](https://bugzil.la/1339844 "External link (opens in new tab)")).
*   [`Clients.matchAll()`](/en-US/docs/Web/API/Clients/matchAll) now returns [`Client`](/en-US/docs/Web/API/Client) objects in most recently focused order (see [Firefox bug 1266747](https://bugzil.la/1266747 "External link (opens in new tab)")).
*   Some changes have been made to the observed behavior when the [`Request()`](/en-US/docs/Web/API/Request/Request "Request()") constructor is passed an existing [`Request`](/en-US/docs/Web/API/Request) object instance to make a new instance. The following new behaviors are designed to retain security while making the constructor less likely to throw exceptions:
    *   If this object exists on another origin to the constructor call, the [`Request.referrer`](/en-US/docs/Web/API/Request/referrer) is stripped out.
    *   If this object has a [`Request.mode`](/en-US/docs/Web/API/Request/mode) of `navigate`, the `mode` value is converted to `same-origin`.

### [Audio/Video](#audiovideo)

#### General

*   5.1 surround sound playback is now enabled by default on Windows, macOS, and Linux ([Firefox bug 1334508](https://bugzil.la/1334508 "External link (opens in new tab)"), [Firefox bug 1321502](https://bugzil.la/1321502 "External link (opens in new tab)"), and [Firefox bug 1323659](https://bugzil.la/1323659 "External link (opens in new tab)")).

#### Media Capture and Streams API

*   Usage of a [`MediaStream`](/en-US/docs/Web/API/MediaStream) object as the input parameter to [`URL.createObjectURL()`](/en-US/docs/Web/API/URL/createObjectURL_static "URL.createObjectURL()") has been deprecated — the console will now show a warning (see [Firefox bug 1334564](https://bugzil.la/1334564 "External link (opens in new tab)")). You are advised to use [`HTMLMediaElement.srcObject`](/en-US/docs/Web/API/HTMLMediaElement/srcObject) instead.

#### Web Audio API

*   The method [`AnalyserNode.getFloatFrequencyData()`](/en-US/docs/Web/API/AnalyserNode/getFloatFrequencyData) now correctly represents silent samples in the returned buffer with the value `-Infinity` ([Firefox bug 1336098](https://bugzil.la/1336098 "External link (opens in new tab)")).
*   [`AudioParam.setValueCurveAtTime()`](/en-US/docs/Web/API/AudioParam/setValueCurveAtTime) now throws a `TypeError` exception if any of the specified values aren't finite ([Firefox bug 1308437](https://bugzil.la/1308437 "External link (opens in new tab)")).

#### Encrypted MediaExtensions API

*   The `MediaKeySession.keySystem` string has been removed from the specification, and as such we've taken it out of Firefox 54 ([Firefox bug 1335555](https://bugzil.la/1335555 "External link (opens in new tab)")).
*   Support has been added for the VP9 codec in encrypted streams using [Clear Key](https://w3c.github.io/encrypted-media/#dfn-clear-key "External link (opens in new tab)") and [Widevine](https://www.widevine.com/ "External link (opens in new tab)") ([Firefox bug 1338064](https://bugzil.la/1338064 "External link (opens in new tab)")).
*   Previously, MSE was only allowed to use WebM/VP8 video if the system was considered "fast enough." Now playback of VP8-encoded `webm/video` media is always supported, regardless of system performance.

#### WebRTC

*   TCP ICE candidate support, originally added in Firefox 41, is now enabled by default. This allows the ICE layer to consider candidates that use TCP rather than the preferred UDP for transmission. This can be useful in environments in which UDP is blocked ([Firefox bug 1176382](https://bugzil.la/1176382 "External link (opens in new tab)")). This [blog post](https://blog.mozilla.org/webrtc/active-ice-tcp-punch-firewalls-directly/ "External link (opens in new tab)") explains the feature in more details.

## [Removals from the web platform](#removals_from_the_web_platform)

### [CSS](#css_2)

*   Removed the `-moz` prefixed versions of `isolate`, `isolate-override`, and `plaintext` values for the [`unicode-bidi`](/en-US/docs/Web/CSS/Reference/Properties/unicode-bidi) property ([Firefox bug 1333675](https://bugzil.la/1333675 "External link (opens in new tab)")).

### [HTTP](#http)

*   HTTP/1 Pipelining support has been removed in Firefox 54. Maintaining it as we make the move into a new world full of HTTP/2 and other substantial, standardized improvements to networking performance is not worthwhile given pipelining's compatibility and performance issues. The `network.http.pipelining` preference (as well as the other preferences that start with "network.http.pipelining") is now ignored. See [Firefox bug 1340655](https://bugzil.la/1340655 "External link (opens in new tab)") for further information.
