# Firefox 84 release notes for developers

This article provides information about the changes in Firefox 84 that will affect developers. Firefox 84 was released on December 15, 2020.

**Note:** See also [And now for … Firefox 84](https://hacks.mozilla.org/2020/12/and-now-for-firefox-84/ "External link (opens in new tab)") on Mozilla Hacks.

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

*   The Firefox [Accessibility Inspector](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html "External link (opens in new tab)") now supports displaying the [keyboard tab order](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html#show-web-page-tabbing-order "External link (opens in new tab)") on a web page. This provides a better high-level overview of how the page will be navigated using the keyboard than tabbing through the links ([Firefox bug 1654956](https://bugzil.la/1654956 "External link (opens in new tab)")).

### [HTML](#html)

_No changes._

### [CSS](#css)

*   We've added support for complex selectors to the [`:not`](/en-US/docs/Web/CSS/Reference/Selectors/:not) pseudo-class ([Firefox bug 933562](https://bugzil.la/933562 "External link (opens in new tab)")).

#### Removals

*   We've removed the proprietary `-moz-default-appearance` property values `scrollbar-small` (`scrollbar-width: thin` is used instead) and `scrollbar` (macOS only; `scrollbar-horizontal` and `scrollbar-vertical` are used instead) ([Firefox bug 1673132](https://bugzil.la/1673132 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   Custom date/time formats specified as options to the [`Intl.DateTimeFormat()` constructor](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat/DateTimeFormat) can now include `fractionalSecondDigits` — the number of digits used to represent fractions of a second ([Firefox bug 1645107](https://bugzil.la/1645107 "External link (opens in new tab)")).

### [HTTP](#http)

_No changes._

### [Security](#security)

*   Firefox now ensures that `localhost` URLs — such as `http://localhost/` and `http://dev.localhost/` — refer to the local host's loopback interface (e.g., `http://127.0.0.1`). As a result, resources loaded from `localhost` are now assumed to have been delivered securely (see [Secure contexts](/en-US/docs/Web/Security/Defenses/Secure_Contexts)), and also will not be treated as [mixed content](/en-US/docs/Web/Security/Defenses/Mixed_content) ([Firefox bug 1220810](https://bugzil.la/1220810 "External link (opens in new tab)"), [Firefox bug 1488740](https://bugzil.la/1488740 "External link (opens in new tab)")).

### [APIs](#apis)

*   We've added support for the [`PerformancePaintTiming`](/en-US/docs/Web/API/PerformancePaintTiming) interface of the Paint Timing API ([Firefox bug 1518999](https://bugzil.la/1518999 "External link (opens in new tab)")).
*   The [`Navigator.registerProtocolHandler()`](/en-US/docs/Web/API/Navigator/registerProtocolHandler) method now only accepts two parameters: `scheme` and `url`. `title` has been removed ([Firefox bug 1631464](https://bugzil.la/1631464 "External link (opens in new tab)")).

#### Media, WebRTC, and Web Audio

*   The [`MediaRecorder.start()`](/en-US/docs/Web/API/MediaRecorder/start) method now throws an `InvalidModificationError` if the number of tracks on the stream being recorded has changed ([Firefox bug 1581139](https://bugzil.la/1581139 "External link (opens in new tab)")).

#### Removals

*   The application cache has been removed — developers should use the [Service Worker API](/en-US/docs/Web/API/Service_Worker_API) instead ([Firefox bug 1619673](https://bugzil.la/1619673 "External link (opens in new tab)")).

### [WebAssembly](#webassembly)

_No changes._

### [WebDriver conformance (Marionette)](#webdriver_conformance_marionette)

*   Added chrome scope support for `WebDriver:PerformActions` and `WebDriver:ReleaseActions` ([Firefox bug 1365886](https://bugzil.la/1365886 "External link (opens in new tab)")).
*   The new Fission-compatible API has been enabled by default now. To revert to the former API the `marionette.actors.enabled` preference has to be set to `false` ([Firefox bug 1669169](https://bugzil.la/1669169 "External link (opens in new tab)")).
*   Fixed `WebDriver:SwitchToWindow` to always switch back to the top-level browsing context ([Firefox bug 1305822](https://bugzil.la/1305822 "External link (opens in new tab)")).
*   Improved browsing context checks for `WebDriver:SwitchToParentFrame` ([Firefox bug 1671622](https://bugzil.la/1671622 "External link (opens in new tab)")).
*   Fixed a hang for `WebDriver:Back` encountered when the currently-selected [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) gets unloaded ([Firefox bug 1672758](https://bugzil.la/1672758 "External link (opens in new tab)")).

#### Known bugs

*   After page navigation, accessing a previously-retrieved element might not always raise a "stale element" error, and can also lead to a "no such element" error. To prevent this, set the `marionette.actors.enabled` preference to `false` ([Firefox bug 1684827](https://bugzil.la/1684827 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

*   The [`browsingData.remove()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browsingData/remove) API now supports removing a subset of data types by `cookieStoreId`.
