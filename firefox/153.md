# Firefox 153 release notes for developers

This article provides information about the changes in Firefox 153 that affect developers. Firefox 153 was released on [July 21, 2026](https://whattrainisitnow.com/release/?version=153 "External link (opens in new tab)").

## [Changes for web developers](#changes_for_web_developers)

### [Developer Tools](#developer_tools)

*   The developer tools now provide the heading level for a heading element in the accessibility highlighter and accessibility tree (previously just the fact that it was a heading was shown). The information can be found in the [Accessibility Inspector panel](https://firefox-source-docs.mozilla.org/devtools-user/accessibility_inspector/index.html "External link (opens in new tab)"). ([Firefox bug 1588784](https://bugzil.la/1588784 "External link (opens in new tab)") and [Firefox bug 2044904](https://bugzil.la/2044904 "External link (opens in new tab)")).

### [HTML](#html)

*   HTML parsing rules for [`<select>`](/en-US/docs/Web/HTML/Reference/Elements/select) elements have been updated to allow all nested elements to be parsed into DOM rather than just `<option>`, `<optgroup>`, and `<hr>`. This enables possible future support of [customizable select elements](/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select). ([Firefox bug 2019977](https://bugzil.la/2019977 "External link (opens in new tab)")).
*   The `muted` attribute has now been updated for the [`<audio>`](/en-US/docs/Web/HTML/Reference/Elements/audio#muted) and [`<video>`](/en-US/docs/Web/HTML/Reference/Elements/video#muted) elements to reflect when it is added to or removed from the DOM. This attribute now also matches the state of the [`:muted`](/en-US/docs/Web/CSS/Reference/Selectors/:muted) CSS pseudo-class. ([Firefox bug 2037015](https://bugzil.la/2037015 "External link (opens in new tab)")).

### [CSS](#css)

*   The [`::-webkit-scrollbar`](/en-US/docs/Web/CSS/Reference/Selectors/::-webkit-scrollbar) pseudo-element selector is now recognized, so the `@supports selector(::-webkit-scrollbar)` check returns `true`. Note that this reports the selector as supported even though scrollbar styling via `::-webkit-scrollbar` is not truly implemented. This was added to fix an issue where scrollbars of nested scrollable areas could stack on top of each other. For example, when a scrollbar is set to `display: none` or `width: 0` leaving some content unreachable. ([Firefox bug 2038877](https://bugzil.la/2038877 "External link (opens in new tab)")).

### [JavaScript](#javascript)

*   The [TC39 Intl.Locale info proposal](https://github.com/tc39/proposal-intl-locale-info "External link (opens in new tab)") is now supported. This includes all the instance methods on `Intl.Locale` that are prefixed with "get" — [`getCalendars()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Locale/getCalendars), [`getCollations()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Locale/getCollations), [`getHourCycles()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Locale/getHourCycles), [`getNumberingSystems()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Locale/getNumberingSystems), [`getTextInfo()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Locale/getTextInfo), [`getTimeZones()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Locale/getTimeZones), and [`getWeekInfo()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Locale/getWeekInfo). ([Firefox bug 2037069](https://bugzil.la/2037069 "External link (opens in new tab)")).
*   The [`Error.stackTraceLimit`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error/stackTraceLimit) static data property is supported for setting or getting the maximum number of stack frames captured in an error stack trace. Setting the value smaller than the default can improve performance. ([Firefox bug 2037856](https://bugzil.la/2037856 "External link (opens in new tab)")).
*   Text modules can now be imported into a string using [`with { type: "text" }`](/en-US/docs/Web/JavaScript/Reference/Statements/import/with#text_modules_type_text). Unlike for JavaScript or CSS modules, the media type of the response is ignored, and the content is parsed as text even if the file contains scripts or other executable code. ([Firefox bug 2039881](https://bugzil.la/2039881 "External link (opens in new tab)")).
*   The [`import source`](/en-US/docs/Web/JavaScript/Reference/Statements/import/source) syntax (part of the [TC39 source phase imports](https://github.com/tc39/proposal-source-phase-imports "External link (opens in new tab)") proposal) is now supported. It is similar to the normal [`import`](/en-US/docs/Web/JavaScript/Reference/Statements/import) declaration, but instead of loading and evaluating a module, it produces an object representing the module's source code that can be evaluated later. Note that this feature is not yet useful for developers, as only the syntax is currently supported: the source representation of WebAssembly modules is implemented separately and is not yet available. ([Firefox bug 2043242](https://bugzil.la/2043242 "External link (opens in new tab)")).

### [APIs](#apis)

*   The [`IDBObjectStore.getAllRecords()`](/en-US/docs/Web/API/IDBObjectStore/getAllRecords) and [`IDBIndex.getAllRecords()`](/en-US/docs/Web/API/IDBIndex/getAllRecords) methods are now supported. These retrieve all records (or a specified subset of records) from an object store and index, respectively. ([Firefox bug 1927945](https://bugzil.la/1927945 "External link (opens in new tab)")).
*   The [Picture-in-Picture API](/en-US/docs/Web/API/Picture-in-Picture_API) is now supported on desktop platforms. This provides a convenient mechanism for websites to toggle display of a [`<video>`](/en-US/docs/Web/HTML/Reference/Elements/video) element between a page and a floating always-on-top video window, allowing users to continue watching while they interact with other sites or applications. ([Firefox bug 1463402](https://bugzil.la/1463402 "External link (opens in new tab)")).

#### DOM

*   The [Popover API](/en-US/docs/Web/API/Popover_API) now has more consistent behavior when [`hint` and `auto` popovers are opened and closed](/en-US/docs/Web/API/Popover_API/Using#popover_openclose_interaction_rules). This follows the specification update in [whatwg/html#12345](https://github.com/whatwg/html/pull/12345 "External link (opens in new tab)"). ([Firefox bug 2029974](https://bugzil.la/2029974 "External link (opens in new tab)")).

#### Media, WebRTC, and Web Audio

*   The [`RTCDtlsTransport.getRemoteCertificates()`](/en-US/docs/Web/API/RTCDtlsTransport/getRemoteCertificates) method gets the certificates used by the remote peer to secure the DTLS communication. These can be used for application-layer authentication of a remote peer. ([Firefox bug 1805446](https://bugzil.la/1805446 "External link (opens in new tab)")).
*   The [`decodingInfo()`](/en-US/docs/Web/API/MediaCapabilities/decodingInfo "decodingInfo()") and [`encodingInfo()`](/en-US/docs/Web/API/MediaCapabilities/encodingInfo "encodingInfo()") methods of the [`MediaCapabilities`](/en-US/docs/Web/API/MediaCapabilities) interface now accept the `"webrtc"` configuration type. This allows a site to query whether a given audio or video configuration can be decoded or encoded using WebRTC, and whether doing so will be smooth, power efficient, or both. Support for the non-standard [`transmission`](/en-US/docs/Web/API/MediaCapabilities/encodingInfo#transmission) type, which was used as an alias for `webrtc`, is removed. ([Firefox bug 2037610](https://bugzil.la/2037610 "External link (opens in new tab)") and [Firefox bug 2032075](https://bugzil.la/2032075 "External link (opens in new tab)")).
*   All mandatory and some optional WebRTC "transport" statistics can now be reported in a [`RTCStatsReport`](/en-US/docs/Web/API/RTCStatsReport). The returned object is a [`RTCTransportStats`](/en-US/docs/Web/API/RTCTransportStats) with the following properties: [`dtlsCipher`](/en-US/docs/Web/API/RTCTransportStats/dtlsCipher "dtlsCipher"), [`dtlsRole`](/en-US/docs/Web/API/RTCTransportStats/dtlsRole "dtlsRole"), [`dtlsState`](/en-US/docs/Web/API/RTCTransportStats/dtlsState "dtlsState"), [`iceLocalUsernameFragment`](/en-US/docs/Web/API/RTCTransportStats/iceLocalUsernameFragment "iceLocalUsernameFragment"), [`iceRole`](/en-US/docs/Web/API/RTCTransportStats/iceRole "iceRole"), [`iceState`](/en-US/docs/Web/API/RTCTransportStats/iceState "iceState"), [`id`](/en-US/docs/Web/API/RTCTransportStats/id "id"), [`selectedCandidatePairId`](/en-US/docs/Web/API/RTCTransportStats/selectedCandidatePairId "selectedCandidatePairId"), [`srtpCipher`](/en-US/docs/Web/API/RTCTransportStats/srtpCipher "srtpCipher"), [`timestamp`](/en-US/docs/Web/API/RTCTransportStats/timestamp "timestamp"), [`tlsVersion`](/en-US/docs/Web/API/RTCTransportStats/tlsVersion "tlsVersion"), and [`type`](/en-US/docs/Web/API/RTCTransportStats/type "type"). In addition the `transportId` property is now available on [`RTCOutboundRtpStreamStats`](/en-US/docs/Web/API/RTCOutboundRtpStreamStats/transportId "RTCOutboundRtpStreamStats"), [`RTCRemoteOutboundRtpStreamStats`](/en-US/docs/Web/API/RTCRemoteOutboundRtpStreamStats/transportId "RTCRemoteOutboundRtpStreamStats"), [`RTCRemoteInboundRtpStreamStats`](/en-US/docs/Web/API/RTCRemoteInboundRtpStreamStats/transportId "RTCRemoteInboundRtpStreamStats") and [`RTCInboundRtpStreamStats`](/en-US/docs/Web/API/RTCInboundRtpStreamStats/transportId "RTCInboundRtpStreamStats"). ([Firefox bug 1225723](https://bugzil.la/1225723 "External link (opens in new tab)") and [Firefox bug 2019389](https://bugzil.la/2019389 "External link (opens in new tab)")).

### [WebAssembly](#webassembly)

*   JavaScript Promise Integration (JS-PI) is now enabled, allowing [WebAssembly](/en-US/docs/WebAssembly) modules to interoperate with asynchronous, [`Promise`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)\-based JavaScript APIs. This lets WebAssembly code suspend while waiting for a JavaScript promise and resume when the promise settles. See [`WebAssembly.Suspending`](/en-US/docs/WebAssembly/Reference/JavaScript_interface/Suspending) for an explanation and working example. ([Firefox bug 2044809](https://bugzil.la/2044809 "External link (opens in new tab)")).

### [WebDriver conformance (WebDriver BiDi, Marionette)](#webdriver_conformance_webdriver_bidi_marionette)

#### General

*   Improved the window manipulation commands in Marionette and WebDriver BiDi to allow individual window geometry properties, such as x, y, width, and height, to be adjusted independently. ([Firefox bug 1941404](https://bugzil.la/1941404 "External link (opens in new tab)")).
*   Fixed a bug where click and pointer action commands could fail if the element's first DOMRect (e.g., inline elements spanning multiple lines) was zero-sized. ([Firefox bug 2038932](https://bugzil.la/2038932 "External link (opens in new tab)")).
*   Restricted navigation to privileged pages (certain `about:*` pages, `chrome://`, and `resource://` URLs) when operating in content scope. ([Firefox bug 1579790](https://bugzil.la/1579790 "External link (opens in new tab)")).

#### WebDriver BiDi

*   Extended the `emulation.setLocaleOverride` command to also apply a locale emulation to dedicated and shared workers. ([Firefox bug 2015655](https://bugzil.la/2015655 "External link (opens in new tab)")).
*   Extended the `emulation.setTimezoneOverride` command to also apply a timezone emulation to dedicated and shared workers. ([Firefox bug 2015657](https://bugzil.la/2015657 "External link (opens in new tab)")).
*   Updated the `browsingContext.create` command to no longer emit `browsingContext.domContentLoaded` and `browsingContext.load` events for the initial `about:blank` page when creating new top-level browsing contexts, and to now emit the `browsingContext.contextCreated` event at the end of the creation process. ([Firefox bug 1930594](https://bugzil.la/1930594 "External link (opens in new tab)")).
*   Fixed a bug where functions created by the `script.addPreloadScript` command might have stopped working after several navigations. ([Firefox bug 2046390](https://bugzil.la/2046390 "External link (opens in new tab)")).

#### Marionette

*   Fixed the `Take Element Screenshot` command from WebDriver Classic to crop screenshots of elements which exceed the viewport. ([Firefox bug 2013176](https://bugzil.la/2013176 "External link (opens in new tab)")).
*   Fixed the `Perform Actions` command to properly await internal action finalization, preventing potential race conditions. ([Firefox bug 2031596](https://bugzil.la/2031596 "External link (opens in new tab)")).

## [Changes for add-on developers](#changes_for_add-on_developers)

*   Extensions now require explicit user permission to access `file://` URLs. Previously, access to local files was covered by the "Access your data for all websites" host permission. This change introduces a separate "Access local files on your computer" option in the extension's permissions settings (desktop only), and file access is turned off by default for all extensions, including existing ones. The [`extension.isAllowedFileSchemeAccess()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/extension/isAllowedFileSchemeAccess) method now correctly returns `true` if the user has granted file scheme access; previously, Firefox always returned `false`. Additionally, calling [`devtools.inspectedWindow.eval()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/devtools/inspectedWindow/eval) on `file://` URLs now requires this permission. ([Firefox bug 2034168](https://bugzil.la/2034168 "External link (opens in new tab)"))
*   Supports the [`userScripts.execute()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/userScripts/execute) method, enabling extensions to inject user scripts on demand into a tab or frame. Unlike [`userScripts.register()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/userScripts/register), this method supports one-off injection of multiple script sources executed in a defined order. ([Firefox bug 1930776](https://bugzil.la/1930776 "External link (opens in new tab)"))
*   Adds the [`publicSuffix`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/publicSuffix) API, enabling extensions to determine the registrable domain (eTLD+1) and public suffix of a hostname using the browser's built-in [Public Suffix List](https://publicsuffix.org/ "External link (opens in new tab)"). The API provides three synchronous methods: [`publicSuffix.isKnownSuffix()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/publicSuffix/isKnownSuffix), [`publicSuffix.getKnownSuffix()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/publicSuffix/getKnownSuffix), and [`publicSuffix.getDomain()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/publicSuffix/getDomain). ([Firefox bug 1315558](https://bugzil.la/1315558 "External link (opens in new tab)"))
*   Adds `documentId` to a range of WebExtension APIs, including a new [`runtime.getDocumentId()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/runtime/getDocumentId) method, [`webNavigation`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webNavigation) events and methods, [`webRequest`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest) events, scripting injection targets, and messaging APIs. See [Work with documentId](/en-US/docs/Mozilla/Add-ons/WebExtensions/Work_with_documentId) for the full list of supported events and methods, along with guidance on using `documentId`. ([Firefox bug 1891478](https://bugzil.la/1891478 "External link (opens in new tab)"))
*   Extension content scripts can now read and modify constructed stylesheets in [`document.adoptedStyleSheets`](/en-US/docs/Web/API/Document/adoptedStyleSheets) and [`ShadowRoot.adoptedStyleSheets`](/en-US/docs/Web/API/ShadowRoot/adoptedStyleSheets), without `.wrappedJSObject`. ([Firefox bug 1751346](https://bugzil.la/1751346 "External link (opens in new tab)"))
*   The [`theme`](/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/theme) manifest key's `images.additional_backgrounds` property now supports CSS gradients in addition to image URLs. A new `properties.additional_backgrounds_size` property controls the size of each additional background item. ([Firefox bug 2036647](https://bugzil.la/2036647 "External link (opens in new tab)"))
*   For contextual identities (containers):
    *   Adds the [`contextualIdentities.getSupportedColors()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/contextualIdentities/getSupportedColors) and [`contextualIdentities.getSupportedIcons()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/contextualIdentities/getSupportedIcons) methods to retrieve the supported colors and icons, avoiding the need to hardcode those values. ([Firefox bug 2044712](https://bugzil.la/2044712 "External link (opens in new tab)"))
    *   Updates the colors available. `"turquoise"` is renamed to `"cyan"`, `"toolbar"` is renamed to `"gray"`, and `"violet"` is added. The legacy names `"turquoise"` and `"toolbar"` are accepted for backward compatibility. To avoid hardcoding color names, use [`contextualIdentities.getSupportedColors()`](/en-US/docs/Mozilla/Add-ons/WebExtensions/API/contextualIdentities/getSupportedColors) to retrieve the available colors. ([Firefox bug 2044354](https://bugzil.la/2044354 "External link (opens in new tab)"))

## [Experimental web features](#experimental_web_features)

These features are shipping in Firefox 153 but are disabled by default. To experiment with them, search for the appropriate preference on the `about:config` page and set it to `true`. You can find more such features on the [Experimental features](/en-US/docs/Mozilla/Firefox/Experimental_features) page.

*   **JPEG XL image support** (Nightly): `image.jxl.enabled`
    
    The Rust-based [JPEG XL](https://jpeg.org/jpegxl/ "External link (opens in new tab)") image decoder is now enabled by default in Nightly. ([Firefox bug 2040074](https://bugzil.la/2040074 "External link (opens in new tab)")).
    
*   **`headingoffset` and `headingreset` HTML attributes**: `dom.headingoffset.enabled`
    
    The [`headingoffset`](/en-US/docs/Web/HTML/Reference/Global_attributes/headingoffset) global attribute increases the computed heading level of the [heading elements](/en-US/docs/Web/HTML/Reference/Elements/Heading_Elements) inside the element it is set on, so that a component can use the same heading markup wherever it appears in a page. The [`headingreset`](/en-US/docs/Web/HTML/Reference/Global_attributes/headingreset) attribute stops the offsets of ancestor elements from applying to the headings inside the element it is set on. ([Firefox bug 1974383](https://bugzil.la/1974383 "External link (opens in new tab)")).
    
*   **Tree counting CSS functions**: `layout.css.tree-counting-functions.enabled`
    
    The [`sibling-count()`](/en-US/docs/Web/CSS/Reference/Values/sibling-count) and [`sibling-index()`](/en-US/docs/Web/CSS/Reference/Values/sibling-index) functions are now supported. The `sibling-count()` function returns the number of sibling elements as well as the element itself. The `sibling-index()` function returns the index number of the element in relation to its siblings, this starts from `1` and not `0`. ([Firefox bug 2042063](https://bugzil.la/2042063 "External link (opens in new tab)")).
    
*   **Updating attributes of external resources**: `layout.css.link-parameters.enabled`
    
    The [`link-parameters`](/en-US/docs/Web/CSS/Reference/Properties/link-parameters) CSS property and [`param()`](/en-US/docs/Web/CSS/Reference/Values/param) CSS function are now supported. This allows the user to update attributes of external resources, such as SVGs, that have their attributes set with the [`env()`](/en-US/docs/Web/CSS/Reference/Values/env) CSS function. This means that a single external resource can be used rather than creating multiple variations that only have different colors or other values. ([Firefox bug 2046153](https://bugzil.la/2046153 "External link (opens in new tab)")).
    
*   **CSS basic shapes allow `farthest-corner` and `closest-corner` keywords** (Nightly): `layout.css.ellipse-corners.enabled`
    
    The `farthest-corner` and `closest-corner` keywords can now be used for specifying the radii values of the [`ellipse()`](/en-US/docs/Web/CSS/Reference/Values/basic-shape/ellipse) and [`circle()`](/en-US/docs/Web/CSS/Reference/Values/basic-shape/circle) CSS basic shapes. ([Firefox bug 2037673](https://bugzil.la/2037673 "External link (opens in new tab)")).
