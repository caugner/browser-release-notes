# Firefox 44 release notes for developers

[To test the latest developer features of Firefox, install Firefox Developer Edition](https://www.firefox.com/en-US/channel/desktop/developer/ "External link (opens in new tab)"). Firefox 44 was released on January 26, 2016. This article lists key changes that are useful not only for web developers, but also Firefox and Gecko developers as well as add-on developers.

## [Changes for web developers](#changes_for_web_developers)

### [Developer tools](#developer_tools)

*   [`<link rel="prefetch">`](/en-US/docs/Glossary/Prefetch) now obeys the [`crossorigin`](/en-US/docs/Web/HTML/Reference/Elements/link#crossorigin) attribute ([Firefox bug 1214819](https://bugzil.la/1214819 "External link (opens in new tab)")).

### [CSS](#css)

*   `position: fixed;` now always creates a new stacking context ([Firefox bug 1179288](https://bugzil.la/1179288 "External link (opens in new tab)")).
    
*   The support of [`unicode-range`](/en-US/docs/Web/CSS/Reference/At-rules/@font-face/unicode-range) has been enabled by default ([Firefox bug 1119062](https://bugzil.la/1119062 "External link (opens in new tab)")).
    
*   Our experimental implementation of CSS Writing Modes has been updated to reflect the latest specification:
    
    *   The value `sideways` of the [`text-orientation`](/en-US/docs/Web/CSS/Reference/Properties/text-orientation) property has been implemented and `sideways-right` has been made an alias of it ([Firefox bug 1193488](https://bugzil.la/1193488 "External link (opens in new tab)")).
    *   The value `sideways-rl` and `sideways-lr` of the [`writing-mode`](/en-US/docs/Web/CSS/Reference/Properties/writing-mode) property ([Firefox bug 1193488](https://bugzil.la/1193488 "External link (opens in new tab)") and [Firefox bug 1193519](https://bugzil.la/1193519 "External link (opens in new tab)")).
*   The non-standard properties `-moz-math-display` and `-moz-window-shadow` are no more available from Web content ([Firefox bug 1207002](https://bugzil.la/1207002 "External link (opens in new tab)"), [Firefox bug 1211040](https://bugzil.la/1211040 "External link (opens in new tab)"), and [Firefox bug 1212607](https://bugzil.la/1212607 "External link (opens in new tab)")).
    
*   The [`font-style`](/en-US/docs/Web/CSS/Reference/Properties/font-style) property now distinguishes between `oblique` and `italic` when both variants are available ([Firefox bug 543715](https://bugzil.la/543715 "External link (opens in new tab)")).
    
*   Though not supported, the properties `marks`, [`orphans`](/en-US/docs/Web/CSS/Reference/Properties/orphans), [`page`](/en-US/docs/Web/CSS/Reference/Properties/page), [`size`](/en-US/docs/Web/CSS/Reference/At-rules/@page/size), and [`widows`](/en-US/docs/Web/CSS/Reference/Properties/widows), were parsed and [`@supports`](/en-US/docs/Web/CSS/Reference/At-rules/@supports) was incorrectly reporting them as supported; this has been fixed and the properties are not parsed anymore, nor marked as supported ([Firefox bug 1215702](https://bugzil.la/1215702 "External link (opens in new tab)")).
    
*   The internal value `-moz-mac-unified-toolbar` has been removed from the possible values for the [`appearance`](/en-US/docs/Web/CSS/Reference/Properties/appearance) property ([Firefox bug 1206468](https://bugzil.la/1206468 "External link (opens in new tab)")).
    
*   Several `-webkit` prefixed properties and values have been added for web compatibility, behind the preference `layout.css.prefixes.webkit`, defaulting to `false` ([Firefox bug 837211](https://bugzil.la/837211 "External link (opens in new tab)")):
    
    *   `-webkit-animation`
    *   `-webkit-animation-delay`
    *   `-webkit-animation-direction`
    *   `-webkit-animation-duration`
    *   `-webkit-animation-fill-mode`
    *   `-webkit-animation-iteration-count`
    *   `-webkit-animation-name`
    *   `-webkit-animation-play-state`
    *   `-webkit-animation-timing-function`
    *   `-webkit-text-size-adjust`
    *   `-webkit-transform`
    *   `-webkit-transform-origin`
    *   `-webkit-transform-style`
    *   `-webkit-transition`
    *   `-webkit-transition-delay`
    *   `-webkit-transition-duration`
    *   `-webkit-transition-property`
    *   `-webkit-transition-timing-function`
    *   `-webkit-border-radius`
    *   `-webkit-border-top-left-radius`
    *   `-webkit-border-top-right-radius`
    *   `-webkit-border-bottom-left-radius`
    *   `-webkit-border-bottom-right-radius`
    *   `-webkit-appearance`
    *   `-webkit-background-clip`
    *   `-webkit-background-origin`
    *   `-webkit-background-size`
    *   `-webkit-border-image`
    *   `-webkit-box-shadow`
    *   `-webkit-box-sizing`
    *   `-webkit-user-select`
    *   `-webkit-linear-gradient()` [Firefox bug 1210575](https://bugzil.la/1210575 "External link (opens in new tab)")
    *   `-webkit-radial-gradient"()` [Firefox bug 1210575](https://bugzil.la/1210575 "External link (opens in new tab)")
    *   `-webkit-repeating-linear-gradient()` [Firefox bug 1210575](https://bugzil.la/1210575 "External link (opens in new tab)")
    *   `-webkit-repeating-radial-gradient()` [Firefox bug 1210575](https://bugzil.la/1210575 "External link (opens in new tab)")

### [JavaScript](#javascript)

#### New APIs

*   [`Symbol.toPrimitive`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/toPrimitive), [`Symbol.prototype[Symbol.toPrimitive]()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/Symbol.toPrimitive), and [`Date.prototype[Symbol.toPrimitive]()`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive) have been implemented ([Firefox bug 1054756](https://bugzil.la/1054756 "External link (opens in new tab)")).

#### Changes

*   The [`let`](/en-US/docs/Web/JavaScript/Reference/Statements/let) and [`const`](/en-US/docs/Web/JavaScript/Reference/Statements/const) bindings in the global level have been made compliant with ES2015 semantics. See [Firefox bug 589199](https://bugzil.la/589199 "External link (opens in new tab)") and the blog post ["Breaking changes in let and const in Firefox Nightly 44"](https://blog.mozilla.org/addons/2015/10/14/breaking-changes-let-const-firefox-nightly-44/ "External link (opens in new tab)"). In addition, `let` is now available to default Web JavaScript (strict and non-strict) and does not require a version opt-in anymore ([Firefox bug 932517](https://bugzil.la/932517 "External link (opens in new tab)")).
*   If [typed arrays'](/en-US/docs/Web/JavaScript/Guide/Typed_arrays) (like [`Int8Array`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Int8Array)) and [`ArrayBuffer`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/ArrayBuffer)) constructors are called as a function without the [`new`](/en-US/docs/Web/JavaScript/Reference/Operators/new) operator, a [`TypeError`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypeError) is now thrown as per the ES2015 specification ([Firefox bug 980945](https://bugzil.la/980945 "External link (opens in new tab)"), [Firefox bug 1214936](https://bugzil.la/1214936 "External link (opens in new tab)")).
*   The [`RegExp`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp) sticky flag now follows the ES2015 standard for [anchored sticky regular expressions](/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/sticky#anchored_sticky_flag) ([Firefox bug 773687](https://bugzil.la/773687 "External link (opens in new tab)")).
*   The JavaScript shell (SpiderMonkey's REPL) now defaults to the default, Web-compatible JS version (and not JS1.7+ anymore) ([Firefox bug 1192329](https://bugzil.la/1192329 "External link (opens in new tab)")).

#### Removals

*   Support for the non-standard [`let` blocks](/en-US/docs/Web/JavaScript/Reference/Deprecated_and_obsolete_features#statements_2) has been dropped ([Firefox bug 1167029](https://bugzil.la/1167029 "External link (opens in new tab)").
*   The non-standard and deprecated property `Object.prototype.__noSuchMethod__` has been removed ([Firefox bug 683218](https://bugzil.la/683218 "External link (opens in new tab)")).

### [Interfaces/APIs/DOM](#interfacesapisdom)

#### DOM & HTML DOM

*   For compatibility with specific existing sites, the property `Document.charset` has been implemented as an alias of [`Document.characterSet`](/en-US/docs/Web/API/Document/characterSet) ([Firefox bug 647621](https://bugzil.la/647621 "External link (opens in new tab)")).
*   Support for the `window.sidebar.addSearchEngine()` method, which allowed Web pages to invoke an installation of a Sherlock plugin, has been dropped and now it just logs a warning in the Web Console ([Firefox bug 862148](https://bugzil.la/862148 "External link (opens in new tab)")).
*   To fight unwanted pop-ups, prompts requested in [`beforeunload`](/en-US/docs/Web/API/Window/beforeunload_event "beforeunload") events of pages that have not been interacted with are no more displayed ([Firefox bug 636905](https://bugzil.la/636905 "External link (opens in new tab)")).
*   The deprecated method `MessageEvent.initMessageEvent()` has been reimplemented for backward compatibility ([Firefox bug 949376](https://bugzil.la/949376 "External link (opens in new tab)")).
*   The obsolete property `DocumentType.internalSubset` has been removed ([Firefox bug 801545](https://bugzil.la/801545 "External link (opens in new tab)")).
*   For compatibility with existing sites, the [`Window.orientation`](/en-US/docs/Web/API/Window/orientation) property and the [`orientationchange`](/en-US/docs/Web/API/Window/orientationchange_event "orientationchange") event have been implemented ([Firefox bug 920734](https://bugzil.la/920734 "External link (opens in new tab)")).
*   An [`<iframe>`](/en-US/docs/Web/HTML/Reference/Elements/iframe) with explicit fullscreen request should not exit fullscreen implicitly ([Firefox bug 1187801](https://bugzil.la/1187801 "External link (opens in new tab)")).
*   The events [`mouseover`](/en-US/docs/Web/API/Element/mouseover_event "mouseover"), [`mouseout`](/en-US/docs/Web/API/Element/mouseout_event "mouseout"), [`mouseenter`](/en-US/docs/Web/API/Element/mouseenter_event "mouseenter"), [`mouseleave`](/en-US/docs/Web/API/Element/mouseleave_event "mouseleave"), [`pointermove`](/en-US/docs/Web/API/Element/pointermove_event "pointermove"), [`pointerover`](/en-US/docs/Web/API/Element/pointerover_event "pointerover"), [`pointerout`](/en-US/docs/Web/API/Element/pointerout_event "pointerout"), [`pointerenter`](/en-US/docs/Web/API/Element/pointerenter_event "pointerenter") and [`pointerleave`](/en-US/docs/Web/API/Element/pointerleave_event "pointerleave") are now triggered for disabled form elements ([Firefox bug 218093](https://bugzil.la/218093 "External link (opens in new tab)")).
*   The method [`Element.webkitMatchesSelector()`](/en-US/docs/Web/API/Element/matches "Element.webkitMatchesSelector()") has been added ([Firefox bug 1216193](https://bugzil.la/1216193 "External link (opens in new tab)")) to improve interoperability.
*   To match the spec, the method [`Document.createAttribute()`](/en-US/docs/Web/API/Document/createAttribute) now converts the input to lower case ([Firefox bug 1176313](https://bugzil.la/1176313 "External link (opens in new tab)")).
*   The non-standard `dialog` feature for [`Window.open()`](/en-US/docs/Web/API/Window/open) is no longer available to Web content. It is still available to extensions and other code with chrome privileges ([Firefox bug 1095236](https://bugzil.la/1095236 "External link (opens in new tab)").

#### Canvas

*   A new experimental [`OffscreenCanvas`](/en-US/docs/Web/API/OffscreenCanvas) API that allows rendering contexts (such as [WebGL](/en-US/docs/Web/API/WebGL_API)) to run in [Web Workers](/en-US/docs/Web/API/Web_Workers_API) has been implemented. To use this experimental API set `gfx.offscreencanvas.enabled` to `true` in about:config ([Firefox bug 709490](https://bugzil.la/709490 "External link (opens in new tab)")). This API includes:
    *   The [`OffscreenCanvas`](/en-US/docs/Web/API/OffscreenCanvas) interface,
    *   [`HTMLCanvasElement.transferControlToOffscreen()`](/en-US/docs/Web/API/HTMLCanvasElement/transferControlToOffscreen), and
    *   `WebGLRenderingContext.commit()`.
    *   Several WebGL interfaces are now also available in a worker context when this API is enabled.

#### WebGL

*   Uniform Buffer Objects have been implemented ([Firefox bug 1048747](https://bugzil.la/1048747 "External link (opens in new tab)")).

#### IndexedDB

*   The [`IDBIndex.getAll()`](/en-US/docs/Web/API/IDBIndex/getAll) and [`IDBIndex.getAllKeys()`](/en-US/docs/Web/API/IDBIndex/getAllKeys), and there counterparts on [`IDBObjectStore`](/en-US/docs/Web/API/IDBObjectStore) are now available by default ([Firefox bug 1196841](https://bugzil.la/1196841 "External link (opens in new tab)")).

#### Service Workers

*   The `ServiceWorkerMessageEvent` and [`ExtendableMessageEvent`](/en-US/docs/Web/API/ExtendableMessageEvent) interfaces have been implemented ([Firefox bug 1143717](https://bugzil.la/1143717 "External link (opens in new tab)") and [Firefox bug 1207068](https://bugzil.la/1207068 "External link (opens in new tab)")).
*   [`Headers`](/en-US/docs/Web/API/Headers) objects now support a pair iterator, meaning that the methods [`Headers.entries()`](/en-US/docs/Web/API/Headers/entries), [`Headers.keys()`](/en-US/docs/Web/API/Headers/keys), and [`Headers.values()`](/en-US/docs/Web/API/Headers/values) are now available; [`Symbol.iterator`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/iterator) now also returns the default iterator for them ([Firefox bug 1108181](https://bugzil.la/1108181 "External link (opens in new tab)")).
*   The [`XMLHttpRequest`](/en-US/docs/Web/API/XMLHttpRequest) API has been disabled on Service Workers ([Firefox bug 931243](https://bugzil.la/931243 "External link (opens in new tab)")).
*   The interface [`FetchEvent`](/en-US/docs/Web/API/FetchEvent) now extends [`ExtendableEvent`](/en-US/docs/Web/API/ExtendableEvent), giving it access to the [`ExtendableEvent.waitUntil()`](/en-US/docs/Web/API/ExtendableEvent/waitUntil) method. ([Firefox bug 1214772](https://bugzil.la/1214772 "External link (opens in new tab)")).
*   Following a recent change in the specification, `FetchEvent.client` has been removed ([Firefox bug 1218135](https://bugzil.la/1218135 "External link (opens in new tab)")).
*   To match the latest specification, the `ServiceWorkerContainer.onreloadpage` has been removed ([Firefox bug 1218139](https://bugzil.la/1218139 "External link (opens in new tab)")).
*   The event handlers `ServiceWorkerGlobalScope.onbeforeevicted` and `ServiceWorkerGlobalScope.onevicted` have been removed as they weren't following the spec. They will be reintroduced in the future, but their removal will allow feature detection to work as expected ([Firefox bug 1218142](https://bugzil.la/1218142 "External link (opens in new tab)")).
*   In the [`FetchEvent()`](/en-US/docs/Web/API/FetchEvent/FetchEvent "FetchEvent()") constructor, if the `isReload` member is not present in the options dictionary, it now defaults to `false` ([Firefox bug 1216401](https://bugzil.la/1216401 "External link (opens in new tab)")).
*   The [`Client.frameType`](/en-US/docs/Web/API/Client/frameType) property is now implemented on the right interface; it was on [`WindowClient`](/en-US/docs/Web/API/WindowClient) before ([Firefox bug 1218146](https://bugzil.la/1218146 "External link (opens in new tab)")).
*   When AppCache is used to provide offline support for a page, a warning message is now displayed in the console advising developers to use [Service workers](/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers) instead ([Firefox bug 1204581](https://bugzil.la/1204581 "External link (opens in new tab)").)
*   Service workers have been enabled by default in Gecko.

#### WebRTC

*   WebRTC interfaces have been _unprefixed_ ([Firefox bug 1155923](https://bugzil.la/1155923 "External link (opens in new tab)")). In particular:
    
    *   `mozRTCPeerConnection` is now [`RTCPeerConnection`](/en-US/docs/Web/API/RTCPeerConnection).
    *   `mozRTCIceCandidate` is now [`RTCIceCandidate`](/en-US/docs/Web/API/RTCIceCandidate).
    *   `mozRTCSessionDescription` is now [`RTCSessionDescription`](/en-US/docs/Web/API/RTCSessionDescription).
*   The [`RTCDataChannel.bufferedAmountLowThreshold`](/en-US/docs/Web/API/RTCDataChannel/bufferedAmountLowThreshold) property, as well as the [`bufferedamountlow`](/en-US/docs/Web/API/RTCDataChannel/bufferedamountlow_event "bufferedamountlow") event and its event handler, have been implemented ([Firefox bug 1178091](https://bugzil.la/1178091 "External link (opens in new tab)")).
    
*   The attribute [`RTCPeerConnection.canTrickleIceCandidates`](/en-US/docs/Web/API/RTCPeerConnection/canTrickleIceCandidates) has been added, the non-standard method `RTCPeerConnection.updateIce()` removed ([Firefox bug 1209744](https://bugzil.la/1209744 "External link (opens in new tab)")).
    
*   The [`MediaStream`](/en-US/docs/Web/API/MediaStream) interface now supports the [`MediaStream.addTrack()`](/en-US/docs/Web/API/MediaStream/addTrack) and [`MediaStream.removeTrack()`](/en-US/docs/Web/API/MediaStream/removeTrack) methods ([Firefox bug 1103188](https://bugzil.la/1103188 "External link (opens in new tab)")).
    
*   The constructor [`MediaStream()`](/en-US/docs/Web/API/MediaStream/MediaStream "MediaStream()") has been implemented ([Firefox bug 1070216](https://bugzil.la/1070216 "External link (opens in new tab)")).
    
*   Support for the non-standard constraint style option list for `RTCOfferOptions` has been removed.
    

#### New APIs

*   An experimental implementation of the Canvas API in Workers has landed: [`OffscreenCanvas`](/en-US/docs/Web/API/OffscreenCanvas) and [`HTMLCanvasElement.transferControlToOffscreen()`](/en-US/docs/Web/API/HTMLCanvasElement/transferControlToOffscreen) are available behind the `gfx.offscreencanvas.enabled` preference, currently disabled by default ([Firefox bug 709490](https://bugzil.la/709490 "External link (opens in new tab)")).
*   The Text2Speech API, part of Web Speech API, has now an OS X backend. But this is disabled by default ([Firefox bug 1003452](https://bugzil.la/1003452 "External link (opens in new tab)")).

#### Miscellaneous

*   [`URLSearchParams`](/en-US/docs/Web/API/URLSearchParams) objects now support a pair iterator, meaning that the methods [`URLSearchParams.entries()`](/en-US/docs/Web/API/URLSearchParams/entries), [`URLSearchParams.keys()`](/en-US/docs/Web/API/URLSearchParams/keys), and [`URLSearchParams.values()`](/en-US/docs/Web/API/URLSearchParams/values) are now available; [`Symbol.iterator`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/iterator) now also returns the default iterator for them ([Firefox bug 1085284](https://bugzil.la/1085284 "External link (opens in new tab)")).
*   [`FormData`](/en-US/docs/Web/API/FormData) objects now support a pair iterator, meaning that the methods [`FormData.entries()`](/en-US/docs/Web/API/FormData/entries), [`FormData.keys`](/en-US/docs/Web/API/FormData/keys), and [`FormData.values()`](/en-US/docs/Web/API/FormData/values) are now available; [`Symbol.iterator`](/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/iterator) now also returns the default iterator for them ([Firefox bug 1127703](https://bugzil.la/1127703 "External link (opens in new tab)")).
*   When [`XMLHttpRequest.send()`](/en-US/docs/Web/API/XMLHttpRequest/send) is used with an HTML document, it now uses `text/html` instead of `application/xml` ([Firefox bug 918771](https://bugzil.la/918771 "External link (opens in new tab)")).
*   Speech synthesis (text-to-speech) has been implemented in Firefox Desktop for Mac and Linux, hidden behind the `media.webspeech.synth.enabled` flag in `about:config` ([Firefox bug 1003452](https://bugzil.la/1003452 "External link (opens in new tab)"), [Firefox bug 1003464](https://bugzil.la/1003464 "External link (opens in new tab)").) See [Web Speech API](/en-US/docs/Web/API/Web_Speech_API) for more information.
*   Elements inside a [`<frame>`](/en-US/docs/Web/HTML/Reference/Elements/frame) or an [`<object>`](/en-US/docs/Web/HTML/Reference/Elements/object) can't be set fullscreen anymore ([Firefox bug 1212299](https://bugzil.la/1212299 "External link (opens in new tab)")).
*   Sanitization of WOFF fonts is a bit more stricter, leading to more incorrect fonts being rejected, this sanitization is made a bit less stricter in Firefox 46 ([Firefox bug 1193050](https://bugzil.la/1193050 "External link (opens in new tab)") and [Firefox bug 1244693](https://bugzil.la/1244693 "External link (opens in new tab)")).

### [Other](#other)

*   Due to breaking changes in Firefox 44 ([bug 1202902](https://bugzil.la/1202902 "External link (opens in new tab)")), add-ons packed with [cfx](https://web.archive.org/web/20201201072958/https://developer.mozilla.org/en-US/docs/Archive/Add-ons/Add-on_SDK/Tools/cfx "External link (opens in new tab)") will not work any longer. To make your add-on compatible again, please use [jpm](https://web.archive.org/web/20210221222338/https://developer.mozilla.org/en-US/docs/Archive/Add-ons/Add-on_SDK/Tools/jpm "External link (opens in new tab)"). See the [_cfx_ to _jpm_ migration guide](https://web.archive.org/web/20181116093809/https://developer.mozilla.org/en-US/docs/Archive/Add-ons/Add-on_SDK/Tools/cfx_to_jpm "External link (opens in new tab)").
