## CSS und UI

### Scroll-Container mit einer Achse

**Verfügbar in nicht stabilen Versionen (Beta, Entwickler und Canary).**

Erweitert die `overflow`\-Property, um scrollbare Werte zusammen mit `clip` zu unterstützen (z. B. `overflow: scroll clip`). Dadurch kann `position: sticky` durch verschiedene übergeordnete Scroll-Container pro Achse eingeschränkt werden. Außerdem können Sie dafür sorgen, dass eine Achse mit `overflow: clip` an Ort und Stelle bleibt.

[Tracking-Fehler #440038212](https://issues.chromium.org/issues/440038212) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5067363861004288) | [Spezifikation](https://github.com/w3c/csswg-drafts/pull/13903)

### Die Property `scroll-axis-lock`

`scroll-axis-lock` ist eine CSS-Property, mit der Sie Browser anweisen können, die Scrollbewegung eines Nutzers nicht auf eine Achse zu beschränken.

Webbrowser beschränken die Scrollbewegung eines Nutzers oft auf eine einzelne Achse, wenn diese Bewegung mit deutlich mehr Bewegung auf einer Achse als auf der senkrechten Achse beginnt. In vielen Fällen verbessert dieses Verhalten die Nutzerfreundlichkeit, da versehentliches Scrollen entlang der senkrechten Achse vermieden wird, wenn der Nutzer nur auf einer Achse scrollen wollte. Wenn Sie jedoch möchten, dass ein Element immer diagonal gescrollt werden kann, zwingt dieses Sperrverhalten den Nutzer, die Touchgeste in einem Winkel zu starten, der die Sperrung nicht auslöst.

[Tracking-Fehler #479472367](https://issues.chromium.org/issues/479472367) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5908461532610560) | [Spezifikation](https://github.com/w3c/csswg-drafts/pull/14152)

### Interoperable Dispatch-Zeit für `transitionrun`\- und Media Query-Ereignisse

Die Dispatch-Zeit von Blink für `transitionrun`\-Ereignisse für Animationen und `change`\-Ereignisse für Media Queries wird an die HTML-Spezifikation angepasst, sodass die Zeit mit Gecko und WebKit interoperabel ist. Gemäß der HTML-Spezifikation für die Ereignisschleife des Fensters werden `transitionrun`\-Ereignisse in Schritt 3.11 ausgelöst, auch für Animationen, die früher in derselben Iteration erstellt wurden (anstatt sie für eine spätere Iteration zu verzögern). `change`\-Ereignisse für Media Queries werden in Schritt 3.10 ausgelöst, bevor ausstehende Animationsereignisse ausgelöst werden (anstatt sie in Schritt 3.11 mit Animationsereignissen zu mischen).

[Tracking-Fehler #397737222](https://issues.chromium.org/issues/397737222) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/6312504658624512) | [Spezifikation](https://html.spec.whatwg.org/multipage/webappapis.html#event-loop-processing-model)

## DOM und HTML

### Funktionselemente: `<camera>` und `<microphone>`

Die Funktionselemente `<camera>` und `<microphone>` sind deklarative, vom Nutzer aktivierte HTML-Steuerelemente, die denselben zugrunde liegenden Mechanismus wie das Element `<usermedia>` verwenden, mit einem wichtigen Unterschied: Sie fordern eine einzelne Funktion an. Das Element `<camera>` fordert die Videoaufnahme an, während das Element `<microphone>` die Audioaufnahme anfordert. Wie bei `<usermedia>` wird eine vom Browser gesteuerte, streng formatierte UI in die Seite eingebettet, um ein starkes, beabsichtigtes Nutzersignal (ein Klick) zu gewährleisten, bevor eine Berechtigungsanfrage ausgelöst oder ein Stream gestartet wird.

Die Elemente `<camera>` und `<microphone>` bieten ein spezielles, semantisches HTML-Steuerelement für diese Anwendungsfälle mit einer einzelnen Funktion. Sie behalten dasselbe Sicherheitsmodell, dieselben strengen Formatierungsbeschränkungen und denselben integrierten Pfad zur Wiederherstellung von Berechtigungen wie `<usermedia>`, bieten aber eine besser zugeschnittene und ergonomischere API, wenn Sie keinen gemischten Media-Zugriff benötigen.

[Tracking-Fehler #531672795](https://issues.chromium.org/issues/531672795) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5153829504024576) | [Spezifikation](https://w3c.github.io/mediacapture-extensions/#the-camera-html-element)

### XML-Parsing in Rust für Nicht-XSLT-Szenarien

Um die Browsersicherheit zu verbessern und Nutzer vor speicherbezogenen Sicherheitslücken zu schützen, wird in Chrome 153 die XML-Parsing-Engine auf eine speichersichere Rust-Implementierung für mehrere gängige Szenarien aktualisiert. Dieses Update beseitigt potenzielle Speicherbeschädigungsfehler und behält gleichzeitig die volle Kompatibilität mit bestehenden Webstandards bei.

Chrome hat bereits damit begonnen, XSLT einzustellen und zu entfernen. Während dieser Prozess läuft, verarbeitet der neue, sicherere Parser die folgenden Szenarien, in denen kein XSLT erforderlich ist:

*   `DOMParser` Web API
*   Zugriff auf `responseXML` von `XMLHttpRequest`
*   Eigenständige SVG-Bilder (direkter Zugriff auf ein `image.svg`\-Dokument als Navigation der obersten Ebene)
*   Externe SVG-Bilder (Einbetten eines SVG als externe Bildressource in ein Hauptdokument)

[Tracking-Fehler #466303347](https://issues.chromium.org/issues/466303347) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5309598397497344) | [Spezifikation](https://www.w3.org/TR/xml)

## JavaScript

### Iterator Join

Fügt JavaScript eine Methode hinzu, um den Inhalt eines Iterators zu einem String zu verketten. Die `join()` Methode von `Iterator` Instanzen ähnelt `Array.prototype.join()`: Sie gibt einen String zurück, der die Verkettung aller vom Iterator erzeugten Elemente ist, getrennt durch Kommas oder einen angegebenen Trennstring.

[Tracking-Fehler #465715798](https://issues.chromium.org/issues/465715798) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5095183554314240) | [Spezifikation](https://tc39.es/proposal-iterator-join)

### Gemeinsame Iteration

Fügt Methoden hinzu, um den Fortschritt mehrerer Iteratoren in JavaScript zu synchronisieren (allgemein als Zip bezeichnet), einschließlich `Iterator.zip()` und `Iterator.zipKeyed()`.

[Tracking-Fehler #465357675](https://issues.chromium.org/issues/465357675) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/6249068542164992) | [Spezifikation](https://github.com/tc39/proposal-joint-iteration)

## Medien, Sensoren und Eingabe

### Unterstützung für die Dekodierung von Immersive Audio Model and Formats (IAMF)

Unterstützung für die Dekodierung und Wiedergabe des Immersive Audio Model and Formats (IAMF)-Containers in HTML-Media-Elementen über Media Source Extensions (MSE). IAMF ist ein offenes, lizenzfreies räumliches Audioformat, das kanalbasierte, szenenbasierte und objektbasierte Audiopräsentationen unterstützt. Durch die Unterstützung dieses Standards können Webentwickler konsistente, immersive 3D-Audioerlebnisse auf verschiedenen Geräten bereitstellen, ohne auf proprietäre Formate zurückgreifen oder komplexe diskrete Audiokanalrouten in JavaScript verwalten zu müssen.

[Tracking-Fehler #535279329](https://issues.chromium.org/issues/535279329) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5113656292540416) | [Spezifikation](https://aomediacodec.github.io/iamf/latest-approved.html)

### WebAudio: Konfigurierbares Render-Quantum

Fügt `AudioContext` und `OfflineAudioContext` einen optionalen `renderSizeHint` hinzu. So können Sie die Größe des WebAudio-Render-Quantums anpassen, indem Sie eine bestimmte Ganzzahl übergeben, den Standardwert von 128 Frames verwenden, indem Sie den Hinweis weglassen oder `"default"` übergeben, oder den Browser auffordern, eine optimale Größe auszuwählen, indem Sie `"hardware"` angeben.

[Tracking-Fehler #40637820](https://issues.chromium.org/issues/40637820) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5078190552907776) | [Spezifikation](https://webaudio.github.io/web-audio-api/#dom-baseaudiocontext-renderquantumsize)

### WebGPU: Funktion `buffer_view`

Fügt eine WGSL-Sprachfunktion hinzu, um Daten in Variablen neu zu interpretieren. Mit dieser Funktion können Sie eine einzelne einheitliche, Speicher- oder Arbeitsgruppenvariable in mehrere logische Variablen unterteilen. Außerdem kann der Datentyp in der Variablen im Programm als mehrere Typen interpretiert werden.

[Tracking-Fehler #506523198](https://issues.chromium.org/issues/506523198) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5094091886034944) | [Spezifikation](https://github.com/gpuweb/gpuweb/pull/6291)

## Ursprungstests

### JavaScript-Marker für das Selbst-Profiling

Mit der JavaScript Self-Profiling API kann eine Webanwendung ihre eigenen Aufrufstacks abtasten, um die Leistung auf Geräten von echten Nutzern zu messen. Diese Funktion fügt jeder erfassten Stichprobe ein optionales Markerfeld hinzu, das den Typ der Browseraktivität angibt, die ausgeführt wurde, als die Stichprobe aufgenommen wurde: Skript, Garbage Collection, Stil, Layout, Rendering oder anderes. Eine Ablaufverfolgung zeigt normalerweise Lücken zwischen Stacks, die nicht interpretiert werden können. Mit Markern können Sie diese Zeit der Browserarbeit zuordnen, die außerhalb von JavaScript stattfindet. So können Sie beispielsweise die Skriptausführung von der Neuberechnung des Stils, dem Layout oder einer automatischen Speicherbereinigungs-Pause unterscheiden. Dadurch lassen sich langsame Ablaufverfolgungen einfacher analysieren und optimieren.

## Einstellung und Entfernung

### Protected Audience einstellen und entfernen

Die Protected Audience API bietet eine Methode für interessenbezogene Werbung ohne Drittanbieter-Cookies oder websiteübergreifendes Tracking von Nutzern. Nach der Ankündigung von Chrome, dass der aktuelle Ansatz für Drittanbieter-Cookies beibehalten wird, ist geplant, die Protected Audience API (zusammen mit den zugehörigen Privacy Sandbox-APIs) einzustellen und zu entfernen.

[ChromeStatus.com-Eintrag](https://chromestatus.com/feature/6552486106234880) | [Spezifikation](https://wicg.github.io/turtledove)

### Gruppen ähnlicher Websites (Related Website Sets, RWS) einstellen und entfernen

Gruppen ähnlicher Websites (Related Website Sets, RWS), früher als First-Party-Sets bezeichnet, bieten Entwicklern ein Framework, um Beziehungen zwischen Websites zu deklarieren und so einen eingeschränkten websiteübergreifenden Cookie-Zugriff für bestimmte, nutzerorientierte Zwecke zu ermöglichen. Nach der Ankündigung von Chrome, dass der aktuelle Ansatz für Drittanbieter-Cookies beibehalten wird, ist geplant, Gruppen ähnlicher Websites einzustellen und zu entfernen.

[ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5194473869017088) | [Spezifikation](https://wicg.github.io/first-party-sets)

### Shared Storage API einstellen und entfernen

Die Shared Storage API ist eine datenschutzfreundliche Web API, die Speicher ermöglicht, der nicht nach Erstanbieter-Website partitioniert ist. Nach der Ankündigung von Chrome, dass der aktuelle Ansatz für Drittanbieter-Cookies beibehalten wird, ist geplant, die Shared Storage API (zusammen mit den zugehörigen Privacy Sandbox-APIs) einzustellen und zu entfernen.

[Tracking-Fehler #462465887](https://issues.chromium.org/issues/462465887) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5076349064708096) | [Spezifikation](https://wicg.github.io/shared-storage)

### `document.requestStorageAccessFor` einstellen und entfernen

Die API `requestStorageAccessFor` (rSAFor) ist eine Erweiterung der Storage Access API, mit der eine Website der obersten Ebene im Namen eingebetteter Websites Zugriff auf nicht partitionierte („Erstanbieter“-)Cookies anfordern kann. Da sie nur in Chrome verwendet werden kann, um Speicherzugriff zwischen Websites von Gruppen ähnlicher Websites anzufordern, ist geplant, sie zusammen mit Gruppen ähnlicher Websites einzustellen und zu entfernen.

[ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5162221567082496) | [Spezifikation](https://privacycg.github.io/requestStorageAccessFor)

### Attribution Reporting API einstellen und entfernen

Die Attribution Reporting API ist eine datenschutzfreundliche Web API, mit der Anzeigen-Conversions ohne Drittanbieter-Cookies oder websiteübergreifendes Nutzer-Tracking gemessen werden können. Nach der Ankündigung von Chrome, dass der aktuelle Ansatz für Drittanbieter-Cookies beibehalten wird, ist geplant, die Attribution Reporting API (zusammen mit den zugehörigen Privacy Sandbox-APIs) einzustellen und zu entfernen.

[ChromeStatus.com-Eintrag](https://chromestatus.com/feature/6320639375966208) | [Spezifikation](https://wicg.github.io/attribution-reporting-api)

### Nicht standardmäßige Navigationen, die auf `_current` ausgerichtet sind, entfernen

Blink unterstützte zuvor Navigationen, die auf `_current` ausgerichtet waren. Diese Funktion wird in Chrome 153 entfernt, da sie nicht standardmäßig ist und nur selten im Web verwendet wird.

[Tracking-Fehler #539212797](https://issues.chromium.org/issues/539212797) | [ChromeStatus.com-Eintrag](https://chromestatus.com/feature/5121089536262144) | [Spezifikation](https://html.spec.whatwg.org/#the-rules-for-choosing-a-navigable)
