## CSS Scroll Snap

**Advertencia:** Esta publicación hace referencia a **CSS Scroll Snap**, que es el estándar actual, y no se debe confundir con _CSS Scroll Snap Points_, que dejó de estar disponible y ya no forma parte de la ruta de estándares.

[CSS Scroll Snap](https://developer.mozilla.org/docs/Web/CSS/CSS_Scroll_Snap) te permite crear experiencias de desplazamiento fluidas y elegantes, ya que declaras posiciones de ajuste de desplazamiento que le indican al navegador dónde detenerse después de cada operación de desplazamiento. Esto es muy útil para los carruseles de imágenes o las secciones paginadas en las que quieres que el usuario se desplace hasta un punto específico.

En el caso de un carrusel de imágenes, agregaría `scroll-snap-type: x mandatory;` al contenedor de desplazamiento y `scroll-snap-align: center;` a cada imagen. Luego, a medida que el usuario se desplaza por el carrusel, cada imagen se desplazará suavemente hasta la posición perfecta.

  

```
#gallery {
  scroll-snap-type: x mandatory;
  overflow-x: scroll;
  display: flex;
}

#gallery img {
   scroll-snap-align: center;
}
```

El ajuste de desplazamiento con CSS funciona bien, incluso cuando los objetivos de ajuste tienen diferentes tamaños o cuando son más grandes que el elemento de desplazamiento. Consulta la publicación [Desplazamiento bien controlado con CSS Scroll Snap](https://developers.google.com/web/updates/2018/07/css-scroll-snap?hl=es-419) para obtener más detalles y muestras que puedes probar.

## Cortes de pantalla (también conocidos como muescas)

![teléfono celular con corte de pantalla](https://developer.chrome.com/static/blog/new-in-chrome-69/image/mobile-phone-display-cut-1a79878e3b6bf.png?hl=es-419)

Los navegadores agregan un margen adicional en un dispositivo móvil con corte de pantalla para evitar que el corte cubra el contenido.

Cada vez se lanzan más [dispositivos móviles](https://www.google.com/search?q=what+phones+have+a+notch&hl=es-419) con un corte de pantalla, que a veces se denomina muesca. Para solucionar ese problema, los navegadores agregan un poco de margen adicional a tu página para que la muesca no oculte el contenido.

**¿Pero qué sucede si quieres usar ese espacio?**

Con las variables de entorno de CSS y la etiqueta meta [`viewport-fit`](https://www.w3.org/TR/css-round-display-1/#viewport-fit-descriptor), ahora puedes hacerlo. Por ejemplo, para indicarle al navegador que se expanda al área de corte de pantalla, configura la propiedad `viewport-fit` en la etiqueta meta `viewport` como `cover`.

```
<meta name='viewport' content='initial-scale=1, viewport-fit=cover'>
```

Luego, puedes usar las `safe-area-inset-*` [variables de entorno de CSS](https://drafts.csswg.org/css-env-1/) para diseñar tu contenido.

```
.content {
  padding: 16px;
  padding-left: env(safe-area-inset-left);
  padding-right: env(safe-area-inset-right);
}
```

**Nota:** **Recuerda:** Es importante probar bien esto, ya que le indicas al navegador que está bien si parte del contenido se oculta detrás del corte de pantalla. Y no olvides probarlo en modo horizontal y vertical.

En el blog de WebKit, hay una excelente publicación sobre el [diseño de sitios web para el iPhone X](https://webkit.org/blog/7929/designing-websites-for-iphone-x/). También puedes consultar la [explicación](https://docs.google.com/document/d/1lbZi18_5cMlLOphpFqTbuI4B0YGykQvvtRbw6j67UyE/preview?hl=es-419) para obtener más detalles.

## API de Web Locks

La [API de Web Locks](https://developer.mozilla.org/docs/Web/API/Web_Locks_API) te permite adquirir un bloqueo de forma asíncrona, mantenerlo mientras se realiza el trabajo y, luego, liberarlo. Mientras se mantiene el bloqueo, ningún otro script del origen puede adquirir el mismo bloqueo, lo que ayuda a coordinar el uso de recursos compartidos.

Por ejemplo, si una app web que se ejecuta en varias pestañas quiere asegurarse de que solo una pestaña se sincronice con la red, el código de sincronización intentaría adquirir un bloqueo llamado `network_sync_lock`.

```
navigator.locks.request('network_sync_lock', async lock => {
  // The lock has been acquired.
  await do_something();
  await do_something_else();
  // Now the lock will be released.
});
```

La primera pestaña que adquiera el bloqueo sincronizará los datos con la red. Si otra pestaña intenta adquirir el mismo bloqueo, se pondrá en cola. Una vez que se libere el bloqueo, se le otorgará el bloqueo a la siguiente solicitud en la cola y se ejecutará.

MDN tiene una excelente [introducción a Web Locks](https://developer.mozilla.org/docs/Web/API/Web_Locks_API) que incluye una explicación más detallada y muchos ejemplos. También puedes profundizar y consultar la [especificación](https://github.com/WICG/web-locks).

## Y mucho más

Por supuesto, estos son solo algunos de los cambios que se incluyen en Chrome 69 para desarrolladores. Hay muchos más.

![gradiente cónico](https://developer.chrome.com/static/blog/new-in-chrome-69/image/conical-gradient-31b4e21e98c89.jpg?hl=es-419)

*   Desde la especificación de CSS4, ahora puedes crear transiciones de color alrededor de la circunferencia de un círculo con [degradados cónicos](https://www.w3.org/TR/css-images-4/#gradients). [Lea Verou](https://lea.verou.me/) tiene un [polyfill de `conic-gradient()` CSS](https://leaverou.github.io/conic-gradient/) que puedes usar, y la página incluye una gran cantidad de muestras enviadas por la comunidad muy interesantes.
*   Hay un nuevo método [`toggleAttribute()`](https://developer.mozilla.org/docs/Web/API/Element/toggleAttribute) en los elementos que activa o desactiva la existencia de un atributo, de manera similar a [`classList.toggle()`](https://developer.mozilla.org/docs/Web/API/Element/classList).
*   Los arrays de JavaScript tendrán dos métodos nuevos: [`flat()` y `flatMap()`](https://developers.google.com/web/updates/2018/03/smooshgate?hl=es-419). Devuelven un array nuevo con todos los elementos de los subarrays incluidos en él.
*   Además, [`OffscreenCanvas`](https://developers.google.com/web/updates/2018/08/offscreen-canvas?hl=es-419) mueve el trabajo del subproceso principal a un subproceso de trabajo, lo que ayuda a eliminar los cuellos de botella del rendimiento.
