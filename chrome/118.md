## Regra `@scope` do CSS.

A regra `@scope` at-rule permite que os desenvolvedores definam regras de estilo para uma determinada raiz de escopo e estilizem elementos de acordo com a proximidade dessa raiz.

Com `@scope`, é possível substituir estilos com base na proximidade, o que é diferente dos estilos CSS usuais que são aplicados com base apenas na ordem da fonte e na especificidade. No exemplo abaixo, há dois temas.

```
<div class="lightpink-theme">
  <a href="#">I'm lightpink!</a>
  <div class="pink-theme">
    <a href="#">Different pink!</a>
  </div>
</div>
```

sem escopo, o estilo aplicado é o último declarado.

Sem @scope

.pink-theme a { color: hotpink; }
.lightpink-theme a { color: lightpink; }

![Dois links, o primeiro diz "I'm lightpink!", e o segundo diz "Different pink". Ambos os links são rosa claro, e o texto dos links diz "sources order declaration style".](https://developer.chrome.com/static/blog/new-in-chrome-118/image/two-links-first-reads-b3878d24257d9.jpg?hl=pt-br)

Com o escopo, é possível ter elementos aninhados, e o estilo aplicado é o do ancestral mais próximo.

Com @scope

@scope (.pink-theme) {
    a {
        color: hotpink;
    }
}

@scope (.lightpink-theme){
    a {
        color: lightpink;
    }
}

![Dois links, o primeiro diz "I'm lightpink!" (Eu sou rosa claro!) e o segundo diz "Different pink" (Rosa diferente), o segundo link é um rosa mais escuro, está abaixo do estilo de ancestral mais próximo do texto dos links e tem uma marca de seleção verde ao lado.](https://developer.chrome.com/static/blog/new-in-chrome-118/image/two-links-first-reads-bcff55df1153e.jpg?hl=pt-br)

O escopo também evita que você escreva nomes de classes longos e complicados, além de facilitar o gerenciamento de projetos maiores e evitar conflitos de nomenclatura.

Sem @scope

<div class="first-container">
  <h1 class="first-container\_\_main-title"> I'm the main title</h1>
</div>

<div class="second-container">
  <h1 class="second-container\_\_main-title"> I'm the main title, but somewhere else</h1>
</div>

.first-container\_\_main-title {
  color: grey;
}

.second-container\_\_main-title {
  color: mediumturquoise;
}

Com @scope

<div class="first-container">
  <h1 class="main-title"> I'm the main title</h1>
</div>

<div class="second-container">
  <h1 class="main-title"> I'm the main title, but somewhere else</h1>
</div>

@scope(.first-container){
  .main-title {
   color: grey;
  }
}
@scope(.second-container){
  .main-title {
   color: mediumturquoise;
  }
}

Com o escopo, também é possível estilizar um componente sem estilizar certas coisas que estão aninhadas. Você pode ter "buracos" em que o estilo de escopo não se aplica.

Como no exemplo a seguir, podemos aplicar estilo ao texto e excluir controles ou vice-versa.

![representação do HTML acima, com as palavras em escopo ao lado da primeira e da terceira div e a palavra excluída ao lado da segunda e da quarta div.](https://developer.chrome.com/static/blog/new-in-chrome-118/image/representation-the-html-f9a8ff0147b7a.jpg?hl=pt-br)

```
<div class="component">
  <div class="purple">
    <h1>Drink water</h1>
    <p class="purple">hydration is important</p>
  </div>
  <div class="click-here">
    <p>not in scope</p>
    <button>click here</button>
  </div>

  <div class="purple">
    <h1 class="purple">Exercise</h1>
    <p class="purple">move it move it</p>
  </div>

  <div class="link-here">
    <p>Excluded from scope</p>
    <a href="#"> link here </a>
  </div>
</div>
```

```
@scope (.component) to (.click-here, .link-here) {
  div {
    color: purple;
    text-align: center;
    font-family: sans-serif;
  }
}
```

Confira o artigo [Limitar o alcance dos seletores com a regra @scope do CSS](https://developer.chrome.com/articles/at-scope?hl=pt-br) para mais informações.

## Recurso de mídia `prefers-reduced-transparency`

Usamos consultas de mídia para oferecer experiências que se adaptam às preferências e condições do dispositivo do usuário. Essa versão do Chrome adiciona um novo valor que pode ser usado para adaptar a experiência do usuário: `prefers-reduced-transparency`.

Um novo valor que você pode testar com consultas de mídia é `prefers-reduced-transparency`, que permite que os desenvolvedores adaptem o conteúdo da Web à preferência selecionada pelo usuário para reduzir a transparência no SO, como a configuração "Reduzir transparência" no macOS. As opções válidas são `reduce` ou `no-preference`.

```
.translucent {
  opacity: 0.4;
}

@media (prefers-reduced-transparency) {
  .translucent {
    opacity: 0.8;
  }
}
```

Confira como fica com o DevTools:

Para mais informações, consulte a documentação [prefers-reduced-transparency](https://developer.mozilla.org/docs/Web/CSS/@media/prefers-reduced-transparency).

_Correção: uma versão anterior deste artigo se referia a um novo recurso de mídia [`scripting`](https://developer.mozilla.org/docs/Web/CSS/@media/scripting) incluído nesta versão. Na verdade, será na versão 120._

## Melhorias no painel "Origens" do DevTools

O DevTools tem as seguintes melhorias no painel **Origens**: o recurso [espaço de trabalho](https://developer.chrome.com/docs/devtools/workspaces?hl=pt-br) melhorou a consistência, principalmente renomeando o painel **Origens** > **Sistema de arquivos** para **Espaço de trabalho**, além de outros textos da interface. O [**Origens** > **Espaço de trabalho**](https://developer.chrome.com/docs/devtools/workspaces?hl=pt-br) também permite sincronizar as mudanças feitas no DevTools diretamente nos arquivos de origem.

Além disso, agora é possível reordenar os painéis no lado esquerdo do painel **Origens** arrastando e soltando. O painel **Origens** agora pode mostrar JavaScript inline nos seguintes tipos de script: [`module`](https://developer.mozilla.org/docs/Web/JavaScript/Guide/Modules), [`importmap`](https://developer.mozilla.org/docs/Web/HTML/Element/script/type/importmap), [`speculationrules`](https://developer.chrome.com/docs/devtools/application/debugging-speculation-rules?hl=pt-br) e destacar a sintaxe dos tipos de script `importmap` e `speculationrules`, que contêm JSON.

![Antes e depois da impressão bonita e do destaque de sintaxe do tipo de script de regras de especulação.](https://developer.chrome.com/static/blog/new-in-chrome-118/image/before-after-pretty-prin-e339f766d1a5f.png?hl=pt-br)

Confira [Novidades do Chrome DevTools](https://developer.chrome.com/blog/new-in-devtools-118?hl=pt-br) para saber mais sobre as atualizações do Chrome DevTools 118.

## E muito mais.

Claro que há muito mais.

*   A [API WebUSB](https://developer.chrome.com/articles/usb?hl=pt-br) agora está exposta a [service workers registrados por extensões do navegador](https://developer.chrome.com/docs/extensions/mv3/service_workers?hl=pt-br), permitindo que os desenvolvedores usem a API ao responder a eventos de extensão.
    
*   Para ajudar os desenvolvedores a reduzir o atrito nos fluxos de solicitação de pagamento, removemos a exigência de ativação do usuário em `Payment Request` e `Secure Payment Confirmation`.
    
*   [O ciclo de lançamentos do Chrome está ficando mais curto](https://developer.chrome.com/blog/faster-chrome-releases-round2?hl=pt-br). As versões estáveis serão lançadas a cada três semanas, começando com o Chrome 119, que será lançado em três semanas.
