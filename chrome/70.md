## Windows 和 Linux 上的桌面版漸進式網頁應用程式

**使用者現在可以在 Windows 和 Linux 上安裝電腦版漸進式網頁應用程式！**

 

安裝完成後，系統會透過「開始」功能表啟動這些應用程式，並以與其他已安裝應用程式相同的方式執行，但不會顯示網址列或分頁。[服務工作者](https://developers.google.com/web/fundamentals/primers/service-workers/?hl=zh-tw)可確保應用程式快速可靠，讓使用者在[應用程式視窗](https://developers.google.com/web/updates/2018/05/dpwa?hl=zh-tw#the_app_window)中獲得與其他已安裝應用程式相同的體驗。

開始使用這項服務的步驟與您目前所做的並無二致。您為現有漸進式網頁應用程式所做的所有工作，仍適用於這個新版應用程式！如果您的應用程式符合標準的 [PWA 標準](https://developers.google.com/web/fundamentals/app-install-banners/?hl=zh-tw#criteria)，Chrome 就會觸發 [`beforeinstallprompt`](https://developers.google.com/web/fundamentals/app-install-banners/?hl=zh-tw#listen_for_beforeinstallprompt) 事件。儲存事件，然後[新增一些 UI](https://developers.google.com/web/fundamentals/app-install-banners/?hl=zh-tw#notify_the_user_your_app_can_be_installed) (例如安裝應用程式按鈕)，告訴使用者可以安裝您的應用程式。接著，當使用者按下按鈕時，請針對儲存的事件呼叫 [`prompt()`](https://developers.google.com/web/fundamentals/app-install-banners/?hl=zh-tw#show_the_prompt)；Chrome 就會向使用者顯示提示。如果使用者按一下「新增」，Chrome 就會將 PWA 新增至其開始功能表和電腦桌面。

詳情請參閱我的[電腦版 PWA](https://developers.google.com/web/progressive-web-apps/desktop?hl=zh-tw) 文章。

**注意：**Mac 支援功能預計會在 Chrome 72 推出。在 Chrome 70 中新增了 Linux 支援功能，但在本篇文章的原始版本中不小心遺漏了這項資訊。

## 憑證管理 API：公開金鑰憑證

[Credential Management API](https://developer.mozilla.org/docs/Web/API/Credential_Management_API) 可讓使用者輕鬆登入。這可讓您的網站與瀏覽器的[憑證管理工具](https://developer.mozilla.org/docs/Web/API/PasswordCredential)或 Google 和 Facebook 等[聯合帳戶服務](https://developer.mozilla.org/docs/Web/API/FederatedCredential)互動，以便進行登入。

![](https://developer.chrome.com/static/blog/new-in-chrome-70/image/dlNQwA1kTHjDdHTTOPMK.png?hl=zh-tw)

Chrome 70 新增了第三種憑證：[**公開金鑰憑證**](https://developer.mozilla.org/docs/Web/API/PublicKeyCredential)，可讓網頁應用程式建立及使用強大的加密認證，並在應用程式範圍內使用憑證，以便驗證使用者。

我對這項功能感到非常興奮，因為它可讓網站使用我的指紋進行雙重驗證。但也支援其他類型的安全金鑰，並提供更完善的網路安全防護。

如需更多詳細資訊，請參閱 [Credential Management API 說明文件](https://developers.google.com/web/fundamentals/security/credential-management/?hl=zh-tw)，或試試 [WebAuthn 示範](https://webauthndemo.appspot.com/?hl=zh-tw)，瞭解如何開始使用！

## 名稱為 `workers`

[Workers](https://developer.mozilla.org/docs/Web/API/Worker) 是將 JavaScript 從主執行緒移至背景的簡單方法。這對於維持網站互動性至關重要，因為這表示在執行耗時或複雜的 JavaScript 運算時，主執行緒不會鎖定。

**不使用 WebWorkers**

![](https://www.gstatic.com/images/icons/material/system/2x/settings_black_48dp.png)

**主執行緒**  
執行大量繁重的 JavaScript，導致使用者體驗變慢且不流暢。

**使用 WebWorkers**

![](https://www.gstatic.com/images/icons/material/system/2x/settings_black_48dp.png)

**主執行緒**  
不會執行大量 JavaScript，因此可提供快速流暢的體驗。

![](https://www.gstatic.com/images/icons/material/system/2x/settings_black_48dp.png)

**WebWorker**  
執行大量繁重的 JavaScript，不會影響主執行緒。

在 Chrome 70 中，worker 現已具有 [`name` 屬性](https://www.chromestatus.com/feature/4594144336936960)，該屬性是由建構函式中的選用引數指定。

```
const url = '/scripts/my-worker.js';
const wNYC = new Worker(url, {name: 'NewYork'});
const oSF = {name: 'SanFrancisco'};
const wSF = new Worker(url, oSF);
```

當您有多個使用相同網址的 worker 時，這可讓您透過 `name` 區分專屬 worker。您也可以在 DevTools 主控台中列印名稱，這樣就能更輕鬆地瞭解您要對哪個 worker 進行偵錯！

在 Firefox、Edge 和 Safari 中，您可以為 worker 命名。詳情請參閱 [GitHub 上的討論串](https://github.com/whatwg/html/issues/2477)。

當然，這只是 Chrome 70 中針對開發人員的部分異動內容，還有更多內容。
